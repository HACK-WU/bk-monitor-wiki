## 简介

采集配置落盘后必须通知 `bkunifylogbeat` 重新加载才能生效。本篇讲两件平台相关的事：

1. **配置重载 `reloadBkunifylogbeat`**：Linux/Darwin 通过读 pid 文件后发 `SIGUSR1` 信号；Windows 通过写"信号文件"触发；
2. **containerd 路径解析 `resolveContainerdV2Path`**：为 CRI 容器计算根路径与真实日志路径，各平台策略不同。

这两个函数用 Go 的构建标签（build tag）按平台分文件实现，接口签名一致、行为按平台特化。

## 组件详细分析

### Linux/Darwin 重载：SIGUSR1

Linux 与 Darwin 实现完全一致，流程：

1. `ioutil.ReadFile(config.BkunifylogbeatPidFile)` 读 pid 文件；
2. `scanPidLine` 解析 pid——用 `fmt.Sscanln` 读一个整数，内容空/解析失败/非正数均返回 `-1`；
3. `os.FindProcess(pid)` 取进程；
4. `proc.Signal(syscall.SIGUSR1)` 发送信号。

`bkunifylogbeat` 约定收到 `SIGUSR1` 后重新加载配置目录。任一步失败返回 error，上层通过 `CheckErrorFn` 记录日志但不中断主流程。

```go
pid := scanPidLine(pidContent)
if pid <= 0 {
	return fmt.Errorf("not get pid")
}
proc, err := os.FindProcess(pid)
// ...
err = proc.Signal(syscall.SIGUSR1)
```

Darwin 实现与 Linux 相同，主要为方便在 macOS 上本地开发调试（`SIGUSR1` 在类 Unix 系统通用）。

### Windows 重载：信号文件

Windows 没有 `SIGUSR1`，改为**写文件触发**：`os.Create(config.WindowsReloadPath)` 创建/覆盖信号文件并写入 `"signal"`。`bkunifylogbeat` 的 Windows 版监视该文件变更来触发重载。实现更简单，无需 pid 解析。

```go
f, err := os.Create(config.WindowsReloadPath)
// ...
_, err = f.Write([]byte("signal"))
```

### containerd 路径解析：resolveContainerdV2Path

该函数在 `ContainerdRuntime.Inspect`（《06》）中被调用，为 CRI 容器返回 `(rootPath, logPath, error)`。

Linux/Darwin 策略：

- **根路径**：`pid != 0` 时用 `/proc/{pid}/root`（进程命名空间视角的容器根文件系统）；`pid == 0`（拿不到进程）时**回退**拼接 containerd state 路径：`{ContainerdStatePath}/io.containerd.runtime.v2.task/{ContainerdNamespace}/{容器ID}/rootfs`；
- **日志路径**：取 CRI status 的 `LogPath`，再用 `define.EvalSymlinks`（《05》）解析软链得到真实路径；解析失败则保留原 LogPath 并返回 error。

Windows 策略：直接返回空根路径与原始 `LogPath`（不做 /proc 与软链解析，因平台不支持）。

```go
rootPath := fmt.Sprintf("/proc/%d/root", pid)
if pid == 0 {
	rootPath = filepath.Join(config.ContainerdStatePath, ContainerdTaskDirName,
		config.ContainerdNamespace, containerStatus.Status.Id, ContainerdRootFsDirName)
}
realLogPath, err := define.EvalSymlinks(logPath)
if err == nil {
	logPath = realLogPath
}
```

配置重载与路径解析通过 Go 构建标签实现"接口统一、平台特化"：Linux/Darwin 用 `SIGUSR1` 通知重载并支持 `/proc` + 软链的精确路径解析，Windows 用信号文件重载并退化路径解析。这一层是采集配置真正生效的最后触发点，也是模块跨平台运行的适配基础。
