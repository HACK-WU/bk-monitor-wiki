## 简介

bk-log-sidecar 是标准的 controller-runtime 管理器（manager），其配置由**命令行参数**与**环境变量**两部分驱动：

- 框架层参数由 `controller-runtime` 注入（metrics、health probe、zap 日志）；
- 业务层参数由 `config.FlagInit()` 在自己的 `flag.CommandLine` 上注册（CRI 地址、agent pid 文件、bk_env 等）；
- 节点身份与环境变量通过 `os.Getenv` 读取，用于「单节点缓存过滤」与 vcluster 适配。

本篇梳理全部参数、环境变量、常量及 `main()` 的启动装配顺序。

## 命令行参数总览

`main()` 在 `flag.Parse()` 之前显式注册了 2 个框架参数并绑定 zap 的日志 flag：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--metrics-bind-address` | `:8080` | Prometheus 指标端点（`MetricsBindAddress`） |
| `--health-probe-bind-address` | `:8081` | 健康检查/就绪检查探针端点（`HealthProbeBindAddress`） |
| `--zap-*` | — | zap 日志选项（`opts.BindFlags(flag.CommandLine)`，`Development: true`） |

zap flag 包括 `--zap-devel`、`--zap-encoder`、`--zap-log-level`、`--zap-stacktrace-level` 等，由 `sigs.k8s.io/controller-runtime/pkg/log/zap` 提供。

```go
flag.StringVar(&metricsAddr, "metrics-bind-address", ":8080", "The address the metric endpoint binds to.")
flag.StringVar(&probeAddr, "health-probe-bind-address", ":8081", "The address the probe endpoint binds to.")
opts := zap.Options{Development: true}
opts.BindFlags(flag.CommandLine)
flag.Parse()
```

| `ContainerdAddress` | `--containerd-address` | `/run/containerd/containerd.sock` | containerd socket 地址 |
| `ContainerdStatePath` | `--containerd-state-path` | `/run/containerd` | containerd state 目录（路径回退用） |
| `DockerSocket` | `--docker-socket` | `unix:///var/run/docker.sock` | docker socket |

| `BkunifylogbeatPidFile` | `--bkunifylogbeat-pid-file` | `""` | bkunifylogbeat pid 文件（SIGUSR1 用） |

## 环境变量

除命令行参数外，节点身份与 vcluster 注解键由环境变量决定：

| 用途 | 变量/常量 | 默认值 | 说明 |
|------|-----------|--------|------|
| 节点身份 | `CurrentNodeNameKey` = `MY_NODE_NAME` | 无 | 用于缓存 filter 与「单节点」运行（见下节） |
| vcluster Pod 名 | `VCLUSTER_POD_NAME_ANNOTATION_KEY` | `vcluster.loft.sh/name` | 可被环境变量覆盖 |
| vcluster Pod UID | `VCLUSTER_POD_UID_ANNOTATION_KEY` | `vcluster.loft.sh/uid` | 同上 |
| vcluster 命名空间 | `VCLUSTER_POD_NAMESPACE_ANNOTATION_KEY` | `vcluster.loft.sh/namespace` | 同上 |
| vcluster 工作负载名 | `VCLUSTER_WORKLOAD_NAME_ANNOTATION_KEY` | `vcluster.loft.sh/owner-set-name` | 同上 |
| vcluster 工作负载类型 | `VCLUSTER_WORKLOAD_TYPE_ANNOTATION_KEY` | `vcluster.loft.sh/owner-set-kind` | 同上 |
| vcluster 标签 | `VCLUSTER_LABELS_ANNOTATION_KEY` | `vcluster.loft.sh/labels` | 同上 |
| vcluster 标签键 | `VCLUSTER_LABEL_KEY` | `vcluster.loft.sh/managed-by` | 用于 `IsVclusterPod` 判断 |
| vcluster 管理注解 | `VCLUSTER_MANAGED_ANNOTATIONS_KEY` | `vcluster.loft.sh/managed-annotations` | 同上 |

其中 vcluster 相关键通过 `GetEnvDefault(envVar, defaultValue)` 求值：环境变量存在且非空时取环境变量，否则用默认值。

```go
VclusterPodNameAnnotationKey = GetEnvDefault("VCLUSTER_POD_NAME_ANNOTATION_KEY", "vcluster.loft.sh/name")
// ... 其余 7 个同理

func GetEnvDefault(envVar string, defaultValue string) string {
	if v, ok := os.LookupEnv(envVar); ok && len(v) > 0 {
		return v
	}
	return defaultValue
}
```

## 配置常量与辅助函数

`config/constant.go` 定义了领域常量（均为编译期常量，除 vcluster 注解键外）：

- **容器标签键**：`ContainerLabelK8sContainerName/PodName/PodNamespace`（`io.kubernetes.container.name` 等），用于 Docker 事件解析容器元数据；
- **配置类型**：`StdLogConfig`/`ContainerLogConfig`/`NodeLogConfig`（`std_log_config`/`container_log_config`/`node_log_config`），对应《02》三种 CR；
- **输入类型**：`StdLogConfigInput`/`ContainerLogConfigInput`/`NodeLogConfigInput` 均为 `"tail"`；
- **环境标签键**：`BkEnvLabelName = "bk_env"`，配合 `BkEnv`（命令行）做环境匹配；
- **节点名键**：`CurrentNodeNameKey = "MY_NODE_NAME"`。

## 启动流程与节点亲和

`main()` 装配顺序：

1. `init()`：注册 `clientgoscheme` + `bluekingv1alpha1` 到 `scheme`，调用 `config.FlagInit()`；
2. `flag.Parse()` 解析全部参数；
3. `ctrl.NewManager`：除 `Scheme`、`MetricsBindAddress`(`:8080`)、`Port`(9443)、`HealthProbeBindAddress`(`:8081`) 外，关键点是 `NewCache`——用 `os.Getenv(config.CurrentNodeNameKey)` 对 `Pod`/`Node` 做 `fields.Selector` 过滤，**只缓存本节点的 Pod 与同名 Node**，实现「单节点 DaemonSet」的本地缓存亲和；
4. `NewBkLogSidecar(mgr)` + `BkLogConfigReconciler{...}.SetupWithManager(mgr)` 注册 CRD 控制器；
5. `AddHealthzCheck("healthz", healthz.Ping)` / `AddReadyzCheck("readyz", healthz.Ping)`；
6. `mgr.Add(bkLogSidercar)` 注册 `Runnable`；
7. `HttpProf != ""` 时协程 `http.ListenAndServe(config.HttpProf, nil)` 暴露 pprof；
8. `ctrl.SetupSignalHandler()` 捕获信号，`mgr.Start(ctx)` 阻塞运行；`ctx.Done()` 后调用 `bkLogSidercar.Stop()`。

```go
NewCache: cache.BuilderWithOptions(cache.Options{
	SelectorsByObject: cache.SelectorsByObject{
		&corev1.Pod{}:  {Field: fields.SelectorFromSet(fields.Set{"spec.nodeName": os.Getenv(config.CurrentNodeNameKey)})},
		&corev1.Node{}: {Field: fields.SelectorFromSet(fields.Set{"metadata.name": os.Getenv(config.CurrentNodeNameKey)})},
	},
})
// ...
if config.HttpProf != "" {
	go func() { _ = http.ListenAndServe(config.HttpProf, nil) }()
}
```

## 结论

bk-log-sidecar 的配置是「框架参数 + 业务 flag + 环境变量」三层组合：框架层负责 metrics/health/zap；业务层（`config.FlagInit`）负责 CRI 地址、agent pid/config 路径、`bk_env`、pprof 等运行参数；环境变量提供节点身份（`MY_NODE_NAME`）与 vcluster 注解键覆盖。其中 `MY_NODE_NAME` 通过缓存选择器实现单节点缓存，是整个 sidecar「每节点只管自己」的运行基础。
