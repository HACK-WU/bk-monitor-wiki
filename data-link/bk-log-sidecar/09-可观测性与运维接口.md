## 简介

作为长期运行的 DaemonSet 组件，bk-log-sidecar 通过 controller-runtime 自带能力暴露四类运维接口：**日志**、**指标**、**健康探针**、**pprof**。本篇梳理这些接口的来源、注册方式与使用场景，便于排障与监控接入。

## 日志（zap）

日志统一走 controller-runtime 的 zap logger：

- `opts := zap.Options{Development: true}` → `opts.BindFlags(flag.CommandLine)` 注入 `--zap-*` 系列 flag；
- `ctrl.SetLogger(zap.New(zap.UseFlagOptions(&opts)))` 设为全局 logger；
- 业务代码通过 `ctrl.Log.WithName("xxx")` 取带名字段的子 logger（如 `setup`、`utils`），结构化输出 level/msg/caller。

```go
opts := zap.Options{Development: true}
opts.BindFlags(flag.CommandLine)
flag.Parse()
ctrl.SetLogger(zap.New(zap.UseFlagOptions(&opts)))
```

## 指标（Prometheus）

模块自定义唯一指标 `container_cache_total`，用于统计容器内缓存数量，维度为 `cri`：

- `prometheus.NewCounterVec`，`Subsystem: "cri"`，`Name: "container_cache_total"`，`Help: "current cache container count"`，标签 `[cri]`；
- 通过 `clmetrics.Registry.MustRegister(...)` 注册到 controller-runtime 的全局 Prometheus registry（地址即 `--metrics-bind-address`，默认 `:8080`，路径 `/metrics`）；
- 对外暴露函数 `NewContainerCacheTotal(cri string) prometheus.Counter`，调用方 `WithLabelValues(cri)` 后 `Inc()`，在《05》容器缓存命中时递增。

```go
containerCacheTotal = prometheus.NewCounterVec(prometheus.CounterOpts{
	Subsystem: "cri",
	Name:      "container_cache_total",
	Help:      "current cache container count",
}, []string{"cri"})

func NewContainerCacheTotal(cri string) prometheus.Counter {
	return containerCacheTotal.WithLabelValues(cri)
}

func init() {
	clmetrics.Registry.MustRegister(containerCacheTotal)
}
```

> 该指标是观察 sidecar「识别到了多少容器」的核心观测点，建议接入监控后配置缓存数趋势告警。

## 健康检查与就绪检查

通过 controller-runtime 的 `healthz.Ping` 注册两个探针，均绑定 `--health-probe-bind-address`（默认 `:8081`）：

```go
if err := mgr.AddHealthzCheck("healthz", healthz.Ping); err != nil { ... }
if err := mgr.AddReadyzCheck("readyz", healthz.Ping); err != nil { ... }
```

`healthz.Ping` 默认只检测 manager 的 runnable 是否启动，作为 K8s `livenessProbe`/`readinessProbe` 的 HTTP 端点。

## pprof 性能分析

模块内置 pprof，由 `--httpprof` 控制（默认 `127.0.0.1:16060`，空字符串关闭）：

- `main.go` 顶部 `_ "net/http/pprof"` 匿名导入，路由挂在默认 `http.DefaultServeMux`；
- `config.HttpProf != ""` 时启动协程 `http.ListenAndServe(config.HttpProf, nil)`，暴露 `/debug/pprof/` 系列端点（goroutine、heap、profile 等）。

```go
if config.HttpProf != "" {
	go func() {
		err = http.ListenAndServe(config.HttpProf, nil)
		// ...
	}()
}
```

> 默认只监听 `127.0.0.1`，需进入容器或经 `kubectl port-forward` 才能访问；生产环境排障时临时改参数为 `0.0.0.0:16060` 即可远程抓取。

## 优雅启动与停止

- `ctrl.SetupSignalHandler()` 返回带 cancel 的 `context.Context`，捕获 `SIGINT`/`SIGTERM`；
- `mgr.Start(ctx)` 阻塞运行 controller 与全部 Runnable（含 `bkLogSidercar`）；
- `<-ctx.Done()` 收到停止信号后，显式调用 `bkLogSidercar.Stop()` 释放资源（如停止事件监听、清理容器缓存），再退出进程。

```go
setupLog.Info("starting manager")
ctx := ctrl.SetupSignalHandler()
if err := mgr.Start(ctx); err != nil {
	setupLog.Error(err, "problem running manager")
	os.Exit(1)
}
<-ctx.Done()
bkLogSidercar.Stop()
```

## 结论

bk-log-sidecar 的可观测性全部构建在 controller-runtime 标准能力之上：zap 提供结构化日志，`:8080/metrics` 暴露 `cri_container_cache_total` 缓存指标，`:8081` 提供 healthz/readyz 探针，`:16060` 可选暴露 pprof。运维侧只需按 K8s 探针约定接入 `:8081`、按 Prometheus scrape 接入 `:8080`，即可完成基本监控与排障。
