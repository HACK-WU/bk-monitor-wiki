## 简介

`store` 包为 BMW 的元数据/配置/缓存提供统一的键值存储抽象，屏蔽 Redis、Consul、MySQL、Elasticsearch、InfluxDB、Memcache、bbolt 等多种后端差异。上层业务（如 relation 元数据、告警 CMDB 缓存、周期任务存储）通过 `Store` 接口读写，按场景选用不同后端。本篇梳理接口与各后端实现要点。

## Store 接口

```go
type Store interface {
	Open() error
	Put(key, val string, modifyIndex uint64, expiration time.Duration) error
	Get(key string) (uint64, []byte, error)
	Delete(key string) error
	Close() error
}
```

`Put` 的 `modifyIndex` 支持 CAS 语义（Consul 等后端据此做并发安全写入）。附 `DummyStore`（全部空实现）与 `CreateDummyStore()` 供测试/无存储场景使用。各后端在 `store/utils.go` 提供 `String2byte`（unsafe 零拷贝 string→[]byte）。

## Redis 后端（存储/依赖/缓存）

`store/redis/redis.go` 提供三类单例：

- `GetStorageRedisInstance()`（`StorageRedis*` 配置）：通用存储型 Redis；
- `GetCacheRedisInstance()`（`StorageDependentRedis*` 配置）：依赖/缓存型 Redis；
- 实现 `Open/Put/Get/Delete/Close`：`Put=SET`（带过期）、`Get=GET`、`Delete=EXISTS+DEL`。

配置侧（`config.go`）三类 Redis 各有独立连接参数：`BrokerRedis*`（broker 队列）、`StorageRedis*`（存储）、`StorageDependentRedis*`（依赖缓存），支持 standalone / sentinel 两种模式。

- `store/influxdb/influxdb.go`：`GetClient`/`QueryDB` 封装 InfluxDB v1 客户端，用于时序指标查询；

## 结论

`store` 以统一的 5 方法 `Store` 接口屏蔽 7 种后端差异：Redis（存储/依赖/缓存三类单例）承载通用 KV 与周期任务，Consul 提供 CAS 安全的全局配置，MySQL 承载关系型元数据，Elasticsearch 适配多版本日志检索，InfluxDB 管时序，Memcache(ristretto) 做进程内缓存，bbolt 做嵌入式持久化。配置体系（`config.go`）为每类后端提供独立的连接与超时参数，使 BMW 能在不同部署环境下灵活组合存储后端。
