## 简介

`config` 包基于 viper 实现配置加载，支持「YAML 文件 + 环境变量覆盖」，并为 Redis/Consul/MySQL/ES 等十余类组件提供集中配置项。配套 `common` 包定义队列相关常量与默认值。本篇梳理加载机制、配置项分类、关键默认值，以及 `common` 常量。

## 配置加载机制

- `FilePath`（默认 `./bmw.yaml`）由根命令 `--config` 指定；
- `InitConfig()`：`viper.SetConfigFile(FilePath)` 读文件 → `AutomaticEnv()` + `SetEnvPrefix("bmw")` + 环境变量分隔符 `.`→`_`（如 `bmw_worker_queues`）→ `keys=viper.AllKeys()` → 依次调用 `initVariables`/`initMetadataVariables`/`initClusterMetricVariables`/`initApmVariables`/`initAlarmConfig` 填满全局变量；
- `GetValue[T any](key, def, getter...)`：泛型取值，先校验 key 是否在 `keys` 中（Map 类型除外），再从 viper 读取并按类型（含 slice 逐元素类型校验）转换，缺失或异常回退默认值。

```go
func InitConfig() {
	viper.SetConfigFile(FilePath)
	viper.ReadInConfig()
	viper.AutomaticEnv(); viper.SetEnvPrefix("bmw")
	viper.SetEnvKeyReplacer(strings.NewReplacer(".", "_"))
	keys = viper.AllKeys()
	initVariables(); initMetadataVariables(); ...
}
```

## 业务配置

`config` 包按业务拆分初始化函数与独立文件：

- `initMetadataVariables` / `metadata_config.go`：元数据计算相关配置；
- `initClusterMetricVariables` / `clustermetric_config.go`：集群指标（如 `ESClusterMetricReport*`）配置；
- `initApmVariables` / `apm_config.go`：APM 预计算配置；
- `initAlarmConfig` / `alarm_config.go`：告警相关配置。

这些函数由 `InitConfig` 在一次加载中统一调用，保证全量配置就绪。

## SchemaProvider

`SchemaProviderType`（键 `schemaProvider.type`，默认 `static`）控制「元数据 schema 提供方」：

- `static`：使用硬编码 schema；
- `redis`：从 Redis 动态获取；
- 空：同 static 兜底。

`cmd/worker.go` 在启动时 `relation.NewProviderManager(ctx, ..., SchemaProviderType, redisClient, ...)` 初始化 `SchemaProvider`，失败则**优雅降级**（日志告警，继续以 nil provider 运行）。`internal/relation` 通过 `InitSchemaProvider` 接收。

## 结论

BMW 配置体系以 viper 为核心，`InitConfig` 一次性从 `bmw.yaml` + `bmw_*` 环境变量加载并填入全局变量，配合泛型 `GetValue` 做类型安全取值；配置覆盖日志、三类 Redis、Consul、MySQL、ES、bbolt、Worker/Scheduler 参数、三套 HTTP 端口（10211/10212/10213）、加密与网关、SchemaProvider 等。`common` 包提供队列 key 与框架默认常量，与 `config` 的运行时默认值形成双层兜底。整套配置驱动了 BMW 在不同部署形态下的行为。
