## 简介

`define` 包是整个 collector 的数据契约中心，定义了在 Receiver、Processor、Exporter 之间流转的核心类型：`Record`（处理单元）、`Token`（鉴权与路由）、`Task`（调度单元）、`Event`（派生事件）以及并发与配置的常量。理解这些结构是理解后续各层的基础。

本节为概念性内容，不直接分析具体文件。

## Record 与 RecordType

`Record` 是 Processor 链传输的数据类型，包含：`RecordType`（数据类型）、`RequestType`（请求类型：http/grpc/icmp/derived/tars）、`RequestClient`（客户端 IP）、`Token`（鉴权信息）、`Metadata`（元数据 map）、`Data`（any，按类型承载具体协议数据）。`Unwrap()` 将 `*.derived` 类型还原为原始类型，用于派生后回流处理。

`RecordType` 枚举了全部数据类型：`traces`/`metrics`/`logs`/`profiles` 及其派生 `*.derived`，以及协议专有类型 `pushgateway`/`remotewrite`/`proxy`/`pingserver`/`fta`/`beat`/`tars`/`logpush`。`IntoRecordType` 将字符串转为 `RecordType` 并返回是否 Derived（以 `.derived` 后缀判断）。

常量区定义了各协议 `Source*` 前缀（如 `SourceOtlp="otlp"`）与鉴权 `Key*`（如 `KeyToken="X-BK-TOKEN"`、`KeyDataID="X-BK-DATA-ID"`、`KeyTenantID="X-Tps-TenantID"`），用于 HTTP Header 解析路由。

## Token 与 DataID 路由

`Token` 承载 Record 校验与路由所需信息：`Type`、`Original`（原始 token 串）、`BizId`、`AppName`、`MetricsDataId`/`TracesDataId`/`ProfilesDataId`/`LogsDataId`/`ProxyDataId`/`BeatDataId` 等多个 DataID。`BizApp()` 返回 `bk_biz_id-bk_app_name` 拼接串，`GetDataID(rtype)` 依据 `RecordType` 返回对应 DataID（如 traces→TracesDataId、metrics 系列→MetricsDataId、logs→LogsDataId、proxy→ProxyDataId），这是 Record 路由到具体 Pipeline 的核心依据。

`SetTokenInfo` 将解码出的 Token 暴露为 Prometheus 指标 `receiver_token_info` 便于观测。

## Task 调度单元

`Task` 代表调度单元，接口暴露：`PipelineName()`（所属流水线）、`Record()`（处理数据）、`StageCount()`（处理器步骤数）、`StageAt(i)`（第 i 个处理器名）。`task` 私有实现持有 `pipelineName`、`processors []string`、`record`，由 `NewTask` 构造。`TaskQueue` 是基于 channel 的 `Task` 队列，容量 `Concurrency()*QueueAmplification`，`Push` 区分 `Guarantee`（阻塞）与 `DropIfFull`（满丢弃），`Get` 返回只读 channel。

## Event 与队列

`Event` 接口用于派生事件：`DataId()`、`Data()`（common.MapStr）、`RecordType()`、`Token()`。`CommonEvent` 是默认实现，`NewCommonEvent` 构造。`GatherFunc` 为事件收集回调。`EventQueue` 是基于 `[]Event` 的 channel 队列，容量与 Push 语义同 `TaskQueue`。派生类 Processor（如 tracesderiver）常通过 `EventQueue` 把生成的事件回流到后续处理。

## 并发模型

`concurrency.go` 定义并发基座：`QueueAmplification = 2`、`AcquireTimeout = 5s`、`Concurrency() = coreNum * 2`、`CoreNum()`、`SetCoreNum(n)`（<=0 忽略并同步 `GOMAXPROCS`）。所有队列容量均按 `Concurrency()*QueueAmplification` 计算，保证 worker 数与队列缓冲成比例。`PushMode`（`Guarantee`/`DropIfFull`）在 Record/Task/Event 三类队列中统一生效。

## 子配置 SubConfig

子配置通过常量区分作用域：`SubConfigFieldDefault/Service/Instance`。配置类型常量 `ConfigTypePrivileged/Platform/SubConfig/ReportV2/Report` 标识来源；字段常量 `ConfigFieldApmConfig/Processor/Pipeline/Receiver/Pusher/Exporter/Proxy/Pingserver/Cache` 标识配置归属的子树。`ApmConfig` 含 `Patterns []string`，用于 APM 相关匹配。这些常量被 `confengine` 用于三级查找与配置分发（详见 `10-配置系统ConfEngine`）。

## 结论

`define` 包以 `Record` 为流转核心，用 `Token.GetDataID` 完成 DataID 路由，`Task`/`Event` 作为调度与派生载体，配合 `concurrency` 的并发基座与 `subconfig` 的配置常量，为 Receiver、Processor、Exporter、Controller 各层提供了统一且解耦的数据契约。
