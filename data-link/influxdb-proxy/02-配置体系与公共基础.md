## 全局配置对象

`common` 包维护一个进程级全局配置对象 `Config`（`Configuration` 接口实例），几乎所有子包读取配置都走它，并通过 `sync.RWMutex` 保护并发读写。具体实现 `ViperConfiguration` 基于 viper，`ReloadConfigFile` 负责重新加载配置文件。

- `hook.go`：`Config Configuration` 全局变量、`NewConfiguration`、`Lock sync.RWMutex`。
- `define.go`：`Configuration` 接口（含 `ReloadConfigFile`）。
- `config.go`：`ViperConfiguration` 结构体、`ReloadConfigFile`、`NewViperConfiguration`。
- `const.go`：kafka/backend/http/consul 等配置键常量。

## 事件驱动初始化

配置的加载不是一次性硬编码，而是通过**事件总线**解耦各子包的默认值注入与自身初始化：`common.ReloadConfigFile` 在解析前后分别发布 `EvSysConfigPreParse` / `EvSysConfigPostParse` 事件，`http.config.go` 与 `logging.logger.go` 各自订阅，完成本子包的默认值设置与日志器初始化。这样新增子包无需修改配置主流程，只需订阅事件即可。

## Tag 解析与路由生成

`common/tags.go` 是整个代理**路由决策的核心算法来源**，提供 Tag 维度解析与 backend 路由生成：

- `GenerateBackendRoute`：根据 tag 集合生成 backend 路由键，被 `cluster`、`transport`、`http/rebalance` 共用，是「按 tag 分片到 backend」的唯一算法入口。
- `GetTagsKey` / `AnaylizeTagsKey` / `GetTags` / `GetSelectTag`：tag key 的拼装、解析、提取与 select 维度识别。

这保证了 route/cluster/transport 三处对「同一份 tag 数据应如何落到哪个 backend」的认知一致，是可热更新、无状态纯函数。

## FlowID 追踪

`common/flowid.go` 的 `GetFlow` 从请求头 `X-Trace-ID` 取出或生成 FlowID，并贯穿查询/写入全链路，用于日志串联与问题定位。配合 `common/metric.go` 的 `PanicCountInc` 等，构成基础可观测性支撑。

## 事件总线与统一日志

`golang/eventbus` 提供全局 `Bus`（`Publish` / `Subscribe` / `SubscribeAsync` / `SubscribeOnce` / `Unsubscribe`），是 `common` / `http` / `logging` 之间基于主题解耦协作的枢纽（见「事件驱动初始化」）。`logging` 在 `logrus` 之上封装带调用栈 `stack` 字段的 `Entry`（`NewEntry` / `ConfigLogger`），支持 stdout/stderr/file/null 输出与级别、格式配置，并通过事件总线在配置解析阶段完成初始化。
