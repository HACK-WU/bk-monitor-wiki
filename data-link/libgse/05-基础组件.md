## 简介

除通信层与输出层外，libgse 还提供一组被各业务包复用的基础组件。它们彼此依赖较少，主要服务于：事件处理公共能力（common）、运行期可观测性（logp/monitoring）、生命周期管理（reloader/pidfile/storage）和调试（debug）。

## common 公共组件

`pkg/libgse/common/` 提供三类基础能力：

- **集合类型**：`Set`（`map[string]bool`，`NewSet`/`Insert`/`Delete`/`Exist`/`Keys`/`Copy`/`Size`）与 `InterfaceSet`（key 为 `interface{}`）。
- **流控 `FlowLimiter`**：基于 `golang.org/x/time/rate`。`NewFlowLimiter(bytesRate)` 将字节速率按 1KB=1 token 折算（至少 1 token）；`Consume(n)` 按字节数换算 token 并 `ReserveN` 阻塞限速。被 `output/gse`、`output/bkpush` 复用做发送限流。
- **工具函数 `utils.go`**：
  - 字符串：`FirstCharToUpper`/`FirstCharToLower`、`CharsToString`(int8 数组转字符串)、`MD5`、`MakePifFilePath`。
  - 数值/类型：`TryToInt`/`TryToNumber`/`TryToFloat64`、`FloatEquals`(EPSILON)、`MinUInt`/`MaxUInt`、`CounterDiff`(考虑溢出)。
  - 时间/地区：`GetDateTime`、`GetLocation`(读 `/etc/sysconfig/clock` 或 `/etc/timezone`)、`GetUTCTimestamp`。
  - 网络：`ValidateIPAddress`、`Ip2uint32Littlendian`/`UInt32ToipLittlendian`。
  - 列表：`DiffList`/`AddList`/`CombineList`；`ReadLines`；`ScanPidLine`；`PrintStruct`(调试)。
  - `MapStr` 是 `common.MapStr` 的类型别名，作为事件字段容器贯穿全模块。

## monitoring 指标上报

指标分两个层次：

1. **基础指标注册**（`monitoring/bkmonitoring.go`）：在 `monitoring.Default` 下建 `bkbeat` 与 `bkbeat_tasks` 两个 registry，提供 `NewBool`/`NewString`/`NewInt`/`NewFloat`，以及按 dataid 的 `NewXxxWithDataID`（为不同 dataid 动态建子 registry）。`output/gse` 的 `MetricGse*`（如 `gse_publish_total`）即通过此注册。
2. **采集器指标上报**（`monitoring/report/bkpipe/`）：`report.RegisterReporterFactory("bkpipe", makeReporter)` 注册周期上报器。
   - `reporter.snapshotLoop` 按 `Period`(默认 60s) 周期性 `CollectFlatSnapshot` 并 `makeDeltaSnapshot` 计算增量（gauge 指标取原值，counter 取差值）。
   - `getTaskMetric` 把 `bkbeat_tasks.<dataID>.<metric>` 风格键解析回 `dataID` 与 `metric`，非任务指标归到 `dataID=0`。
   - 最终按 `beat`/`tasks` 维度组装 `metrics`+`dimension`（含 `bk_biz_id`/`type`/`version`/`task_data_id`/可选 k8s 标签），经 `bkpipeSender.Report` → `DataQualityMonitorSender.Report`（即 `gse.Output.Report`）上报。
   - `config`：默认 `BkBizID=2`、`Period=60s`，支持 `extra_labels` 从 env/file 注入标签；`DataID`/`TaskDataID` 为空则仅打日志。

## reloader 热重启

`pkg/libgse/reloader/` 提供配置热重载能力：

- `ReloadIf` 接口：`Reload(*common.Config)`。
- `Reloader`：封装 handler、name、`done` 通道与信号 fd（默认 `sigReload`，可用 `WithReloaderSig2()` 切换为 `sigReload2` 即 SIGUSR2）。
- `NewReloader(name, handler, opts...)`：构造实例，信号触发时调用 `handler.Reload`。

## storage 磁盘存储

`pkg/libgse/storage/` 是键值存储的薄封装，用于持久化 `gseindex` 等需要跨进程/重启保留的状态。

- `Storage` 接口：`Set`/`Get`/`List`/`Del`/`Close`/`Destroy`/`SetFlushInterval`。
- 包级 `_storage` 由 `Init(path, config)` 通过 `NewLocalStorage` 初始化（底层见 `skv.go`/`diskv_aix.go` 等平台实现）。
- 包函数 `Get`/`Set`/`List`/`Del`/`Close`/`Destroy` 为便利封装；`Set` 对空 key/value 直接忽略。

## debug 调试

`pkg/libgse/debug/` 暴露一个 HTTP handler，用于线上调试与 pprof 下载。

- `NewDebugHandler(version)`：返回 `http.Handler`，挂载：
  - `/cmds`：列出可用命令。
  - `/version`：返回版本。
  - `/cmds/loglevel`：GET 取当前日志级别，PUT `value=debug|info|warning|error|critical` 设置。
  - `/debug/pprof/[name]`：下载指定类型 pprof 文件。
- 典型用法：`go http.ListenAndServe("localhost:6060", debug.NewDebugHandler("v1.x"))`。

## pidfile 进程锁

`pkg/libgse/pidfile/` 基于 `nightlyone/lockfile` 保证单实例运行。

- `GetPid(pidFilePath)`：读取 pid 文件并 `ScanPidLine` 解析（<=0 视为失败）。
- `TryLock(pidFilePath)`：确保目录存在，`lockfile.New` + `TryLock` 抢锁（失败说明已有实例在跑）。
- `UnLock()`：释放锁。

## 结论

基础组件是 libgse 的「地基」：`common` 提供集合/限流/通用工具并被输出层广泛复用；`logp`/`monitoring` 负责运行期可观测性，指标最终经 `gse.Output` 回灌；`reloader`/`storage`/`pidfile` 支撑生命周期与状态持久化；`debug` 提供线上诊断入口。理解这些组件有助于在排查发送限流、指标缺失、重复启动等问题时快速定位。
