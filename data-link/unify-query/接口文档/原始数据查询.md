## 接口说明

| 项 | 值 |
|----|----|
| 方法 / 路径 | POST `/query/ts/raw` |
| Handler | `HandlerQueryRaw` |
| 鉴权 | `MetaData` + `JwtAuth` |
| 用途 | 返回未经聚合的原始数据点（按 `limit`/`from` 分页），用于明细排查 |

请求体复用 `QueryTs`。响应为 `ListData`（`total`/`list`/`done`/`trace_id`/`status`/`result_table_id`），直接返回数据对象（HTTP 200）；失败 `ErrResponse`（HTTP 400）。

## 请求示例

```json
{
  "space_uid": "bkcc__2",
  "query_list": [
    {
      "reference_name": "a",
      "table_id": "system.cpu_summary",
      "field_name": "usage",
      "conditions": {"field_list": [{"field": "bk_target_ip", "operator": "=", "value": ["10.0.0.1"]}]}
    }
  ],
  "start_time": "1657848000",
  "end_time": "1657851600",
  "step": "1m",
  "limit": 100,
  "from": 0
}
```

## 请求字段说明

请求体复用 `QueryTs`（与 [结构体查询接口](结构体查询.md#请求字段说明) 一致）。本接口常用字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `space_uid` | string | 否 | 空间 UID；可由 `X-Bk-Scope-Space-Uid` 头注入覆盖 |
| `query_list` | array[Query] | 否 | 子查询列表 |
| `start_time` / `end_time` | string | 否 | 起止时间（秒级时间戳） |
| `step` | string | 否 | 步长，如 `"1m"` |
| `limit` / `from` | int | 否 | 点数限制 / 翻页起始（明细分页） |

子查询项 `Query`、过滤条件、聚合方法、可枚举 `data_source` 的完整定义见 [结构体查询接口](结构体查询.md#请求字段说明)。

## 返回字段说明

成功响应为 `ListData`（`service/http/response.go#L60-L70`），HTTP 200、直接返回数据对象：

| 字段 | 类型 | 说明 |
|------|------|------|
| `total` | int64 | 数据总数 |
| `list` | array[object] | 原始数据点列表（每行一个 map） |
| `done` | bool | 是否查询完成（scroll 翻页时用于判断是否到达末尾） |
| `trace_id` | string | 链路 ID |
| `status` | object | 状态信息 |
| `result_table_id` | array[string] | 结果表 ID 列表（始终返回，无路由时为空数组） |
| `result_table_options` | object | 结果表选项（可选，`omitempty`） |

失败响应 `ErrResponse`：`{"trace_id": "...", "error": "..."}`。

### 返回字段与请求字段的映射关系

返回为 `ListData`，与 `PromData` 的分组表不同，这里是**扁平的原始数据点**：

| 返回字段 | 与请求字段的映射关系 |
|---------|-------------------|
| `list[]` | 每个元素是一个原始数据点（map），键包含时间字段、`query_list[].field_name` 指定的指标字段（如 `usage`）以及 `query_list[].dimensions` 指定的维度标签（未指定则返回数据实际携带的全部标签）；值由存储层返回 |
| `total` | 满足 `conditions` 与 `start_time`/`end_time` 的总点数，受 `limit`/`from` 分页 |
| `done` | 是否到达数据末尾（本接口恒为 `true`，分页由 `limit`/`from` 控制） |
| `result_table_id` | 由 `table_id` 经路由解析得到 |
| `trace_id` / `status` | 链路与状态信息 |

> 说明：原始数据查询不做维度分组，因此没有 `group_keys`；维度直接作为每行的字段出现在 `list[]` 的 map 中。
