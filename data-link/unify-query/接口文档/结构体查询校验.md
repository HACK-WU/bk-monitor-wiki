## 接口说明

| 项 | 值 |
|----|----|
| 方法 / 路径 | POST `/check/query/ts` |
| Handler | `HandlerCheckQueryTs` |
| 鉴权 | `MetaData` + `JwtAuth` |
| 用途 | 与 `/query/ts` 同请求体，但仅做解析、路由与存储预览体校验，不下发真实查询 |

失败时返回 `ErrResponse`（HTTP 400）；JWT 鉴权失败返回 401。

## 请求示例

与 `/query/ts` 一致，复用 `QueryTs` 结构：

```json
{
  "space_uid": "bkcc__2",
  "query_list": [
    {
      "reference_name": "a",
      "table_id": "system.cpu_summary",
      "field_name": "usage",
      "function": [{"method": "MEAN"}],
      "time_aggregation": {"method": "SUM", "window": "1m"}
    }
  ],
  "start_time": "1657848000",
  "end_time": "1657851600",
  "step": "1m"
}
```

## 响应示例

成功返回 `CheckQueryTsDataResponse`（HTTP 200，直接返回数据对象）：

```json
{
  "data": [
    {"metricql": "sum(system_cpu_summary_usage{bk_biz_id=\"2\"})"}
  ],
  "route_info": [
    {"table_id": "system.cpu_summary", "db": "influxdb", "is_strict": false}
  ],
  "trace_id": "b2c3d4e5"
}
```

> `data` 为各子查询对应 `tsdb.Instance.GetRequestBody` 的序列化预览；仅路由预览（无存储预览体）时 `data` 可为空仍返回 200。`route_info` 与子查询一一对应，用于排障。
