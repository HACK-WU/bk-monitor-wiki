# Issue 使用总览

Issue 是 BK-Monitor 告警处理链路中的**问题聚合与跟踪域**。核心目标：将海量告警按"同一具体问题"聚合为 Issue，帮助运维人员聚焦问题根因而非逐条处理告警事件。

## 能力清单

| 能力 | 使用场景 | 对应入口 |
|------|----------|----------|
| 告警聚合 | 同策略同维度组合的告警自动归并到同一 Issue | `IssueAggregationProcessor.process`（引擎侧） |
| Issue 列表搜索 | 按状态、优先级、负责人、策略、维度、影响范围等条件查询 | `POST /issue/search` |
| Issue 详情查看 | 查看单个 Issue 的元数据、告警摘要、活动日志 | `GET /issue/detail`、`GET /issue/activities` |
| 状态管理 | 指派、解决、重开、归档、恢复、改优先级、重命名 | `POST /issue/assign`、`/issue/resolve` 等 |
| 批量操作 | 对多个 Issue 并发执行同一操作，单条失败隔离 | `_run_batch` 框架 |
| 合并/拆分 | 将多个 Issue 合并为一个，或将子 Issue 从主 Issue 拆分 | `POST /issue/merge`、`POST /issue/split` |
| 影响范围 | 自动按关联告警汇总受影响的主机、集群、Pod、APM 服务 | `sync_issue_alert_stats` 周期任务 |
| TAPD 集成 | Issue 与 TAPD 工作项打通：创建/关联/解绑/重新关联 | TAPD 集成子专家 |
| LLM 标题 | 新建 Issue 后异步生成可读标题 | `dispatch_llm_title` |
| API Gateway | 通过蓝鲸 API 网关访问 Issue 操作 | `api/issue/default.py` |
| bkm-cli 诊断 | CLI 场景查询 Issue 详情/列表/活动 | `kernel_api/rpc/functions/bkm_cli/issue.py` |

## 能力边界

Issue 不负责：
- 告警的生成与触发（由告警策略引擎负责）
- 通知渠道的发送逻辑（由通知渠道管理模块负责）
- 策略配置本身的 CRUD（由策略管理模块负责）
- TAPD 单据内部的流转状态同步（仅维护 Issue ↔ TAPD 的关联关系）

## 已知问题与常见坑

| # | 现象 | 触发条件 | 正确做法 |
|---|------|----------|----------|
| 1 | 聚合后的 Issue 维度缺失，告警未进入任何 Issue | `issue_config.aggregate_dimensions` 中的维度在告警 origin_alarm.data.dimensions 中缺失/为空 | 检查策略配置的聚合维度是否来自原始告警维度；不能依赖 trigger 阶段收编后的 alert.dimensions |
| 2 | 同策略同维度告警出现多个活跃 Issue | 指纹生成前的 legacy 数据或并发创建竞态 | processor 使用 Redis 锁 + ES 标准查找 + Legacy 兜底三级查找；异常时通过周期任务补偿 |
| 3 | `issue/search` 查询结果为空但 ES 有数据 | `bk_biz_ids` 未传或权限校验失败 | IssueBusinessActionPermission 支持从 `bk_biz_ids` 列表提取业务 ID；确认 IAM 有 VIEW_EVENT 权限 |
| 4 | TAPD 接口返回 403 未授权 | 用户未在 TAPD 完成 OAuth 授权或 token 过期 | 先调用 `tapd/user_workspace` 携带 `success_url` 获取 `auth_url` 完成授权 |
| 5 | 解决/归档后的 Issue 在列表仍显示为活跃 | 时间分片查询中 `resolved_time` 未正确归属 | `end_time` 约束 `create_time`，`start_time` 约束 `resolved_time`；分片按 `resolved_time` 唯一归属 |
