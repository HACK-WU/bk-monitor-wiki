# Issue 能力契约

> 本契约覆盖父专家级别的跨子域能力：IssueDocument 核心查询与状态、聚合处理器入口、周期任务入口、LLM 标题派发。具体 API 端点契约见各子专家。

## 1. IssueDocument — ES 文档模型

### 1.1 `IssueDocument.get_issue_or_raise(issue_id, bk_biz_id=None)`

**用途**：按 ID 精确查询单条 Issue；不存在或业务归属不匹配时抛出 `IssueNotFoundError`。

**参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `issue_id` | str | 是 | Issue ID，形如 `{timestamp}{uuid8}` |
| `bk_biz_id` | int | 否 | 若传入，查出后校验归属，防止越权 |

**返回**：`IssueDocument` 实例。

**异常**：
- `IssueNotFoundError`：Issue 不存在，或 `bk_biz_id` 不匹配。

**约束**：
- 使用 `all_indices=True` 查询，避免跨天漏查。
- 返回的 `_source` 中若含 `id` 字段会先 pop，再显式传入 `meta.id`，防止 UPSERT 退化为 INSERT。

**示例**：
```python
from bkmonitor.documents.issue import IssueDocument, IssueNotFoundError

try:
    issue = IssueDocument.get_issue_or_raise("1722300000a1b2c3d4", bk_biz_id=2)
except IssueNotFoundError:
    # 不存在或无权限
    issue = None
```

契约来源：`IssueDocument.get_issue_or_raise`

### 1.2 `IssueDocument.to_cache_dict()`

**用途**：生成用于 Redis 缓存的完整字典，避免缓存读取端字段缺失。

**返回**：`dict`。

**约束**：
- 使用 `skip_empty=False`，保留空字段。
- ES 更新路径仍使用默认 `to_dict(skip_empty=True)`，防止局部更新误清空字段。

契约来源：`IssueDocument.to_cache_dict`

## 2. 聚合处理器

### 2.1 `IssueAggregationProcessor(alert, strategy).process()`

**用途**：在告警处理阶段（fta_action）将单条告警聚合到对应 Issue，不存在则创建。

**构造参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `alert` | `AlertDocument` | 当前告警文档 |
| `strategy` | dict | 策略配置，需包含 `id` 与 `issue_config` |

**返回**：`bool` — 是否成功关联/创建。

**行为语义**：
1. 校验 `issue_config.is_enabled`、告警级别、条件过滤。
2. 从 `origin_alarm.data.dimensions` 取维度计算指纹；任一维度缺失则跳过。
3. 三级查找活跃 Issue：Redis 缓存 → ES 标准查找 → Legacy 兜底。
4. 无活跃 Issue 则加分布式锁创建。
5. 关联告警（`AlertDocument.issue_id` UPSERT）。
6. 新建 Issue 后异步派发 LLM 标题任务。

**约束**：
- 指纹生成必须使用 adapter 收编前的原始维度，不能用 `alert.dimensions`。
- 高基数时仅 metric + warning，不阻塞新建。
- 锁按 fingerprint 粒度，获取失败会跳过该告警。

**示例**：
```python
from alarm_backends.service.fta_action.issue_processor import IssueAggregationProcessor
from bkmonitor.documents.alert import AlertDocument

alert = AlertDocument.get(id="alert_id")
strategy = {"id": 123, "bk_biz_id": 2, "issue_config": {...}}
ok = IssueAggregationProcessor(alert=alert, strategy=strategy).process()
```

契约来源：`IssueAggregationProcessor.process`

### 2.2 `gen_issue_fingerprint(strategy_id, aggregate_dimensions, data_dimensions)`

**用途**：生成 Issue 唯一指纹。

**参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `strategy_id` | int | 策略 ID |
| `aggregate_dimensions` | list[str] | 聚合维度名列表 |
| `data_dimensions` | dict | 原始维度取值 |

**返回**：`str | None` — 指纹；维度缺失时返回 `None`。

**约束**：
- 空 `aggregate_dimensions` 退化为按 strategy_id 隔离。
- 任一维度缺失/为空/全空白 → `None`。
- 维度按 key 排序，值做 `str(...).strip()` 归一化。

契约来源：`gen_issue_fingerprint`

## 3. 周期任务

### 3.1 `sync_issue_alert_stats()`

**用途**：后台周期任务，同步全量活跃 Issue 的告警统计、漏关联补偿、影响范围重算、孤立检测、Legacy 哨兵续命。

**参数**：无。

**返回**：无。

**行为语义**：
- 扫描活跃 Issue。
- 对每条 Issue 更新 `alert_count`、`last_alert_time`。
- 回填 `AlertDocument.issue_id` 未写入的告警（O(N+M) 优化）。
- 重算 `impact_scope`。
- 检测 5 分钟无关联告警的 orphan Issue 并告警。
- 为 Legacy 数据续 30 天 TTL。

**约束**：
- 任务执行期间对 Issue 只读查询外，可能并发写 ES。
- 大策略下注意 ES 查询性能。

契约来源：`alarm_backends.service.fta_action.tasks.issue_tasks.sync_issue_alert_stats`

## 4. LLM 标题

### 4.1 `dispatch_llm_title(issue)`

**用途**：新建 Issue 后异步派发 LLM 标题生成任务。

**参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `issue` | `IssueDocument` | 新建 Issue |

**返回**：无。

**行为语义**：
- 发送到 `celery_llm_task` 独立队列。
- 受部署开关 `ENABLE_ISSUE_LLM_TITLE` + 业务白名单两级闸门控制。
- CAS 检查：写入前确认当前 name 仍为默认名。
- 失败静默，不重试不入队。

**约束**：
- 不保证一定生成成功；调用方不应阻塞等待。

契约来源：`alarm_backends.service.fta_action.llm_title.dispatch_llm_title`

## 5. Issue 合并/展开

### 5.1 `IssueMergeResolver.merge(main_issue_id, source_issue_ids, operator)`

**用途**：将多个 Issue 合并到主 Issue。

**参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `main_issue_id` | str | 主 Issue ID |
| `source_issue_ids` | list[str] | 被合并 Issue ID 列表 |
| `operator` | str | 操作人 |

**返回**：合并后的主 Issue。

**异常**：
- `IssueFrozenError`：目标 Issue 处于冻结状态（已归档/已解决）。

契约来源：`bkmonitor.issue_merge.IssueMergeResolver.merge`

### 5.2 `IssueMergeResolver.split(issue_id, operator, split_alert_ids=None)`

**用途**：将子 Issue 从主 Issue 拆分恢复为独立 Issue。

**参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `issue_id` | str | 子 Issue ID |
| `operator` | str | 操作人 |
| `split_alert_ids` | list[str] | 可选，指定拆分时要带走的告警 ID |

**返回**：拆分后的新 Issue。

契约来源：`bkmonitor.issue_merge.IssueMergeResolver.split`

## 6. 权限与访问

### 6.1 IAM Action

| 接口类型 | IAM Action |
|----------|------------|
| 只读接口 | `VIEW_EVENT` |
| 写操作 | `MANAGE_EVENT` |

### 6.2 无需 `bk_biz_id` 的接口

`issue/search`、`issue/top_n`、`issue/recent_assignees`、`tapd/workspace`、`tapd/user_workspace` 允许不传业务 ID，由业务层自行限制数据范围。

## 7. 数据契约

- Issue 唯一持久化存储：ES 索引 `bkfta_issue`。
- 活动日志持久化：ES 索引 `bkfta_fta_issue_act`。
- 活跃 Issue 缓存：Redis（非持久化，可重建）。
