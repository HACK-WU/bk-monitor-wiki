# Issue 使用流程

## 流程 1：告警自动聚合为 Issue

### 业务目标
一条告警触发后，系统根据策略配置的聚合维度自动找到或创建对应 Issue，并将告警关联进去。

### 调用顺序
```
告警产生 → IssueAggregationProcessor.process() → gen_issue_fingerprint() → 查找活跃 Issue → 创建/关联 → 异步 dispatch_llm_title()
```

### 示例
```python
from alarm_backends.service.fta_action.issue_processor import IssueAggregationProcessor
from bkmonitor.documents.alert import AlertDocument

alert = AlertDocument.get(id="alert_xxx")
strategy = {
    "id": 123,
    "bk_biz_id": 2,
    "issue_config": {
        "is_enabled": True,
        "alert_levels": ["P0", "P1"],
        "aggregate_dimensions": ["bk_target_ip", "bk_target_cloud_id"],
    },
}
ok = IssueAggregationProcessor(alert=alert, strategy=strategy).process()
# ok=True 表示告警已成功关联到某个 Issue
```

### 事务边界
- 一次 `process()` 调用对应一条告警的处理。
- 分布式锁保证同 fingerprint 并发创建唯一 Issue。
- ES 写入失败会重试 1 次，仍失败抛异常。

### 预期结果
- 告警 `AlertDocument.issue_id` 被更新为对应 Issue ID。
- 活跃 Issue 的 `alert_count` 在后续周期任务中同步更新。
- 新建 Issue 默认状态为 `pending_review`，默认名为系统生成名。

### 错误处理
- `fingerprint is None`：维度缺失，告警不进入任何 Issue，仅 metric 上报。
- 锁获取失败：跳过该告警，不阻塞告警主链路。

## 流程 2：Issue 列表查询

### 业务目标
按状态、优先级、负责人等条件查询 Issue 列表。

### 调用顺序
```
POST /issue/search → SearchIssueResource → IssueQueryHandler.search() → IssueQueryTransformer
```

### 示例
```python
import requests

resp = requests.post(
    "https://bk-monitor.example.com/fta/issue/search/",
    json={
        "bk_biz_ids": [2],
        "status": ["unresolved"],
        "priority": ["P0", "P1"],
        "page": 1,
        "page_size": 20,
    },
    headers={"X-CSRFToken": "..."},
)
data = resp.json()["data"]
issues = data["list"]
```

### 事务边界
- 只读查询，无事务。
- 默认排序 `-first_alert_time, priority, status`。

### 预期结果
- 返回当前用户有权限的业务下的 Issue 列表。
- 虚拟状态 `MY_ASSIGNEE` / `NO_ASSIGNEE` 会被转换为具体 ES 查询条件。

## 流程 3：批量解决 Issue

### 业务目标
将多个未解决 Issue 标记为已解决。

### 调用顺序
```
POST /issue/resolve → ResolveIssueResource → _run_batch() → IssueDocument.resolve()
```

### 示例
```python
import requests

resp = requests.post(
    "https://bk-monitor.example.com/fta/issue/resolve/",
    json={
        "issues": [
            {"bk_biz_id": 2, "issue_id": "1722300000a1b2c3d4"},
            {"bk_biz_id": 2, "issue_id": "1722300000e5f6g7h8"},
        ]
    },
    headers={"X-CSRFToken": "..."},
)
result = resp.json()["data"]
# result: {"succeeded": [...], "failed": [{"issue_id": "...", "message": "..."}]}
```

### 事务边界
- 每条 Issue 独立一个线程任务并发执行。
- 单条失败不影响其他条目。

### 预期结果
- 成功条目的 Issue 状态变为 `resolved`，并记录 `status_change` 活动日志。
- 失败条目返回 `issue_id` 与错误信息。

### 错误处理
- 状态不允许（如已归档）会进入 `failed` 列表。
- IAM 无 `MANAGE_EVENT` 权限时整体请求被拦截。

## 流程 4：Issue 合并

### 业务目标
将多个同一问题衍生的 Issue 合并到主 Issue，统一跟踪。

### 调用顺序
```
POST /issue/merge → MergeIssueResource → IssueMergeResolver.merge()
```

### 示例
```python
import requests

resp = requests.post(
    "https://bk-monitor.example.com/fta/issue/merge/",
    json={
        "bk_biz_id": 2,
        "main_issue_id": "1722300000main0001",
        "source_issue_ids": ["1722300000sub0001", "1722300000sub0002"],
    },
    headers={"X-CSRFToken": "..."},
)
main_issue = resp.json()["data"]
```

### 事务边界
- 合并操作会修改多个 Issue 文档，使用 ES UPSERT 持久化。
- 合并后源 Issue 标记为合并进主 Issue，不可再单独操作。

### 预期结果
- 主 Issue 继承被合并 Issue 的告警关联。
- 被合并 Issue 状态冻结，并记录 `MERGED_INTO` 活动日志。

### 错误处理
- 任一目标 Issue 已归档/已解决会抛 `IssueFrozenError`。

## 流程 5：TAPD 创建并关联

### 业务目标
为某个 Issue 在 TAPD 创建单据并建立关联。

### 调用顺序
```
POST /issue/create_tapd → CreateTapdResource → TAPD API → IssueTapdRelation → 活动日志
```

### 示例
```python
import requests

resp = requests.post(
    "https://bk-monitor.example.com/fta/issue/create_tapd/",
    json={
        "bk_biz_id": 2,
        "issue_id": "1722300000a1b2c3d4",
        "workspace_id": "123456",
        "title": "订单服务异常",
        "description": "由监控 Issue 自动创建",
    },
    headers={"X-CSRFToken": "..."},
)
relation = resp.json()["data"]
```

### 事务边界
- 先调 TAPD 接口创建单据，成功后写本地关联关系。
- 失败时本地不建立关联。

### 预期结果
- TAPD 单据创建成功。
- `IssueTapdRelation` 记录建立。
- Issue 活动日志新增 `create_tapd` 记录。

### 错误处理
- TAPD 未授权返回 403 + `auth_url`。
- 工作区未绑定返回明确错误信息。
