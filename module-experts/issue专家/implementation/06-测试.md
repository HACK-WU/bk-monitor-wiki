### 测试文件详解

**① test_issue_fingerprint.py — 聚合引擎指纹与迁移（64 用例）**

- 覆盖：`gen_issue_fingerprint`（空维度退化/缺失/排序稳定性/跨策略区分/值归一化）、`IssueAggregationProcessor` 原始维度提取、Legacy 活跃 Issue 迁移（哨兵/重试/失败）、backfill 每策略去重、维度快照严格匹配指纹。
- 被测源码：`alarm_backends/service/fta_action/issue_processor.py`。

**② test_issue_merge.py — 合并/拆分（72 用例）**

- 覆盖：合并冻结异常（`IssueFrozenError`）、跨业务禁止、冲突携带主 ID、Resolver fast-path noop、上下文注入（main/member 角色）、状态冲突提示、expand/filter 逻辑、影响范围并集、活动内容格式、拆分信息契约。
- 被测源码：`bkmonitor/issue_merge.py` + `fta_web/issue/resources.py`（Merge/Split Resource）+ `kernel_api/views/v4/issue.py`。
- **角色要求**：用例同时 import `kernel_api.views.v4.issue` 与 `fta_web.issue.resources`，需 **api 角色**（同时挂 monitor_web/fta_web 与 alarm_backends）；worker/web 角色下部分用例因 app 未注册而失败（非逻辑问题，见 §4）。

**③ test_issue_llm_title.py — LLM 标题生成（大量用例）**

- 覆盖：提示词模板渲染、业务模板校验/解析/设置、标题校验（拒绝多行/md5/IP/trace_id）、示例解析、业务白名单、派发闸门（env + 白名单两级）、失败静默。
- 被测源码：`alarm_backends/service/fta_action/llm_title.py`。

**④ test_regenerate_issue_llm_title_command.py — 标题重生成命令（4 用例）**

- 覆盖：命令强制显式模式、dry-run 去重不重生成、顺序执行、超过 20 个唯一 Issue 拒绝。

**⑤ test_issue_resources.py — Web Resource 层（21 用例）**

## 3. 运行方式

### 3.1 环境要求

- Python 3.11 + 项目 `.venv`（系统 Python 缺 `bkcrypto`）。
- 显式注入环境变量（`pyproject.toml` 的 `D:` 前缀在变量已置空时不生效）：

```bash
export BKAPP_DEPLOY_PLATFORM=community
export DJANGO_CONF_MODULE=<按 §3.2 选角色>
export USE_DYNAMIC_SETTINGS=0
```

- 绕过 `filterwarnings` 解析失败问题（Django 4.2.27 无 `RemovedInDjango51Warning`）：

```bash
# 所有命令追加：--override-ini "filterwarnings="
```

### 3.2 运行命令（按功能域）

```bash
cd /root/bk-monitor/bkmonitor

# ① 聚合引擎指纹（worker 角色，纯单测，最快）
BKAPP_DEPLOY_PLATFORM=community DJANGO_CONF_MODULE=conf.worker.development.community USE_DYNAMIC_SETTINGS=0 \
  .venv/bin/python -m pytest alarm_backends/tests/service/fta_action/test_issue_fingerprint.py -q --override-ini "filterwarnings="

# ② 合并/拆分（⚠️ 必须 api 角色，worker/web 角色下部分用例失败）
BKAPP_DEPLOY_PLATFORM=community DJANGO_CONF_MODULE=conf.api.development.community USE_DYNAMIC_SETTINGS=0 \
  .venv/bin/python -m pytest alarm_backends/tests/service/fta_action/test_issue_merge.py -q --override-ini "filterwarnings="

# ③ LLM 标题（worker 角色）
BKAPP_DEPLOY_PLATFORM=community DJANGO_CONF_MODULE=conf.worker.development.community USE_DYNAMIC_SETTINGS=0 \
  .venv/bin/python -m pytest alarm_backends/tests/service/fta_action/test_issue_llm_title.py \
  alarm_backends/tests/service/fta_action/test_regenerate_issue_llm_title_command.py -q --override-ini "filterwarnings="

# ④ Web API 层（web 角色）
BKAPP_DEPLOY_PLATFORM=community DJANGO_CONF_MODULE=conf.web.development.community USE_DYNAMIC_SETTINGS=0 \
  .venv/bin/python -m pytest packages/fta_web/tests/issue/test_issue_resources.py \
  packages/fta_web/tests/alert/test_issue_merge_expand.py -q --override-ini "filterwarnings="

# ⑤ kernel_api / RPC（api 角色）
BKAPP_DEPLOY_PLATFORM=community DJANGO_CONF_MODULE=conf.api.development.community USE_DYNAMIC_SETTINGS=0 \
  .venv/bin/python -m pytest kernel_api/tests/test_issue_v4.py \
  kernel_api/rpc/tests/test_bkm_cli_inspect_issue.py -q --override-ini "filterwarnings="

# ⑥ AST 契约测试（无需 Django 栈，任意角色）
.venv/bin/python -m pytest tests/api/fta/test_issue_activities_contract.py -q
```

> **角色速查**：worker=纯后台逻辑单测；web=Web/API 层；api=跨层（同时挂 monitor_web + alarm_backends）。混跑会因 app 注册差异导致假失败。

### 3.3 测试设计模式（本模块特色）

- **纯单测为主**：指纹/合并/LLM 标题均为纯逻辑测试，无 django_db、无外部服务依赖，可快速回归核心算法。
- **Mock 隔离**：API 层用 `monkeypatch` 隔离 ES/CMDB/查询依赖（如 `test_issue_resources.py` 的 `mock.patch("bkmonitor.documents...")`）。
- **AST 契约测试**：`test_issue_activities_contract.py` 用 `ast.parse` 检查源码结构而非运行 Django 栈，验证只读修复契约——是"免依赖验证契约"的轻量方案。

## 4. 已知失败

当前开发环境（稀疏检出 43%、Django 4.2.27）下运行 Issue 测试的已知失败，逐切面标注见 [test/known-failures.md](../test/known-failures.md)。

核心结论：

| # | 问题 | 影响 |
|---|------|------|
| 1 | `test_bkm_cli_inspect_issue.py` 在 worker 角色下收集期失败（`monitor_web.extend_account` 未注册） | 需 api 角色运行；该文件 import 链经过 `kernel_api.rpc.functions.bkm_cli` 包 `__init__`（引入 admin/collect 模块） |
| 2 | `test_issue_trend_contract.py::test_issue_list_renders_before_trend_is_loaded` 读取前端 TS 文件失败（`webpack/src/trace/pages/alarm-center/services/issues-services.ts` 缺失） | 稀疏检出缺前端文件；完整检出后可过 |
| 3 | `test_issue_merge.py` 在 worker（8 failed）/web（5 failed）角色下部分失败，但 **api 角色 72 全过** | 角色选择问题，非逻辑 bug；按 §3.2 用 api 角色运行 |
| 4 | 全局前置：`filterwarnings` 配置与 Django 4.2.27 不兼容 + 环境变量需显式注入 | 所有测试需 `--override-ini "filterwarnings="` + 显式 env |

## 5. 测试缺口

优先级从高到低：

1. **`IssueDocument` 状态机全流程单测**——状态流转（assign/resolve/archive/reopen/restore）目前仅靠 API 用例间接覆盖，状态机前置条件（冻结/已解决不可操作）无直接测试。
2. **`sync_issue_alert_stats` 周期任务单测**——影响范围重算、孤立检测、Legacy 续命、漏关联补偿（O(N+M) backfill 路径）。
3. **TAPD 集成单测**——OAuth 回调、工作区绑定/解绑/重绑、token 加解密、tombstone 阻断自动回绑，当前零覆盖。
4. **`IssueQueryHandler` 时间分片查询单测**——`end_time` 约束 `create_time` / `start_time` 约束 `resolved_time` 的分片归属正确性。
5. **`dispatch_llm_title` CAS 写入竞态测试**——写入前确认 name 仍为默认名的并发保护。
