### `SearchIssueResource.perform_request(validated_request_data) -> dict`

契约来源：`fta_web.issue.resources.SearchIssueResource`

> 注意：本专家 agent.md 端点总览中曾写作 `IssueSearchResource`，源码实际类名为 `SearchIssueResource`，请以本契约为准。

- **用途**：按条件分页查询 Issue 列表。
- **参数**：

  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `bk_biz_ids` | `list[int]` | 是 | 业务 ID 列表；结果仅返回这些业务下有权限的数据 |
  | `status` | `list[str]` | 否 | 状态过滤；支持真实状态 `pending_review`/`unresolved`/`resolved`/`archived`，以及虚拟状态 `MY_ASSIGNEE`/`NO_ASSIGNEE` |
  | `priority` | `list[str]` | 否 | 优先级过滤：`P0`/`P1`/`P2` |
  | `assignee` | `list[str]` | 否 | 负责人精确过滤 |
  | `strategy_id` | `list[int]` | 否 | 策略 ID 过滤 |
  | `strategy_name` | `str` | 否 | 策略名称精确查询（内部映射到 `strategy_name.raw`） |
  | `fingerprint` | `str` | 否 | Issue 指纹精确查询 |
  | `name` | `str` | 否 | Issue 名称精确查询（内部映射到 `name.raw`） |
  | `dimension_values.{key}` | `str` | 否 | 维度值精确过滤 |
  | `impact_scope.{dimension}` | `str` | 否 | 影响范围维度过滤 |
  | `start_time` | `int` | 否 | 时间戳（秒）；约束 `resolved_time` 在该时间之后 |
  | `end_time` | `int` | 否 | 时间戳（秒）；约束 `create_time` 在该时间之前 |
  | `page` | `int` | 否 | 页码，默认 1 |
  | `page_size` | `int` | 否 | 每页条数，默认 20 |
  | `ordering` | `str` | 否 | 排序字段，默认 `-first_alert_time`；可传 `-first_alert_time`、`priority`、`status` 等 |

- **返回**：`dict` — `{"total": int, "list": [IssueDict, ...]}`。
- **异常**：IAM 无权限时由 `IssueBusinessActionPermission` 拦截。
- **约束**：虚拟状态 `MY_ASSIGNEE`/`NO_ASSIGNEE` 会转换为具体 ES 查询条件；时间范围语义与常规查询不同，见 [Issue 查询子专家](../issue-query/agent.md)。
- **使用示例**：
  ```python
  from core.drf_resource import resource

  result = resource.issue.search_issue(
      bk_biz_ids=[2],
      status=["unresolved"],
      priority=["P0", "P1"],
      page=1,
      page_size=20,
  )
  issues = result["list"]
  ```

### `SplitIssueResource.perform_request(validated_request_data) -> dict`

契约来源：`fta_web.issue.resources.SplitIssueResource`

> 2026-09-02 REQ-20260901-001 批量拆分变更后增量修正：本节为 web 薄壳契约，批量执行语义在 api role 端 kernel_api `SplitResource`（`kernel_api/views/v4/issue.py`）。

- **用途**：将子 Issue 从主 Issue 拆分恢复为独立 Issue（web 端薄壳，单次透传 `api.issue.split` 到 api role 执行；operator 由 web 端 `get_request_username()` 注入）。
- **参数**：

  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `bk_biz_id` | `int` | 是 | 业务 ID |
  | `member_issue_id` | `str` | 二选一 | **旧单条契约**：单条拆分。行为/响应 shape/失败抛错语义与变更前完全一致（apigw `issue.yaml` isPublic 外部消费者依赖），前端适配期间兼容保留，适配完成后移除 |
  | `member_issue_ids` | `list[str]` | 二选一 | **新批量契约**：≤50 条，去重保序；单条拆分传长度 1 的列表 |
  | `reasons` | `list[str]` | 否 | 拆分依据；缺省/空列表均合法（下游已按空兜底），批量时同一 reasons 应用到全部条目 |

  - `member_issue_id` 与 `member_issue_ids` 必须二选一：双传或都不传由序列化器 `validate` 拒绝。

- **返回**：
  - 旧单条：`{"status": "ok", "member_issue_id": ...}`；失败抛 HTTP 错误。
  - 批量：`{"status": "ok", "results": [{"member_issue_id", "status": "ok"|"skipped"|"failed", "message"?}]}` — `skipped` = 关系不存在或已被并发拆分（幂等跳过，`message: "relation not active"`）；`failed` 统一通用文案 `"split failed"`（内部细节仅日志不下发）。
- **异常**：旧单条路径失败抛 `SplitNotFoundError`（404/3337104，关系不存在或已被拆分）等；批量路径不抛领域错误，异常体现在 `results[].status`。
- **约束**（kernel_api 批量执行语义）：逐条独立执行、无跨条目事务、部分失败不阻塞其余条目；`_mark_split` 条件 UPDATE（`WHERE status=active`）防并发/重复拆分，rowcount=0 记 skipped；ES 重置按主 Issue 分组合并调用 `bulk_reset_for_split`（同组明细通常一个主 → 1 次 bulk）。
- **使用示例**：
  ```python
  from core.drf_resource import resource

  # 批量拆分（≤50，单条传长度 1 的列表）
  result = resource.issue.split_issue(
      bk_biz_id=2,
      member_issue_ids=["1751234567sub0001", "1751234567sub0002"],
      reasons=["告警已恢复"],
  )
  # result["results"] = [{"member_issue_id": "...", "status": "ok"}, ...]
  ```

### `ListMergeSourcesResource.perform_request(validated_request_data) -> dict`

契约来源：`fta_web.issue.resources.ListMergeSourcesResource`

> 2026-08-31 commit 438a146（已合并主 Issue 支持继续合并）新增返回字段 `via_issue_id`，其余字段未变。

- **用途**：查询主 Issue 的全部合并来源（当前 active 成员 + 已拆分历史），数据源以 MySQL 关系表为主，成员名称/状态/最新告警描述从 ES 补齐。
- **参数**：

  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `bk_biz_id` | `int` | 是 | 业务 ID |
  | `main_issue_id` | `str` | 是 | 主 Issue ID（`IssueIDField`，实为 CharField） |

- **返回**：`dict` — `{"main_issue_id": str, "active_members": [item, ...], "split_history": [item, ...]}`；无任何关系时两个列表为空。`item` 公共字段：

  | 字段 | 类型 | 含义 |
  |------|------|------|
  | `member_issue_id` | `str` | 成员 Issue ID |
  | `member_name` | `str` | 成员名称；ES 不存在时为 `"{issue_id} (已删除)"` |
  | `anomaly_message` | `str` | 成员最新告警描述；查询失败 fail-open 兜底 `"--"` |
  | `merge_reasons` | `list[str]` | 合并依据 |
  | `merge_operator` | `str` | 合并操作人（取关系行 create_user） |
  | `merge_time` | `int` | 合并时间，秒级 Unix 时间戳，无则 0 |
  | `status` | `str` | 关系状态 `active`/`split`（旧字段，保留一个发布周期向后兼容） |
  | `relation_status` | `str` | 同义新字段，新代码优先使用 |
  | `member_es_status` | `str \| null` | 成员自身 ES 状态 `pending_review`/`unresolved`/`resolved`/`archived`；ES 缺失为 null，前端按"已删除"占位 |
  | `via_issue_id` | `str \| null` | **新增**。上一跳主 Issue ID：该成员是"随着某个已成组的主一起被改挂（reparent）并入"时非空，记录它此前所属的主；直接合并进来的成员为 `null`。纯溯源标签，可能指向已不在本组的 Issue（上一跳主随后被拆分），不得假设它仍是本组成员 |

  `split_history` 条目额外含：

  | 字段 | 类型 | 含义 |
  |------|------|------|
  | `split_reasons` | `list[str]` | 拆分依据，模型 default=None 统一 `or []` 兜底 |
  | `split_operator` | `str` | 拆分操作人（取关系行 update_user） |
  | `split_time` | `int` | 拆分时间，秒级时间戳 |
  | `split_kind` | `str \| null` | 拆分触发类型；新写入固定 `manual`，历史数据可能为 `by_main_resolve`/`by_main_archive` |

- **异常**：无业务异常；anomaly_message 批量查询失败仅 warning，不影响主返回。
- **约束**：排序按关系行 create_time 降序。
- **使用示例**：

  ```python
  from core.drf_resource import resource

  result = resource.issue.list_merge_sources(bk_biz_id=2, main_issue_id="1751234567main0001")
  reparented = [m for m in result["active_members"] if m["via_issue_id"]]
  ```

## 权限类

### `IssueBusinessActionPermission`

契约来源：`fta_web.issue.views.IssueViewSet.IssueBusinessActionPermission`

- **用途**：Issue 专用业务权限校验，处理 `bk_biz_id` 的三种来源。
- **行为语义**：
  - 批量写操作：从 `body.issues[*].bk_biz_id` 提取。

## 批量操作框架

### `_run_batch(issues, action_fn, max_workers=10)`

契约来源：`fta_web.issue.resources._run_batch`

- **用途**：批量操作公共执行框架。
- **参数**：

  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `issues` | `list[dict]` | 是 | 每项含 `bk_biz_id` 与 `issue_id` |
  | `action_fn` | `Callable[[int, str], dict]` | 是 | 单条操作函数，接收 `(bk_biz_id, issue_id)` |
  | `max_workers` | `int` | 否 | 并发线程数，默认 10 |

- **返回**：`dict` — `{"succeeded": [dict, ...], "failed": [{"bk_biz_id", "issue_id", "message"}, ...]}`。
- **异常**：不抛出业务异常；单条失败进入 `failed` 列表。
- **约束**：单条失败不影响其他条目；调用方需自行处理 `failed` 结果。
- **使用示例**：
  ```python
  from fta_web.issue.resources import _run_batch

  def resolve_one(bk_biz_id, issue_id):
      issue = IssueDocument.get_issue_or_raise(issue_id, bk_biz_id=bk_biz_id)
      return issue.resolve(operator="admin")

def _run_batch(
    issues=[{"bk_biz_id": 2, "issue_id": "1751234567a1b2c3d4"}],
    action_fn=resolve_one,
)
# 注意：succeeded 列表中每条为 action_fn 的原始返回值；failed 列表含 bk_biz_id / issue_id / message，
# 若异常来自 api role 中转，还可能携带 code / detail 字段。
