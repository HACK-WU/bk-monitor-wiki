# 使用总览：Issue 查询子专家

> 契约快照生成于 2026-07-31（commit `d3a9a5be677864b0cf6af1ca5537b9c1fe97069f`）。
> 若使用中发现行为与契约不符，可能代码已变更——expert-lookup 会自动增量修正，或用 expert-team 全量重建。

## 能力清单

Issue 查询子专家负责把前端/内部调用的搜索条件转换为 Elasticsearch 查询，并返回经过清洗、翻译、视图注入的 Issue 数据。

- **Issue 列表搜索**：按业务、状态、时间、条件、query_string 等过滤，支持分页、排序、聚合与趋势。
- **Issue TopN 统计**：按指定字段（优先级、影响范围维度、业务等）聚合分布，支持大时间范围分片并行。
- **Issue 趋势查询**：按 Issue ID 批量查询告警数量时间序列，自动处理合并/拆分视图。
- **字段转换与翻译**：把前端字段名/中文显示名转换为 ES 字段与枚举值，返回时翻译为可读显示名。
- **业务权限收敛**：自动处理授权业务、无权限但负责人可见、未传业务仅我负责三种可见性。
- **合并/拆分视图注入**：主 Issue 展示 member 摘要、被拆分 Issue 展示 `split_info`。

## 能力边界

本模块不处理以下事项：

- **Issue 写操作**：创建、指派、解决、归档、改优先级、重命名等由 Issue 状态子专家负责。
- **TAPD 集成**：TAPD 授权、工作空间绑定、单据创建/关联由 TAPD 集成子专家负责。
- **合并/拆分关系管理**：合并/拆分动作本身由 Issue 状态子专家处理；查询子专家只读取关系并注入视图。
- **告警详情查询**：Issue 关联的告警列表/详情由告警中心接口提供，查询子专家只读取 `AlertDocument` 做趋势与摘要。
- **索引生命周期管理**：ES 索引创建、rollover、mapping 变更由运维/后台任务负责。

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| `bk_biz_ids=[-1]` 查不到数据 | 直接用于 ES `terms` 过滤 | 框架内部已解析为实际授权业务，调用方无需处理；若直接写底层查询需用 `get_biz_filter_ids()` |
| TopN 返回 count 虚高 | `fields` 列表含重复字段且未去重 | 入口已自动去重；自定义调用 `handler.top_n()` 时自行去重 |
| `show_trend=True` 时列表查询慢 | 每行都查 AlertDocument 并聚合趋势 | 不需要趋势时显式传 `show_trend=False` |
| `impact_scope.*` TopN 的 `name` 为空 | 该维度下无 `display_name` 数据 | 退化为 raw id，属于数据缺失，非查询 bug |
| `status` 传 `MY_ASSIGNEE`/`NO_ASSIGNEE` 后结果里看不到该状态 | 这两个是虚拟状态，非真实存储状态 | 结果 `status` 字段仍为 `unresolved` 等真实状态；负责人信息看 `assignee` |
| 查询结果缺少某些 Issue | 它们是 active member 被合并进主 Issue | 正常行为；如需查看可在主 Issue 的 `merge_status.active_members` 中找到 |
