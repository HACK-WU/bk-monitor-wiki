# 使用总览：Issue 状态聚合子专家

> 契约快照生成于 2026-07-30（commit 3d5f4af571b7f7027087171fba670a43217b830b）。
> 若使用中发现行为与契约不符，可能代码已变更——expert-lookup 会自动增量修正，或用 expert-team 全量重建。

## 能力清单

本专家覆盖 Issue 的状态机、告警聚合、周期同步与 LLM 标题生成四个子域：

- **Issue 状态机**：对单个 Issue 执行 `assign`（首次指派）、`resolve`（解决）、`archive`（归档）、`reopen`（重新打开）、`restore`（恢复归档）、`add_comment`（添加评论）、`update_priority`（修改优先级）、`rename`（重命名）。
- **告警聚合到 Issue**：`IssueAggregationProcessor.process` 在 fta_action 阶段把一条告警关联到已有活跃 Issue 或创建新 Issue。
- **周期同步**：`sync_issue_alert_stats` 定时扫描活跃 Issue，回填漏关联告警、刷新 `alert_count` / `last_alert_time` / `impact_scope`、检测 orphan Issue、续命 legacy 迁移哨兵。
- **LLM 标题生成**：`generate_issue_llm_title` 在新建 Issue 后异步为日志类告警生成可读标题；`regenerate_issue_llm_title` 与 `refresh_issue_llm_title_examples` 提供运维补偿与 few-shot 缓存刷新。

## 能力边界

本专家**不覆盖**以下内容：

- Issue 列表查询、排序、搜索、TopN 聚合（由 Issue 查询子专家覆盖）。
- TAPD 单据创建/关联/解绑（由 TAPD 集成子专家覆盖）。
- Issue 合并/拆分的业务入口与关系管理（合并层由 `IssueMergeResolver` 提供，子专家仅说明状态机受冻结守卫影响）。
- 策略 Issue 聚合配置的 CRUD（配置层由 `StrategyIssueConfigService` 提供，本专家只消费配置）。

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| 状态机调用报 `IssueFrozenError` | 目标 Issue 是当前活跃合并关系的 member | 合并 member 的状态只能随主 Issue 级联变更；如需独立操作，先走拆分流程 |
| `resolve`/`archive` 后再对同一 Issue 调用返回空列表 | 幂等设计：已是目标状态则 no-op | 这是预期行为，批量操作结果中应视为 succeeded |
| `rename` 报 `IssueNameDuplicatedError` | 同业务下存在同名 Issue 且 `enforce_unique=True` | 用户手工改名保持 `enforce_unique=True`（默认）；系统自动标题传 `enforce_unique=False` |
| 新建 Issue 未触发 LLM 标题 | 未设置 `ENABLE_ISSUE_LLM_TITLE` 或业务不在白名单 | 检查部署 env 与 `ISSUE_LLM_TITLE_BIZ_WHITE_LIST`；非日志类告警本就跳过 |
| 周期任务后 `alert_count` 仍显示旧值 | ES 近实时刷新，或该 Issue 是 legacy（fingerprint=null） | legacy Issue 被周期任务跳过；正常 Issue 等待刷新即可 |
| `restore` 后状态回到 `resolved` | 归档前状态就是 `resolved`，从活动日志反推得到 | 如需回到活跃态，再从 `resolved` 执行 `reopen` |
