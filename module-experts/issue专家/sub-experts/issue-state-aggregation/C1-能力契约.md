## IssueDocument（`bkmonitor/documents/issue.py`）

契约来源：`IssueDocument` 类

### `get_issue_or_raise(issue_id, bk_biz_id=None)`

- **用途**：按 ID 查询单条 Issue；不存在或业务归属不匹配时抛异常。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `issue_id` | `str` | 是 | Issue 唯一 ID。 |
  | `bk_biz_id` | `int \| None` | 否 | 传入时会校验 Issue 的业务归属；不匹配按「不存在」处理，避免泄露跨业务 Issue 存在信息。 |
- **返回**：`IssueDocument` 实例。
- **异常**：
  - `IssueNotFoundError`：Issue 不存在，或 `bk_biz_id` 不匹配。
- **约束**：
  - 使用 `all_indices=True` 查询，避免跨天索引导致漏查。
  - 查询结果会正确处理 `_source` 中的 `id` 字段，防止 UPSERT 退化为 INSERT。
- **使用示例**：
  ```python
  from bkmonitor.documents.issue import IssueDocument

  issue = IssueDocument.get_issue_or_raise("1751234567a1b2c3d4", bk_biz_id=2)
  print(issue.status, issue.name)
  ```

### `assign(assignees, operator)`

- **用途**：首次指派负责人；仅能在 `pending_review` 状态下调用，调用后 Issue 进入 `unresolved`。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `assignees` | `list[str]` | 是 | 负责人标识列表，会整体替换当前 `assignee`。 |
  | `operator` | `str` | 是 | 操作人，写入活动日志。 |
- **返回**：`list[dict]` — 该 Issue 全部活动日志（含本次新增），按时间降序排列。
- **异常**：
  - `ValueError`：当前状态不是 `pending_review`。
  - `IssueFrozenError`：当前 Issue 是活跃合并关系的 member。
- **约束**：
  - 若当前状态不是 `pending_review`，应调用 `reassign`（改派不触发状态流转）。
- **使用示例**：
  ```python
  issue = IssueDocument.get_issue_or_raise("1751234567a1b2c3d4", bk_biz_id=2)
  activities = issue.assign(assignees=["admin"], operator="admin")
  ```

### `reassign(assignees, operator)`

- **用途**：改派负责人；任意状态均可调用，不触发状态流转。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `assignees` | `list[str]` | 是 | 新负责人列表，整体替换。 |
  | `operator` | `str` | 是 | 操作人。 |
- **返回**：`list[dict]` — 全部活动日志。
- **异常**：
  - `IssueFrozenError`：当前 Issue 是活跃合并关系的 member。
- **约束**：
  - 非 `pending_review` 状态下想变更负责人，必须走本方法；`assign` 会报错。
- **使用示例**：
  ```python
  activities = issue.reassign(assignees=["operator_a", "operator_b"], operator="admin")
  ```

### `resolve(operator)`

- **用途**：标记 Issue 为已解决；`pending_review` 或 `unresolved` → `resolved`。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `operator` | `str` | 是 | 操作人。 |
- **返回**：`list[dict]` — 全部活动日志；已是 `resolved` 时返回空列表（幂等 no-op）。
- **异常**：
  - `ValueError`：当前状态不是活跃状态（`pending_review`/`unresolved`）。
  - `IssueFrozenError`：当前 Issue 是活跃合并关系的 member（幂等短路先于冻结守卫，重复 resolve 不抛）。
- **约束**：
  - 幂等：重复调用返回空列表，不报错、不写活动日志。
  - 调用成功会级联把所有 active member 同步为 `resolved`（不破坏合并关系）。
- **使用示例**：
  ```python
  activities = issue.resolve(operator="admin")
  ```

### `archive(operator)`

- **用途**：归档 Issue；`pending_review` 或 `unresolved` → `archived`。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `operator` | `str` | 是 | 操作人。 |
- **返回**：`list[dict]` — 全部活动日志。
- **异常**：
  - `ValueError`：当前状态不是活跃状态。
  - `IssueFrozenError`：当前 Issue 是活跃合并关系的 member。
- **约束**：
  - 调用成功会级联把所有 active member 同步为 `archived`。
- **使用示例**：
  ```python
  activities = issue.archive(operator="admin")
  ```

### `reopen(operator)`

- **用途**：重新打开 Issue；仅 `resolved` → `unresolved`。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `operator` | `str` | 是 | 操作人。 |
- **返回**：`list[dict]` — 全部活动日志。
- **异常**：
  - `ValueError`：当前状态不是 `resolved`。
  - `IssueFrozenError`：当前 Issue 是活跃合并关系的 member。
- **约束**：
  - 会清空 `resolved_time`。
  - 调用成功会级联把所有 active member 同步为 `unresolved`。
- **使用示例**：
  ```python
  activities = issue.reopen(operator="admin")
  ```

### `restore(operator)`

- **用途**：恢复归档 Issue；`archived` → 归档前状态。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `operator` | `str` | 是 | 操作人。 |
- **返回**：`list[dict]` — 全部活动日志。
- **异常**：
  - `ValueError`：当前状态不是 `archived`。
  - `IssueFrozenError`：当前 Issue 是活跃合并关系的 member。
- **约束**：
  - 归档前状态从历史活动日志推断；无记录时兜底为 `pending_review`。
  - 若恢复到活跃态，清空 `resolved_time`；若恢复到 `resolved`，保留 `resolved_time`。
- 调用成功会级联把所有 active member 同步到同一目标状态。
- **使用示例**：
  ```python
  activities = issue.restore(operator="admin")
  ```

### 合并/拆分说明

- 合并/拆分写操作由 Web 层 `MergeIssueResource` / `SplitIssueResource` 转发到 api role 的 `MergeResource` / `SplitResource` 执行。
- 关系持久化在 MySQL `IssueMergeRelation`（`bkmonitor_issue_merge_relation`）。
- 主 Issue 状态变更会级联同步 active member 的 ES `status`；被拆分的 member 状态保持当前状态不变。
- 查询/详情路径通过 `IssueMergeResolver` 进行 display_id 折叠、member 排除、聚合数据 union。

### `add_comment(content, operator)`

- **用途**：添加跟进评论；若当前为 `pending_review`，会自动流转到 `unresolved`。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `content` | `str` | 是 | 评论内容。 |
  | `operator` | `str` | 是 | 评论作者/操作人。 |
- **返回**：`list[dict]` — 全部活动日志（含本次 `comment` 与可能的状态变更）。
- **异常**：
  - `IssueFrozenError`：当前 Issue 是活跃合并关系的 member。
- **约束**：
  - 空内容应在外层校验；本方法按传入值写入。
- **使用示例**：
  ```python

  ```

### `update_priority(priority, operator)`

- **用途**：修改 Issue 优先级；任意状态均可调用，若当前为 `pending_review` 会自动流转到 `unresolved`。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `priority` | `str` | 是 | 优先级枚举：`P0`（高）、`P1`（中）、`P2`（低）。 |
  | `operator` | `str` | 是 | 操作人。 |
- **返回**：`list[dict]` — 全部活动日志。
- **异常**：
  - `IssueFrozenError`：当前 Issue 是活跃合并关系的 member。
- **约束**：
  - 优先级变更不写 `priority_change` 外的副作用。
- **使用示例**：
  ```python
  from constants.issue import IssuePriority

  activities = issue.update_priority(priority=IssuePriority.P0, operator="admin")
  ```

### `rename(new_name, operator, enforce_unique=True, content=None)`

- **用途**：重命名 Issue。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `new_name` | `str` | 是 | 新名称，首尾空白会被 strip。 |
  | `operator` | `str` | 是 | 操作人。 |
  | `enforce_unique` | `bool` | 否 | `True`（默认）时同业务下禁止重名；`False` 时允许重名，供系统自动标题使用。 |
  | `content` | `str \| None` | 否 | 写入 `NAME_CHANGE` 活动日志的附加审计内容；`operator="system"` 时用于记录真实发起人。 |
- **返回**：`list[dict]` — 全部活动日志；名称未变化时直接返回当前活动列表。
- **异常**：
  - `IssueNameDuplicatedError`：`enforce_unique=True` 且同业务已存在同名 Issue。
  - `IssueFrozenError`：当前 Issue 是活跃合并关系的 member。
- **约束**：
  - 用户手工改名应保持 `enforce_unique=True`（默认）。
  - LLM 标题生成等系统路径应传 `enforce_unique=False`。
- **使用示例**：
```python
  activities = issue.rename(new_name="订单服务 DB 超时", operator="admin")
  ```

### `gen_issue_fingerprint(strategy_id, aggregate_dimensions, data_dimensions)`

契约来源：`alarm_backends.service.fta_action.issue_processor.gen_issue_fingerprint`

- **用途**：生成 Issue 唯一指纹（count_md5）。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `strategy_id` | `int` | 是 | 策略 ID。 |
  | `aggregate_dimensions` | `list[str]` | 是 | 聚合维度列表，来自 `issue_config.aggregate_dimensions`。 |
  | `data_dimensions` | `dict` | 是 | 原始告警维度，取自 `alert.event.extra_info.origin_alarm.data.dimensions`。 |
- **返回**：`str \| None`；任一维度缺失/为空时返回 `None`，调用方应跳过该告警。
- **约束**：
  - 空 `aggregate_dimensions` 时退化为按 strategy 单桶。
  - 每个元素带 `strategy:{id}` / `{key}={value}` 前缀防错位与跨策略碰撞。
  - 维度按 key 排序，值做 `str(...).strip()` 归一化。

## IssueAggregationProcessor（`alarm_backends/service/fta_action/issue_processor.py`）

契约来源：`IssueAggregationProcessor` 类

### `__init__(alert, strategy)`

- **用途**：构造聚合处理器实例。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `alert` | `AlertDocument` | 是 | 待关联的告警文档实例。 |
  | `strategy` | `dict` | 是 | 策略缓存字典，需包含 `id`、`bk_biz_id`、`name`、`issue_config` 等字段。 |
- **返回**：处理器实例。
- **约束**：
  - `strategy` 通常来自 `StrategyCacheManager` 的缓存对象；`issue_config` 字段决定聚合行为。

### `process()`

- **用途**：主入口——把当前告警关联到已有活跃 Issue，或创建新 Issue。
- **参数**：无实例方法参数（构造时传入 `alert`/`strategy`）。
- **返回**：`bool`
  - `True`：告警成功关联/创建 Issue（`alert.issue_id` 已写入）。
  - `False`：未进入 Issue 池（策略未开启、级别不匹配、条件过滤、缺维度、抢锁失败等）。
- **异常**：
  - 内部捕获 ES/Redis 异常并打日志；不会向上抛阻断 fta_action 主流程。
- **约束**：
  - 聚合维度取值来自 `alert.event.extra_info.origin_alarm.data.dimensions`，不是 `alert.dimensions`。
  - 缺任一聚合维度时直接返回 `False`（不打错误）。
  - 同 fingerprint 并发新建 Issue 时，仅一个 worker 能拿到分布式锁。
  - 新建 Issue 后，若部署 env 与业务白名单允许，会异步派发 LLM 标题任务。
- **使用示例**：
  ```python
  from alarm_backends.service.fta_action.issue_processor import IssueAggregationProcessor

  for alert in alerts:
      IssueAggregationProcessor(alert, strategy).process()
  ```

### `sync_issue_alert_stats()`

- **用途**：Celery 周期任务入口，扫描全量活跃 Issue，同步统计与补偿漏关联告警。
- **参数**：无。
- **返回**：无（`ignore_result=True`）。


## LLM 标题派发入口（`alarm_backends/service/fta_action/tasks/issue_tasks.py`）

### `generate_issue_llm_title(issue_id, bk_biz_id, default_name, alert_id, alert_retry_attempt=0)`

- **用途**：新建 Issue 后异步派发 LLM 标题生成任务。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `issue_id` | `str` | 是 | 目标 Issue ID。 |
  | `bk_biz_id` | `int` | 是 | 业务 ID。 |
  | `default_name` | `str` | 是 | 创建时的默认名，用于 CAS 校验（防止覆盖用户抢先改名）。 |
  | `alert_id` | `str` | 是 | 用于取关联日志的告警 ID。 |
  | `alert_retry_attempt` | `int` | 否 | 告警查询重试次数，自动路径保持默认 0。 |
- **返回**：无（`ignore_result=True`）。
- **异常**：
  - 所有失败静默处理，保留默认名，不入队重试。
- **约束**：
  - 队列：`celery_llm_task`。
  - 仅当日志类告警且关联内容非空、业务在白名单、未触发限流时才真正生成。
  - 只有 `alert_not_found` 会按 1s/3s 延迟重试。
- **使用示例**：
  ```python
  from alarm_backends.service.fta_action.tasks.issue_tasks import generate_issue_llm_title

  generate_issue_llm_title.delay(
      issue_id=issue.id,
      bk_biz_id=2,
      default_name=issue.name,
      alert_id=alert.id,
  )
  ```

### `regenerate_issue_llm_title(issue_id, bk_biz_id, *, alert_id=None, operator="system")`

- **用途**：运维显式补偿：对指定 Issue 重新生成 LLM 标题（同步执行）。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | `issue_id` | `str` | 是 | 目标 Issue ID。 |
  | `bk_biz_id` | `int` | 是 | 业务 ID。 |
  | `alert_id` | `str \| None` | 否 | 指定用于取日志的告警；不传则取该 Issue 最新关联告警。 |
  | `operator` | `str` | 否 | 审计发起人标识；非 `system` 时写入 `NAME_CHANGE` content，但 rename operator 恒为 `system`。 |
- **返回**：`dict` — `{"issue_id", "bk_biz_id", "result", "old_name", "new_name"}`。
- **异常**：
  - 资格检查失败时返回对应 `result` 字段（如 `skipped_user_renamed`、`skipped_inactive` 等），不抛异常。
- **约束**：
  - 绕过 `ENABLE_ISSUE_LLM_TITLE` 部署闸门与业务白名单（运维显式发起）。
  - 保留业务级限流。
  - 当前名已被真实用户修改、Issue 非活跃、为活跃合并 member 时跳过。
- **使用示例**：
  ```python
  from alarm_backends.service.fta_action.tasks.issue_tasks import regenerate_issue_llm_title

  result = regenerate_issue_llm_title(
      issue_id="1751234567a1b2c3d4",
      bk_biz_id=2,
      operator="ops_admin",
  )
  print(result["result"], result["old_name"], result["new_name"])
  ```
