# 使用总览：TAPD 集成子专家

> 契约快照生成于 2026-07-31。
> 若使用中发现行为与契约不符，可能代码已变更——expert-lookup 会自动增量修正，或用 expert-team 全量重建。

## 能力清单

TAPD 集成子专家覆盖 Issue 与 TAPD 之间的授权、工作区管理和单据关联能力：

- **用户态 OAuth 授权**：生成 TAPD 用户态授权 URL、处理 OAuth 回调、加密存储/读取/删除用户 access_token。
- **应用态工作区授权**：生成 `open_app_install` 安装 URL、处理应用安装回调、建立本地 `TapdWorkspaceBinding`。
- **工作区管理**：查询已授权 TAPD 项目、查询用户可见 TAPD 项目（含五态标记）、手动解绑/重新关联工作区、撤销用户授权。
- **单据字段与搜索**：获取 TAPD story/bug 的核心字段定义、搜索已有 TAPD 单据。
- **Issue-TAPD 关联**：为 Issue 创建 TAPD 单据并自动关联、将 Issue 关联到已有 TAPD 单据、查询 Issue 的 TAPD 关联列表。

## 能力边界

本模块不处理以下事项：

- 不实现 TAPD 单据的状态双向同步策略（仅写入 `sync_status` 标记位，具体同步由外部消费方决定）。
- 不在解绑时撤回 TAPD 侧的应用授权（仅删除本地 binding 并写入 tombstone）。
- 不覆盖 TAPD API SDK 本身（通过 `api.tapd.*` 调用，TAPD API 细节不在本模块内）。
- 不处理 Issue 状态机操作（创建/关联 TAPD 前仅做合并冻结校验，状态变更由 Issue 核心模块负责）。
- 不处理业务空间/租户转换，调用方需自行将 `bk_biz_id` 转换为 `space_uid`/`bk_tenant_id`（参考 [bkmonitor/bkmonitor/utils/tenant.py](file://bkmonitor/bkmonitor/utils/tenant.py)）。

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| 调用 `tapd/user_workspace` 返回 403 但没有 `auth_url` | 请求未传 `success_url` | 该接口仅在携带 `success_url`（以及可选 `error_url`）时才返回可跳转的 `auth_url`，否则只提示未授权 |
| 已手动解绑的工作区自动变回 bound | `tapd/user_workspace` 对 importable 项目会静默尝试 `try_bind_importable` | 手动解绑会写入 tombstone，tombstone 存在时不会再自动重绑 |
| 创建 bug 单据时序列化器报错 | `tapd_type=bug` 时未传 `te` | bug 类型必须提供 `te`（测试人员），story 类型不需要 |
| 解绑工作区时报"存在活跃 Issue 关联" | 该工作区下仍有待审核/未解决的 Issue 关联了 TAPD 单据 | 先解决或归档相关 Issue，再执行解绑 |
| 重绑时提示授权失效 | 用户态 token 已过期或被清除 | 先重新走用户态 OAuth 授权，再调用重绑接口 |
| `signed_state` 校验失败 | URL 中 state 被截断/过期/篡改 | state 有效期 15 分钟，需完整透传，禁止手动修改 |
