## 流程一：用户态授权

**业务目标**：让当前登录用户完成 TAPD 用户态 OAuth 授权，使后续 TAPD 接口能够代表该用户调用。

### 调用顺序

1. 前端调用 `POST /fta/issue/tapd/user_workspace/`，传入 `bk_biz_id`、`success_url`、`error_url`。
2. 后端检查 Redis `tapd_uat:{tenant}:{user}` 是否存在有效 token。
3. 若未授权，后端返回 `{"result": false, "code": 403, "data": {"auth_url": "..."}}`。
4. 前端跳转到 `auth_url`，用户在 TAPD 完成授权。
5. TAPD 重定向到 `tapd_user_oauth_callback/`，后端用 code 换 token 并加密写入 Redis。
6. 后端 302 重定向到 `success_url`，前端回到业务页面。
7. 再次调用 `tapd/user_workspace/` 即可获取工作区列表。

### 事务边界

- 步骤 3 为只读查询，无事务。
- 步骤 5 写入 Redis token，非 DB 事务；失败时重定向到 `error_url`。

### 预期结果

- Redis 中存在 `tapd_uat:{tenant}:{user}`，后续 TAPD 接口可正常调用。

### 错误处理

- 用户取消授权：TAPD 回调携带 `error=access_denied`，后端重定向到 `error_url`。
- `signed_state` 过期/被篡改：后端重定向到 `error_url` 或 `/`。
- 用户 mismatch：后端重定向到 `error_url`。

### 使用示例

```python
import requests

BASE = "http://bkmonitor.example.com"
cookies = {"bk_ticket": "..."}

# 1. 查询用户工作区，触发授权引导
resp = requests.post(
    f"{BASE}/fta/issue/tapd/user_workspace/",
    json={
        "bk_biz_id": 2,
        "success_url": "/fta/issue/?tab=tapd#success",
        "error_url": "/fta/issue/?tab=tapd#error",
    },
    cookies=cookies,
)
data = resp.json()
if not data["result"] and data["code"] == 403 and data["data"].get("auth_url"):
    # 2. 前端跳转授权
    auth_url = data["data"]["auth_url"]
    print(f"请跳转授权: {auth_url}")
    # 用户授权后，TAPD 会 302 回到 success_url
else:
    print("已授权或无需授权", data["data"])
```

## 流程二：创建 TAPD 单并关联

**业务目标**：为某个 Issue 在 TAPD 创建缺陷/需求单据，并自动建立 Issue-TAPD 关联关系。

### 调用顺序

1. 前端调用 `POST /fta/issue/issue/get_tapd_fields/`，获取指定项目/单据类型的核心字段定义。
2. 前端调用 `POST /fta/issue/issue/create_tapd/`，传入 Issue ID、项目、字段值、`sync_status`。
3. 后端校验 Issue 存在、归属正确、未合并冻结。
4. 后端调用 TAPD API 创建单据。
5. 后端写入 `IssueTapdRelation`，`link_mode` 为 `create`。
6. 后端写入 `CREATE_TAPD` 活动日志并返回完整活动列表。

### 事务边界

- 步骤 3~6 在单次 Resource 调用内完成，无显式 DB 事务包裹；TAPD 调用、MySQL 写入、ES 写入相互独立。
- TAPD 单据创建失败会抛异常，整体失败；本地关联与活动日志写入失败会记录日志但不阻塞主流程。

### 预期结果

- TAPD 侧生成对应 story/bug。
- `IssueTapdRelation` 出现一条 `link_mode=create` 的记录。
- Issue 活动日志中出现 `create_tapd` 类型记录。

### 错误处理

- Issue 合并冻结：返回 `MERGE_FREEZE_VIOLATION`。
- bug 类型未传 `te`：序列化器 400 报错。
- TAPD API 失败：BKAPIError 上抛，前端按统一错误处理。

### 使用示例

```python
import requests

BASE = "http://bkmonitor.example.com"
cookies = {"bk_ticket": "..."}

# 1. 获取字段定义
fields_resp = requests.post(
    f"{BASE}/fta/issue/issue/get_tapd_fields/",
    json={"bk_biz_id": 2, "workspace_id": 10104801, "tapd_type": "bug", "template_id": 0},
    cookies=cookies,
)
print(fields_resp.json()["data"])

# 2. 创建 TAPD 单并关联
create_resp = requests.post(
    f"{BASE}/fta/issue/issue/create_tapd/",
    json={
        "bk_biz_id": 2,
        "issue_id": "2026073100000001abc12345",
        "tapd_type": "bug",
        "workspace_id": 10104801,
        "name": "【监控告警】CPU 使用率异常",
        "description": "关联告警已聚合为 Issue，详见监控平台。",
        "owner": "zhangsan",
        "priority_label": "高",
        "iteration_id": "123456789",
        "te": "lisi",
        "sync_status": True,
    },
    cookies=cookies,
)
print(create_resp.json()["data"])
```

## 流程三：手动解绑/重绑工作区

**业务目标**：当业务不再需要某个 TAPD 项目时手动解绑；后续需要时重新关联。

### 解绑调用顺序

1. 前端调用 `POST /fta/issue/tapd/unbind_workspace/`，传入 `bk_biz_id`、`workspace_id`。
2. 后端校验本地 `TapdWorkspaceBinding` 存在。
3. 后端检查是否存在活跃（待审核/未解决）Issue 关联该项目。
4. 若存在活跃关联，返回 400 并提示先解决/归档相关 Issue。
5. 在同一事务中写入 `TapdWorkspaceManualUnbind` tombstone 并删除 `TapdWorkspaceBinding`。
6. 返回 `{"success": True}`。

### 重绑调用顺序

1. 前端调用 `POST /fta/issue/tapd/rebind_workspace/`，传入 `bk_biz_id`、`workspace_id`。
2. 后端校验用户态 token 有效。
3. 后端校验当前用户仍有权访问该 TAPD 项目，且项目级应用授权仍然存在。
4. 在同一事务中删除 tombstone 并创建/复用 `TapdWorkspaceBinding`。
5. 返回 `{"success": True, "workspace": {"id": ..., "name": ...}}`。

### 事务边界

- 解绑：tombstone 写入 + binding 删除在同一张事务内。
- 重绑：tombstone 删除 + binding 创建在同一张事务内。

### 预期结果

- 解绑后：`tapd/user_workspace` 中该项目标记为 `manually_unbound`，不会自动重绑。
- 重绑后：项目恢复 `bound` 状态，可继续创建/关联 TAPD 单。

### 错误处理

- 解绑时存在活跃 Issue 关联：返回具体活跃 Issue ID 列表，前端引导用户处理。
- 重绑时用户态 token 失效：code=403，前端重新走用户态授权。
- 重绑时应用授权已失效：code=403，前端引导重新安装应用。

### 使用示例

```python
import requests

BASE = "http://bkmonitor.example.com"
cookies = {"bk_ticket": "..."}

# 解绑
unbind_resp = requests.post(
    f"{BASE}/fta/issue/tapd/unbind_workspace/",
    json={"bk_biz_id": 2, "workspace_id": "10104801"},
    cookies=cookies,
)
print(unbind_resp.json()["data"])

# 重绑
rebind_resp = requests.post(
    f"{BASE}/fta/issue/tapd/rebind_workspace/",
    json={"bk_biz_id": 2, "workspace_id": "10104801"},
    cookies=cookies,
)
print(rebind_resp.json()["data"])
```

## 流程四：关联已有 TAPD 单据

**业务目标**：将某个 Issue 与 TAPD 中已存在的 story/bug 单据建立关联，而不是新建单据。

### 调用顺序

1. 前端调用 `POST /fta/issue/issue/search_tapd_items/`，搜索并选择目标单据。
2. 前端调用 `POST /fta/issue/issue/link_tapd/`，传入 `issue_id`、`workspace_id`、`tapd_items`、`sync_status`。
3. 后端校验 Issue 存在、归属正确、未合并冻结，且 `tapd_items` 在 1~200 条之间。
4. 后端校验 TAPD 项目已与当前业务关联。
5. 后端校验所选单据在 TAPD 中存在且属于该项目。
6. 后端对每条单据查重：已存在的关联更新 `sync_status`，不重复创建。
7. 后端为实际新建的关联写入 `TAPD_LINK` 活动日志。
8. 返回关联结果列表与活动列表。

### 事务边界

- 单次 Resource 调用内完成校验、查重、创建/更新、记日志，无显式 DB 事务包裹。
- ES 活动日志写入失败会记录日志但不阻塞主流程。

### 预期结果

- `bkmonitor_issue_tapd_relation` 出现 `link_mode=link` 的记录。
- Issue 活动日志中出现 `tapd_link` 类型记录。

### 错误处理

- Issue 合并冻结：返回 `MERGE_FREEZE_VIOLATION`。
- `tapd_items` 为空或超过 200 条：400。
- 单据不存在或不属于该项目：400。
- `tapd_items` 内 `tapd_id` 重复：400。

### 使用示例

```python
import requests

BASE = "http://bkmonitor.example.com"
cookies = {"bk_ticket": "..."}

# 1. 搜索已有单据
search_resp = requests.post(
    f"{BASE}/fta/issue/issue/search_tapd_items/",
    json={
        "bk_biz_id": 2,
        "workspace_id": 10104801,
        "tapd_type": "story",
        "name": "监控",
        "limit": 10,
    },
    cookies=cookies,
)
items = search_resp.json()["data"]

# 2. 关联到 Issue
link_resp = requests.post(
    f"{BASE}/fta/issue/issue/link_tapd/",
    json={
        "bk_biz_id": 2,
        "issue_id": "2026073100000001abc12345",
        "workspace_id": 10104801,
        "tapd_items": [
            {"tapd_id": item["id"], "tapd_type": item["tapd_type"], "tapd_title": item["name"]}
            for item in items
        ],
        "sync_status": False,
    },
    cookies=cookies,
)
print(link_resp.json()["data"])
```
