# C1-能力契约：kernel_api 网关专家

> 黑盒契约：只写"怎么用"，实现细节见 implementation/。代码示例为使用方代码（调用者视角）。

## 1. URL 路由注册（urls.py）

### register_url(prex, views_module_list, namespace)
- **用途**：把一组视图模块注册为一个 `ResourceRouter` 的 URL 前缀。
- **参数**：
  - `prex`：URL 前缀正则，如 `r"^api/v4/"`。
  - `views_module_list`：视图模块（模块名或模块对象），模块内所有 `ResourceViewSet` 自动注册。
  - `namespace`：URL namespace，如 `api.v4`。
- **返回**：`re_path` 对象（可直接 append 到 urlpatterns）。
- **约束**：视图模块内的 ViewSet 通过 `resource_routes` 定义 endpoint。
- **契约来源**：`kernel_api.urls.register_url`

### register_v2() / register_v3() / register_v4()
- **用途**：注册对应版本的 API 路由。
  - v2 → `/api/v2/`（视图模块 `views.v2`）
  - v3 → `/api/v3/{模块名}/`（按 `INSTALLED_APIS` 环境变量过滤，默认 `collector,meta,models,query`）
  - v4 → `/api/v4/`（视图模块 `views.v4`）
- **参数行为语义**：`INSTALLED_APIS` 环境变量（逗号分隔）决定 v3 暴露哪些模块；未设置时用 `DEFAULT_INSTALLED_APIS`。
- **扩展**：`settings.ALLOW_EXTEND_API=True` 时 v2/v3/v4 均追加 `extend_views` 模块（见 §5）。
- **契约来源**：`kernel_api.urls.register_v2/register_v3/register_v4`

### 使用示例（新增一个 v4 endpoint）
```python
# 1) 在 kernel_api/views/v4/mymodule.py 定义视图
from core.drf_resource.viewsets import ResourceRoute, ResourceViewSet

class MyModuleViewSet(ResourceViewSet):
    resource_routes = [
        ResourceRoute("POST", MyActionResource, endpoint="my_action"),
    ]
    # URL: /api/v4/my_action/
```
```python
# 2) 在 kernel_api/views/v4/__init__.py 加入导出
from .mymodule import *  # noqa
```
> 环境初始化（Django settings 指向 api 角色）假设已就绪。

## 2. 认证与授权（middlewares/authentication.py）

> 完整认证契约见子专家 [认证与安全子专家](sub-experts/认证与安全子专家/C1-能力契约.md)。此处仅列网关侧入口行为。

### AuthenticationMiddleware.process_view(request, view, *args, **kwargs)
- **用途**：请求进入视图前的统一认证入口（Django 中间件）。
- **认证方式选择**（按优先级）：
  1. **apigw JWT**：请求头 `X-Bkapi-From: apigw` + `X-Bkapi-Jwt` → `BkJWTClient.validate()`，RS512 验签，取 `app.app_code` / `user.username`。
  2. **MCP 请求**：请求头 `X-Bkapi-Mcp-Server-Name`（或 `X-Bk-Request-Source` 匹配、app_code 匹配）→ `_handle_mcp_auth`，按 MCP 服务映射 IAM 权限动作校验。
  3. **API Token**：请求头 `Authorization: Bearer <token>` → `ApiAuthToken` 校验（有效性/视图白名单/命名空间 `biz#{id}`）。
  4. **app_code 白名单**：`is_match_api_token(request, bk_tenant_id, app_code)` 按 `ApiAuthToken` 记录的 `namespaces`（`biz#all` / `biz#{id}`）授权。
- **返回**：通过则设置 `request.user`（必要时 `request.biz_id` / `request.skip_check` / `request.token`）返回 None；失败返回 `HttpResponseForbidden`。
- **约束**：视图类设置 `login_exempt=True` 跳过认证；`/grafana/` 路径且无 app_code 时用 `admin` 用户豁免。
- **契约来源**：`kernel_api.middlewares.authentication.AuthenticationMiddleware`

## 3. 异常处理（exceptions.py）

### api_exception_handler(exc, context)
- **用途**：kernel_api 的 DRF 统一异常处理器（`REST_FRAMEWORK.EXCEPTION_HANDLER` 指定）。
- **行为语义**：
  - 所有业务异常渲染为 `{code, result: false, message, data}`；HTTP 状态码**恒为 200**。
  - `code` 取 `exc.code`（无则 500）；DRF 异常（有 `detail`）额外带 `detail` 键。
  - `data` 仅白名单透传 `error_code` / `next_actions` 两个键（`exc.data` 其余内容丢弃，防泄露）。
  - `ValidationError` 不记日志，其余异常记 `logger.exception`。
- **返回**：`Response(json_data, content_type="application/json")`。
- **约束**：前端/web 网关识别业务错误请认 `body.code`，不要依赖 HTTP 状态码。
- **契约来源**：`kernel_api.exceptions.api_exception_handler`

### 使用示例（让 web 端识别业务错误码）
```python
# web 端 packages/xxx/resources.py
from core.drf_resource.contrib.api import APIResource
from core.errors.issue import IssueRenameConflictError

class RenameIssueResource(APIResource):
    def perform_request(self, validated_request_data):
        try:
            return api.issue.rename(validated_request_data)   # 走 kernel_api 网关
        except BKAPIError as e:
            if e.data.get("code") == 3327001:                 # kernel_api 透传的 body.code
                raise IssueRenameConflictError()
            raise
```

## 4. 字段适配（adapters.py）

### ApiRenderer.format_field(result, level=0)
- **用途**：响应渲染时递归把内核字段名映射为蓝鲸规范字段名。
- **参数行为语义**：`level=0` 不转换（最外层）；`level<0` 递归全部层级。
- **映射示例**：`biz_id→bk_biz_id`、`app_code→bk_app_code`、`plat_id→bk_cloud_id`、`company_id→bk_supplier_id`。
- **附加行为**：MCP 请求（存在 trace_id）时响应注入 `trace_id` 字段。
- **契约来源**：`kernel_api.adapters.ApiRenderer`

### ApiModelFilterSet
- **用途**：过滤器基类，把 `bk_biz_id` 等蓝鲸规范参数自动映射回内核字段（`API_FIELD_FORMATED_MAPPINGS` 反向）。
- **约束**：`Meta.extend_fields` 可显式声明映射；未声明时按 `get_extend_fields()` 自动推导。
- **契约来源**：`kernel_api.adapters.ApiModelFilterSet`

## 5. 扩展点（extend_views / extend_resource / extend_utils）

- **用途**：`ALLOW_EXTEND_API=True` 时，kernel_api 动态加载 `extend_views`（附加 ViewSet 模块）到 v2/v3/v4；`extend_resource`、`extend_utils` 提供扩展 Resource / 工具位。
- **行为语义**：扩展模块不存在时 `urls.py` 捕获 `ImportError` 置 `extend_views=None`，不影响主路由。
- **约束**：扩展点是可选加载，扩展代码不能依赖主代码 import 顺序。
- **契约来源**：`kernel_api.urls`（`try: from kernel_api import extend_views`）

## 6. DB 路由（dbroutors.py）

### KernelAPIRouter
- **用途**：Django `DATABASE_ROUTERS`，把 `monitor_api`、`metadata` 两个 app_label 的模型路由到 `settings.BACKEND_DATABASE_NAME` 库，其余走 `default`。
- **方法**：`db_for_read` / `db_for_write` / `allow_relation` / `allow_migrate`。
- **约束**：`allow_migrate` 返回 `app_label not in routers`，即 backend 库不迁移这两个 app（迁移走主库）。
- **契约来源**：`kernel_api.dbroutors.KernelAPIRouter`

## 7. 运维工具（management/commands/check_apis.py）

### `python manage.py check_apis [-c CONFIG] [--doc_path DOC_PATH]`
- **用途**：校验 API 配置 YAML（默认 `kernel_api/docs/monitor.yaml`）完整性：name/label 非空、path 唯一、对应 API 文档存在。
- **返回**：stdout 打印不合规项 `{path}: {错误信息}`。
- **契约来源**：`kernel_api.management.commands.check_apis.Command`
