# C2-使用流程：kernel_api 网关专家

## 流程 1：新增一个对外内核 API（v4）

**业务目标**：在 `/api/v4/` 下暴露一个新的业务能力。

**调用顺序**：
1. 在 `views/v4/{module}.py` 定义 `ResourceViewSet`，`resource_routes` 声明 `ResourceRoute("POST", XxxResource, endpoint="xxx")`。
2. 业务逻辑写在 `XxxResource.perform_request`（可直接复用 `resource/` 下的内部 Resource）。
3. 在 `views/v4/__init__.py` 加 `from .{module} import *`。
4. （可选）在 `support-files/apigw/resources.yaml` 注册网关资源并补 API 文档。

**事务边界**：每个 Resource 的 `perform_request` 是独立请求；批量写操作需在 Resource 内显式管理事务。

**预期结果**：`POST /api/v4/xxx/` 返回蓝鲸标准 envelope（result/message/data，字段经 `ApiRenderer` 映射）。

**错误处理**：抛 `Error` 子类 → `api_exception_handler` 渲染 200 + body.code。

**代码示例**：
```python
# views/v4/example.py
from core.drf_resource.viewsets import ResourceRoute, ResourceViewSet

class ExampleViewSet(ResourceViewSet):
    resource_routes = [ResourceRoute("POST", GetExampleResource, endpoint="get_example")]
```
```python
# views/v4/__init__.py 追加
from .example import *  # noqa
```
```python
# 调用（任意客户端）
import requests
resp = requests.post(
    "https://<host>/api/v4/get_example/",
    json={"bk_biz_id": 2},
    headers={"X-Bkapi-From": "apigw", "X-Bkapi-Jwt": "<jwt>", "X-Bk-Tenant-Id": "default"},
)
data = resp.json()  # {"result": true, "message": "", "data": {...}, "code": 0}
```

## 流程 2：web 端通过 kernel_api 访问告警后台能力

**业务目标**：monitor_saas（web 角色）调用 alarm_backends 能力（策略缓存/告警检测等）。

**调用顺序**：
1. web 端定义 `APIResource` 子类（如 `api/issue/default.py` 的 `RenameResource`），`action` 指向 kernel_api 的 endpoint 路径（如 `/app/issue/rename/`）。
2. 请求经 API 网关到达 kernel_api，由 `AuthenticationMiddleware` 完成 apigw JWT 认证。
3. kernel_api 内 `views/v4/{module}.py` 的 Resource 执行（可访问 alarm_backends 挂载模块）。
4. 响应 200 + body.code 回传 web 端；web 端 `APIResource` 检查 `body.result`，失败抛 `BKAPIError`。

**事务边界**：跨进程，无共享事务；每次调用独立。

**预期结果**：web 端拿到标准化结果；业务失败时 `BKAPIError.data` 含上游 `code`/`message`。

**错误处理**：web 端 `except BKAPIError as e` 按 `e.data.get("code")` 识别并重抛专有错误（见 C1 §3）。

**代码示例**：
```python
# web 端 api/issue/default.py
from core.drf_resource.contrib.api import APIResource

class RenameResource(APIResource):
    method = "POST"
    action = "/app/issue/rename/"   # 网关映射到 kernel_api /api/v4/issue/rename/
    IS_STANDARD_FORMAT = True
```
```python
# web 端业务调用
from core.drf_resource import api
result = api.issue.rename({"issue_id": "xxx", "name": "新标题", "bk_biz_id": 2})
```

## 流程 3：调用内核 RPC 函数（KernelRPCResource）

**业务目标**：统一调用 admin/bkm-cli 等内核 RPC 函数（渐进式披露）。

**调用顺序**：
1. `func_name="__meta__", params.action="list"` 查可调用函数列表。
2. `params.action="detail", target_func_name=<函数名>` 查函数入参 schema。
3. 正式调用：`func_name=<函数名>, params={...}`。

**事务边界**：RPC 函数全部为只读/巡检语义；写操作经 bkm-cli op 白名单 + 审计元数据管控。

**预期结果**：`{func_name, protocol, result}`，result 为函数返回值。

**错误处理**：未知函数抛 `CustomException`（提示先查 `__meta__`）；bkm-cli 走 `BkmCliOpCallResource`（只接受 op_id）。

**代码示例**：
```python
# 经 HTTP 调用 KernelRPCResource（views/v4/kernel_rpc.py，endpoint=call）
resp = requests.post(
    "https://<host>/api/v4/call/",
    json={"func_name": "admin.cluster_info.list", "params": {"bk_biz_id": 2}},
    headers={"X-Bkapi-From": "apigw", "X-Bkapi-Jwt": "<jwt>"},
)
print(resp.json()["data"]["result"])
```
