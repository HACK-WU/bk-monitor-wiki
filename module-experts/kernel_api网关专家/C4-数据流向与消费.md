# C4-数据流向与消费：kernel_api 网关专家

> 黑盒视角：只写数据"从哪来、到哪去、用来干嘛"，不写消费方处理逻辑。

## 1. ApiAuthToken（API Token 认证数据）

- **来源接口**：`kernel_api.middlewares.authentication` 读取 `bkmonitor.models.ApiAuthToken`（`AuthType.API` 记录）；admin RPC `admin.api_auth_token.*` 提供 CRUD。
- **去向**：`AuthenticationMiddleware._handle_api_token_auth` 校验 Bearer Token；`is_match_api_token` 读缓存（`APP_CODE_TOKENS`，300s 刷新）做 app_code 命名空间授权。
- **消费方**：API 网关（Token 调用方）、kernel_api 认证中间件、后台管理面（admin.api_auth_token RPC）。
- **业务用途**：控制外部系统按 app_code × 命名空间（`biz#all` / `biz#{id}`）访问内核 API 的权限。

## 2. resource_data（Resource 请求采样）

- **来源接口**：`core.drf_resource.models.ResourceDataManager`（框架层，`settings.ENABLE_RESOURCE_DATA_COLLECT=True` 时启用），kernel_api 的 Resource 执行自动记录。
- **去向**：`resource_data` 表（按 `RESOURCE_DATA_COLLECT_RATIO` 采样）。
- **消费方**：线上排查者（查历史入参/返回）、调试工具。
- **业务用途**：排查线上问题时的请求快照。

## 3. APIGW 公钥（认证缓存）

- **来源接口**：`AuthenticationMiddleware.get_apigw_public_keys()` 经 `api.bk_apigateway.get_public_key` 获取，缓存于 `login_db` cache。
- **去向**：`BkJWTClient.validate()` 做 RS512 JWT 验签。
- **消费方**：kernel_api 认证中间件。
- **业务用途**：apigw JWT 签名验证，认证可信调用方。

## 4. 运营指标（OperationMetric，resource/operation）

- **来源接口**：`resource/operation/registry.py` 的 `OPERATION_METRIC_REGISTRY`（各 handler 注册）；对外经 `GetOperationMetricResource` / `GetOperationOverviewResource` 取值。
- **去向**：`operation_mcp:metric:*` Redis 缓存（`cache_ttl>0` 且未显式 end_time 时）；取值结果返回 MCP 调用方。
- **消费方**：AI MCP / 运营人员（指标目录 + 取值）。
- **业务用途**：运营数据（基础监控/存储/APM/日志/AIOps 分类）的渐进披露与取值，供 AI 问答。

## 5. 认证请求头（输入侧数据流）

- **来源**：API 网关透传的 `X-Bkapi-Jwt`、`X-Bk-Tenant-Id`、`X-Bk-Token-App-Code`、`X-Bkapi-Mcp-Server-Name`、`X-Bkapi-Permission-Action` 等请求头。
- **去向**：`AuthenticationMiddleware.process_view` → 设置 `request.user` / `request.biz_id` / `request.skip_check` / `request.token`。
- **消费方**：kernel_api 内所有 ViewSet/Resource（经 `get_request_username()`、`request.biz_id` 等读取）。
- **业务用途**：建立请求身份与租户/业务上下文，供后续权限与数据边界使用。
