## 路由注册机制

`register_url(prex, views_module_list, namespace)` 的实现：
1. 用 `__import__(views_module, fromlist=["*"])` 导入视图模块（或直接接受模块对象）。
2. 创建 `ResourceRouter()`，逐个 `router.register_module(views_module)` 扫描模块内所有 `ResourceViewSet` 子类。
3. 返回 `re_path(prex, include((router.urls, "kernel_api"), namespace=namespace))`。

`register_v3()` 的裁剪逻辑：
- `ROOT_MODULE_V3 = "kernel_api.views.v3"`。
- `apis = {m: f"{ROOT_MODULE_V3}.{m}" for m in package_contents(ROOT_MODULE_V3) if m in INSTALLED_APIS}`——`INSTALLED_APIS` 从环境变量读取，默认 `["collector","meta","models","query"]`。
- 每个模块注册为独立 URL 前缀：`/api/v3/{name}/`。

章节来源：[urls.py](file://bkmonitor/kernel_api/urls.py)（关键符号：`register_url` / `register_v3` / `package_contents`）

## 认证实现要点

`AuthenticationMiddleware.process_view` 判定顺序（源码确认）：

```python
# 伪代码梳理，见 authentication.py:603
if view.login_exempt: return None                      # 登录豁免
if use_apigw_auth(request):                            # X-Bkapi-From=apigw 且带 JWT
    request.jwt = BkJWTClient(...); jwt.validate()     # RS512 验签
if use_mcp_auth(request, app_code):                    # MCP 请求头 / 旧头 / app_code
    return _handle_mcp_auth(request, username)         # IAM 权限动作校验 + 指标上报
if use_api_token_auth(request):                        # Authorization: Bearer
    return _handle_api_token_auth(request, view)       # ApiAuthToken 校验
# 兜底：app_code 白名单 + 用户自动创建
if not app_code or is_match_api_token(...):            # ApiAuthToken namespaces 授权
    request.user = auth.authenticate(username, bk_tenant_id)  # AppWhiteListModelBackend 自动建用户
```

**关键实现细节**：
- `get_apigw_public_keys()` 用 `functools.lru_cache(maxsize=1)` + `login_db` cache 缓存公钥，公钥为空时 120s 短缓存防抖。
- `AppWhiteListModelBackend.authenticate` 用 `User.objects.get_or_create` 自动建用户；多租户模式下校验用户租户与当前租户匹配，不匹配时查 `bk_login` 确认后更新 `tenant_id`。
- MCP 认证中 `OPENCLAW_RECOVERING_MCP_TOOLS` 白名单限流 OpenClaw 工具；`_report_mcp_metric` 上报 `MCP_REQUESTS_TOTAL` 指标。

章节来源：[middlewares/authentication.py](file://bkmonitor/kernel_api/middlewares/authentication.py)（关键符号：`AuthenticationMiddleware.process_view` / `AppWhiteListModelBackend.authenticate` / `BkJWTClient.validate` / `is_match_api_token`）

## 异常渲染实现

`api_exception_handler(exc, context)`：
1. `ValidationError` 跳过日志，其余 `logger.exception(exc)`。
2. `json_data = failed(six.text_type(exc))`——`bkmonitor.utils.common_utils.failed` 生成 `{result: false, message, data: {}}`。
3. `code = getattr(exc, "code", 500)`；DRF 异常（有 `detail`）补 `json_data["detail"]` 并取 `status_code` 作为 code。
4. **data 白名单**：仅当 `exc.data` 为 dict 时透传 `error_code`/`next_actions` 两个键。
5. `Response(json_data, content_type="application/json")`——**不带 status**，HTTP 恒 200。

**设计意图**（源码注释确认）：`failed()` 默认清空 data；整体透出 `exc.data` 会让 `BKAPIError` 把上游原始响应体泄露到所有 API 角色端点。

章节来源：[exceptions.py](file://bkmonitor/kernel_api/exceptions.py)（关键符号：`api_exception_handler`）

## 字段映射实现

`ApiRenderer(MainJSONRenderer).format_field(result, level=0)`：
- `level == 0` 不转换（保留最外层 envelope 键）。
- 递归深层时把 `API_FIELD_FORMATED_MAPPINGS` 中的键映射为蓝鲸规范键（`biz_id→bk_biz_id`、`plat_id→bk_cloud_id` 等）。
- `get_result` 中为 MCP 请求注入 `trace_id`（`get_mcp_trace_id`）。

`ApiModelFilterSet` 在 `__init__` 中把请求参数 `bk_biz_id` 等反向映射回内核字段名再交给 DjangoFilterBackend。

章节来源：[adapters.py](file://bkmonitor/kernel_api/adapters.py)（关键符号：`ApiRenderer.format_field` / `ApiModelFilterSet` / `API_FIELD_FORMATED_MAPPINGS`）

## 结论

kernel_api 网关的横切能力集中在 4 个文件：路由（urls.py）负责版本化装配，认证（authentication.py）负责身份与授权，异常（exceptions.py）负责统一 envelope 渲染（恒 200 + body.code），适配（adapters.py）负责字段规范映射。诊断问题时优先定位这四个文件。
