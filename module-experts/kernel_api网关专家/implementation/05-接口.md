## 简介

kernel_api 通过 URL 前缀暴露三套版本 API，外加 grafana 代理、apm/rum 接口等。本文列出网关层接口总览（具体 endpoint 见各子专家）。

章节来源：[urls.py](file://bkmonitor/kernel_api/urls.py)（关键符号：`urlpatterns`）

## URL 版本概览

| 前缀 | 版本 | 视图模块 | 说明 |
|------|------|----------|------|
| `/api/v2/` | v2 | `views/v2`（bkdata / monitorapi / component） | 历史/兼容版本，含告警、用户配置、全局配置、主机快照 |
| `/api/v3/{mod}/` | v3 | `views/v3`（collector / meta / models / query） | 按 `INSTALLED_APIS` 裁剪；meta 暴露 metadata 数据源/结果表能力 |
| `/api/v4/` | v4 | `views/v4`（40+ 文件） | 当前主版本，覆盖告警/策略/日志/事件/Issue/RPC 等 |
| `/rest/v2/` | grafana | `monitor_web.grafana.views` | grafana 数据源接口（含 `query-api`、`o/bk_monitorv3` 别名） |
| `/apm_api/v1/` | apm | `apm.urls` | APM 接口 |
| `/rum_api/v1/` | rum | `rum.urls` | RUM 接口 |
| `/ping` / `/docs/` / `/admin/` | 工具 | — | 健康检查 / API 文档 / Django admin |

章节来源：[urls.py](file://bkmonitor/kernel_api/urls.py)（关键符号：`register_v2` / `register_v3` / `register_v4` / `urlpatterns`）

## 认证方式

见 [01-架构.md#请求生命周期](01-架构.md#请求生命周期) 与子专家 [认证与安全子专家](../sub-experts/认证与安全子专家/implementation/01-架构.md)。按请求头选择：

- **apigw JWT**：`X-Bkapi-From: apigw` + `X-Bkapi-Jwt`（RS512）
- **API Token**：`Authorization: Bearer <token>`（`ApiAuthToken`）
- **MCP**：`X-Bkapi-Mcp-Server-Name`（IAM 权限动作校验）
- **app_code 白名单**：`HTTP_BK_APP_CODE` + `is_match_api_token`（命名空间授权）

## 响应格式与错误码

- 成功：`{result: true, message: "", data: {...}, code: 0}`（字段经 `ApiRenderer` 映射）。
- 业务失败：HTTP **恒 200**，`{result: false, message: str(exc), code: <exc.code>, data: {...}}`。
- `code` 取值：`exc.code`（`Error` 子类自定义，如 3327001）或 DRF `status_code`；默认 500。
- `data` 白名单键：`error_code` / `next_actions`。
- 认证失败：HTTP 403（中间件直接返回 `HttpResponseForbidden`）。

**错误码约定**：`3` 开头统一为蓝鲸平台错误（3301xxx=外部API、3300xxx=业务逻辑）；kernel_api 侧专有错误码需避免与 `core/errors/upgrade.py` 3318001 等已占用段冲突（见记忆《错误码段冲突与 HTTP 状态码网关透传丢失》）。

## 结论

接口面由 `urls.py` 统一装配，v4 为当前主版本（子专家覆盖），v2/v3 为兼容层；错误响应统一 envelope + 恒 200 + body.code，前端识别业务错误必须读 body.code。
