## 简介

kernel_api 测试分两层：`kernel_api/tests/`（视图/Resource 级）与 `kernel_api/rpc/tests/`（RPC 函数级）。整体为 pytest + mock 风格，外部依赖（DB/ES/Kafka/CMDB）以 mock 隔离。

章节来源：[tests/](file://bkmonitor/kernel_api/tests/)

## 测试位置与覆盖

### kernel_api/tests/（7 文件）

| 文件 | 覆盖对象 |
|------|----------|
| test_alert_mcp.py | MCP 告警相关 Resource（alert.py 的 MCP 系列：list_alert / list_alert_top_n 等） |

- **test_admin_rpc.py**（137KB）：admin 域大部分函数（api_auth_token / apm / bcs_cluster / cluster_info / collect_config / datalink / es_storage / result_table / space / storage 等）的单元校验。
- **test_bkm_cli_*.py**：逐函数覆盖 bkm-cli op（assignment / commands / env_info / es / inspect_bcs_metadata / inspect_issue / inspect_strategy_config / platform_bkdata / platform_gse / platform_source / read_cache_key / read_config_cache / read_db_model 等）。

## 运行方式

```bash
cd /root/bk-monitor/bkmonitor
# 需 Django settings 初始化（api 角色）+ .venv + 显式环境变量
/root/bk-monitor/bkmonitor/.venv/bin/python -m pytest bkmonitor/kernel_api/rpc/tests/ \
    --override-ini "filterwarnings=" \
    -o addopts=""
```

> 全局前置（PROJECT.md §5）：`--override-ini "filterwarnings="`（pyproject 引用的 `RemovedInDjango51Warning` 在 Django 4.2.27 解析失败）+ 显式 `BKAPP_DEPLOY_PLATFORM=community` 等环境变量。

## 测试可执行性

- **状态**：⚠️ **依赖外部环境**（PROJECT.md 标注）。
- 大量用例 mock 了 DB/外部调用，理论上纯单测可跑；但 Django settings 加载依赖完整检出 + `.venv` + 环境变量，当前环境未逐条实测。
- 已知风险：`test_admin_rpc.py` 覆盖极广，存在因注册表状态/DB 残留导致的不稳定可能（未实证，标注为待验证）。

## 测试缺口

- **认证中间件**：`middlewares/authentication.py`（27KB）无对应单测文件——JWT 验签、API Token 命名空间、MCP 权限链路均缺自动化覆盖，属高价值补测点。
- **ApiRenderer 字段映射**：`adapters.py` 无单测。
- **api_exception_handler**：异常渲染与 data 白名单无单测。

## 结论

RPC 层测试覆盖较完整（admin/bkm_cli 逐函数），视图/Resource 层覆盖核心 MCP 场景；认证中间件与横切适配是明显测试缺口。测试可执行性为"依赖外部环境"，运行需 Django settings + .venv。
