# C0-使用总览：RPC 函数注册子专家

## 1. 能力清单

| 能力 | 说明 | 关键类/函数 |
|------|------|-------------|
| RPC 函数注册 | 装饰器 / 直接注册 / Resource 包装注册三种方式 | `KernelRPCRegistry.register` / `register_function` / `register_resource` |
| 函数列表披露 | `__meta__` 元协议（list / detail）渐进披露函数与 schema | `KernelRPCRegistry.list_functions` / `get_function_detail` |
| 函数执行 | 按 `func_name` 查表执行，未找到抛 CustomException | `KernelRPCRegistry.execute` |
| admin 运维巡检 | `admin.<域>.<操作>` 系列（api_auth_token / cluster_info / es_storage / datasource / storage / space 等） | `rpc/functions/admin/*` |
| bkm-cli 只读命令 | `bkm_cli.*` 系列（readonly 命令 / db / es / cache / issue / strategy 巡检等） | `rpc/functions/bkm_cli/*` |
| op 白名单 | op_id → func_name 映射 + 审计元数据，防绕过 func_name 直接调用 | `BkmCliOpRegistry` |
| 租户推断 | 按 bk_biz_id / space_uid / table_id / bk_data_id 等反查租户并注入 | `inject_bk_tenant_id` / `infer_bk_tenant_id` |
| 平台信息 | 平台/环境/诊断信息（info / biz_scene / metadata_* 巡检） | `rpc/functions/{info,biz_scene,metadata}.py` |

## 2. 能力边界

- **全部只读语义**：RPC 函数为巡检/诊断/信息查询；bkm-cli 有 AST 只读守卫（`platform_catalog/_lint.py`）。
- **不经 `RESOURCE_RPCS` 列表注册**：当前仅 `resources.py` 用该机制且为空；admin/bkm_cli/metadata 走装饰器式注册（导入期生效）。
- **`__meta__` 为保留函数名**：业务函数禁止注册 `__meta__`（`register_function` 显式拦截）。
- **不直接暴露前端**：RPC 经 `KernelRPCResource` / `BkmCliOpCallResource`（views/v4/kernel_rpc.py、bkm_cli.py 的 ViewSet）对外暴露。

## 3. 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| 报「未找到可调用函数」 | `func_name` 拼错或函数未注册 | 先调 `__meta__` action=list 查函数列表；确认函数在对应模块 |
| 报「无法根据 xx 反查 bk_tenant_id，命中了多个租户」 | 传入的标识字段在多个租户命中 | 显式传 `bk_tenant_id` 明确租户 |
| bkm-cli op 报 404 `target_not_found` | op_id 不在白名单 | 客户端用 `mapStatusToCode(404)` 映射；op_id 需在 `BkmCliOpRegistry` 注册 |
| 报「result 值必须是有效 JSON」 | 函数返回 datetime / Decimal 等非 JSON-safe 对象 | 出口 `BkmCliOpCallResource` 已统一 `json.dumps(default=str)` 归一；新增 op 无需逐函数补丁 |
| 新增函数不生效 | 新增函数文件未 import / 未用装饰器注册 | `load_builtin_functions` 按 `iter_modules` 导入顶层模块，子包需 `__init__.py` 全量 import 成员 |
