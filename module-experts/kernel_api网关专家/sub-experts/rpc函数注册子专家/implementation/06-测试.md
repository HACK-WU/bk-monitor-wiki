## 运行方式

```bash
cd /root/bk-monitor/bkmonitor
/root/bk-monitor/bkmonitor/.venv/bin/python -m pytest bkmonitor/kernel_api/rpc/tests/ \
    --override-ini "filterwarnings=" -o addopts=""
```

> 全局前置：Django settings 初始化（api 角色）+ `.venv` + 显式 `BKAPP_DEPLOY_PLATFORM=community` 等环境变量（PROJECT.md §5）。

## 测试可执行性

- ⚠️ **依赖外部环境**（PROJECT.md 标注）；单测用 mocker/mock 隔离 DB/外部调用，理论纯单测可跑，但依赖 settings 加载链完整。
- 已确认：`test_bkm_cli_rpc.py` 的 `_cleanup_registries` fixture 保证全局注册表测试隔离。

## 测试缺口

- `rpc/functions/metadata.py`（81KB，7 个函数）未见独立测试文件（可能在 test_admin_rpc.py 内覆盖，需确认）。
- `rpc/functions/biz_scene.py`（biz_scene_related_info）无独立测试。
- 租户推断 `inject_bk_tenant_id` / `infer_bk_tenant_id` 的边界（多租户冲突抛错）未见专门单测文件。

## 结论

RPC 子专家测试覆盖较好（admin/bkm-cli 逐函数 + 注册表状态隔离）；metadata/biz_scene 函数与租户推断边界是潜在缺口。
