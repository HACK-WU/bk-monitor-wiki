## 2. 能力边界

- **只做装配**：v4 视图是"薄装配层"，业务逻辑在内部 Resource / 挂载 app 的 Resource 中。
- **不重复实现**：与 `fta_web`/`monitor_web` 已有的 ViewSet 大量复用（继承或 ResourceRoute 引用）。
- **endpoint 命名**：`ResourceRoute("POST", XxxResource, endpoint="xxx")` → URL `/api/v4/xxx/`；`AlertViewSet` 部分 endpoint 带 `/` 前缀（如 `alert/search`）。
- **v4 是主版本**：新功能优先加 v4；v2/v3 为兼容层（父专家范围）。

## 3. 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| 接口报 404 | endpoint 未注册 / `__init__.py` 未导出模块 | 确认 `views/v4/__init__.py` 含 `from .{module} import *` 且 ViewSet 的 `resource_routes` 声明了 endpoint |
| 错误显示为 500（非业务码） | web 端经网关调用，kernel_api 恒 200 + body.code | 前端/web 端认 `body.code`（见父专家 C1） |
| Issue 重名 409 | 调用 rename 重名 | kernel_api 抛 code 3327001，web 端识别转 409（见记忆《三层错误传播链路与专有错误码》） |
| MCP 调用时间跨度超限 | 查询跨度 > `MCP_MAX_TIME_SPAN_SECONDS` | 拆批查询 |
