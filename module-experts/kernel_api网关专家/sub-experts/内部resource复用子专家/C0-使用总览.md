## 2. 能力边界

- **不直接暴露前端**：这些 Resource 经 `views/` 的 ViewSet 暴露（见 v4 API 视图子专家）；前端不能直接调 `resource/` 内容。
- **薄封装模式**：常做一层参数适配/别名映射后复用下游 Resource（如 `resource.alert.xxx()` 或 `SomeResource().request()`）。
- **纯计算/查询型**：无独立持久化模型（认证 Token 等落在 `bkmonitor.models`），故不产出 C4。
- **运营指标只读**：operation 全部只读取值，MANUAL 类型无 handler（不可程序化）。

## 3. 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| MCP 请求报时间跨度超限 | `start_time`/`end_time` 跨度 > `settings.MCP_MAX_TIME_SPAN_SECONDS` | 使用 `TimeSpanValidationPassThroughSerializer`（serializers/mixins.py），拆批查询 |
| bkm-cli 报「result 值必须是有效 JSON」 | 函数返回 datetime/Decimal 等非 JSON-safe | 出口已统一归一（`BkmCliOpCallResource`）；不要逐函数补丁 |
| 运营指标取不到值 | 环境未部署对应能力（eBPF/doris）或 MANUAL 类型 | 用 `GetOperationMetricResource` 时检查 `supported_envs`/`programmable`；overview 默认跳过 slow 指标 |
| 日志搜索无结果 | 索引集/场景维度条件不匹配 | 先调 `GetIndexSetListResource`/`ListLogScenesResource` 确认可用范围 |
| 复用 resource 时线程安全 | 直接持有实例多次 `request()` | 用全局入口 `resource.xxx.yyy()`（内部自动新建临时实例）或用 `SomeResource().request()` 新建 |

## 5. 强依赖与外部依赖

- 复用 `core.drf_resource`（Resource 基类）与 `fta_web`/`metadata`/`monitor_web` 等挂载 app 的 Resource（告警/策略/日志/元数据查询）。
- `rpc/`（KernelRPCRegistry / BkmCliOpRegistry）为 RPC 子专家范围，此处仅入口 Resource。
