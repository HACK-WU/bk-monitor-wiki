## MCP 告警 Resource 实现

`resource/alert.py`（44KB）的结构（源码 confirmed）：
- **序列化层**：`PassThroughSerializer`（透传未定义字段）→ `BusinessScopedSerializer`（业务范围）→ `AlertRelatedRequestSerializer` / `ConfirmedBusinessScopedSerializer`；`ShieldNoticeConfigSerializer` / `ActionExecuteConfigSerializer` 定义屏蔽通知/套餐执行配置。
- **Resource 层**：
  - `ListAlertResource` / `ListAlertTopNResource` / `ListStrategySnapshotResource`：查询入口。
  - `AlertRelatedResource` + 7 个继承子类（`ListAlertEventsResource` / `ListAlertEventTSResource` / `ListAlertEventTagDetailResource` / `ListAlertK8sTargetResource` / `ListAlertHostTargetResource` / `ListAlertTracesResource` / `ListAlertLogRelationsResource`）：关联数据查询，共享关联请求序列化。
  - MCP 策略/屏蔽/通知组/套餐系列：`SearchAlarmStrategiesResource` 等 14 个 Resource，均带 `perform_request` 实现业务并调用下游。

> 实现细节：各 Resource 的 `perform_request` 调用 `resource.fta_web.xxx` / `SearchAlertResource` 等下游并适配参数；具体下游调用链需读源码确认（本批未逐行展开）。

章节来源：[resource/alert.py](file://bkmonitor/kernel_api/resource/alert.py)（关键符号：`ListAlertResource` / `AlertRelatedResource` / `SearchAlarmStrategiesResource`）

## 运营指标实现

`resource/operation/`：
- **registry.py**：`OperationMetric` dataclass（key/category/name/unit/description/handler_type/handler/supported_envs/biz_scoped/slow/cache_ttl/note）+ 全局 `OPERATION_METRIC_REGISTRY`；`register_metric`（key 重复抛错）、`get_metric`、`iter_metrics`（按分类/环境过滤）。`HandlerType` 枚举（promql/collector/orm/api/manual）、`MetricCategory` 枚举（base/storage/apm/log/aiops）。
- **handlers.py**（40KB）：各指标取数 handler，统一签名 `handler(bk_biz_id, end_time=None)`，调用 `register_metric` 注册。
- **resources.py**：3 个通用 Resource：
  - `ListOperationMetricsResource`：目录。
  - `GetOperationMetricResource`：单值；`_resolve_value` 在 `cache_ttl>0` 且未显式 `end_time` 时走 `operation_mcp:metric:{key}:{biz}` 缓存。
  - `GetOperationOverviewResource`：批量；`slow` 指标默认跳过（`include_slow` 可纳入），单指标异常降级到 `error` 字段。

章节来源：[resource/operation/registry.py](file://bkmonitor/kernel_api/resource/operation/registry.py)（关键符号：`OperationMetric` / `register_metric`）；[resource/operation/resources.py](file://bkmonitor/kernel_api/resource/operation/resources.py)（关键符号：`GetOperationMetricResource`）

## 协议入口实现

- **KernelRPCResource**（kernel_rpc.py）：`func_name` + `params` 协议；`__meta__` 元协议（list/detail）；普通调用前 `inject_bk_tenant_id`。详见 RPC 子专家。
- **BkmCliOpCallResource**（bkm_cli.py）：`op_id` + `params` 协议；`BkmCliOpRegistry.resolve` 映射 func_name；出口 `json.loads(json.dumps(raw_result, default=str))` 统一 JSON-safe 归一；响应含 `audit`（capability/risk/confirmation/audit_tags）。

章节来源：[resource/bkm_cli.py](file://bkmonitor/kernel_api/resource/bkm_cli.py)（关键符号：`BkmCliOpCallResource.perform_request`）

## 结论

内部 Resource 层以"薄封装 + 下游复用"为主，MCP 系列集中在 alert.py，运营指标走 registry/handlers/resources 三段式。协议入口（RPC/bkm-cli）是本层对 RPC 子专家的桥接点。
