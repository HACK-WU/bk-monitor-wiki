# C0-使用总览：认证与安全子专家

## 1. 能力清单

| 能力 | 说明 | 关键类/函数 |
|------|------|-------------|
| apigw JWT 认证 | 解析 `X-Bkapi-Jwt`（RS512），取 app_code / username | `BkJWTClient.validate()` |
| API Token 认证 | `Authorization: Bearer <token>` 校验（有效性/视图/命名空间） | `AuthenticationMiddleware._handle_api_token_auth` |
| MCP 请求认证 | 按 MCP Server Name 映射 IAM 权限动作校验 + 指标上报 | `AuthenticationMiddleware._handle_mcp_auth` |
| app_code 命名空间授权 | 按 `ApiAuthToken.namespaces`（`biz#all`/`biz#{id}`）授权 | `is_match_api_token()` |
| 用户自动创建 | `AppWhiteListModelBackend` 按 username+tenant 自动建用户，多租户校验 | `AppWhiteListModelBackend.authenticate` |
| apigw 公钥缓存 | 从 `api.bk_apigateway.get_public_key` 获取公钥并缓存 | `AuthenticationMiddleware.get_apigw_public_keys` |

## 2. 能力边界

- **不做 IAM 全量权限校验**：api 角色 `SKIP_IAM_PERMISSION_CHECK=True`，仅 MCP 请求走 IAM 权限动作；普通 app_code 请求走命名空间白名单。
- **不处理前端登录态**：前端通过 API 网关统一认证；本中间件只认网关透传的请求头。
- **CSRF 豁免**：`KernelSessionAuthentication.enforce_csrf` 直接置 `csrf_processing_done=True`。

## 3. 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| JWT 解析失败报 public key not found | 请求头 `kid` 对应的公钥未从 apigw 获取到（缓存/网络） | 检查 `FROM_APIGW_NAME` 配置与 apigw 公钥发布；公钥获取失败会 120s 短缓存防抖 |
| MCP 请求缺 `bk_biz_id` 被拒（403） | MCP 认证要求业务上下文 | 调用方必须携带 `bk_biz_id`（GET / POST 表单 / JSON body） |
| MCP 权限拒绝（insufficient MCP permissions） | 请求 MCP 服务的权限动作未授权 | 检查 `MCPPermission.has_permission` 与 IAM 动作配置 |
| 多租户用户租户 ID 不匹配 403 | `user.tenant_id != bk_tenant_id` | `AppWhiteListModelBackend` 会自动确认后更新；确认失败则拒绝 |
| API Token 403 namespace not allowed | Token 的 namespaces 不含当前 `biz#{id}` | 创建 Token 时配置 `biz#all` 或对应业务命名空间 |
| `get_request_tenant_id()` 不可靠 | 标准请求中 `RequestProvider` 未调 `set_request()` | 用 `bk_biz_id_to_bk_tenant_id(bk_biz_id)` 反查租户（见记忆《get_request_tenant_id 在标准请求中不安全》） |
