## MCP 认证实现

`_handle_mcp_auth(request, username)` 核心流程（源码确认）：

1. **识别**：`mcp_server_name = request.META.get("HTTP_X_BKAPI_MCP_SERVER_NAME")`，`tool_name = extract_tool_name_from_path(request.path)`（取路径最后一段）。
2. **OpenClaw 分支**：`mcp_server_name == settings.OPENCLAW_RECOVERING_MCP_SERVER_NAME` 时，校验 username 非空 + tool_name ∈ `OPENCLAW_RECOVERING_MCP_TOOLS`；通过则固定 `request.biz_id = OPENCLAW_RECOVERING_BK_BIZ_ID`、`request.skip_check=True`、`request.openclaw_identity_scoped=True`。
3. **权限动作解析**：优先 `get_mcp_permission_action_by_server_name(mcp_server_name)`；回落 `HTTP_X_BKAPI_PERMISSION_ACTION` 请求头。
4. **豁免**：`tool_name ∈ settings.MCP_PERMISSION_EXEMPT_TOOLS` → `skip_check=True`，上报 `exempt` 指标。
5. **bk_biz_id 获取**：GET 参数 → POST 表单 → JSON body；缺失返回 403 `"Missing bk_biz_id in request parameters"`；非整数 403。
6. **权限校验**：`MCPPermission(action=action).has_permission(request, mock_view)`；拒绝 403。
7. **指标**：`_report_mcp_metric` 上报 `MCP_REQUESTS_TOTAL`（status: accessed/permission_denied/invalid_params/error/exempt）。

章节来源：[middlewares/authentication.py](file://bkmonitor/kernel_api/middlewares/authentication.py)（关键符号：`_handle_mcp_auth` / `extract_tool_name_from_path` / `_report_mcp_metric`）

## API Token 认证实现

`_handle_api_token_auth(request, view)`（源码确认）：

1. `token = request.META["HTTP_AUTHORIZATION"][7:]`（去 `Bearer ` 前缀）。
2. `ApiAuthToken.objects.get(token=token)`；不存在 403；`is_expired()` 403；`is_allowed_view(view)` 403。
3. `is_allowed_namespace(f"biz#{request.biz_id}")`：`biz_id` 空则 403 `"params bk_biz_id is required"`，否则按 namespaces 判断。
4. **Token 类型分支**：
   - `as_code` → 用户替换为 `system`；`grafana` → 替换为 `admin`；两者均 `auth.login` + `skip_check=True`。
   - `entity` → 替换为 `record.create_user or system`，`request.token=token`，`skip_check=True`。
   - 其他（观测/告警）→ 保留原用户，仅 `request.token=token`。

章节来源：[middlewares/authentication.py](file://bkmonitor/kernel_api/middlewares/authentication.py)（关键符号：`_handle_api_token_auth`）

## JWT 验签实现

`BkJWTClient.validate()`（源码确认）：
- 读 `HTTP_X_BKAPI_JWT`；空 → `(False, "request headers jwt content is empty")`。
- `jwt.get_unverified_header(raw_content)` 取 `alg`（默认 RS512）与 `kid`。
- `public_key = public_keys.get(kid)`；缺失 → `(False, "public key of {kid} not found")`。
- `jwt.decode(raw_content, public_key, algorithms=algorithm)`；失败 → `(False, decode error)`。
- 成功：`app = AttrDict(result["app"])`（兼容 `bk_app_code`→`app_code`），`user = AttrDict(result["user"])`。

公钥来源 `get_apigw_public_keys()`：遍历 `FROM_APIGW_NAME`，从 `api.bk_apigateway.get_public_key` 获取；空值 120s 缓存、非空长期缓存。

章节来源：[middlewares/authentication.py](file://bkmonitor/kernel_api/middlewares/authentication.py)（关键符号：`BkJWTClient.validate` / `get_apigw_public_keys`）

## 用户自动创建实现

`AppWhiteListModelBackend.authenticate`（源码确认）：
- `User.objects.get_or_create(username=username, defaults={"nickname": username, "tenant_id": bk_tenant_id})`。
- 单租户：`user.tenant_id != DEFAULT_TENANT_ID` → 强制改回默认租户并保存。
- 多租户：`user.tenant_id != bk_tenant_id` → 若 `user.username == get_admin_username(bk_tenant_id)` 或 `api.bk_login.batch_query_user_display_info(...)` 命中 → 更新 `tenant_id` 并保存。
- 异常时 `logger.error` 并返回 None。

章节来源：[middlewares/authentication.py](file://bkmonitor/kernel_api/middlewares/authentication.py)（关键符号：`AppWhiteListModelBackend.authenticate`）

## 结论

认证链路为"请求头分流 → 专用校验 → 用户/上下文注入"，MCP 分支承担 IAM 权限 + 指标上报，Token 分支按类型定制用户语义，JWT 走公钥验签。排查认证问题按分支定位对应实现即可。
