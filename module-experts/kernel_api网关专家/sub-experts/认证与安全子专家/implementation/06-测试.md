## 简介

认证与安全子专家覆盖单文件 `middlewares/authentication.py`，**当前无对应单测文件**——`kernel_api/tests/` 下 7 个测试均聚焦 Resource 业务逻辑，未覆盖认证中间件。

章节来源：[tests/](file://bkmonitor/kernel_api/tests/)

## 测试覆盖

- **无**：`middlewares/authentication.py` 的 JWT 验签、API Token 命名空间校验、MCP 权限链路、用户自动创建均无自动化测试。
- 间接覆盖：`rpc/tests/test_admin_api_auth_token.py` 覆盖 `admin.api_auth_token.*` 函数的注册/调用（涉及 `ApiAuthToken` 模型），但非认证中间件本身。

## 运行方式

当前无本子专家专属测试可运行；若后续补测，运行方式同父专家：

```bash
cd /root/bk-monitor/bkmonitor
/root/bk-monitor/bkmonitor/.venv/bin/python -m pytest bkmonitor/kernel_api/tests/ \
    --override-ini "filterwarnings=" -o addopts=""
```

## 测试可执行性

- ⚠️ **依赖外部环境**（PROJECT.md 标注）；认证中间件测试需 mock `ApiAuthToken` / `api.bk_apigateway` / `MCPPermission` 等外部依赖。

## 测试缺口

1. **JWT 验签**：`BkJWTClient.validate` 各失败分支（空内容/坏 header/公钥缺失/decode 失败）无测试。
2. **API Token 命名空间**：`_handle_api_token_auth` 的 Token 类型分支（as_code/grafana/entity/观测）无测试。
3. **MCP 权限**：`_handle_mcp_auth` 的 OpenClaw 白名单、豁免工具、bk_biz_id 缺失/非法、权限拒绝与指标上报无测试。
4. **用户自动创建**：`AppWhiteListModelBackend.authenticate` 多租户租户更新分支无测试。

> 认证是网关安全闸门，上述缺口属高价值补测点。

## 结论

认证与安全子专家无自动化测试覆盖，测试缺口集中在中间件各认证分支；建议优先补 MCP 与 Token 分支用例。
