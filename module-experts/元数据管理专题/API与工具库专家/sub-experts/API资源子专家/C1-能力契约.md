## 一、Resource 基类 API

### Resource 抽象基类

**文件**: [`resources/base.py`](file://bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/resources/base.py)

```python
class Resource(ABC):
    RequestSerializer: type[Serializer] | None = None
    ResponseSerializer: type[Serializer] | None = None
    many_request_data: bool = False
    many_response_data: bool = False

    def __init__(self, context: Any = None): ...
    def __call__(self, *args, **kwargs) -> Any: ...  # 线程安全入口
    def request(self, request_data=None, **kwargs) -> Any: ...  # 主流程
    def validate_request_data(self, request_data) -> Any: ...
    def validate_response_data(self, response_data) -> Any: ...
    @abstractmethod
    def perform_request(self, validated_request_data) -> Any: ...
```

**契约**:
- 子类必须实现 `perform_request()`
- 子类必须定义 `RequestSerializer`（可选但推荐）
- `__call__` 保证线程安全（每次创建新实例）
- 所有异常统一转换为 `BkApiError`

## 四、请求处理契约

### 4.1 请求生命周期

```
1. Resource()(request_data)  ← 线程安全入口
2. validate_request_data()   ← 参数校验（RequestSerializer）
3. perform_request()         ← 业务逻辑（子类实现）
4. validate_response_data()  ← 响应校验（ResponseSerializer）
5. 异常 → BkApiError         ← 统一异常转换
```

### 4.2 参数校验契约

- `TenantIdField` 自动从 request 注入 `bk_tenant_id`
- 校验失败抛出 `Exception`，由 `request()` 统一转换为 `BkApiError`
- `format_serializer_errors()` 将 DRF errors 转为人类可读格式

### 4.3 错误处理契约

```python
# 所有异常统一转换为:
BkApiError(
    module="metadata_resource",
    action=resource_name,
    method="",
    url=resource_name,
    message=str(e),
    status_code=HTTPStatus.BAD_REQUEST,
)
```
