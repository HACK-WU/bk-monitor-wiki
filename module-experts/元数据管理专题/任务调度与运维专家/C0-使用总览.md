## 一、Celery 任务体系

### 1.1 任务入口

任务模块通过 `task/__init__.py` 导出两个核心子模块：

- `task/config_refresh.py` — 配置刷新与存储管理任务
- `task/custom_report.py` — 自定义上报与事件/日志任务

```python
# task/__init__.py:1-2
from .config_refresh import *  # noqa
from .custom_report import *  # noqa
```

| 队列名 | 用途 | 配置来源 |

| `celery_long_task_cron` | 长耗时任务（ES 索引轮转等） | 硬编码于 `manage_es_storage`、`clean_disable_es_storage` |

### 1.4 任务调度策略

- **共享锁（share_lock）**: 通过 `@share_lock` 装饰器保证同一任务不会重叠执行，TTL 防止死锁
- **队列隔离**: 长耗时任务使用独立队列 `celery_long_task_cron`，避免阻塞通用任务
- **重试机制**: `tenacity.retry` 指数退避重试（如 `create_es_storage_index` 最多 4 次）
- **并发控制**: 按 ES 集群分组并发执行，使用线程池 `ThreadPoolExecutor`

## 三、运维工具

### 3.1 Redis 分布式锁

`tools/redis_lock.py` — `DistributedLock` 类

- **用途**: 基于 Redis 的分布式锁，用于多实例环境下任务互斥
- **核心方法**: `acquire()`（非阻塞获取）、`release()`（释放）、`renew()`（手动续约）
- **使用场景**: `watch_bkbase_meta_redis_task` 中用于保证只有一个实例监听计算平台 Redis 变更

### 3.2 批量操作工具

`task/utils.py` — `bulk_handle()` 和 `chunk_list()`

- `bulk_handle(handler, data, bulk_size, is_wait_finish)` — 多线程批量处理
- `chunk_list(data, size)` — 列表按固定大小切分

## 四、种子数据加载

### 4.1 数据文件

种子数据位于 `data/` 目录，包含 JSON 和 YAML 两种格式：

| 文件 | 格式 | 加载时机 | 内容 |
|------|------|---------|------|
| `init_label.json` | JSON | `migrations/0002_initial_data.py` | 标签定义 |
| `init_cluster_info.json` | JSON | `migrations/0002_initial_data.py` | 集群信息 |
| `init_datasource.json` | JSON | `migrations/0002_initial_data.py` | 数据源定义 |
| `init_resulttable.json` | JSON | `migrations/0002_initial_data.py` | 结果表定义 |
| `init_data.json` | JSON | `migrations/0002_initial_data.py` | 综合初始化数据 |
| `init_storage.json` | JSON | `migrations/0002_initial_data.py` | 存储配置 |
| `init_ts_or_event_group.json` | JSON | `migrations/0002_initial_data.py` | 时序/事件组 |
| `k8s_metrics/*.yaml` | YAML | 运行时加载 | K8s 指标定义 |

### 4.2 加载机制

- 通过 Django migration `0002_initial_data.py` 在数据库迁移时自动加载
- 使用 `migration_util.py` 中的辅助函数（`add_datasource`、`add_resulttable`、`add_esstorage` 等）
- 批量创建使用 `batch_size=500`
