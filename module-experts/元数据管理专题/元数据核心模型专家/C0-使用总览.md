## 一、能力概览

本专家覆盖 bk-monitor 元数据管理模块的核心模型层，提供以下能力：

### 1.1 数据源管理（DataSource）

- **数据源全生命周期**：创建、更新、启用/停用、配置同步
- **多协议支持**：通过 Kafka 消息队列接入，支持 GSE 和 BkData（计算平台）两种 DataID 来源
- **配置同步**：自动同步 Consul（ETL 配置）、GSE（路由配置）
- **空间归属**：支持空间类型隔离、授权空间管理
- **多租户**：通过 `bk_tenant_id` 实现租户级数据隔离

### 1.2 结果表管理（ResultTable）

- **结果表全生命周期**：创建、修改、升级为全业务、CMDB 层级拆分
- **多存储后端**：支持 ES、InfluxDB、Doris、Kafka、Redis、BkData、Argus 七种存储
- **Schema 模式**：free（无固定字段）、dynamic（动态字段）、fixed（固定字段）
- **字段管理**：字段创建、批量创建、默认字段生成、保留字检查
- **数据链路**：自动应用 V3/V4 数据链路，支持 VM 接入、日志 V4 链路、事件组 V4 链路
- **选项配置**：结果表级别的分段查询、字段黑名单、CMDB 层级等开关

### 1.3 公共基础模型

- **Label 标签体系**：数据源标签（source_label）、结果表标签（result_table_label）、数据类型标签（type_label）
- **OptionBase 选项基类**：统一的选项值存储与类型转换机制
- **BaseModel/BaseModelWithTime**：审计字段抽象基类

### 1.4 实体关系（EntityRelation）

- **EntityMeta 抽象基类**：类似 Kubernetes 资源模型的实体元数据框架
- **ResourceDefinition**：资源类型定义，含字段列表，支持 Redis 缓存
- **RelationDefinition**：关联关系定义，支持静态/动态、单向/双向、归属关系
- **CustomRelationStatus**：自定义关联状态

## 二、典型使用场景

### 场景 1：创建一个新的监控数据源

```python
from bk_monitor_base.metadata.models.data_source import DataSource

# 创建一个自定义上报数据源
data_source = DataSource.create_data_source(
    data_name="my_custom_metric",
    etl_config="bk_standard_v2_time_series",
    operator="admin",
    source_label="custom",
    type_label="time_series",
    bk_tenant_id="default",
    space_type_id="bkcc",
    space_id="2",
)
# 返回创建好的 DataSource 实例
# 已自动完成：Kafka 集群分配、MQ 配置创建、Consul/GSE 配置同步
```

### 场景 2：为数据源创建结果表

```python
from bk_monitor_base.metadata.models.result_table import ResultTable

result_table = ResultTable.create_result_table(
    bk_data_id=data_source.bk_data_id,
    table_id="my_custom_metric",
    table_name_zh="我的自定义指标",
    is_custom_table=True,
    schema_type="free",
    operator="admin",
    default_storage="influxdb",
    bk_tenant_id="default",
    field_list=[
        {"field_name": "cpu_usage", "field_type": "float", "tag": "metric"},
        {"field_name": "hostname", "field_type": "string", "tag": "dimension"},
    ],
)
# 已自动完成：字段创建、存储创建、数据链路应用
```

### 场景 3：修改结果表配置

```python
result_table.modify(
    operator="admin",
    table_name_zh="更新后的指标名",
    is_enable=True,
    option={"segmented_query_enable": True},
)
```

### 场景 4：查询标签信息

```python
from bk_monitor_base.metadata.models.common import Label

# 获取所有非管理员标签
labels = Label.get_label_info(include_admin_only=False)
# 返回按类型分组的标签字典
```

### 场景 5：定义实体关系

```python
from bk_monitor_base.metadata.models.entity_relation import ResourceDefinition, RelationDefinition

# 定义资源类型
resource = ResourceDefinition.objects.create(
    namespace="bkmonitor",
    name="host",
    fields=[
        {"namespace": "bkmonitor", "name": "bk_host_id", "required": True},
        {"namespace": "bkmonitor", "name": "ip", "required": True},
    ],
)

# 定义关联关系
relation = RelationDefinition.objects.create(
    namespace="bkmonitor",
    name="host_to_pod",
    from_resource="host",
    to_resource="pod",
    category="dynamic",
    is_directional=True,
)
```

## 三、快速上手指南

### 3.1 理解核心概念

1. **DataSource（数据源）** = 数据接入的入口，对应一个 Kafka Topic
2. **ResultTable（结果表）** = 数据的逻辑表结构，一个数据源可以有多个结果表
3. **DataSourceResultTable** = 数据源与结果表的 N:1 映射关系
4. **ResultTableField** = 结果表的字段定义（指标/维度/时间戳）
5. **Storage** = 数据的物理存储后端（ES/InfluxDB/Doris 等）

### 3.2 数据流

```
数据上报 → DataSource(Kafka) → ETL清洗 → ResultTable(逻辑表) → Storage(物理存储)
```

### 3.3 关键约束

- 数据源名称 `data_name` + `bk_tenant_id` 联合唯一
- 结果表 `table_id` + `bk_tenant_id` 联合唯一
- 数据源与结果表通过 `DataSourceResultTable` 建立 (bk_data_id, table_id, bk_tenant_id) 三联合唯一映射
- 全业务结果表（bk_biz_id=0）不得以数字下划线开头
- 固定 schema 结果表不允许新增字段

## 四、常见问题

### Q1: 数据源创建后如何确认配置已生效？

数据源创建后会自动调用 `refresh_outer_config()`，同步 Consul 和 GSE 配置。可通过检查 Consul 路径 `{CONSUL_PATH}/data_id/{transfer_cluster_id}/{data_id}` 确认。

### Q2: 结果表创建后数据链路未生效？

检查 `apply_datalink()` 的调用条件：
- InfluxDB 存储需要 `enable_v2_vm_data_link` 开关开启且 etl_config 在 `ENABLE_V4_DATALINK_ETL_CONFIGS` 列表中
- 日志 V4 链路需要 `OPTION_ENABLE_V4_LOG_DATA_LINK` 选项
- 数据源 `created_from` 必须为 `BKDATA` 才会走 V4 链路

### Q3: 如何判断结果表是否进入 V4 链路？

检查 `DataSource.created_from` 是否为 `DataIdCreatedFromSystem.BKDATA.value`，以及 `DataSource.etl_config` 是否在 `ENABLE_V4_DATALINK_ETL_CONFIGS` 中。

### Q4: 字段创建失败提示"结果表字段不可变更"？

结果表的 `schema_type` 为 `fixed` 时不允许新增字段。需要先确认结果表的 schema 类型。
