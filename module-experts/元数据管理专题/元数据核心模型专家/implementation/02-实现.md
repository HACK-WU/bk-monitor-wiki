## 一、DataSource 核心实现

### 1.1 创建流程 (`create_data_source`)

**文件**: `data_source.py` 行 499-700

```
1. 校验标签存在性 (source_label, type_label)
2. 校验 data_name 在租户下唯一
3. 获取/分配 Kafka 集群 (mq_cluster)
4. 分配 DataID:
   - V4 链路: 从计算平台申请 (apply_for_data_id_from_bkdata)
   - V3 链路: 从 GSE 申请 (apply_for_data_id_from_gse)
   - 自增: 数据库自增 + 范围校验 (MIN_DATA_ID ~ MAX_DATA_ID)
5. 事务内:
   a. 创建 DataSource 记录 (mq_config_id 先填 0)
   b. 创建 KafkaTopicInfo (MQ 配置) 并回填 mq_config_id
   c. 设置 space_uid (从 space_uid 或 bk_biz_id 推导)
   d. 创建 DataSourceOption (含 drop_metrics_etl_configs 和时间单位)
6. 保存空间-数据源关系 (SpaceDataSource)
7. 刷新外部配置 (Consul + GSE)
```

**关键代码位置**:
- DataID 分配逻辑: 行 580-630
- 事务创建: 行 635-680
- 空间关系保存: 行 685-700

### 1.2 更新流程 (`update_config`)

**文件**: `data_source.py` 行 800-920

```
1. 逐项检查并更新: etl_config, mq_cluster_id, data_name, data_description
2. 更新 option (create_or_update)
3. 处理 is_enable:
   - 仅 BKGSE 来源有效
   - 停用时删除 Consul 配置
4. 更新空间属性: is_platform_data_id, space_type_id, space_uid, created_from
5. 保存并刷新外部配置
6. 处理授权空间关系
```

### 1.3 配置同步 (`refresh_outer_config`)

**文件**: `data_source.py` 行 1250-1270

```
refresh_outer_config()
├── refresh_gse_config()      — 同步路由到 GSE ZK
│   ├── can_refresh_consul_and_gse() 检查 (is_enable + BKGSE)
│   └── refresh_gse_config_to_gse()  — 查询/更新 GSE 路由
└── refresh_consul_config()   — 同步配置到 Consul
    ├── 跳过 IGNORED_CONSUL_SYNC_DATA_IDS
```

### 1.4 to_json 序列化

**文件**: `data_source.py` 行 220-300

序列化输出包含:
- 基础信息: bk_data_id, bk_tenant_id, data_name, token

## 二、ResultTable 核心实现

### 2.2 修改流程 (`modify`)

**文件**: `result_table.py` 行 1149-1500

```
1. 更新 table_name_zh
2. 更新 default_storage (校验存储存在)
3. 如果 free schema 且有 field_list:
   a. 删除旧用户配置字段
   b. 删除旧清洗类 option
   c. 重建默认字段
   d. 批量创建新字段
   e. 级联更新 CMDB 拆分表
4. 更新 label
5. 处理 external_storage (创建/更新/删除)
6. 更新 option (清理清洗类 → 批量写入)
7. 处理 is_enable:
   - 启用: ES 索引创建/更新
   - 停用: 删除数据链路
8. 推送空间路由
9. 应用数据链路 (force_update 条件判断)
```

**force_update_datalink 触发条件**:
- `OPTION_ENABLE_FIELD_BLACK_LIST` 值变更
- `OPTION_ENABLE_FIELD_BLACK_LIST` 为 False（非自动发现）

### 2.3 数据链路应用 (`apply_datalink`)

**文件**: `result_table.py` 行 600-680

```
apply_datalink()
├── InfluxDB 存储:
│   ├── V4 链路条件: created_from=BKDATA + etl_config in ENABLE_V4_DATALINK_ETL_CONFIGS
│   ├── 插件 V4 链路: OPTION_ENABLE_PLUGIN_V4_DATA_LINK + bk_exporter/bk_standard
│   └── 执行: access_bkdata_vm.delay() (on_commit)
├── ES/Doris 存储:
│   ├── 日志 V4: OPTION_ENABLE_V4_LOG_DATA_LINK → apply_log_datalink()
│   └── 事件组 V4: etl_config=bk_standard_v2_event → apply_event_group_datalink()
└── 兜底: BKGSE 来源刷新 Consul 配置
```

### 2.4 升级为全业务 (`upgrade_result_table`)

**文件**: `result_table.py` 行 1505-1570

```
1. 校验: bk_biz_id != 0 且 !is_deleted
2. 标记旧记录: is_deleted=True, bk_biz_id=0
3. 提取新 table_id (去掉业务前缀)
4. 迁移字段: ResultTableField.table_id 更新
5. 迁移存储: 深拷贝 → 删除旧 → 保存新
6. 迁移数据源关系: DataSourceResultTable.table_id 更新
7. 自身 table_id 更新为新值
```

### 2.5 CMDB 层级拆分 (`set_metric_split`)

**文件**: `result_table.py` 行 1575-1700

```
1. 校验: 非公共数据源 (data_id >= 10000 或 allow_all_cmdb_level)
2. 检查是否已存在拆分记录
3. 检查自身是否已是拆分目标
4. 获取或创建输出数据源:
   - 已有 Kafka 存储: 复用 topic/partition
   - 无: 创建新 Kafka 存储
5. 创建 CMDBLevelRecord
```

## 四、OptionBase 实现

### 4.1 值类型自动识别

**文件**: `common.py` 行 150-170

```python
@classmethod
def _parse_value(cls, value):
    if type(value) in (bool, list, dict):
        val = json.dumps(value)
        val_type = "bool" if isinstance(value, bool) else ("list" if isinstance(value, list) else "dict")
    elif type(value) in (int,):
        val = json.dumps(value)
        val_type = "int"
    else:
        val, val_type = value, "string"
    return val, val_type
```

### 4.2 值反序列化

**文件**: `common.py` 行 200-220

```python
def get_value(self):
    try:
        option_value = self.TYPE_OPTION_DICT[self.value_type]
        real_value = option_value(self.value) if self.value_type != "string" else str(self.value)
    except KeyError:
        trans_method = getattr(self, f"_trans_{self.value_type}")
        real_value = trans_method()
    return real_value
```
