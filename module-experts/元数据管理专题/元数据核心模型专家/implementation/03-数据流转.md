## 一、数据源→结果表→存储引擎 数据链路

### 1.1 整体数据流

```mermaid
sequenceDiagram
    participant Client as "客户端/采集器"
    participant GSE as "GSE Data服务"
    participant Kafka as "Kafka MQ"
    participant Transfer as "Transfer(ETL)"
    participant Consul as "Consul"
    participant Storage as "存储后端"
    participant Query as "查询模块"

    Client->>GSE: 上报数据
    GSE->>Kafka: 写入 Topic
    Note over Transfer,Consul: Transfer 从 Consul 拉取配置
    Transfer->>Consul: 读取 data_id 配置
    Consul-->>Transfer: ETL配置 + 结果表 + 字段 + 存储路由
    Transfer->>Kafka: 消费数据
    Transfer->>Transfer: ETL 清洗
    Transfer->>Storage: 写入 (ES/InfluxDB/Doris/...)
    Query->>Storage: 查询数据
```

### 1.2 DataSource 配置同步到 Consul

**触发时机**:
- 数据源创建 (`create_data_source` → `refresh_outer_config`)
- 数据源更新 (`update_config` → `refresh_outer_config`)
- 结果表创建/修改 (`refresh_etl_config` → `data_source.refresh_consul_config`)

**Consul 路径**: `{CONSUL_PATH}/data_id/{transfer_cluster_id}/{data_id}`

**同步内容** (`DataSource.to_json(is_consul_config=True)`):
```json
{
  "bk_data_id": 1001,
  "bk_tenant_id": "system",
  "mq_config": {
    "storage_config": {"topic": "xxx", "partition": 1},
    "batch_size": 1000,
    "cluster_config": {...}
  },
  "etl_config": "bk_standard",
  "option": {...},
  "result_table_list": [
    {
      "bk_biz_id": 2,
      "result_table": "system.cpu_summary",
      "shipper_list": [{"cluster_type": "influxdb", ...}],
      "field_list": [...],
      "schema_type": "free",
      "option": {...}
    }
  ]
}
```

### 1.3 GSE 路由同步

**触发时机**: `refresh_gse_config()` → `refresh_gse_config_to_gse()`

**流程**:
1. 查询 GSE 现有路由
2. MD5 比对新旧配置
3. 不一致则调用 `api.gse.update_route()` 更新

**路由配置** (`DataSource.gse_route_config`):
```json
{
  "name": "stream_to_{plat_name}_{mq_type}_{topic}",
  "stream_to": {
    "stream_to_id": 1,
    "kafka": {"topic_name": "xxx"}
  }
}
```

## 二、ResultTable 创建时的数据链路选择

### 2.1 链路决策树

```mermaid
flowchart TD
    Start(["ResultTable 创建"]) --> CheckStorage{"default_storage?"}
    
    CheckStorage -->|"InfluxDB"| CheckV4{"V4 链路条件?"}
    CheckV4 -->|"created_from=BKDATA<br/>+ etl_config in V4列表"| V4VM["V4 VM 链路<br/>access_bkdata_vm.delay()"]
    CheckV4 -->|"插件 V4 开关"| PluginV4["插件 V4 链路<br/>先 register_to_bkbase<br/>再 access_bkdata_vm"]
    CheckV4 -->|"否"| V3Consul["V3 链路<br/>refresh_consul_config()"]
    
    CheckStorage -->|"ES/Doris"| CheckLog{"日志 V4?"}
    CheckLog -->|"OPTION_ENABLE_V4_LOG_DATA_LINK"| LogV4["日志 V4 链路<br/>apply_log_datalink()"]
    CheckLog -->|"事件组 V4"| EventV4["事件组 V4 链路<br/>apply_event_group_datalink()"]
    CheckLog -->|"否"| DefaultConsul["默认 Consul 同步"]
```

### 2.2 V4 链路条件详解

**必须同时满足**:
1. `settings.metadata.enable_v2_vm_data_link` 为 True（或 `enable_influxdb_storage` 为 False）
2. `DataSource.etl_config` 在 `ENABLE_V4_DATALINK_ETL_CONFIGS` 列表中
3. `DataSource.created_from == DataIdCreatedFromSystem.BKDATA.value`

**插件 V4 额外条件**:
- `ResultTableOption.OPTION_ENABLE_PLUGIN_V4_DATA_LINK` 为 True
- `DataSource.etl_config` 为 `bk_exporter` 或 `bk_standard`
- 如果 `created_from == BKGSE`，先调用 `register_to_bkbase()`

### 2.3 日志 V4 链路

**条件**: `default_storage` 为 ES 或 Doris，且 `OPTION_ENABLE_V4_LOG_DATA_LINK` 为 True

**执行**: `apply_log_datalink(bk_tenant_id, table_id)`

### 2.4 事件组 V4 链路

**条件**: `DataSource.etl_config == bk_standard_v2_event`

**执行**: `apply_event_group_datalink(bk_tenant_id, table_id)`

## 三、EntityRelation 跨模块数据流

### 3.1 整体架构

```mermaid
flowchart LR
    subgraph "metadata 模块"
        ER_Model["entity_relation.py<br/>模型定义"]
        ER_Task["task/entity_relation.py<br/>缓存刷新任务"]
    end

    subgraph "APM 模块"
        TopoModel["apm/models/topo.py<br/>拓扑模型"]
        RelDiscover["apm/core/discover/relation.py<br/>关系发现"]
        InstDiscover["apm/core/discover/instance.py<br/>实例发现"]
    end

    subgraph "bkm_ipchooser 模块"
        TopoTool["tools/topo_tool.py<br/>拓扑工具"]
        TopoHandler["handlers/topo_handler.py<br/>拓扑处理器"]
    end

    subgraph "Redis"
        Cache["资源/关系定义缓存"]
    end

    ER_Model -->|"定义"| Cache
    ER_Task -->|"全量刷新"| Cache
    TopoModel -->|"落库"| RelDiscover
    TopoModel -->|"落库"| InstDiscover
    Cache -->|"消费"| TopoTool
    Cache -->|"消费"| TopoHandler
```

### 3.2 数据流向

1. **定义阶段**: metadata 侧通过 `ResourceDefinition` / `RelationDefinition` 定义实体类型和关系
2. **缓存阶段**: `task/entity_relation.py` 全量刷新任务将定义写入 Redis，通过发布订阅通知消费者
3. **发现阶段**: APM 侧通过 OTLP Span 自动发现拓扑节点、关系和实例
4. **查询阶段**: bkm_ipchooser 通过 Redis 缓存查询实体关系

### 3.3 本专家范围边界

| 层 | 位置 | 本专家覆盖 |
|----|------|-----------|
| 模型定义 | `metadata/models/entity_relation.py` | ✅ 全部 |
| 缓存刷新 | `metadata/task/entity_relation.py` | ❌ 归任务调度与运维专家 |
| APM 发现 | `apm/core/discover/` | ❌ 归 APM 模块 |
| 拓扑查询 | `bkm_ipchooser/` | ❌ 归 bkm_ipchooser 模块 |

## 四、空间路由数据流

### 4.1 结果表启用时的路由推送

```mermaid
sequenceDiagram
    participant RT as "ResultTable.modify()"
    participant Space as "get_space_by_table_id()"
    participant Task as "push_and_publish_space_router"
    participant Redis as "Redis"
    participant Query as "unify-query"

    RT->>Space: 查询空间信息
    Space-->>RT: {space_type_id, space_id}
    alt InfluxDB 存储
        RT->>Task: push_and_publish_space_router(space_type, space_id, [table_id])
        Task->>Redis: 写入路由
        Task->>Redis: 发布订阅通知
    else 其他存储
        RT->>Task: on_commit → push_and_publish_space_router.delay()
    end
    Query->>Redis: 读取路由
```

### 4.2 数据源的空间归属

数据源通过 `SpaceDataSource` 表维护空间归属关系：
- `from_authorization=False`: 归属空间
- `from_authorization=True`: 授权空间
