## 一、能力概览

本子专家覆盖 bk-monitor 元数据管理模块的数据源（DataSource）全生命周期管理，提供以下能力：

### 1.1 数据源生命周期管理

- **创建数据源**：自动分配 DataID、Kafka 集群、MQ 配置，同步 Consul/GSE 配置
- **更新数据源**：支持修改名称、ETL 配置、Kafka 集群、启用/停用
- **配置同步**：自动同步 Consul（ETL 配置）和 GSE（路由配置）
- **序列化输出**：`to_json()` 支持 Consul 配置格式和完整信息格式

### 1.2 DataID 分配策略

- **自增分配**：数据库自增 + 范围校验（`MIN_DATA_ID` ~ `MAX_DATA_ID`）
- **GSE 申请**：通过 `apply_for_data_id_from_gse()` 从 GSE 获取
- **计算平台申请**：通过 `apply_for_data_id_from_bkdata()` 从 BkData 获取（V4 链路）

### 1.3 多租户与空间管理

- **租户隔离**：通过 `bk_tenant_id` 实现租户级数据隔离
- **空间归属**：支持 `space_type_id` + `space_uid` 空间归属
- **授权空间**：通过 `authorized_spaces` 管理跨空间授权
- **SpaceDataSource 关系**：自动维护空间-数据源关联

### 1.4 标签体系

- **数据源标签（source_label）**：如 `bkmonitor`、`custom`、`bkdata`
- **数据类型标签（type_label）**：如 `time_series`、`event`、`log`
- **标签校验**：创建时自动校验标签存在性

### 1.5 选项配置（DataSourceOption）

- **时间相关**：`time_precision`、`timestamp_precision`、`align_time_unit`
- **数据处理**：`disable_metric_cutter`、`allow_metrics_missing`、`allow_dimensions_missing`
- **数据丢弃**：`drop_metrics_etl_configs`（指标为空时丢弃记录）

## 二、典型使用场景

### 场景 1：创建自定义时序上报数据源

```python
from bk_monitor_base.metadata.models.data_source import DataSource

# 创建自定义时序数据源
data_source = DataSource.create_data_source(
    data_name="my_custom_metric",
    etl_config="bk_standard_v2_time_series",
    operator="admin",
    source_label="custom",
    type_label="time_series",
    bk_tenant_id="default",
    space_type_id="bkcc",
    space_id="2",
)
# 返回: DataSource 实例
# 自动完成: DataID 分配 → Kafka 集群选择 → MQ 配置创建 → Consul/GSE 同步
```

### 场景 2：创建 V4 链路数据源

```python
# V4 链路数据源（etl_config 在 ENABLE_V4_DATALINK_ETL_CONFIGS 中）
data_source = DataSource.create_data_source(
    data_name="v4_metric_data",
    etl_config="bk_standard_v2_time_series",
    operator="admin",
    source_label="bkmonitor",
    type_label="time_series",
    bk_tenant_id="default",
    bk_biz_id=2,
)
# DataID 从计算平台（BkData）申请
# created_from 自动设为 BKDATA
```

### 场景 3：更新数据源配置

```python
# 修改数据源名称和 ETL 配置
data_source.update_config(
    operator="admin",
    data_name="renamed_metric",
    etl_config="bk_standard_v2_time_series",
    option={"disable_metric_cutter": True},
)
# 自动刷新 Consul 和 GSE 配置
```

### 场景 4：停用数据源

```python
# 仅 BKGSE 来源的数据源支持停用
data_source.update_config(
    operator="admin",
    is_enable=False,
)
# 自动删除 Consul 配置路径
```

### 场景 5：查询数据源关联的空间

```python
space_info = data_source.get_spaces_by_data_id(
    bk_tenant_id="default",
    bk_data_id=1001,
)
# 返回: {"space_type_id": "bkcc", "space_id": "2"}
```

## 三、快速上手指南

### 3.1 理解核心概念

1. **DataSource（数据源）** = 数据接入的入口，对应一个 Kafka Topic
2. **DataID** = 数据源的唯一数字标识，由自增/GSE/BkData 分配
3. **ETL Config** = 数据清洗配置，决定 Transfer 如何处理原始数据
4. **MQ Config** = Kafka Topic 配置（topic 名称、分区数、批次大小）
5. **Consul 配置** = Transfer 从 Consul 拉取的 ETL 配置，包含结果表列表、字段、存储路由

### 3.2 数据源创建流程

```
1. 校验标签存在性 (source_label, type_label)
2. 校验 data_name 在租户下唯一
3. 获取/分配 Kafka 集群
4. 分配 DataID（自增/GSE/BkData）
5. 事务内创建 DataSource + MQ 配置 + Option
6. 保存空间-数据源关系
7. 刷新外部配置（Consul + GSE）
```

### 3.3 关键约束

- `data_name` + `bk_tenant_id` 联合唯一
- DataID 范围：`MIN_DATA_ID` ~ `MAX_DATA_ID`
- 仅 `created_from=BKGSE` 的数据源支持停用
- V4 链路要求 Kafka 集群已注册到 BkBase
- 全业务结果表的数据源自动设为平台级（`is_platform_data_id=True`）

## 四、常见问题

### Q1: DataID 超出了范围怎么办？

DataID 分配时会校验范围。如果自增 ID 超过 `MAX_DATA_ID`，会抛出 `ValueError("数据源ID分配达到最大上限")`。如果小于 `MIN_DATA_ID` 且该 ID 未被占用，会自动使用最小 ID。

### Q2: 数据源创建后 Consul 配置未生效？

检查 `is_refresh_config` 参数是否为 True（默认）。如果创建时 Consul 刷新失败，后台 cron 任务会定期重试。

### Q3: 如何判断数据源走 V3 还是 V4 链路？

检查 `DataSource.datalink_version` 属性。V4 链路条件：`created_from=BKDATA` 且 `etl_config` 在 `ENABLE_V4_DATALINK_ETL_CONFIGS` 中。

### Q4: 修改数据源 ETL 配置后需要做什么？

`update_config()` 会自动调用 `refresh_outer_config()` 刷新 Consul 和 GSE 配置，无需手动操作。
