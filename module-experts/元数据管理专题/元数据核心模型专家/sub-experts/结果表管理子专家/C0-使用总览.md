## 一、能力概览

本子专家覆盖 bk-monitor 元数据管理模块的结果表（ResultTable）全生命周期管理，提供以下能力：

### 1.1 结果表生命周期管理

- **创建结果表**：自动创建默认字段、存储、数据源映射、数据链路
- **修改结果表**：支持修改名称、标签、存储、字段、选项、启用/停用
- **升级为全业务**：将单业务结果表升级为全业务结果表（bk_biz_id=0）
- **CMDB 层级拆分**：按 CMDB 层级创建拆分结果表和数据源

### 1.2 Schema 模式

- **free**：无固定字段，字段可动态增删，修改时先清理再重建
- **dynamic**：动态字段，支持字段自发现
- **fixed**：固定字段，不允许新增字段

### 1.3 多存储后端

通过 `REAL_STORAGE_DICT` 支持 7 种存储：

| 存储类型 | 存储类 | 说明 |
|---------|--------|------|
| `elasticsearch` | ESStorage | 日志/事件存储 |
| `influxdb` | InfluxDBStorage | 时序指标存储（默认） |
| `doris` | DorisStorage | OLAP 分析存储 |
| `kafka` | KafkaStorage | 消息队列存储 |
| `redis` | RedisStorage | 缓存存储 |
| `bkdata` | BkDataStorage | 计算平台存储 |
| `argus` | ArgusStorage | Argus 存储 |

### 1.4 字段管理

- **默认字段**：time、bk_biz_id、bk_supplier_id、bk_cloud_id、ip 等 9 个默认字段
- **自定义字段**：支持 metric/dimension/timestamp/group 四种标签
- **字段类型**：int、long、float、string、boolean、object、nested、timestamp
- **保留字检查**：防止使用系统保留字段名

### 1.5 数据链路

- **V3 链路**：传统 Consul 配置同步，Transfer 消费 Kafka 写入 InfluxDB
- **V4 VM 链路**：计算平台 VM 存储，通过 `access_bkdata_vm` 异步任务
- **插件 V4 链路**：插件类型数据源走 V4 链路（需先 register_to_bkbase）
- **日志 V4 链路**：ES/Doris 存储 + `OPTION_ENABLE_V4_LOG_DATA_LINK`
- **事件组 V4 链路**：`etl_config=bk_standard_v2_event` 自动触发

### 1.6 选项配置

- **分段查询**：`OPTION_SEGMENTED_QUERY_ENABLE`（bool）
- **字段黑名单**：`OPTION_ENABLE_FIELD_BLACK_LIST`（bool）
- **CMDB 层级**：`OPTION_CMDB_LEVEL_CONFIG`（list）
- **ES 唯一字段**：`OPTION_ES_DOCUMENT_ID`（list）
- **单指标单表**：`OPTION_IS_SPLIT_MEASUREMENT`（bool）

## 二、典型使用场景

### 场景 1：创建自定义时序结果表

```python
from bk_monitor_base.metadata.models.result_table import ResultTable

result_table = ResultTable.create_result_table(
    bk_data_id=1001,
    table_id="my_custom_metric",
    table_name_zh="我的自定义指标",
    is_custom_table=True,
    schema_type="free",
    operator="admin",
    default_storage="influxdb",
    bk_tenant_id="default",
    field_list=[
        {"field_name": "cpu_usage", "field_type": "float", "tag": "metric"},
        {"field_name": "hostname", "field_type": "string", "tag": "dimension"},
    ],
)
# 自动完成：默认字段创建 → 自定义字段创建 → 存储创建 → 数据链路应用
```

### 场景 2：创建 ES 日志结果表（V4 链路）

```python
result_table = ResultTable.create_result_table(
    bk_data_id=1002,
    table_id="my_app_log",
    table_name_zh="应用日志",
    is_custom_table=True,
    schema_type="free",
    operator="admin",
    default_storage="elasticsearch",
    bk_tenant_id="default",
    option={"enable_log_v4_data_link": True},
)
# ES 存储 + 日志 V4 链路
```

### 场景 3：修改结果表配置

```python
result_table.modify(
    operator="admin",
    table_name_zh="更新后的指标名",
    is_enable=True,
    option={"segmented_query_enable": True},
    field_list=[
        {"field_name": "new_field", "field_type": "float", "tag": "metric"},
    ],
)
# free schema 下自动清理旧字段 → 重建默认字段 → 创建新字段
```

### 场景 4：升级为全业务结果表

```python
# 将单业务结果表 2_my_metric 升级为全业务 my_metric
result_table.upgrade_result_table(operator="admin")
# 自动完成：标记删除 → 字段迁移 → 存储迁移 → 数据源关系迁移
```

### 场景 5：CMDB 层级拆分

```python
# 按 CMDB 层级（如"set"）创建拆分结果表
record = result_table.set_metric_split(
    cmdb_level="set",
    operator="admin",
)
# 返回 CMDBLevelRecord 实例
# 自动创建目标结果表和数据源
```

## 三、快速上手指南

### 3.1 理解核心概念

1. **ResultTable（结果表）** = 数据的逻辑表结构，一个数据源可以有多个结果表
2. **Schema Type** = 字段管理模式（free/dynamic/fixed）
3. **Default Storage** = 数据默认写入的物理存储
4. **ResultTableField** = 结果表的字段定义（指标/维度/时间戳）
5. **DataSourceResultTable** = 数据源与结果表的 N:1 映射

### 3.2 结果表创建流程

```
1. 校验 label 存在性
2. table_id 转小写
3. 校验 data_source 存在
4. 校验 table_id 在租户下唯一
5. 全业务结果表命名校验
6. 创建 ResultTable 记录
7. 创建 DataSourceResultTable 映射
8. 确定目标业务ID
9. 创建空间-数据源关联
10. 创建默认字段
11. 批量创建自定义字段
12. 创建存储
13. 应用数据链路
```

### 3.3 关键约束

- `table_id` + `bk_tenant_id` 联合唯一
- 全业务结果表（bk_biz_id=0）不得以数字下划线开头
- `fixed` schema 不允许新增字段（`is_force_add=False`）
- `free` schema 修改字段时会先清理旧字段再重建
- 结果表启用时自动推送 Redis 空间路由

## 四、常见问题

### Q1: 结果表创建后数据链路未生效？

检查 `apply_datalink()` 的调用条件：
- InfluxDB 存储需要 `enable_v2_vm_data_link` 开关开启且 etl_config 在 `ENABLE_V4_DATALINK_ETL_CONFIGS` 列表中
- 日志 V4 链路需要 `OPTION_ENABLE_V4_LOG_DATA_LINK` 选项
- 数据源 `created_from` 必须为 `BKDATA` 才会走 V4 链路

### Q2: free schema 修改字段后旧数据怎么办？

`modify()` 在 free schema 下会先删除旧用户配置字段，再重建默认字段和新字段。CMDB 层级拆分表会级联更新。

### Q3: 如何判断结果表是否进入 V4 链路？

检查 `DataSource.created_from` 是否为 `DataIdCreatedFromSystem.BKDATA.value`，以及 `DataSource.etl_config` 是否在 `ENABLE_V4_DATALINK_ETL_CONFIGS` 中。

### Q4: 升级全业务结果表后 table_id 怎么变？

`upgrade_result_table()` 会去掉业务前缀。例如 `2_my_metric` → `my_metric`。旧记录标记为 `is_deleted=True`。
