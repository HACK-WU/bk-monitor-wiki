**free schema 字段重建流程**:
1. 删除旧用户配置字段（`is_config_by_user=True`）
2. 删除旧清洗类 option
3. 重建默认字段
4. 批量创建新字段
5. 级联更新 CMDB 拆分表

### 1.3 升级为全业务结果表

**方法**: `ResultTable.upgrade_result_table()`

**文件**: `result_table.py` 行 1505-1570

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `operator` | str | 是 | 操作者 |

**返回值**: `True`

**异常**:
- `ValueError("结果表不可操作，请确认后重试")` — 已是全业务或已删除

**升级步骤**:
1. 校验：bk_biz_id != 0 且 !is_deleted
2. 标记旧记录：is_deleted=True, bk_biz_id=0
3. 提取新 table_id（去掉业务前缀，如 `2_my_metric` → `my_metric`）
4. 迁移字段：ResultTableField.table_id 更新
5. 迁移存储：深拷贝 → 删除旧 → 保存新
6. 迁移数据源关系：DataSourceResultTable.table_id 更新
7. 自身 table_id 更新为新值

## 五、约束条件

### 5.1 唯一性约束

| 模型 | 约束字段 |
|------|---------|
| ResultTable | `(table_id, bk_tenant_id)` |
| ResultTableField | `(table_id, field_name, bk_tenant_id)` |
| DataSourceResultTable | `(bk_data_id, table_id, bk_tenant_id)` |

### 5.2 Schema 约束

- `fixed` schema 不允许新增字段（`is_force_add=False` 时）
- `free` schema 修改字段时会先清理旧字段再重建
- `dynamic` schema 支持字段自发现

### 5.3 存储约束

- 默认存储必须在 `REAL_STORAGE_DICT` 中注册
- InfluxDB 存储修改时需校验存储路由存在（`enable_influxdb_storage=True` 时）
- ES 存储启用时自动创建/更新索引
