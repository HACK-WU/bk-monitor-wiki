## 一、能力清单

本专家覆盖 bk-monitor 所有内置种子数据的定义、加载与作为"数据字典"层的查询对接。

### 1.1 数据源注册

通过 [init_datasource.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/init_datasource.json) 定义系统内置数据源，每条记录包含：

- `bk_data_id`（1000-1099 为内置数据源）
- `source_label`（`bk_monitor` / `bk_data` / `custom`）
- `type_label`（`time_series` / `event` / `log`）
- `etl_config`（ETL 清洗配置名）
- `option_list`（数据源选项，如 `inject_local_time`、`timestamp_precision`）

### 1.2 结果表注册

通过 [init_resulttable.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/init_resulttable.json) 定义系统内置结果表，每条记录包含：

- `table_id`（如 `system.cpu_summary`、`apache.net`）
- `field_list`（字段列表，含 `field_name`、`tag`、`unit`、`description`）
- `default_storage`（`influxdb` / `elasticsearch`）
- `label`（结果表分类标签）

### 1.3 字段定义

每个结果表的 `field_list` 定义了该表的所有字段，`tag` 字段区分角色：

- `"metric"` — 指标字段（可聚合计算）
- `"dimension"` — 维度字段（用于分组过滤）
- `"timestamp"` — 时间字段

### 1.4 指标描述与单位

通过 [description_unit.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/description_unit.json) 提供指标的：

- `item_display` — 中文显示名（如"使用率(usage)"）
- `conversion_unit` — 单位（如 `%`、`ms`、`bytes`）
- `description` — 详细描述（含含义说明）
- `category_display` — 分类（如"处理器(CPU)"）

与 UnifyQuery 查询链路的对接：`table="system.cpu_summary"` + `field="usage"` → 匹配 `result_table_id` + `item` 获取单位 `%` 和中文描述。

### 1.5 K8s 指标/事件定义

- [k8s_metrics/](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/k8s_metrics/) 下 25 个 YAML 文件定义 K8s 各组件内置指标（apiserver, kubelet, etcd, container, node, coredns 等），每个指标含 `field_name` + `tag_list`
- [k8s_events.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/k8s_events.json) 定义 26 个 K8s 内置事件（Backoff, Failed, Unhealthy 等），每个事件含 `event_name` + `dimension_list`

### 1.6 标签分类

通过 [init_label.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/init_label.json) 定义三级标签体系：

- `source_label` — 数据来源标签（`bk_monitor`、`bk_data`、`custom`）
- `type_label` — 数据类型标签（`time_series`、`event`、`log`）
- `result_table_label` — 结果表分类标签（`host_process`、`component`、`applications` 等），支持两级层级（parent_label）

### 1.7 存储路由与集群配置

- [init_storage.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/init_storage.json) — 定义哪些结果表走 Kafka 存储（36 个表）
- [init_cluster_info.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/init_cluster_info.json) — 定义初始集群（Kafka/InfluxDB/ES 各一个）

### 1.8 时序组与事件组

通过 [init_ts_or_event_group.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/init_ts_or_event_group.json) 定义：

- 9 个内置时序组（`bkunifylogbeat_common.base`、`custom_report_aggate.base` 等）
- 1 个内置事件组（`gse_event_report_base`）

### 1.9 BKCI 数据指标

通过 [bkci_data.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/bkci_data.json) 定义 BKCI 构建机的系统指标（cpu_detail, disk, io, load, mem, net, netstat, swap），含 metric 类型标注。

## 二、能力边界

### 本专家覆盖

- 种子数据文件的 JSON/YAML 结构定义
- 种子数据的加载机制（Django Migration + 运行时加载）
- UnifyQuery 查询链路中 table/field/unit/description 的映射来源
- K8s 内置指标/事件的全局缓存机制

### 不覆盖

- DataSource/ResultTable/ResultTableField 等 Model 的字段定义和 ORM 行为（归元数据核心模型专家）
- 存储引擎的创建和管理（归存储与数据链路专家）
- 用户运行时通过 API 动态创建的数据源/结果表
- UnifyQuery 查询引擎的实现细节
- 告警策略如何使用这些指标

## 三、已知问题与常见坑

| 问题 | 说明 |
|------|------|
| **result_table_id 格式不一致** | `description_unit.json` 使用下划线格式（`system_cpu_summary`），Migration 加载时转换为点号格式（`system.cpu_summary`）。修改种子数据时需注意两种格式的对应关系 |
| **init_data.json 为旧版格式** | 仅被 `bkmonitor/metadata/migrations/0002_create_initial_metadata.py` 使用，新版 Migration 使用 `init_datasource.json` + `init_resulttable.json`。两套 Migration 互斥（不同 app） |
| **K8s 指标文件有两份** | `bk-monitor-base` 和 `bkmonitor` 各有一份 `k8s_metric.py`，BASE_DIR 解析方式不同（`os.path.dirname` vs `os.getcwd()`），但都指向 `metadata/data/k8s_metrics/` |
| **集群信息占位** | `init_cluster_info.json` 中的域名和端口在 Migration 加载时被清空为占位值，实际值由定时任务刷入 |
| **description_unit 导入幂等性** | `0008_import_field_descriptions.py` 直接更新 ResultTableField 的 description 和 unit，重复执行会覆盖已有值 |
