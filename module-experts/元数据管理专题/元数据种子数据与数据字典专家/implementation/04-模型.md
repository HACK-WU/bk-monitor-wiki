## 三、field_list 中 tag 的角色分类

`tag` 字段是 UnifyQuery 查询引擎正确构建查询的基础，分为三种角色：

| tag 值 | 角色 | UnifyQuery 行为 | 示例字段 |
|--------|------|----------------|---------|
| `"metric"` | 指标字段 | 可聚合计算（AVG/SUM/MAX/MIN/COUNT） | `usage`, `total_accesses_min`, `free`, `load1` |
| `"dimension"` | 维度字段 | 用于 GROUP BY 分组过滤 | `ip`, `hostname`, `bk_biz_id`, `device_name` |
| `"timestamp"` | 时间字段 | 时间范围过滤 | `time` |

**设计维度分析**：

**维度 1：tag 对查询的影响** — UnifyQuery 根据 `tag` 决定字段的查询方式。`tag="metric"` 的字段会出现在 `metrics` 参数中并应用聚合函数，`tag="dimension"` 的字段会出现在 `group_by` 参数中。

**维度 2：tag 对存储的影响** — InfluxDB 中 `tag="dimension"` 的字段会被创建为 InfluxDB tag（索引），`tag="metric"` 的字段会被创建为 InfluxDB field（值）。这直接影响查询性能。

**章节来源**: [init_resulttable.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/init_resulttable.json) field_list 中的 tag 字段

## 四、init_label.json 三级分类体系

**位置**: [init_label.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/init_label.json) L1-L200

### 4.1 一级分类：label_type

| label_type | 用途 | 数量 |
|-----------|------|------|
| `source_label` | 数据来源分类 | 3 个（bk_monitor, bk_data, custom） |
| `type_label` | 数据类型分类 | 3 个（time_series, event, log） |
| `result_table_label` | 结果表业务分类 | 16 个（含两级层级） |

### 4.2 result_table_label 两级层级

```
一级分类 (level=1)
├── applications (用户体验)
│   ├── application_check (业务应用) [level=2]
│   ├── uptimecheck (服务拨测) [level=2, is_admin_only=true]
│   └── apm (APM) [level=2]
├── services (服务)
│   ├── service_module (服务模块) [level=2]
│   └── component (组件) [level=2]
├── hosts (主机&云平台)
│   ├── host_process (进程) [level=2]
│   ├── os (操作系统) [level=2]
│   ├── host_device (主机设备) [level=2]
│   └── kubernetes (kubernetes) [level=2]
├── data_center (数据中心)
│   └── hardware_device (硬件设备) [level=2]
└── others (其他)
    └── other_rt (其他) [level=2]
```

**Label 模型字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `label_id` | string | 标签 ID（唯一），如 `"host_process"` |
| `label_name` | string | 标签显示名，如 `"进程"` |
| `label_type` | string | 标签类型 |
| `is_admin_only` | bool | 是否仅管理员可见 |
| `parent_label` | string/null | 父标签 ID，`null` 表示一级分类 |
| `level` | int/null | 层级（1 或 2），source_label/type_label 为 null |
| `index` | int/null | 排序索引 |

**设计维度分析**：

**维度 1：层级设计** — `result_table_label` 支持两级层级（通过 `parent_label` 引用），而 `source_label` 和 `type_label` 是扁平结构（`level=null`）。这种设计允许结果表有更细粒度的业务分类。

**维度 2：权限控制** — `is_admin_only` 字段控制标签的可见性。目前只有 `uptimecheck`（服务拨测）标记为 `true`。

**章节来源**: [init_label.json](file:///root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/data/init_label.json) L1-L200

```
{table_id}|{field}|{unit}|{description}
```

**示例**：

```
system.cpu_summary|usage|percent|CPU使用率
system.cpu_summary|idle|percentunit|CPU空闲率
system.io|await|ms|I/O平均等待时长
system.mem|buffer|decbytes|内存buffered大小
```

**说明**：这是一个纯速查文件，不被任何代码直接加载。用于人工快速查阅表字段信息。
