## 一、Storage 类层次

```
StorageResultTable (Mixin, 抽象基类)
├── InfluxDBStorage  + InfluxDBTool
├── RedisStorage
├── KafkaStorage
├── ESStorage
├── BkDataStorage
├── ArgusStorage
└── DorisStorage

ClusterInfo (独立模型, 集群信息)
StorageClusterRecord (集群迁移记录)
SpaceRelatedStorageInfo (空间关联存储信息)
```

### 1.1 StorageResultTable Mixin

位置：[storage.py](/root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/models/storage.py#L655)

提供所有存储模型的公共模板方法：

- `create_table` — 抽象方法，创建存储记录
- `get_client` — 抽象方法，获取存储客户端
- `add_field` — 抽象方法，添加字段
- `consul_config` — 返回 Consul 配置
- `storage_type` — 返回存储类型常量
- `storage_cluster` — 返回关联的 ClusterInfo（含缓存）
- `update_storage` — 更新存储配置，ES 类型自动处理集群迁移

### 1.2 ClusterInfo 集群模型

位置：[storage.py](/root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/models/storage.py#L82)

统一的集群信息管理模型，支持 8 种集群类型。关键设计：

- `CLUSTER_TYPE_CHOICES` 定义支持的集群类型枚举
- `unique_together = ("bk_tenant_id", "cluster_type", "cluster_name")` 保证租户+类型+名称唯一
- `consul_config` 属性返回 Consul 存储配置（含 SSL 证书 base64 编码）
- `cluster_init` 方法处理 ES 集群初始化（禁用 write_ 前缀自动索引创建）
- `create_cluster` 类方法使用 `@atomic` 事务保证一致性
- `refresh_consul_storage_config` 类方法批量刷新 Consul

## 二、InfluxDB 存储架构

### 2.1 核心模型

```
InfluxDBStorage (models.Model, StorageResultTable, InfluxDBTool)
├── 主键: table_id
├── 关联: storage_cluster_id → ClusterInfo
├── 关联: influxdb_proxy_storage_id → InfluxDBProxyStorage
└── 配置: database, real_table_name, source_duration_time, down_sample_*, proxy_cluster_name, partition_tag
```

### 2.2 Proxy 路由架构

```
InfluxDBStorage
  └── influxdb_proxy_storage_id → InfluxDBProxyStorage
        ├── proxy_cluster_id → ClusterInfo (InfluxDB Proxy 集群)
        └── instance_cluster_name → InfluxDBClusterInfo (后端 InfluxDB 实例)
```

`get_influxdb_storage` 方法按优先级查找 proxy storage 映射：
1. 如果 `influxdb_proxy_storage_id` 存在，直接查询
2. 如果 `proxy_cluster_name` 和 `storage_cluster_id` 都存在，精确匹配
3. 如果只有一个存在，取第一个匹配记录
4. 都没有则取默认记录

### 2.3 Tag 分区架构

```
InfluxDBTagInfo
├── 唯一键: (database, measurement, tag_name, tag_value, cluster_name)
├── host_list: 使用中的机器列表
├── manual_unreadable_host: 静态不可读机器
└── force_overwrite: 是否强制写入
```

Tag 分区通过 Consul 路径 `{CONSUL_PATH}/influxdb_info/tag_info` 下发，格式为 `{database}/{measurement}/{tag_name}=={tag_value}`。

## 三、ES 存储架构

### 3.1 核心模型

```
ESStorage (models.Model, StorageResultTable)
├── 主键: id (BigAutoField)
├── 唯一键: (table_id, bk_tenant_id)
├── 索引配置: date_format, slice_size, slice_gap, retention
├── 暖数据: warm_phase_days, warm_phase_settings
├── 时区: time_zone
├── 索引设置: index_settings, mapping_settings
├── 快照关联: EsSnapshot (通过 table_id)
└── 集群迁移: StorageClusterRecord (通过 table_id + cluster_id)
```

### 3.2 索引生命周期

```
创建 → 分片 (slice_size/slice_gap) → 暖数据迁移 (warm_phase_days) → 过期删除 (retention) → 快照备份 (EsSnapshot)
```

### 3.3 Consul 路由刷新

`ESStorage.refresh_consul_table_config` 将 ES 表配置写入 Consul：
- 路径：`{CONSUL_PATH}/unify-query/data/es/info/{table_id}`
- 内容：`storage_id`, `alias_format`, `date_format`, `date_step`
- 已废弃的结果表会清理 Consul 路径

### 3.4 集群迁移机制

`StorageResultTable.update_storage` 在 ES 集群变更时：
1. 更新旧集群记录（`is_current=False`, `disable_time=now`）
2. 创建新集群记录（`is_current=True`, `enable_time=now`）
3. 刷新 `RESULT_TABLE_DETAIL` 路由（含虚拟 RT）

## 四、Kafka 存储架构

```
KafkaStorage (models.Model, StorageResultTable)
├── 主键: id (BigAutoField)
├── 唯一键: (table_id, bk_tenant_id)
├── topic: 默认格式 {prefix}_{table_id}
├── partition: 分区数
└── retention: 数据过期时间（默认 1800000ms = 30 分钟）
```

Kafka 存储主要用于实时告警数据流，数据保留时间短。`ensure_topic` 方法依赖 Kafka 服务端自动创建 topic。

## 五、Doris 存储架构

```
DorisStorage (models.Model, StorageResultTable)
├── 主键: table_id + bk_tenant_id
├── table_type: PRIMARY_TABLE_TYPE (主键模型) / DUPLICATE_TABLE_TYPE (明细模型)
├── field_config_mapping: 字段/分词配置 (JSON)
├── expire_days: 过期天数
└── 自动创建 StorageClusterRecord
```

## 六、数据链路编排架构

### 6.1 整体架构

```
DataLink (编排器)
  ├── STRATEGY_RELATED_COMPONENTS: 策略→组件映射
  ├── STORAGE_TYPE_MAP: 策略→存储类型映射
  ├── compose_configs: 策略分发
  │   ├── compose_standard_time_series_configs
  │   ├── compose_bk_plugin_time_series_config
  │   ├── compose_bcs_federal_proxy_time_series_configs
  │   ├── compose_bcs_federal_subset_time_series_configs
  │   ├── compose_basereport_time_series_configs
  │   ├── compose_base_event_configs
  │   ├── compose_system_proc_configs
  │   ├── compose_log_configs
  │   └── compose_custom_event_configs
  └── apply_data_link: 链路上线主流程
```

### 6.2 组件配置模型层次

```
DataLinkResourceConfigBase (抽象基类)
├── DataIdConfig
├── ResultTableConfig
├── VMStorageBindingConfig
├── ESStorageBindingConfig
├── DorisStorageBindingConfig
├── DataBusConfig
├── ConditionalSinkConfig
└── ClusterConfig (集群注册到 BKBase)
```

### 6.3 组件关联关系

```
DataId → DataBus → {VMStorageBinding → ResultTable}
                 → {ESStorageBinding → ResultTable}
                 → {DorisBinding → ResultTable}
                 → {ConditionalSink → VMStorageBinding → ResultTable}
```

关联键：
- `data_link_name` — 同一条链路下的组件归组键
- `(bk_tenant_id, namespace, name)` — 组件唯一键
- BKBase 层通过 `spec.sources[].name` / `spec.sinks[].name` 关联

## 七、ES 快照架构

```
EsSnapshot (快照配置)
  ├── 唯一键: (table_id, target_snapshot_repository_name)
  ├── snapshot_days: 快照保留天数（0 = 永久）
  └── status: running / stopped

EsSnapshotRepository (快照仓库)
  ├── repository_name + cluster_id + bk_tenant_id
  └── is_deleted: 软删除标记

EsSnapshotIndice (快照索引)
  └── 关联 EsSnapshot + 索引名

EsSnapshotRestore (快照恢复)
  └── 恢复任务记录
```

关键设计：
- `_lock_snapshot_scope` 使用 `select_for_update` 分布式锁
- `_lock_and_validate_create_snapshot` 在锁保护下校验业务规则

## 八、InfluxDB 集群架构

```
InfluxDBClusterInfo (集群拓扑)
  ├── cluster_name + host_name + port
  └── 通过 Consul 下发配置

InfluxDBHostInfo (主机信息)
  ├── host_name + port + status
  └── 集群主机健康状态

InfluxDBProxyStorage (Proxy 映射)
  ├── proxy_cluster_id → ClusterInfo (Proxy 集群)
  ├── instance_cluster_name → InfluxDBClusterInfo (后端实例)
  └── is_default: 是否默认映射

InfluxDBTool (Mixin)
  ├── push_to_redis: 推送路由到 Redis
  ├── clean_redis_config: 清理过期配置
  └── Redis Key: {INFLUXDB_KEY_PREFIX}:{key}
```

## 九、VM 架构

```
AccessVMRecord (VM 接入记录)
  ├── data_type: bcs_cluster_k8s / bcs_cluster_custom / user_custom / access_vm
  ├── result_table_id → vm_result_table_id 映射
  └── refresh_vm_router: 刷新 VM 查询路由到 Redis

SpaceVMInfo (空间 VM 信息)
  ├── space_type + space_id
  ├── vm_cluster_id → ClusterInfo
  └── vm_retention_time: 保留时间

BkDataClean (清洗配置渲染)
  └── 使用 Jinja2 模板渲染 BKBase 清洗配置

BkDataStorage (存储配置渲染)
  └── 渲染 BKBase VM 存储配置
```
