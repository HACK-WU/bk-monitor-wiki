### 1.2 InfluxDBStorage 创建流程

位置：[storage.py](/root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/models/storage.py#L827-L1027)

核心逻辑：
1. 如果未指定 `storage_cluster_id`，使用默认 InfluxDB 集群
2. 校验 `table_id` 唯一性
3. 解析 `database` 和 `real_table_name`（从 `table_id` 按 `.` 分割）
4. 如果未指定 `influxdb_proxy_storage_id`，通过 `get_influxdb_storage` 查找
5. 创建 `InfluxDBStorage` 记录
6. 通过 `InfluxDBTool.push_to_redis` 推送路由到 Redis

### 1.3 ESStorage 创建流程

位置：[storage.py](/root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/models/storage.py#L2097-L2300)

核心逻辑：
1. 如果未指定 `cluster_id`，使用默认 ES 集群
2. 校验 `table_id` 唯一性
3. 创建 `ESStorage` 记录
4. 创建 `StorageClusterRecord`（enable_time=1970-01-01）
5. 如果 `enable_create_index=True`，创建 ES 索引

### 1.4 存储配置更新（update_storage）

位置：[storage.py](/root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/models/storage.py#L705-L825)

核心逻辑：
1. 遍历 `UPGRADE_FIELD_CONFIG` 中定义的字段
2. 逐一更新匹配的字段
3. ES 类型特殊处理：检测 `storage_cluster_id` 变化 → 创建/更新 `StorageClusterRecord` → 刷新 ES 路由
4. 保存模型

## 四、ES 快照管理

### 4.1 快照创建

位置：[es_snapshot.py](/root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/models/es_snapshot.py#L39-L553)

核心流程：
1. `_lock_snapshot_scope` — 使用 `select_for_update` 锁定相关快照记录
2. `_lock_and_validate_create_snapshot` — 在锁保护下校验：
   - table_ids 对应的 ESStorage 存在
   - 所有 table_ids 在同一 ES 集群
   - 快照仓库存在且未删除
   - 同一仓库下无重复快照配置
   - 无冲突的 running 状态快照
