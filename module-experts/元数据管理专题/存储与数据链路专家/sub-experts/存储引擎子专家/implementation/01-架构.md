## 一、类层次结构

```
StorageResultTable (Mixin, 抽象基类)
├── InfluxDBStorage  + InfluxDBTool
├── RedisStorage
├── KafkaStorage
├── ESStorage
├── BkDataStorage
├── ArgusStorage
└── DorisStorage

ClusterInfo (独立模型)
StorageClusterRecord (集群迁移记录)
SpaceRelatedStorageInfo (空间关联存储)
```

## 二、ClusterInfo 集群模型架构

位置：[storage.py#L82](/root/bk-monitor/bk-monitor-base/src/bk_monitor_base/metadata/models/storage.py#L82)

统一管理 8 种集群类型，核心设计：
- `CLUSTER_TYPE_CHOICES` 定义支持类型
- `unique_together = ("bk_tenant_id", "cluster_type", "cluster_name")`
- `password` 使用 `SymmetricTextField` 加密存储
- `consul_config` 属性返回 Consul 配置（SSL 证书 base64 编码）
- `cluster_init` 处理 ES 集群初始化
- `create_cluster` 使用 `@atomic` 事务

## 三、InfluxDB 存储架构

### 3.1 核心模型

```
InfluxDBStorage
├── 主键: table_id
├── 关联: storage_cluster_id → ClusterInfo
├── 关联: influxdb_proxy_storage_id → InfluxDBProxyStorage
└── 配置: database, real_table_name, source_duration_time, down_sample_*, proxy_cluster_name, partition_tag
```

### 3.2 Proxy 路由

```
InfluxDBStorage → InfluxDBProxyStorage
  ├── proxy_cluster_id → ClusterInfo (Proxy 集群)
  └── instance_cluster_name → InfluxDBClusterInfo (后端实例)
```

`get_influxdb_storage` 三级查找优先级：
1. 精确 ID 匹配
2. 双字段匹配（proxy_cluster_name + storage_cluster_id）
3. 单字段或默认记录

### 3.3 Tag 分区

```
InfluxDBTagInfo
├── 唯一键: (database, measurement, tag_name, tag_value, cluster_name)
├── host_list: 使用中的机器
├── manual_unreadable_host: 静态不可读机器
└── force_overwrite: 强制写入标记
```

Consul 路径: `{CONSUL_PATH}/influxdb_info/tag_info`
格式: `{database}/{measurement}/{tag_name}=={tag_value}`

## 四、ES 存储架构

### 4.1 核心模型

```
ESStorage
├── 主键: id (BigAutoField)
├── 唯一键: (table_id, bk_tenant_id)
├── 索引配置: date_format, slice_size, slice_gap, retention
├── 暖数据: warm_phase_days, warm_phase_settings
├── 时区: time_zone
└── 快照关联: EsSnapshot (通过 table_id)
```

### 4.2 索引生命周期

```
创建 → 分片 (slice_size/slice_gap) → 暖数据迁移 (warm_phase_days) → 过期删除 (retention) → 快照备份
```

### 4.3 Consul 路由

路径: `{CONSUL_PATH}/unify-query/data/es/info/{table_id}`
内容: `storage_id`, `alias_format`, `date_format`, `date_step`

### 4.4 集群迁移

`update_storage` 检测 `storage_cluster_id` 变化时：
1. 旧集群记录: `is_current=False`, `disable_time=now`
2. 新集群记录: `is_current=True`, `enable_time=now`
3. 刷新 RESULT_TABLE_DETAIL 路由（含虚拟 RT）

## 五、Kafka 存储架构

```
KafkaStorage
├── 主键: id (BigAutoField)
├── 唯一键: (table_id, bk_tenant_id)
├── topic: 默认格式 {prefix}_{table_id}
├── partition: 分区数
└── retention: 1800000ms (30 分钟)
```

## 六、Doris 存储架构

```
DorisStorage
├── table_type: PRIMARY_TABLE_TYPE / DUPLICATE_TABLE_TYPE
├── field_config_mapping: 字段/分词配置 (JSON)
├── expire_days: 过期天数
└── 自动创建 StorageClusterRecord
```

## 七、ES 快照架构

```
EsSnapshot (快照配置)
├── 唯一键: (table_id, target_snapshot_repository_name)
├── snapshot_days: 0 = 永久
└── status: running / stopped

EsSnapshotRepository (快照仓库)
├── repository_name + cluster_id + bk_tenant_id
└── is_deleted: 软删除

EsSnapshotIndice (快照索引)
└── FK → EsSnapshot

EsSnapshotRestore (快照恢复)
└── 恢复任务记录
```

分布式锁: `_lock_snapshot_scope` 使用 `select_for_update`

## 八、InfluxDB 集群架构

```
InfluxDBClusterInfo → Consul: {CONSUL_PATH}/influxdb_info/cluster_info
InfluxDBHostInfo → Consul: {CONSUL_PATH}/influxdb_info/host_info
InfluxDBProxyStorage: proxy_cluster_id + instance_cluster_name + is_default
InfluxDBTool.push_to_redis → Redis: {INFLUXDB_KEY_PREFIX}:{key}
```

## 九、VM 架构

```
AccessVMRecord
├── data_type: bcs_cluster_k8s / bcs_cluster_custom / user_custom / access_vm
├── result_table_id → vm_result_table_id 映射
└── refresh_vm_router → Redis 路由

SpaceVMInfo
├── space_type + space_id
├── vm_cluster_id → ClusterInfo
└── vm_retention_time

BkDataClean / BkDataStorage / BkDataStorageWithDataID
└── Jinja2 模板渲染 BKBase 配置
```
