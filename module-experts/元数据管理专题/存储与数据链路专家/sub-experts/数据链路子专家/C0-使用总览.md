## 一、数据链路概述

数据链路（DataLink）是 bk-monitor 与 BKBase 数据链路平台之间的桥接层，负责：

- 按链路策略组装 BKBase 组件配置
- 通过 BKBase API 下发或删除链路资源
- 同步监控侧元数据状态

## 二、链路策略

| 策略 | 场景 | 存储类型 | 组件 |
|------|------|---------|------|
| `BK_STANDARD_V2_TIME_SERIES` | 标准单指标单表时序 | VM | ResultTable + VMStorageBinding + DataBus |
| `BK_EXPORTER_TIME_SERIES` | 采集插件时序（Exporter） | VM | ResultTable + VMStorageBinding + DataBus |
| `BK_STANDARD_TIME_SERIES` | 采集插件时序（Standard） | VM | ResultTable + VMStorageBinding + DataBus |
| `BCS_FEDERAL_PROXY_TIME_SERIES` | 联邦代理集群时序 | VM | ResultTable + VMStorageBinding |
| `BCS_FEDERAL_SUBSET_TIME_SERIES` | 联邦子集群时序 | VM | ResultTable + VMStorageBinding + ConditionalSink + DataBus |
| `BASEREPORT_TIME_SERIES_V1` | 主机基础采集时序 | VM | ResultTable + VMStorageBinding + ConditionalSink + DataBus |
| `BASE_EVENT_V1` | 基础事件 | ES | ResultTable + ESStorageBinding + DataBus |
| `SYSTEM_PROC_PERF` | 系统进程性能 | VM | ResultTable + VMStorageBinding + DataBus |
| `SYSTEM_PROC_PORT` | 系统进程端口 | VM | ResultTable + VMStorageBinding + DataBus |
| `BK_LOG` | 日志链路 | ES + Doris | ResultTable + ESStorageBinding + DorisStorageBinding + DataBus |
| `BK_STANDARD_V2_EVENT` | 标准自定义事件 | ES | ResultTable + ESStorageBinding + DataBus |

## 三、组件类型

| 组件 | Kind | 说明 |
|------|------|------|
| `DataIdConfig` | `DataId` | 数据源配置（BKBase DataId） |
| `ResultTableConfig` | `ResultTable` | 结果表配置（BKBase ResultTable） |
| `VMStorageBindingConfig` | `VmStorageBinding` | VM 存储绑定 |
| `ESStorageBindingConfig` | `ElasticSearchBinding` | ES 存储绑定 |
| `DorisStorageBindingConfig` | `DorisBinding` | Doris 存储绑定 |
| `DataBusConfig` | `Databus` | 清洗任务配置 |
| `ConditionalSinkConfig` | `ConditionalSink` | 条件路由 |

## 四、典型场景

### 场景 1：创建标准时序链路

1. `DataLink.apply_data_link(data_source, table_id, bk_biz_id, storage_cluster_name, strategy=BK_STANDARD_V2_TIME_SERIES)`
2. 自动组装 DataId → ResultTable → VMStorageBinding → DataBus
3. 下发 BKBase API
4. 同步元数据

### 场景 2：创建日志链路

1. `DataLink.apply_data_link(..., strategy=BK_LOG)`
2. 自动组装 ESStorageBinding + DorisStorageBinding + DataBus
3. 至少需要一个存储绑定

### 场景 3：删除链路

1. `DataLink.delete_data_link()`
2. 逆序清理组件（先删 BKBase，再删本地）
3. 删除 DataLink 自身

### 场景 4：查询组件状态

1. `config.component_status` → 实时查询 BKBase
2. 状态流转：Initializing → Creating → Pending → OK
