# C0-使用总览

## 一、能力清单

### 1.1 自定义上报能力

CustomReport 模块提供三种自定义上报类型，共享 CustomGroupBase 抽象基类的统一生命周期管理：

| 类型 | 核心类 | 存储引擎 | 数据模型 | 文件大小 |
|------|--------|---------|---------|---------|
| 时序 | `TimeSeriesGroup` | InfluxDB / VM | Group → Scope → Metric | 2593 行 (106KB) |
| 事件 | `EventGroup` | Elasticsearch | EventGroup → Event | 471 行 |
| 日志 | `LogGroup` | 计算平台 | LogGroup（无子指标模型） | 153 行 |

**统一创建流程**（CustomGroupBase.create_custom_group）：
1. `pre_check` — 校验标签存在性、data_id 唯一性、同名组唯一性
2. `_create` — 生成 table_id、创建 group 记录
3. `create_result_table` — 创建结果表、关联存储引擎、创建时间字段
4. `update_metrics` — 子类实现，创建指标/维度字段
5. `DataSourceOption` — 添加 flat_batch_key 数据源选项
6. `refresh_custom_report_config` — 异步刷新配置到节点管理

### 1.2 时序自定义上报 (TimeSeriesGroup)

最复杂的自定义上报类型，核心特点：

- **三层数据模型**：TimeSeriesGroup（数据源级）→ TimeSeriesScope（指标分组）→ TimeSeriesMetric（具体指标）
- **指标同步双通道**：Redis 通道（Transfer 上报的 ZSET 指标缓存）+ BkData 通道（计算平台 API）
- **单指标单表模式**（`is_split_measurement=True`）：每个指标独立结果表，`table_id` 格式 `bk_k8s_{group_name}_{field_name}`
- **维度过滤**：`get_ts_metrics_by_dimension` 按维度名/值过滤指标
- **指标过期**：超过 `time_series_metric_expired_seconds` 的指标自动排除

### 1.3 事件自定义上报 (EventGroup)

存储于 Elasticsearch，核心特点：

- **固定字段结构**：`event`(object)、`target`(keyword)、`dimensions`(object)、`event_name`(keyword)
- **自动 ES 文档 ID 配置**：`[event, target, dimensions, event_name, time]`
- **维度自动发现**：通过 ES 聚合查询 `event_name` 和 `dimensions` 字段
- **默认启用 V4 事件组数据链路**
- **状态管理**：normal / sleep 两种状态

### 1.4 日志自定义上报 (LogGroup)

最简单的自定义上报类型：

- **无子指标模型**：无 `update_metrics` 实现
- **自动生成 bk_data_token**：用于上报鉴权
- **配置下发**：创建/修改后下发配置到 BkCollector
- **名称不可修改**：不允许修改 `log_group_name`（避免 token 变化）

### 1.5 记录规则能力 (RecordRule)

预计算规则管理：

- **规则配置解析**：YAML 规则 → PromQL → BKSQL 转换
- **源表自动发现**：通过指标反查 VM 结果表，支持显式指定和自动查找
- **计算平台集成**：组装 stream_source → promql_v2 → vm_storage 三节点数据流
- **生命周期管理**：创建/启动/停止/删除数据流

## 二、能力边界

**本子专家负责**：
- CustomGroupBase 及其子类（TimeSeriesGroup/EventGroup/LogGroup）的完整生命周期
- TimeSeriesScope/TimeSeriesMetric 的指标分组和维度管理
- Event 模型的事件和维度管理
- RecordRule/ResultTableFlow 的规则管理与计算平台对接
- 自定义上报相关的常量定义

**本子专家不负责**：
- Space/SpaceType/SpaceDataSource/SpaceResource 模型定义（归空间管理子专家）
- SpaceTableIDRedis 的路由推送（归空间管理子专家）
- 数据源（DataSource）和结果表（ResultTable）的核心模型定义（归专家1）
- 存储引擎配置（InfluxDB/ES/VM）的创建和管理（归专家2）
- 后台异步任务调度（归专家4）

## 三、已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|---------|---------|
| 自定义时序指标不显示 | 指标过期（超过 `time_series_metric_expired_seconds`） | 确认数据上报正常，检查 Redis 中指标时间戳 |
| 自定义时序指标重复 | 指标名大小写不同但视为同一指标 | 指标名大小写不敏感，统一使用小写 |
| 事件组 ES 文档 ID 配置缺失 | 未设置 `OPTION_ES_DOCUMENT_ID` | 创建事件组时自动添加 `event/target/dimensions/event_name/time` 字段 |
| 事件维度自动发现失败 | ES 客户端连接失败或索引不存在 | 检查 ES 存储配置和索引状态 |
| 日志组 Token 变化 | 修改了 `log_group_name` | 不允许修改 `log_group_name`，使用 `modify_log_group` 时不传此参数 |
| 记录规则数据流创建失败 | 未授权源结果表 | 先调用 `batch_add_permission` 授权 |
| 记录规则源表为空 | 指标过期或空间下无对应结果表 | 检查 `time_series_metric_expired_seconds` 配置和空间路由 |
| 单指标单表模式下查询不到数据 | table_id 格式不匹配 | 确认 `make_metric_table_id` 生成的 table_id 格式 |
| 已删除的自定义组被修改 | `is_delete=True` 时仍调用 modify | modify 方法会检查 `is_delete` 并抛 ValueError |

| 关系 | 说明 |
|------|------|
