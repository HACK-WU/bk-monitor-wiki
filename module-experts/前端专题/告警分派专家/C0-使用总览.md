# 使用总览：告警分派专家

> 契约快照生成于 2026-10-14（commit ff89f63ff4）。
> 若使用中发现行为与契约不符，可能代码已变更——expert-lookup 会自动增量修正，或用 expert-team 全量重建。

## 能力清单

告警分派前端（`monitor-pc/pages/alarm-dispatch/`）覆盖「告警自动分派」功能域的配置与管理：

- **规则组管理（列表页 `/alarm-dispatch`）**：规则组新建 / 删除（调试并删除）/ 组名与优先级行内编辑 / 展开收起 / 关键字搜索（组名、标签、告警组名、组 ID）/ 规则只读总览 / 全局效果调试
- **分派规则配置（配置页 `/alarm-dispatch-config/:id`）**：规则增删改复制、告警组选择、匹配条件编辑、通知与通知升级、ITSM 流程套餐、等级调整、追加标签、启停、统一设置（公共条件下发）、查找替换、批量编辑、逐格变更追踪与撤回
- **匹配条件编辑（`CommonCondition`）**：字段/方法/值 tag 式编辑，字段按 CMDB 属性 / 告警策略 / 告警事件分类，支持维度二级选项、策略维度联动、通知人员远程搜索、只读模式
- **效果调试（`DebuggingResult`，三种角色）**：全局效果调试（只读预览）/ 调试并删除 / 调试并生效——所有「生效/删除」动作的统一确认闸门
- **规则搬运（CSV 导入导出）**：列表字段导出为 CSV 下载；CSV 导入追加为可编辑规则行
- **外部直达（query 契约）**：从告警组管理页（`?groupName=`）与告警流转记录（`?group_id=`）直达并预填搜索

## 开发者调用入口（最小指引）

- **页面跳转 / 直达**：
  ```js
  // 直达规则组列表（可携带搜索词）
  this.$router.push({ name: 'alarm-dispatch', query: { groupName: name } });
  // 直达规则配置页
  this.$router.push({ name: 'alarm-dispatch-config', params: { id: String(id) } });
  ```
  2 条路由的完整契约（meta / 参数 / 离开拦截）见 [C1 第一节](./C1-能力契约.md)
- **接口调用**：`import { listAssignGroup, listAssignRule, createAssignGroup } from 'monitor-api/modules/model'`、`import { matchDebug, batchUpdate } from 'monitor-api/modules/assign'`——9 个核心方法与提交体结构见 [C1 第三节](./C1-能力契约.md)
- **核心组件**：`<CommonCondition :value="conditions" @change="..." />`、`<DebuggingResult :is-show="show" :rule-groups-data="debugData" @save-success="..." />`——props/events 契约见 [C1 第二节](./C1-能力契约.md)
- **数据模型**：`RuleData`（规则行：前端态 + 脏标记 + `getSubmitParams()` 提交变换）、`RuleGroupData`（规则组）——字段与行为语义见 [C1 第五节](./C1-能力契约.md)

## 能力边界

本模块**不做**：

- **分派规则的执行**：条件匹配与分派动作由 fta 后端 assign 引擎在告警处理流水线中执行（本模块只负责配置与调试预览）
- **告警组本体管理**：告警组增删改查属 `pages/alarm-group`（本模块仅复用其 `AlarmGroupDetail` 详情抽屉、权限常量，并以新窗口跳转 `#/alarm-group/add`）
- **流程套餐（ITSM）管理**：套餐增删改属 set-meal（本模块仅只读展示套餐详情、新窗口跳转 `#/set-meal-add`）
- **告警详情与处置**：调试命中的告警仅跳转告警中心（不做告警状态操作）
- **平台 action 权限判定**：由 `authorityMixin` + `checkAllowedByActionIds` 统一判定；本模块页面的可编辑性实际由服务端数据字段 `edit_allowed` 驱动（见 C5 决策 10）
- **后端接口实现**：接口契约见 [implementation/05-接口.md](./implementation/05-接口.md)（调用点反推），后端实现不在本专家范围

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| 找删除接口的调用点扑空 | 列表页「删除」确认文案是「调试并删除」，确认后打开调试抽屉 | 真正的 `destroyAssignGroup` 在抽屉「保存」时执行；直接搜删除调用点会看到源码中被注释的旧实现 |
| 配置页改了规则但刷新后没生效 | 配置页所有修改（含组名、优先级）**不即时落库**，必须经「调试并生效」整组提交 | 保存唯一路径：`handleStartDebug` → `DebuggingResult` → `batchUpdate`；只编辑不点调试则一个写请求都不会发出 |
| 调试抽屉「保存」按钮行为不符合预期 | `DebuggingResult.handleSave` 按 `excludeGroups` / `ruleGroupsData` 决定调 `destroyAssignGroup` 还是 `batchUpdate` | 按模式理解：删除模式（excludeGroups 非空）= 删除；配置页模式（ruleGroupsData 非空）= 保存生效；全局调试无保存按钮 |
| 内置规则组编辑/删除按钮禁用且提示「内置的分派规则组不允许修改」 | 服务端返回 `edit_allowed=false` | 这是预期行为，前端不做「强行放开」；列表页与配置页各自独立读取该字段（服务端两处返回不一致时会出现「列表可编辑、配置页只读」错位） |
| 新建规则组后优先级为空 | 自动推算结果 ≥ 10000 时置空（`undefined`） | 不是 bug：默认值 = 现有最大优先级向上取整到 5 的倍数再 +5；≥10000 留空待用户填写 |
| 优先级输入 0 被改成 1、粘贴小数被四舍五入 | `handlePriorityChange` 的输入归一化 | 校验依赖这段归一化而非仅 `max=10000`；写校验相关需求时先读该方法 |
| 外部数据更新后条件编辑器面板仍旧值 | `CommonCondition` 对 `value` prop 的更新不响应（无 value watch） | 外部刷新必须更换组件 key（本模块用 `conditionsRenderKey` / `conditionsKey` / `conditionsSelectorKey` 随机 key 强制重建）；新增刷新场景要自带 key 刷新时机 |
| 调试结果条数与实际不符 | 调试数据范围只取「当前时间窗口前 1000 条」告警 | 验证「是否命中」时不要以条数绝对值为准；改时间窗会重新拉取 |
| 调试/保存失败没有错误提示 | `matchDebug` / `batchUpdate` / `destroyAssignGroup` 均 `.catch` 静默降级 | 失败排查看浏览器网络面板与后端日志；仅成功路径有 `$bkMessage` 提示 |
| 追加标签输入框「修复」后出现异常 | 源码以 `tooltip-key='__null__'`（不可能字符串）规避已知 XSS 注入问题（注释明写） | 不要改回默认值；改动标签编辑组件时保留该防御 |
| 增删条件选项数据源后编辑器渲染时机异常 | `allKVOptions` 以「回调到达 12 次」判定选项装载完成 | 增删选项请求必须同步修改计数（当前 12）；详见 C5 决策 4 |
| CSV 导入后行状态/撤回异常 | 导入链仅做表头全等校验（源码 `// to do 校验`），行级错误静默 console.log | 导入后逐行人工核对；排查「导入行撤回指向错误」见 03-数据流转「结论 3」 |
| 改了旧版条件编辑器却毫无效果 | `common-condition.tsx`（1497 行）与 `common-condition-selector.tsx`（327 行）为**零引用死文件** | 现行实现是 `common-condition-new.tsx`；改动前先 grep 引用链 |
| 列表规则数量超过 1000 条时展示不全 | 列表页 `listAssignRule({ page: 1, page_size: 1000 })` 全量拉取有隐式上限 | 规则数量逼近该量级时评估改为按组拉取或分页 |
| 规则接口失败时列表页直接报错（非空态） | `listAssignRule` 失败降级为 `false` 后，分组逻辑继续对其调用 `.filter` 抛 TypeError | 排查「列表页打不开」时先看该请求是否失败（详见 `implementation/02-实现.md` 技术债 6） |

## 关联模块（非本专家资产）

| 模块 | 关系 |
|------|------|
| `pages/alarm-group`（告警组） | 分派目标实体：复用 `AlarmGroupDetail` 详情抽屉与权限常量；告警组页「相关分派规则」反向跳入本模块（`query.groupName`） |
| `fta-solutions/pages/alarm-dispatch/*` | 独立壳复用：fta 应用同构复用本模块的页面组件与 `authority-map`，改动需双端回归 |
| 告警中心（trace / fta 流转记录） | 出/入口：流转记录的 `#/alarm-dispatch?group_id=` 链接跳入；调试命中告警跳转告警中心 |
| `fta-solutions/pages/setting/set-meal-detail` | 只读展示流程套餐详情（消费本页 provide 的 `authority` / `MANAGE_ACTION_CONFIG`） |
