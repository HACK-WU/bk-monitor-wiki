# 能力契约：告警分派专家

> 契约快照生成于 2026-10-14（commit ff89f63ff4）。
> 若使用中发现行为与契约不符，可能代码已变更——expert-lookup 会自动增量修正，或用 expert-team 全量重建。
>
> **覆盖范围**：本专家是前端功能域，契约覆盖四类公开能力——① 页面路由（对用户/调用方页面）、② 核心组件（对开发者）、③ 请求层方法与提交体（对后端，调用点反推）、④ 领域模型（对扩展规则的开发者）。逐实现细节见 `implementation/`。

## 一、页面路由契约

2 条路由注册于 `router/manager/alarm-dispath.ts`（注意文件名拼写 `dispath`，历史遗留），`meta.navId` 统一 `alarm-dispatch`（菜单归属），均以 `components.noCache` 懒加载。菜单注册于 `router/router-config.ts`（配置 → 告警配置 → 告警分派）。

### alarm-dispatch —— 规则组列表

- **用途**：告警分派主入口；规则组总览、搜索、新建、行内编辑、删除（调试并删除）、全局效果调试。
- **参数**（query 契约，`getRouteParams` 读取）：
  | 参数 | 类型 | 行为语义 |
  |------|------|----------|
  | `groupName` | string | 预填搜索词（来自告警组管理页「相关分派规则」入口）；命中后按告警组名过滤规则组 |
  | `group_id` | string | 同上（来自告警流转记录链接的组 ID）；两者同时存在时 `group_id` 覆盖 `groupName` |
- **meta**：`title=告警分派`、`navId='alarm-dispatch'`、`route.parent='manager'`、`noNavBar: false`。
- **行为语义**：带 query 进入时，搜索在「告警组字典 + 规则数据」两个请求都完成后自动执行一次（`isSearch` 双请求栅栏）。
- **异常**：列表请求失败置空列表并结束 loading（无错误页）。
- **约束**：规则全量拉取 `page_size=1000`（隐式上限）；组搜索为纯前端过滤，不走后端。
- **使用示例**（真实用法，来源 `alarm-group-common/alarm-group.tsx` 的 `handleToAppDispatch`）：
  ```js
  // 从告警组页直达关联的告警分派规则
  this.$router.push({
    name: 'alarm-dispatch',
    query: { groupName: name },
  });
  ```
- 契约来源：`AlarmDispatchPage`（`alarm-dispatch-page.tsx`）/ `AlarmDispatch`（`alarm-dispatch.tsx`）

### alarm-dispatch-config —— 分派规则配置

- **用途**：单个规则组的规则编辑台（行内/批量/统一设置/查找替换/导入导出/调试并生效）。
- **参数**：路径参数 `id`（规则组 id）；通过 `params.id` 读取，无 `props: true`。另有内部刷新豁免参数 `params.refresh`（为真时跳过离开拦截）。
- **meta**：`title=配置规则`、`needBack: true`（显示返回）、`navId='alarm-dispatch'`。
- **行为语义**：**离开拦截**——`isEffect`（已生效保存）直接放行；否则若有未生效修改（`isRuleChange`：行数变化或任一行与快照有差异）弹「是否放弃本次操作？」由用户确认；无改动直接放行。
- **异常**：组/规则加载失败退化为空组初始态（自动生成一条空白可编辑规则）。
- **约束**：空组必须保留至少一条空行（删除到最后一行时回退「空组初始态」而非清空）；内置组（`edit_allowed=false`）禁用「调试并生效」。
- **使用示例**（真实用法，来源 `alarm-dispatch.tsx`）：
  ```js
  // 列表页「配置规则」
  this.$router.push({
    name: 'alarm-dispatch-config',
    params: { id: String(id) },
  });
  ```
- 契约来源：`AlarmDispatchConfigPage`（`alarm-dispatch-config-page.tsx`，含 `beforeRouteLeave`）/ `AlarmDispatchConfig`（`alarm-dispatch-config.tsx`）

> **跨模块直达 URL 形态**（告警流转记录消费，来源 `trace/.../alarm-records.tsx`）：`{origin}{pathname}?bizId={biz_id}#/alarm-dispatch?group_id={group_id}`。

## 二、核心组件契约

### CommonCondition（匹配条件编辑器，现行版）

契约来源：`CommonCondition`（`components/common-condition-new.tsx`）

- **用途**：`ICondtionItem[]` 条件的 tag 式编辑器——字段/方法/值三级选择、字段分类筛选、维度二级选项、策略维度联动、通知人员远程搜索、只读展示。被列表页（只读）/ 配置页 / 调试抽屉 / 查找替换 / 统一设置 5 处使用。
- **props**：
  | 参数名 | 类型 | 默认 | 行为语义 |
  |--------|------|------|----------|
  | `value` | `ICondtionItem[]` | 必填 | 初始条件数据；**仅在组件挂载时读入**，后续更新不响应（见「约束」） |
  | `keyList` | `{id,name}[]` | — | 一级字段选项（`allKVOptions` 装载） |
  | `valueMap` | `Map<string, {id,name}[]>` | — | 各字段的候选值 |
  | `groupKeys` | `Map<string, any[]>` | — | 二级选项（`dimensions/tags/set/module/host` 命中时展开） |
  | `groupKey` | `string[]` | `GROUP_KEYS` | 哪些字段是复合键（决定二级展开行为） |
  | `specialOptions` | `{ [k:string]: TValueMap }` | — | 特殊选项：键为 `field=value`（如 `alert.strategy_id=5`），命中后并入候选值（策略→维度联动） |
  | `readonly` | boolean | `false` | `true` 时全部交互短路（仅展示），用于列表页「匹配规则」列与调试结果 |
  | `needValidate` | boolean | `false` | 控制必填校验的报错展示（空行传 `false` 豁免；配置页传 `!row.isNullData`） |
  | `isOnlyAdd` | boolean | `true` | `true` 时仅提供 AND 连接符（条件之间不支持 OR） |
  | `valueList` / `onValueMapChange` | — | — | **接口声明的预留 prop**（当前模块内无传参与消费点，复用时自行评估语义） |
  | `settingsValue` | `ICondtionItem[]` | — | 统一设置条件；编辑行命中它且被改动时弹「统一设置条件失效」确认 |
  | `replaceData` | `{id,name}[]` | — | 查找替换的新值，用于命中高亮 |
  | `loading` | boolean | — | 选项装载中的 loading 态 |
  | `refreshStrategyList` | `() => Promise<void>` | — | 注入「刷新策略列表」动作（字段为 `alert.strategy_id` 时显示） |
  | `isFormMode` | boolean | `true` | `false` 时用于非表单场景（查找替换/统一设置） |
- **events**：
  | 事件 | 载荷 | 语义 |
  |------|------|------|
  | `change` | `ICondtionItem[]` | 条件变更（差异比对后上报，非每键上报） |
  | `validate` | boolean | 必填校验未通过（`true`=有错） |
  | `repeat` | boolean | 行内存在重复条件 |
  | `settingsChange` | — | 用户确认「变更将使统一设置条件失效」 |
- **异常**：选项数据缺失时对应弹层为空列表（不报错）；远程搜索失败静默。
- **约束**：
  - **外部数据刷新必须换组件 key**：组件对 `value` 的后续更新不响应，外部要在数据变化后强制重建（本模块用随机 key：列表页 `conditionsKey`、配置页 `row.conditionsRenderKey`、统一设置浮层 `conditionsSelectorKey`）。
  - 同一规则内字段（key）重复会报「注意: 名字冲突」。
- **使用示例**（真实用法，来源 `alarm-dispatch-config.tsx` 的 `EColumn.conditions` 分支）：

  ```tsx
    onValidate={v => row.setVerificatory('conditions', v)}
  />
  ```
  只读形态（来源 `alarm-dispatch.tsx`）：
  ```tsx
  <CommonCondition
    key={this.conditionsKey}
    groupKey={GROUP_KEYS}

  ```

### DebuggingResult（效果调试抽屉）

契约来源：`DebuggingResult`（`components/debugging-result.tsx`）

- **用途**：模块**所有「生效/删除」动作的统一确认闸门**——打开即调 `matchDebug` 预览规则命中的告警，用户确认后按模式执行保存或删除。三种角色：

  | 角色 | 触发方 | `ruleGroupsData` / `excludeGroups` | 保存行为 |
  |------|--------|-----------------------------------|----------|
  | 全局效果调试 | 列表页「效果调试」 | `[]` / `[]` | 无保存按钮，仅关闭 |
  | 调试并删除 | 列表页「删除」 | `[]` / `[id]` | `destroyAssignGroup(id)` |
  | 调试并生效 | 配置页「调试并生效」 | `[debugData]` / `[]` | `batchUpdate(debugData[0])` |

- **props**：
  | 参数名 | 类型 | 默认 | 行为语义 |
  |--------|------|------|----------|
  | `isShow` | boolean | `false` | 打开抽屉；置真时立即发起调试请求，置假关闭 |
  | `ruleGroupsData` | `IRuleGroupsDataItem[]` | `[]` | 调试数据（数组恒为 1 项，「防止有批量调试」）；**保存时原样提交**（调试所见=保存所提交）；为空则为全局调试 |
  | `excludeGroups` | `string[]` | `[]` | 删除模式的组 id；保存时按首项删除规则组 |
  | `alarmGroupList` | `any[]` | `[]` | 告警组字典（调试结果中展示组名） |
  | `isViewDebugEffect` | boolean | `false` | 全局效果调试模式（按钮文案「关闭」，无保存） |
  | `conditionProps` | `IConditionProps` | `null` | 条件只读展示所需的选项数据 |
- **events**：`showChange`（抽屉显隐）、`delSuccess`（删除成功）、`saveSuccess`（保存成功）。
- **异常**：调试/保存失败静默（仅不进入成功分支，无 toast）。
- **约束**：调试数据范围取当前时间窗口前 1000 条告警（文案明示）；时间窗默认 `now-7d ~ now`，可改并重新查询。
- **使用示例**（真实用法，来源 `alarm-dispatch.tsx` 删除模式与 `alarm-dispatch-config.tsx` 生效模式）：
  ```tsx
  // 列表页：删除并调试 / 全局效果调试
  <DebuggingResult
    alarmGroupList={this.alarmGroupList}
    conditionProps={this.conditionProps}
    excludeGroups={this.delGroups}
    isShow={this.showDebug}
    isViewDebugEffect={this.isViewDebugEffect}
    ruleGroupsData={[]}
    onDelSuccess={this.handleDelSucess}
    onShowChange={this.handleShowChange}
  />
  // 配置页：调试并生效
  <DebuggingResult
    alarmGroupList={this.alarmGroupList}
    conditionProps={{ keys, valueMap, groupKey: GROUP_KEYS, groupKeys }}
    isShow={this.showSideliner}
    ruleGroupsData={this.debugData}
    onSaveSuccess={this.handleSaveSuccess}
    onShowChange={this.handleShowChange}
  />
  ```

## 三、请求层契约

分发派接口定义于 `monitor-api/modules/model.js`（`rule_groups` / `rules` REST 方法）与 `monitor-api/modules/assign.js`（规则操作）。所有请求经 `base.ts` 的 `request` 封装：自动附加 `bk_biz_id`（或 `space_uid`）、生成 `traceparent`、默认错误弹窗（可用 `{ needMessage: false }` 关闭）。

### listAssignGroup —— 规则组列表

- **用途**：拉取当前业务全部规则组（列表页/配置页加载）。
- **参数**：无（业务上下文由 request 层注入）。
- **返回**：`[{ id, name, priority, edit_allowed, update_time, update_user, bk_biz_id, settings }]`（前端消费字段；`settings.public_conditions` 表示是否设置了统一设置）。
- **异常**：失败由调用方 `.catch(() => [])` 降级为空。
- **约束**：无分页参数（返回全量）。
- **使用示例**：
  ```js
  import { listAssignGroup } from 'monitor-api/modules/model';
  const groups = await listAssignGroup().catch(() => []);
  ```
- 契约来源：`listAssignGroup`（`monitor-api/modules/model.js`，`GET fta/assign/rule_groups/`）

### createAssignGroup —— 新建规则组

- **用途**：新建规则组。
- **参数**：`{ name: string, priority: number }`。
- **返回**：`{ id, ... }` — 新组 id（用于跳转配置页）。
- **异常**：失败由 request 层弹窗提示（默认行为）。
- **约束**：优先级 1~10000 且不得与现有组冲突（前端校验，冲突会被拒绝提交）。
- **使用示例**（来源 `alarm-dispatch.tsx`）：
  ```js
  import { createAssignGroup } from 'monitor-api/modules/model';
  const data = await createAssignGroup({ name: '关键业务分派', priority: 100 });
  this.$router.push({ name: 'alarm-dispatch-config', params: { id: String(data.id) } });
  ```
- 契约来源：`createAssignGroup`（`POST fta/assign/rule_groups/`）

### partialUpdateAssignGroup —— 更新组名/优先级

- **用途**：列表页行内编辑组名或优先级（单字段 PATCH）。
- **参数**：`(pk: number, data: { name?: string } | { priority?: number })`。
- **返回**：通用成功响应（前端仅判真值）。
- **异常**：失败由 request 层提示；成功后列表整体重拉。
- **约束**：每次只提交单个字段（`{ [filed]: value }`）。
- **使用示例**（来源 `alarm-dispatch.tsx` 的 `handleBatchEditSubmit`）：
  ```js
  import { partialUpdateAssignGroup } from 'monitor-api/modules/model';
  await partialUpdateAssignGroup(this.currentId, { priority: 200 });
  ```
- 契约来源：`partialUpdateAssignGroup`（`PATCH fta/assign/rule_groups/{pk}/`）

### destroyAssignGroup —— 删除规则组

- **用途**：删除规则组（「调试并删除」链的最终动作）。
- **参数**：`(pk: number|string)` — 规则组 id。
- **返回**：通用成功响应。
- **异常**：失败静默（`DebuggingResult.handleSave` 内 `.catch(() => false)`）。
- **约束**：**不要直接调用**——删除必须经 `DebuggingResult` 的删除模式（先 `matchDebug` 预览影响面）；组内规则随组一并删除。
- **使用示例**（来源 `debugging-result.tsx` 的 `handleSave`）：
  ```js
  import { destroyAssignGroup } from 'monitor-api/modules/model';
  const ok = await destroyAssignGroup(this.excludeGroups[0]).then(() => true).catch(() => false);
  ```
- 契约来源：`destroyAssignGroup`（`DELETE fta/assign/rule_groups/{pk}/`）

### listAssignRule —— 规则列表

- **用途**：拉取规则（列表页全量 / 配置页按组过滤）。
- **参数**：
  | 参数名 | 类型 | 行为语义 |
  |--------|------|----------|
  | `page` / `page_size` | number | 列表页传 `{ page: 1, page_size: 1000 }`（全量拉取，1000 为隐式上限） |
  | `assign_group_id` | number | 配置页传（仅取当前组的规则） |
- **返回**：`[{ id, assign_group_id, user_groups, conditions, actions, alert_severity, additional_tags, is_enabled, user_type }]`（`user_type`：`main` 负责人 / `follower` 关注人）。
- **异常**：列表页失败会波及分组逻辑（`list` 变 `false` 后 `.filter` 抛 TypeError——已知坑，见 02-实现技术债 6）。
- **约束**：列表页消费**原始 snake_case 行**（仅条件值去引号）；配置页经 `transformDataKey` 转 camelCase 后构造 `RuleData`。
- **使用示例**：
  ```js
  import { listAssignRule } from 'monitor-api/modules/model';
  const rulesOfGroup = await listAssignRule({ assign_group_id: 12 }).catch(() => []);
  ```
- 契约来源：`listAssignRule`（`GET fta/assign/rules/`）

### matchDebug —— 规则匹配调试

- **用途**：以历史时间窗预览规则命中的告警（调试三种角色的统一试算接口）。
- **参数**：
  | 参数名 | 类型 | 行为语义 |
  |--------|------|----------|
  | `bk_biz_id` / `assign_group_id` / `priority` / `group_name` / `rules` / `settings` | — | 配置页传入本次编辑的完整 `debugData[0]`（未保存数据，用于模拟生效效果） |
  | `exclude_groups` | `string[]` | 删除模式传入（试算「排除待删组」后的分派结果） |
  | `start_time` / `end_time` | number | 调试时间窗（秒级时间戳；默认 `now-7d ~ now`） |
- **返回**：`[{ group_id, group_name, priority, alerts_count, rules: [{ user_groups, conditions, is_enabled, is_changed, alerts: [{ id, severity, alert_name, metrics: [{id,name}], content }] }] }]`。
- **异常**：失败由调用方 `.catch(() => [])` 降级为空结果。
- **约束**：只返回时间窗内前 1000 条告警（预览非全量）。
- **使用示例**（来源 `debugging-result.tsx` 的 `getRuleMatchDebug`）：
  ```js
  import { matchDebug } from 'monitor-api/modules/assign';
  import { handleTransformToTimestamp } from 'monitor-pc/components/time-range/utils';
  const [startTime, endTime] = handleTransformToTimestamp(['now-7d', 'now']);
  const res = await matchDebug({
    assign_group_id: 12, priority: 100, group_name: '关键业务分派',
    rules: [/* getSubmitParams() 数组 */], settings: { public_conditions: false },
    start_time: startTime, end_time: endTime,
  }).catch(() => []);
  ```
- 契约来源：`matchDebug`（`monitor-api/modules/assign.js`，`POST fta/assign/rule_operate/match_debug/`）

### batchUpdate —— 整组保存生效

- **用途**：配置页「调试并生效」的保存动作——整组规则一次性提交（无逐条保存接口）。
- **参数**：单个 `debugData[0]`（`{ bk_biz_id, assign_group_id, priority, group_name, rules, settings }`；`rules` 由 `RuleData.getSubmitParams()` 输出，空行剔除；`settings.public_conditions` 前端重算）。
- **返回**：通用成功响应（前端仅判真值，成功后 `isEffect=true` 返回列表页）。
- **异常**：失败静默（无 toast，依赖 request 层默认提示）。
- **约束**：**与 `matchDebug` 必须用同一份数据**（试算=提交的强一致性约定，见 C5 决策 1）；`rules[].id` 缺省表示新增行。
- **使用示例**（来源 `debugging-result.tsx` 的 `handleSave`，成功时响应为真值）：
  ```js
  import { batchUpdate } from 'monitor-api/modules/assign';
  const res = await batchUpdate(this.ruleGroupsData[0]).catch(() => false);
  if (res) {
    this.$bkMessage({ theme: 'success', message: this.$t('保存成功') });
    this.$emit('saveSuccess');
  }
  ```
- 契约来源：`batchUpdate`（`monitor-api/modules/assign.js`，`POST fta/assign/rule_operate/batch_update/`）

### getAssignConditionKeys / searchObjectAttribute —— 条件字段选项

- **用途**：条件编辑器的一级字段列表（`getAssignConditionKeys`，返回 `[{ key, display_key }]`）与 CMDB 对象属性（`searchObjectAttribute`，`bk_obj_id ∈ {set, module, host}`，返回 `[{ bk_property_id, bk_property_name, option }]`）。
- **行为语义**：均由 `allKVOptions` 聚合装载（见第四节）；`option` 为 `string[]` 或 `{id,name}[]`（前端做兼容转换）。
- **约束**：不要在组件内单独调用——与其余 10 路选项数据一起经 `allKVOptions` 装载，避免装载时序不一致。
- 契约来源：`getAssignConditionKeys` / `searchObjectAttribute`（`monitor-api/modules/assign.js`）

### 提交体契约（rules 元素结构）

`RuleData.getSubmitParams()` 是「前端态 → 提交体」的唯一映射点，`matchDebug` / `batchUpdate` 的 `rules[]` 均为此结构（契约来源：`RuleData.getSubmitParams` @ `typing/index.ts`）：

| 字段 | 类型 | 行为语义 |
|------|------|----------|
| `id` | number \| 缺省 | 已有规则 id；新增/复制行为缺省（后端按新增处理） |
| `user_groups` | number[] | 告警组 id 数组（分派目标） |
| `conditions` | `[{ condition, field, method, value }]` | `condition`：`and`/`or`（连接符）；`method`：`eq`(in)/`neq`(not in)/`include`(like)/`exclude`(not like)/`reg`(regex)/`nreg`(nregex)；空数组=不限制 |
| `actions` | array | 通知动作 `{action_type:'notice', is_enabled, upgrade_config:{is_enabled, user_groups, upgrade_interval}}`（`upgrade_interval` 单位分钟）；流程动作 `{action_type:'itsm', action_id}`——`itsm` 且 `action_id` 为空时**被过滤不提交** |
| `alert_severity` | number | 等级调整：`0` 保持原样 / `1` 致命 / `2` 预警 / `3` 提醒 |
| `additional_tags` | `[{key, value}]` | 追加标签 |
| `is_enabled` | boolean | 规则启停 |

## 五、领域模型契约

### RuleData（规则行模型）

契约来源：`RuleData`（`typing/index.ts`）

- **用途**：单条规则的完整前端模型——聚合字段、脏标记、校验位与提交变换；配置页 `tableData` 的元素类型，行编辑即调用其方法。
- **公开字段**（行为语义）：
  | 字段 | 类型 | 语义 |
  |------|------|------|
  | `id` | number | 数据库规则 id；`0` = 新增未保存 |
  | `userGroups` / `conditions` / `actions` / `alertSeverity` / `additionalTags` / `isEnabled` | — | 与提交体字段同义（见第三节提交体契约） |
  | `config` | `{ [field]: boolean }` | **脏标记**：逐列「与上次生效配置不同」；驱动单元格 `is-change` 高亮 |
  | `verificatory` | `{ [field]: boolean }` + `validateTips` | **校验位**：逐列错误标记与提示文案 |
  | `conditionsRenderKey` | number | 条件组件重建 key（外部刷新条件数据后必须换新） |
  | `addId` / `copyId` | number \| null | 新增行/复制行的身份标记（差异对比与撤回的依据） |
- **公开方法与 getter**：
  | 名称 | 行为语义 |
  |------|----------|
  | `getSubmitParams(params?)` | 输出提交体结构（见第三节）；只输出业务字段，前端态（config/verificatory/tag 等）不提交 |
  | `setConditions(v)` / `setActions(value, actionType)` / `setAdditionalTags(list)` / `setIsEnabled(v)` | 原子写入口（写入后需宿主显式调用差异对比） |
  | `setFindReplace(findData, replaceData)` | 查找替换：命中 findData 全部条件才替换，并刷新渲染 key |
  | `setUnifiedSettings(findData, replaceData, curConditions)` | 统一设置：完整包含时替换，有差异时与当前条件合并 |
  | `unshiftConditions(conditions)` | 统一设置「新增」路径：条件前插 + 去重 + 同键合并 |
  | `debugVerificatory()` | 调试前校验：非空行必须有告警组与匹配条件；返回是否有误 |
  | `isNullData`（getter） | 是否空规则（豁免校验/提交过滤的依据；**成立条件包含 `isEnabled === true`**） |
  | `isVerifySuccess`（getter） | 校验是否通过（只覆盖告警组/条件/标签三个校验位） |
- **使用示例**（真实形态，来源 `alarm-dispatch-config.tsx` 与 `debugging-result.tsx`）：
  ```js
  import { RuleData } from './typing';           // 模块内使用；跨模块复用时按相对路径引入
  import { transformDataKey } from 'monitor-common/utils';

  // 回填：后端 snake_case 行 → RuleData
  const row = new RuleData({ ...transformDataKey(apiRule, false) });

  // 编辑
  row.setConditions([{ condition: 'and', field: 'alert.strategy_id', method: 'eq', value: ['5'] }]);
  row.setIsEnabled(true);

  // 提交（batchUpdate 的 rules[]）
  const payload = row.getSubmitParams();
  ```
- **约束**：`isNullData` 的空行豁免依赖「默认空行 + 开关开启」形态；关闭唯一空行开关会让它脱离豁免、被要求补全。构造采用「真值覆盖」——`0` / `false` / 空数组等 falsy 值不会覆盖默认值，新增字段时需验证默认键完整性。

### RuleGroupData（规则组模型）

契约来源：`RuleGroupData`（`typing/index.ts`）

- **用途**：列表页的规则组模型（折叠态 + 规则行集合）。
- **公开字段**：`id` / `name` / `priority`（1~10000，**数值越大优先级越高**）/ `isExpan`（展开态）/ `editAllowed`（内置组不可编辑，来自 `edit_allowed`）/ `updateTime` / `updateUser` / `ruleData`。
- **公开方法**：`setExpan(v)`（展开收起）、`setRuleData(list)`（写入规则行；条件值做去引号规范化）。
- **使用示例**（来源 `alarm-dispatch.tsx`）：
  ```js
  import { RuleGroupData } from './typing';
  const group = new RuleGroupData({
    id: item.id, name: item.name, priority: item.priority,
    isExpan: true, ruleData: [], editAllowed: !!item.edit_allowed,
  });
  group.setRuleData(rulesOfGroup);
  ```
