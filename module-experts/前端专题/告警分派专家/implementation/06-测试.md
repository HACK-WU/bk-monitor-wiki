## 框架与组织

- **运行器与断言**：Node 原生 `node:test` + `node:assert/strict`；命名惯例 `*.test.cjs`（少数 `.test.mjs`）；**直跑真实源码**（不经打包、不建测试双）：TS/TSX 经 `typescript.transpileModule`（CommonJS + ES2022）编译后用 `new Function('require', 'module', 'exports', ...globals)` 执行；依赖经自定义 `require` 映射注入桩，并对 `window` / `location` 等环境按用例注入（`.vue` 另有 `vue/compiler-sfc` 手工装配 render 的手法）。
- **无 CI 入口**：`.github/workflows/` 共 5 个 workflow（`base-pytest.yml`、`codecov.yml`、`label_check.yml`、`unittest.yml`、`web.yml`），实测 grep 无任何执行 `webpack/tests` 或 `node --test` 的内容——测试属本地手工回归。
- **本模块若补测试的可行模式**（参照 `tests/collector-*.test.cjs` 的 `transpileModule` 直跑手法，成本从低到高）：
  1. **纯函数直测（成本最低）**：`typing/condition.ts` 的函数族——`mergeConditions`（同 field+method 合并 value）、`conditionsDeduplication`、`conditionsInclues`、`conditionCompare`、`conditionFindReplace`（含 `isUnshift` 分支）、`statisticsSameConditions`、`topNDataStrTransform`（去首尾双引号）；`typing/index.ts` 的 `deepCompare`。注意模块顶层有 `window.i18n.tc` / `window.i18n.t` 调用（`KEY_FILTER_TAGS`、`LEVELLIST`），直跑需注入 `{ window: { i18n: { t: v => v, tc: v => v } } }` 环境桩，`RuleData` 另需 `monitor-common/utils` 的 `random` 桩。
  2. **类方法层**：`typing/index.ts` 的 `RuleData.getSubmitParams`（提交结构转换）、`setFindReplace` / `setUnifiedSettings` / `unshiftConditions`（条件编辑三兄弟）、`debugVerificatory`、`isNullData`；`RuleGroupData.setRuleData`。均为纯数据变换，断言输入输出即可。
  3. **组件方法层**：`debugging-result.tsx` 的 `getRuleMatchDebug` / `handleSave`（可断言 `matchDebug` / `batchUpdate` / `destroyAssignGroup` 三个分支的调用参数）、`condition.ts` 的 `allKVOptions` / `setDimensionsOfStrategy`（可 stub 12 个接口桩后断言 `setData` 写回与 `end` 回调时序）——参照 `collector-cross-business.test.cjs` 的 `load` + 组件实例化 + context 绑定手法。
  4. **e2e 旅程**（成本最高）：「列表 → 新建组 → 配置规则 → 调试 → 保存生效」依赖真实环境与登录态。

- 告警分派模块**无任何自动化测试**：`tests/` 的 22 个文件中 0 个覆盖本模块（10 组直接关键词全 0 命中；`alarm` / `assign` / `condition` 等宽口径命中逐一核验后全部属其它模块），模块目录无 colocated 测试，`e2e/` 无入库用例；按 skill 规则不产出 `test/known-failures.md`。
