# 使用总览：插件管理专家

> 契约快照生成于 2026-10-13（commit ff89f63ff4）。
> 若使用中发现行为与契约不符，可能代码已变更——expert-lookup 会自动增量修正，或用 expert-team 全量重建。

## 能力清单

插件管理前端（`monitor-pc/pages/plugin-manager/`）覆盖「指标插件管理」功能域的全生命周期：

- **插件列表**：tab 分类（Exporter/Script/DataDog/JMX/BK-Pull/SNMP）+ 关键字搜索（防抖 300ms + CancelToken）+ 排序 + 标签筛选 + 分页 + 删除 + 导出 + 导入（单包/多包）+ 官方标记
- **三步新建/编辑/升级向导**：定义插件（ID 校验/类型/上传包/参数/描述）→ 插件调试（选主机、轮询日志终端、指标合并）→ 完成发布（`release`），三步共享 `pluginInfo` 大对象
- **插件详情**：基本信息 / 上传内容（脚本 monaco 预览）/ 定义参数（历史记录）/ 描述（markdown）+「指标维度」tab
- **指标&维度设置（三条现行路径）**：setmetric 路由页（`metric-dimension-dialog.tsx` 全页形态）、调试向导内嵌弹窗（同组件的弹窗形态）、详情页 tab（`indicator-dimension/` 工具族）
- **插件包管理**：`.gz/.tgz` 导入（单/多文件两套对话框、冲突五级分级）、导出（`download_url`）、LOGO 制作（canvas 裁剪 → base64）
- **调试能力**：目标主机选择（`hostAgentStatus`）、`start/stop debug`、日志轮询（2s，`timeOut>180` 自动停）、终端渲染
- **权限分流**：VIEW / MANAGE / MANAGE_PUBLIC 三档；公共插件（`bk_biz_id === 0`）需双管理权限；draft 草稿态点击名称进编辑向导
- **公共插件与草稿态**：`bk_biz_id === 0` 与 `status === 'draft'` 两个业务态的差异化分流（草稿行禁用「设置指标&维度」入口）

## 开发者调用入口（最小指引）

- **页面跳转**：`this.$router.push({ name: 'plugin-edit', params: { pluginId } })`——6 条路由的路径 / 参数 / 权限契约见 [C1 第一节](./C1-能力契约.md)
- **接口调用**：`import { listCollectorPlugin, retrieveCollectorPlugin, checkIdCollectorPlugin } from 'monitor-api/modules/model'`、`import { saveMetric, pluginRegister, releaseCollectorPlugin } from ...`——32 个方法（含返回结构与行为语义）见 [C1 第三节](./C1-能力契约.md)
- **核心组件**：`<metric-dimension-dialog :is-route-page="true" />`、`<plugin-indicator-dimension :plugin-id="id" :can-edit="true" />`、`<terminal-instance :consoles="logs" />`——props/events 契约见 [C1 第二节](./C1-能力契约.md)

## 能力边界

本模块**不做**：

- **采集配置实例化**：下发插件到目标主机、配置采集目标等在「数据采集」模块（本模块只提供跳转入口 `collect-config` / `collect-config-add`）
- **插件实际执行**：脚本/采集器运行在 bkmonitorbeat 采集器侧（本模块仅做「调试」的前端发起与日志展示）
- **平台权限判定**：交由 `authorityMixin` + `authority/checkAllowedByActionIds` 接口统一判定
- **采集器安装**：跳转「节点管理」
- **后端接口实现**：接口契约见 `implementation/05-接口.md`（调用点反推），后端实现不在本专家范围

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| 重命名权限常量后权限判断静默失效 | `authority.MANAGE_AUTH` 等取值依赖 authority-map 的**导出变量名**（key 即导出名） | 改权限常量名 = 改所有页面权限对象 key；重命名需全量回归权限分流 |
| 公共插件的管理入口未被禁止 | 只判断 `MANAGE_AUTH`——公共插件（`bk_biz_id === 0`）还需 `MANAGE_PUBLIC_AUTH` 同时具备 | 用 `getManageAuth(row)` 判定，勿自行组合单条件（PM 提示：只判断前者会漏禁止） |
| 「保存」后插件/指标没生效 | 步骤2 的「保存」仅置 `saveData.from='save'` 并前进，**真正发布在步骤3 `activated` 中的 `releasePlugin`**；只调 `saveMetric` 不调 `release` 则仅落草稿 | 排查「保存不生效」顺链路看 `step-set-done.vue` 的 `releasePlugin`；`saveMetric` 返回 `token` 时必须补 `releaseCollectorPlugin` |
| 提交的 metric_json 里混入前端态字段 | `descReValue/errValue/isCheck/isDel/isFirst/id/reValue/showInput` 等前端态字段未剔除 | 提交前按 `FRONT_END_FIELD_KEYS`（v2）或对应硬编码数组（v1）剔除；两处清单需同步维护 |
| 分组名校验口径与插件 ID 不一致 | `GROUP_NAME_REGX = /^[_|a-zA-Z][a-zA-Z0-9_]*$/` **允许 `\|`**，与 `judgeIsIllegal`（不允许）不同 | 按入口区分校验口径，不要互相复用 |
| 离开列表页后导入缓存丢失 | `SET_PLUGIN_CONFIG` 缓存仅在跳转目标为 `plugin-add`/`plugin-update` 时保留，其余跳转与刷新一律清空 | 导入冲突后需尽快在弹窗内完成分支选择；跨会话不依赖该缓存 |
| 注册轮询无法中止 | `pluginRegister` 轮询（1500ms）只有 `is_completed` 一个终止条件，组件销毁也不停止 | 后端任务异常不完成时弹窗会长期停留；改造时补超时/取消 |
| 页面离开后调试日志仍在轮询 | `deactivated` 只清 timer 不 `stopDebug`（依赖 `beforeDestroy` 兜底）；`timeOut>180` 触发 `stopDebug` 后轮询链仍会继续到收到终态 | 改动调试链路时留意清理边界；排查「页面关了还在请求」看 `clearTimer` |
| 反复进入向导后事件叠加 | `plugin-instance.vue` 的 `beforeDestroy` 中 `resetscroll` 误用 `$bus.$on`（其余为 `$off`） | 改动该文件时修正为 `$off`；`$bus` 为全局总线，`next/forward` 等通用事件名存在跨模块冲突风险 |
| 改了「指标维度」逻辑但页面无变化 | `plugin-setmetric` 是**路由名**，现指向 `components/metric-dimension-page.tsx`（v1）；同名文件 `plugin-setmetric.vue` 与旧版 `metric-dimension-dialog.vue`（`set-steps/metric-dimension/` 下）已无引用链 | 维护前先确认路径：路由页 = `components/metric-dimension-dialog.tsx`，详情 tab = `components/indicator-dimension/`；勿改死代码分支 |
| 两阶段提交半程失败留下中间态 | `saveMetric`/`pluginRegister` 成功而 `releaseCollectorPlugin` 失败时无回滚，后端处于「新版本已生成、未发布」 | 前端仅 toast 失败；向导编辑场景 `simRelease('success')` 直接展示成功属既有兜底（“修改不影响采集”时不真正发布），理解后再决定是否依赖 |
| 快速切换 tab/排序/分页出现旧数据覆盖 | 列表只有「清空搜索」有 `CancelToken` 取消，其余并发请求无时序保护 | tab/排序/分页快速操作时留意；改造时补请求序号或取消 |
| 指标数量被拦截 | 上限：普通插件 5000 条（`MAX_NUM_METRIC_DIM`），SNMP 500 条（`MAX_NUM_METRIC_DIM_SNMP`） | 超限时 `isAllowAddItem` 拒绝新增；大数据量下 `canSave` 的三重唯一性扫描是 CPU 热点 |
| 步骤2 文案「数据抓取限时 600 秒」与实际不符 | 实际自动停止由 `host.timeOut > 180` 触发（模板文案为硬编码） | 以实际行为为准，勿按文案推断超时 |
| 公共插件「关联配置 / 删除 / 编辑向导」三处口径不一致 | 公共插件（`bk_biz_id=0`）被**其它业务**使用时：① 列表的 `related_conf_count`/`delete_allowed` 按**本业务**关联数计算（`plugin/views.py:280-283`、`:311-313`）→ 显示 `--`、删除按钮可用；② 删除接口按**全业务** `collecting_config_total` 校验（`plugin/views.py:444`、`models/plugin.py:110-111`、`:954-957`）→ 点击后被拒；③ 详情接口（编辑向导回填）的 `related_conf_count` 也是**全业务**口径（`models/plugin.py:279`、`:964-968`）→ 向导锁分类标签（`step-set-plugin.vue:1201-1202`）并提示「去更新插件」（`step-set-done.vue:175-187`） | 公共插件的跨业务使用在列表不可见、但在删除/向导按全量判定——排查「删除失败 / 分类改不了」时先查全业务关联；改造时统一三处口径（2026-10-14 增量补充） |
