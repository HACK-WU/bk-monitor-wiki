# 能力契约：插件管理专家

> 契约快照生成于 2026-10-13（commit ff89f63ff4）。
> 若使用中发现行为与契约不符，可能代码已变更——expert-lookup 会自动增量修正，或用 expert-team 全量重建。
>
> **覆盖范围**：本专家契约覆盖前端功能域的三类公开能力——① 页面路由（对用户）、② 核心组件与编辑器（对开发者）、③ 请求层方法（对后端）。步骤组件内部方法与逐实现细节见 `implementation/`。

## 一、页面路由契约

6 条路由均注册于 `router/integrated/plugin-manager.ts`（`applyGuidePage(routes, ['plugin-add'])` 包装），`meta.navId` 统一为 `plugin-manager`，权限见第四节。

### plugin-manager —— 插件列表

- **用途**：插件管理主入口（tab 分类 / 搜索 / 排序 / 标签筛选 / 分页 / 删除 / 导入导出 / 官方标记）。
- **参数**：无 props；入口包括菜单（集成 → 插件 → 指标插件）、全局搜索、引导页；从采集侧跳入的目标是 `plugin-add`/`plugin-edit` 而非本路由。
- **meta**：`title=插件管理`、`noNavBar: true`、`authority.page=[VIEW_AUTH]`、`route.parent='integrated'`。
- **异常**：列表请求失败置空态 `'500'`；清空搜索时取消 pending 请求（`CancelToken`）；tab/排序/分页切换无取消保护（已知坑）。
- **约束**：`beforeRouteLeave` 仅在目标为 `plugin-update`/`plugin-add` 时保留导入缓存（`SET_PLUGIN_CONFIG`），其余跳转清空。
- **使用示例**：
  ```js
  // 菜单进入
  this.$router.push({ name: 'plugin-manager' });
  // 列表页「新建/导入」
  this.$router.push({ name: 'plugin-add', params: { pluginType: 'Script' } });
  ```
- 契约来源：`plugin-manager.vue`（`PluginManager`）

### plugin-add / plugin-edit / plugin-update —— 三步向导

- **用途**：插件新建（`add`）/ 编辑（`edit`）/ 升级（`update`），共用 `plugin-instance.vue` 容器（三步：定义插件 → 插件调试 → 完成发布）。
- **参数**（经 `$route.params` 读取，这三条路由未声明 `props: true`）：`edit` 需 `pluginId`；`add` 可带 `objectId`（预设分类，采集配置跳入时）；`update` 需 `pluginData`（来自导入冲突弹窗）。三者均可带 `pluginData` 与 `isImportPlugin`（导入后建新）。
- **meta**：`authority.page=[MANAGE_AUTH]`；`plugin-add` 被 `applyGuidePage` **排除**（不注入引导 beforeEnter），其余两条被注入（含 `meta.noChangeLoading`）。
- **行为语义**：`created` 按路由名推导 `type`（`create`/`edit`/`import`）；`beforeRouteEnter` 缓存 `fromRouteName`（步骤3 `close()` 决定回跳采集新增页或插件列表）；`beforeRouteLeave` 在「目标非 `plugin-add`/`plugin-edit` 且 `left.step < 2`」时弹「是否放弃本次操作？」确认。
- **异常**：步骤1 注册失败停在当前步（`registerDialog` 展示失败原因）；步骤2 调试失败展示日志。
- **约束**：`keep-alive` 缓存步骤组件；缓存清理在容器 `beforeDestroy` 与列表页 `beforeRouteLeave` 双端执行。
- **使用示例**：
  ```js
  // 编辑
  this.$router.push({ name: 'plugin-edit', params: { pluginId: row.plugin_id } });
  // 导入冲突 → 升级
  this.$router.push({ name: 'plugin-update', params: { pluginData: conflictData } });
  ```
- 契约来源：`plugin-instance.vue`（`PluginInstance`）

### plugin-detail —— 插件详情

- **用途**：基本信息 / 上传内容（脚本 monaco 预览）/ 定义参数（历史记录）/ 描述 + 「指标维度」tab。
- **参数**（`props: true`）：`pluginId`（必填，传 `plugin-info.vue` 的 `pluginId` prop）。
- **meta**：`title=插件详情`、`navClass='plugin-detail-nav'`、`noNavBar: true`、`authority.page=[VIEW_AUTH]`。
- **异常**：详情请求失败走加载态/空态；指标维度 tab 的加载由 `PluginIndicatorDimension` 自行管理。
- **约束**：详情页「编辑插件」按钮受 `PLUGIN_MANAGE_AUTH`（复用本模块 `MANAGE_AUTH`）守卫。
- **使用示例**：
  ```js
  this.$router.push({ name: 'plugin-detail', params: { pluginId: 'bk_monitor_cpu' } });
  ```
- 契约来源：`plugin-info/plugin-info.vue`（`PluginDetail`）

### plugin-setmetric —— 设置指标&维度

- **用途**：指标与维度的独立编辑页（`metric-dimension-dialog.tsx` 的 `isRoutePage=true` 全页形态）。
- **参数**：`pluginId`（从路由 params 读取）。
- **meta**：`title=设置指标&维度`、`needBack: false`、`noNavBar: false`、`authority.page=[MANAGE_AUTH]`。
- **行为语义**：保存 = `saveMetric`（必要时返回 token）→ `releaseCollectorPlugin` 两阶段提交；成功 `$router.back()`。
- **约束**：列表页入口仅对 `status === 'normal'` 且非官方插件开放（`handleShowMeticr`）。
- **使用示例**：
  ```js
  this.$router.push({ name: 'plugin-setmetric', params: { pluginId: row.plugin_id } });
  ```
- 契约来源：`components/metric-dimension-page.tsx`（`MetricDimensionPage`）

> **通用约束（6 条路由共同）**：`applyGuidePage` 会为除 `plugin-add`（排除名单）外的路由注入「引导数据预加载」`beforeEnter` 并覆盖同名自定义守卫（当前 6 条均无自定义 `beforeEnter`，暂无实际覆盖；新增自定义守卫时务必确认）。组件级守卫（`beforeRouteEnter`/`beforeRouteLeave`）不受影响。

## 三、请求层契约（32 个方法）

`collector_plugin` 系列 20 个（`monitor-api/modules/model.js`）+ `plugin.js` 8 个 + `commons`/`strategies` 4 个。统一由 `monitor-api/base.ts` 的 `request` 处理业务上下文注入 / 响应裁剪 / 错误提示 / FormData 组装（body 含 `File` 自动转 FormData）。

### （1）插件 CRUD 与列表

#### listCollectorPlugin —— 列表主接口（GET `rest/v2/collector_plugin/`）

- **用途**：插件列表（分页/搜索/标签/排序），同时返回各类型计数供 tab 角标。
- **参数**：`{ search_key, plugin_type, page, page_size, order, labels }`——`plugin_type` 空串=全部；`order` 默认 `-update_time`，表头排序（`plugin_id`/`update_time`）会改写；`labels` 为逗号拼接标签 id。
- **返回**：`{ count: { [插件类型]: 数量 }, list: [插件行] }`；行字段含 `plugin_id`、`plugin_display_name`、`plugin_type`、`logo`、`status`（`normal`/`draft`）、`is_official`、`bk_biz_id`、`related_conf_count`、`export_allowed`/`delete_allowed`/`edit_allowed` 等。
- **业务口径**（2026-10-14 增量补充）：注入 `bk_biz_id`（当前业务）后，后端只返回 `bk_biz_id ∈ [0, 当前业务]`——公共插件 + 本业务插件，**不含其它业务插件**（插件 ID 租户内唯一，`models/plugin.py:77-78`；`plugin/views.py:194-197`）；`related_conf_count`/`delete_allowed` 均为**本业务**关联数口径（`plugin/views.py:280-283`、`:311-313`），注意与删除接口的全业务校验口径不同（见 C0 已知问题）。无 `bk_biz_id` 时后端不加业务过滤、仅校验 `MANAGE_PUBLIC_PLUGIN`（`plugin/views.py:196-197`），全租户插件可见。
- **异常**：清空搜索时传 `{ cancelToken }` 取消 pending；失败置空态 `'500'`。
- **使用示例**（真实用法，来源 `getPluginListData`）：
  ```js
  const data = await listCollectorPlugin(
    { search_key, plugin_type, page: 1, page_size: 20, order: '-update_time', labels },
    { cancelToken: new CancelToken(c => (this.cancelListRequest = c)) },
  );
  this.table.data = data.list;
  ```

#### retrieveCollectorPlugin（GET `rest/v2/collector_plugin/{pk}/`）

- **用途**：插件详情（pk = `plugin_id`）；被详情页、步骤1 回填、指标编辑器（v1/v2）共同消费。
- **返回**：`plugin_id, plugin_display_name, plugin_type, description_md, config_version, info_version, metric_json, collector_json, config_json, status, signature, logo(base64), related_conf_count, is_split_measurement, enable_field_blacklist, edit_allowed ...`（完整字段见 `implementation/05-接口.md` 契约示例 2）。
- **行为语义**：`collector_json` 按插件类型形态不同（Script 按系统存 base64 脚本；DataDog/JMX 存 yaml + check_name；Exporter 存文件描述；SNMP 存版本/文件名）。

#### checkIdCollectorPlugin（GET `rest/v2/collector_plugin/check_id/`）

- **用途**：校验插件 ID 是否可用（步骤1 失焦校验）。
- **参数**：`{ plugin_id }`。
- **返回**：`res.result`（true=可用）、`res.message`（错误文案）——调用点传 `{ needRes: true, needMessage: false, needTraceId: false }` 自行消费。
- **使用示例**：`const res = await checkIdCollectorPlugin({ plugin_id }, { needRes: true, needMessage: false });`

#### createCollectorPlugin / editCollectorPlugin（POST `rest/v2/collector_plugin/` / `{pk}/edit/`）

- **用途**：新建 / 编辑插件（步骤1 提交；编辑还用于列表行内改标签）。
- **参数**（关键）：`plugin_id`（新建）、`plugin_display_name`、`plugin_type`、`label`、`bk_biz_id`、`config_version`/`info_version`、`collector_json`、`config_json`、`description_md`、`is_support_remote`、`is_split_measurement`、`enable_field_blacklist`；升级/导入场景追加 `import_plugin_config = { collector_json, config_json, is_support_remote }`（与 `import_plugin_metric_json`）。
- **返回**：`config_version / info_version / need_debug`（供后续注册/调试判断）。

#### deleteCollectorPlugin（POST `rest/v2/collector_plugin/delete/`）

- **用途**：批量删除插件。
- **参数**：`{ plugin_ids: [] }`——**数组**（即使单条）。
- **使用示例**：`await deleteCollectorPlugin({ plugin_ids: ids });`

### （2）导入导出与发布

#### importPluginCollectorPlugin（POST `rest/v2/collector_plugin/import_plugin/`）

- **用途**：导入插件包（`.gz/.tgz`）。
- **参数**：`{ file_data: File }`（请求层自动转 FormData）。
- **返回**：`{ config_version, info_version, is_official, is_safety, duplicate_type, conflict_detail, conflict_ids, conflict_title, plugin_id, license ... }`——`conflict_ids` 1~5 见 C5 决策 1。
- **行为语义**：无冲突且（官方或安全）→ 可直接 `saveAndReleasePlugin(data)`（`bk_biz_id` 官方取 0）；冲突 → `SET_PLUGIN_CONFIG(data)` 缓存后进入弹窗分支（更新/新建/更新至现有）。

#### exportPluginCollectorPlugin（GET `rest/v2/collector_plugin/{pk}/export_plugin/`）

- **用途**：导出插件包。
- **返回**：`{ download_url }` → `downFile(url)`；无 url 提示「导出失败」。

#### releaseCollectorPlugin —— 发布（POST `rest/v2/collector_plugin/{pk}/release/`）

- **用途**：两阶段提交的第二阶段——把已生成的版本正式发布。
- **参数**：`{ config_version, info_version, token }`（`token` 来自 `saveMetric` 响应或 `pluginRegister` 轮询的 `data.token`）。
- **行为语义**：**只有 release 成功，插件/指标变更才真正生效**；失败 `catch(() => false)` 静默（向导由步骤3 展示错误）。
- **使用示例**（来源：`step-set-done.vue` 的 `releasePlugin` / `metric-dimension-dialog.tsx` 的 `handleSave`，变量取自各自调用点局部作用域）：
  ```js
  await releaseCollectorPlugin(plugin_id, { config_version, info_version, token });
  ```

#### saveAndReleasePlugin（POST `rest/v2/save_and_release_plugin/`）

- **用途**：保存并直接发布（一步完成两阶段）——导入官方/安全插件、冲突「更新至现有插件」场景。
- **参数**：导入响应体（含 `plugin_id`、`is_official` 时 `bk_biz_id: 0`）。

### （3）注册与调试（异步）

#### pluginRegister —— 注册插件（POST `rest/v2/register_plugin/`）

- **用途**：插件注册（异步任务，生成插件包）；步骤1 提交后的注册阶段。
- **参数**：`{ plugin_id, config_version, info_version }`，config 传 `{ isAsync: true }`（请求层附加 `X-Async-Task: true`）。
- **行为语义**：返回的异步任务描述对象整体作为参数传给 `queryAsyncTaskResult` **轮询（1500ms）**，直到 `is_completed`；成功后取 `data.token` 写入 `pluginData.token`（供发布）；失败以 `state/message` 提示。**不可中断、无超时**（已知坑）。
- **使用示例**（真实用法，来源 step-set-plugin.vue 的注册流）：
  ```js
  const task = await pluginRegister({ plugin_id, config_version, info_version }, { isAsync: true });
  const poll = () => queryAsyncTaskResult(task).then(res => {
    if (!res.is_completed) return setTimeout(poll, 1500);
    if (res.state === 'SUCCESS') return res.data.token;   // 供 releaseCollectorPlugin
    throw new Error(res.message);
  });
  ```

#### startDebugCollectorPlugin / stopDebugCollectorPlugin / fetchDebugLogCollectorPlugin（调试三件套）

| 方法 | 路径 | 语义 | 行为语义 |
|------|------|------|----------|
| startDebugCollectorPlugin | POST `{pk}/start_debug/` | 启动调试（返回 `task_id`） | 每主机并发；重调试先 `stopDebug` 清 taskId；`{ cancelToken }` 可取消 |

### （4）指标与维度

#### saveMetric —— 保存指标&维度（POST `rest/v2/metric_plugin/save/`）

- **用途**：保存 `metric_json`（两阶段提交第一阶段）。
- **参数**（关键）：
  | 参数名 | 行为语义 |
  |--------|----------|
  | `plugin_id` / `plugin_type` / `config_version` / `info_version` | 插件标识与版本 |
  | `metric_json` | 分组数组（`table_name/table_desc/rule_list/fields`）；**提交前必须剔除前端态字段**（`FRONT_END_FIELD_KEYS`：`descReValue/errValue/isCheck/isDel/isFirst/id/reValue/showInput` 等）；`diff` 类型转为 `{ type: 'double', is_diff_metric: true }` |
  | `need_upgrade` | 路由页/非 token 场景为 `true`（触发版本递增） |
  | `enable_field_blacklist` | 自动采集新增指标开关 |
- **返回**：`{ token?, config_version, info_version }`——**含 `token` 时必须紧跟 `releaseCollectorPlugin`（整个响应体作为参数）**，否则只落草稿。
- **异常**：调用点传 `{ needMessage: false }` 手动 `$bkMessage` 展示。
- **使用示例**（真实用法，来源 metric-dimension-dialog.tsx 的 handleSave）：
  ```js
  const data = await saveMetric(params, { needMessage: false });
  if (data.token) await releaseCollectorPlugin(plugin_id, data);   // 整个响应体回传
  ```

#### getReservedWord（GET `rest/v2/get_reserved_word/`）

- **用途**：获取保留关键字（指标/维度命名校验）。
- **返回**：`RT_RESERVED_WORD_EXACT`（缺省回退整体）；store 缓存 `reservedWords`。

## 四、权限与常量契约

### 权限常量（`authority-map.ts`）

| 常量 | action id | 用途 |
|------|-----------|------|
| `MANAGE_AUTH` | `manage_plugin_v2` | 插件管理：新建/编辑/升级/导入导出/删除/设置指标维度（路由 `plugin/add\|edit\|update\|setmetric` + 按钮级） |
| `VIEW_AUTH` | `view_plugin_v2` | 插件查看：列表与详情页访问 |
| `MANAGE_PUBLIC_AUTH` | `manage_public_plugin` | 公共插件管理——仅针对公共插件（`bk_biz_id === 0`），**与 `MANAGE_AUTH` 同时满足**才可管理 |
| `COLLECTION_VIEW_AUTH` | `view_collection_v2` | 复用采集配置查看权限（常量保留；`step-set-done.vue` 的 `getCollectionAuth` 当前无 UI 消费，属遗留） |
| `COLLECTION_MANAGE_AUTH` | `manage_collection_v2` | 复用采集配置管理权限（同上，待消费） |

- **生效方式**：路由 `meta.authority` → `authorityMixinCreate(pluginManageAuth)`（`created` 批量取权 + 结果缓存 + `@ProvideReactive` 下发）→ 按钮级 `v-authority` 指令 + `getManageAuth(row)` 分流。**key 即导出名**（重命名常量会改变权限对象 key，见 C0 已知坑）。
- **draft 分流**：点击名称——`status !== 'draft'` 或有权限 → 详情页；`draft` 且无管理权限 → 权限申请弹窗。`draft` 行禁用「设置指标&维度」。

### 校验工具（`utils.ts`）

- `judgeIsIllegal(value)`：`/^[_a-zA-Z][a-zA-Z0-9_]*$/`——插件 ID / 名称合法性。
- `metricNameTransFrom(value)`：非法字符转下划线并循环修正开头，用于指标名一键转换。
- 分组名正则（`indicator-dimension/types.ts`）：`GROUP_NAME_REGX = /^[_|a-zA-Z][a-zA-Z0-9_]*$/`（**允许 `|`**，与 `judgeIsIllegal` 不同）；默认分组 `GROUP_DEFAULT_NAME = 'group_default'`（不可编辑/删除）。
- 上限常量：`MAX_NUM_METRIC_DIM = 5000`（普通插件）、`MAX_NUM_METRIC_DIM_SNMP = 500`（SNMP 插件）。
