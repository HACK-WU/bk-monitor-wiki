## 决策清单

### 决策 1：接口契约-导入冲突五级分类与「更新插件」白名单

- **分类**：接口契约
- **动机**：避坑（无差别允许「更新插件」会直接覆盖类型冲突/远程配置冲突/内容一致的包 → 不可逆覆盖）
- **决策**：导入冲突按 `conflict_ids` 分五级——**1** 导入版本不大于当前版本、**2** 插件类型冲突、**3** 远程采集配置项冲突、**4** 插件已关联 N 个采集配置、**5** 导入插件与当前插件内容完全一致；出现 **2/3/5 时不展示「更新插件」入口**（`canIUpdatePlubin`），只能「创建插件」；「更新至现有插件」（官方 + 超级管理员）走 `saveAndReleasePlugin`。
- **背景约束**：冲突分级由后端 `import_plugin` 响应给出（前端不自行推断）；导入结果需缓存后由弹窗驱动分支，缓存仅在 `plugin-add`/`plugin-update` 路由间保留。
- **被否决方案**：无（未找到记录）
- **重新评估触发条件**：后端新增冲突类型或调整分级语义（届时同步 `canIUpdatePlubin` 白名单）
- **关联代码**：`canIUpdatePlubin` / `handleToEdit` @ `plugin-dialog-single.vue`；`handeFileSingel` / `handleSetUpdatePlugin` @ `plugin-manager.vue`
- **证据来源**：代码注释（`plugin-dialog-single.vue` 注释明写冲突五级语义）；`implementation/05-接口.md` 契约示例 5（conflict_ids 与按钮可用性）

### 决策 2：[推测] 架构设计-插件/指标发布走两阶段提交（token）

- **分类**：架构设计
- **动机**：避坑（保存即发布会让未调试/未确认的中间版本直接对外可见）
- **决策**：[推测] 保存阶段（`saveMetric` / `pluginRegister`）只生成新版本并返回 `token`；发布阶段（`releaseCollectorPlugin` 携带 `token + config_version + info_version`）显式执行——**只有 release 成功变更才生效**；`saveMetric` 无 `token` 时视为「仅保存」。
- **背景约束**：插件/指标的生成（打包、校验）与发布在后端是两个阶段；前端需要「先调试/确认、后发布」的时序；向导步骤2 的「保存」刻意只前进不发布，把发布收敛到步骤3。
- **被否决方案**：无（未找到记录）
- **重新评估触发条件**：后端提供原子化「保存即发布」接口，或现有两阶段语义变更
- **关联代码**：`saveMetric` @ `monitor-api/modules/plugin.js`；`releaseCollectorPlugin` @ `modules/model.js`；三处同构实现——`step-set-done.vue`（`releasePlugin`）、`metric-dimension-dialog.tsx`（`handleSave`）、`indicator-dimension/utils.ts`（`savePluginMetricJson`）
- **证据来源**：无直接证据，基于 `saveMetric` 返回 `{token?, config_version, info_version}`、release 消费 token、三处实现同构与 `need_upgrade` 语义推断

### 决策 3：[推测] 接口契约-公共插件双管理权限门禁

- **分类**：接口契约
- **动机**：避坑（公共插件 `bk_biz_id === 0` 被全平台共享，仅凭普通管理权限即可修改会产生跨业务影响）
- **决策**：[推测] 公共插件的管理入口要求 `MANAGE_AUTH`（`manage_plugin_v2`）与 `MANAGE_PUBLIC_AUTH`（`manage_public_plugin`）**同时具备**（`getManageAuth(row)` 对 `bk_biz_id === 0` 的双条件判定）；无权限时 `showAuthorityDetail` 聚合缺失的 actionIds（含 `MANAGE_PUBLIC_AUTH`）拉起权限申请。
- **背景约束**：`MANAGE_PUBLIC_AUTH` 是独立 action（非复用）；公共插件会出现在多个业务的采集配置视图中。
- **被否决方案**：无（未找到记录）
- **重新评估触发条件**：产品调整公共插件管理范围（如按业务授权）或权限模型重构
- **关联代码**：`getManageAuth` / `showAuthorityDetail` @ `plugin-manager.vue`；`MANAGE_PUBLIC_AUTH` @ `authority-map.ts`
- **证据来源**：无直接证据，基于 `getManageAuth` 对 `bk_biz_id === 0` 的双条件实现与独立权限常量的存在推断

### 决策 4：[推测] 兼容处理-指标 diff 类型提交降级为 double + is_diff_metric

- **分类**：兼容处理
- **动机**：兼容（后端指标类型体系不含独立 diff 存储类型）
- **决策**：[推测] 前端展示 `diff` 类型；**提交前转 `{ type: 'double', is_diff_metric: true }`**，详情回显时反向转换为 `diff`；`diff` 仅对 `Script / JMX / Exporter / Pushgateway` 开放（`getMetricTypeList` 白名单）。
- **背景约束**：`metric_json` 直接落后端（无中间转换层）；类型列表按插件类型差异化控制。
- **被否决方案**：无（未找到记录）
- **重新评估触发条件**：后端支持 diff 类型原生存储后可取消双向转换
- **关联代码**：`getMetricTypeList` @ `components/indicator-dimension/utils.ts`；`handleTableDataChange`（diff 归一）@ `components/metric-dimension-dialog.tsx`
- **证据来源**：无直接证据，基于提交前转换 + 回显反向转换 + typeList 白名单的结构推断
