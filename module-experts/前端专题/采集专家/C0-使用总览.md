> 契约快照生成于 2026-10-13（commit ff89f63ff4）。
> 若使用中发现行为与契约不符，可能代码已变更——expert-lookup 会自动增量修正，或用 expert-team 全量重建。

## 能力清单

采集配置前端（`monitor-pc/pages/collector-config/`）覆盖「数据采集」功能域的全生命周期管理：

- **采集配置列表**：分类 tab + 统计卡（本业务口径）+ 关键词搜索（`插件ID:`/`ID:` 前缀）+ 服务端分页 + 5s 状态轮询 + 行操作（查看/可视化/编辑/启停/克隆/删除/升级）
- **四步新建/编辑/克隆向导**：配置（插件/参数/变量）→ 选择目标（拓扑/主机/服务实例）→ 采集下发（保存 + 就绪等待 + 进度轮询 + 回滚）→ 完成（结果统计 + 跳可视化/策略）
- **采集详情**：独立页 5 Tab（配置信息/链路状态/指标维度/存储状态/采集状态）与列表侧滑详情（基本信息 + 采集目标），支持重命名
- **增删目标（3 步）**：目标选择（diff 视图）→ 增量下发（`operation: ADD_DEL`）→ 完成，可回滚
- **启停 / 升级 / 回滚（2 步）**：`toggle`（enable/disable）或 `upgrade`，任务就绪等待 + 10s 进度轮询 + 回滚
- **删除（4 步链路）**：停用（3s 停用进度轮询）→ 可选删关联策略 → 删配置；删除前展示精准/模糊关联策略
- **可视化视图**：以 `sceneId = collect_<id>` 复用 monitor-k8s 场景视图框架（`CommonPage`）展示采集数据源面板
- **执行详情**：单次操作的目标级执行明细（`10s` 轮询至收敛），支持重试/终止/查看日志
- **跨业务只读**：列表可见跨业务配置行，读入口（查看/可视化/状态）跳转配置所属业务，写操作全部拦截（#12736）

## 开发者调用入口（最小指引）

- **页面跳转**：`this.$router.push({ name: 'collect-config-detail', params: { id, title } })`——9 条路由的路径 / 参数 / 权限契约见 [C1 第一节](./C1-能力契约.md)
- **接口调用**：`import { collectConfigList, saveCollectConfig, isTaskReady } from 'monitor-api/modules/collecting'`——33 个方法（含返回结构与行为语义）见 [C1 第三节](./C1-能力契约.md)
- **数据层与复用组件**：`new TableStore(res.data, bizList)`、`new DetailRequest()`、`<config-deploy :all-data="…" :is-running="…" />`——契约见 [C1 第二节](./C1-能力契约.md)

## 能力边界

本模块**不做**：

- **数据下发与采集执行**：配置保存后的下发、采集执行发生在后端与采集器侧（bkmonitorbeat），前端只提交配置并轮询展示状态
- **插件本体管理**：插件的制作/调试/发布/指标维度设置在插件管理功能域（`pages/plugin-manager`，见插件管理专家）；本模块只做插件选择与版本校验（`checkPluginVersion`）
- **采集策略配置**：策略的创建/编辑在策略模块；本模块仅在删除采集任务时支持级联删除关联策略（`list_related_strategy` 查询 + `delete_strategy_config` 删除）
- **采集器安装**：跳转「节点管理」（`$store.getters.bkNodeManHost`）
- **K8s 采集**：容器采集在 `monitor-k8s` 独立功能域（本模块仅对腾讯云 K8s 插件有特判分支）
- **后端接口实现**：接口契约见 `implementation/05-接口.md`（调用点反推），后端实现不在本专家范围

## 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| tab 数字与真实值可能不一致 | 改列表统计相关代码时误用 `TableStore.tabData`（本地旧口径，无 UI 读取者） | 页面统计一律取 `fetchCollectConfigStat` + `getFilterTabList`（服务端口径）；`TableStore.tabData` 为遗留，勿新增消费方 |
| 删除配置后统计卡数字不刷新 | 删除弹层关闭只触发列表重拉（watch `delDialogShow`），不重拉统计 | 需要一致时手动补 `fetchCollectConfigStat`（PM 走查 N3，修复前勿依赖删除后统计实时） |
| 「失败」态配置既不入统计卡也筛不出 | 统计与筛选只取 `task_status=WARNING`（部分失败），`FAILED`（全部失败）被漏 | 排查"为什么统计没算"先看 task_status 取值；改口径需后端支持多值筛选（PM 走查 N1） |
| 已输入的搜索词被静默清空 | 切分类 tab 或点统计卡（`handleTabItemClick` / `handleTabNumClick` 显式置空） | 属现状行为；需要保留关键词时改造这两处（PM 走查 N4） |
| 排序只在当前页生效 | 本地排序（`handleSortChange`）作用于服务端返回的当前页数组，接口固定 `order: '-create_time'` | 跨页排序结论不可信；需全局排序时先推动接口支持（PM 走查 N5） |
| 路由 `beforeEnter` 参数校验不生效 | `collect-config-update` / `-operate-detail` / `-detail` / `-clone` 四条路由的自定义 `beforeEnter` 被 `applyGuidePage` 覆盖 | 依赖这些守卫做参数兜底前先看 `applyGuidePage` 的覆盖逻辑；新增路由守卫留意 excludes 名单 |
| `stop-start-host` 的就绪等待可能被跳过 | `taskReadyStatusPromise` 首行 `clearTimeout(timer)` 先于 `let timer` 声明（TDZ），异常被 `.catch(() => true)` 兜底为"已就绪" | 改动启停流程等待逻辑时先核实该行为（需运行时验证）；同类实现中「先声明后使用」的正确范例是 `target-table` 与 `collector-status-details` |
| 页面销毁后仍可能继续轮询 | `stop-start-host` 与 `collector-status-details` 的 `is_task_ready` 递归用局部定时器，`beforeDestroy` 未清理 | 新增轮询/复用这两处时补清理；排查"页面关了还在发请求"优先看这里 |
| 列表加载抛出 `typeMap` 相关错误 | `TableStore` 构造对 `type_list` 与 `config_list` 的类型一致性有硬依赖（`log`/`Built-In` 被排除） | 后端新增采集类型时必须同步返回 `type_list`；前端新增类型要同步 `defaultTabData` 与 `getFilterTabList` 的过滤 |
| 编辑带「待升级」标记的配置不直接进入 | 行带 `needUpdate` 时先弹「插件已变更，请先升级」提示 | 属预期行为；排查"为什么点编辑没反应"先看该提示 |
| 旧代码不能整目录删除 | `collector-view/` 主体无引用，但其 `variable-set.ts`（performance 模块）、`log-handle.ts` 类型（custom-escalation）、`status-tab-list.tsx` 的 `IStatusData`（performance）被跨模块复用 | 清理旧代码前先 grep 这三个文件；`pages/collector-upgrade/collector-upgrade.vue` 文件存在但全仓无引用（可安全评估删除） |
| 跨业务行点名称/可视化/状态会开新标签页 | 配置行的 `bizId` 与当前业务不一致（列表展示全局插件在其他业务的配置） | 属 #12736 约定行为：读跳所属业务、写操作隐藏；勿按"当前业务直接跳转"改动 |
| 列表异常行没有就地重试入口 | 失败/异常行只能进详情页或目标页再重试（`retry` / `batch_retry_detailed` 接口已就绪，未接入列表行） | 属能力缺口（PM 走查 N6）；需要时就地在行操作列接入既有接口 |
| 低优先级文案/渲染瑕疵 | 「更新记录」空操作人兜底 `'--'` 会把单引号一起渲染；搜索框占位为错别字「搜素」（i18n key 即错字，中文按 key 回退显示） | 属已知瑕疵（PM 走查 N7/N8）；修复改 `collector-config.vue` 模板与 i18n key（错别字项需同步英文词条） |

> 出处说明：`#12736` 等编号的含义与证据见 [C5-关键决策.md](./C5-关键决策.md)；「PM 走查 N1~N8 / Q4」的完整条目见 `.pm/collecting-config-list-review-20261013.md`（仓库工作区根目录）。
