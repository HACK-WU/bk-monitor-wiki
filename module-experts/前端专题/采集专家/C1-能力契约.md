# 能力契约：采集专家

> 契约快照生成于 2026-10-13（commit ff89f63ff4）。
> 若使用中发现行为与契约不符，可能代码已变更——expert-lookup 会自动增量修正，或用 expert-team 全量重建。
>
> **覆盖范围**：本专家契约覆盖前端功能域的三类公开能力——① 页面路由（对用户）、② 数据层类与核心复用组件（对开发者）、③ 请求层方法（对后端）。页面内部私有子组件与逐方法实现见 `implementation/`。

## 一、页面路由契约

9 条路由均注册于 `router/integrated/collector-config.ts`（`applyGuidePage` 包装），`meta.navId` 统一为 `collect-config`，权限分两级（见第四节）。

### collect-config —— 数据采集列表

- **用途**：采集配置的主入口页（分类 tab / 统计卡 / 搜索 / 分页 / 状态轮询 / 行操作）。
- **参数**：无 props；支持 `?id=<配置ID>` 直链（异步加载后自动打开对应详情；跨业务配置以 `location.replace` 跳所属业务）。
- **meta**：`title=数据采集`、`noNavBar: true`、`authority.page=[VIEW_AUTH]`。
- **返回**：无。
- **异常**：首轮列表加载失败 → 表格置 500 空态并停止轮询；统计失败 → 局部「数据获取异常 + 刷新」，不影响列表。
- **约束**：页面挂 keep-alive，`deactivated` 时停止 5s 轮询；离开后不再写数据。
- **使用示例**（真实用法：菜单进入；程序化跳转）：
  ```js
  this.$router.push({ name: 'collect-config' });
  // 带直链（列表加载完成后自动打开详情）
  window.open(`#/collect-config?id=${row.id}`, '_blank');
  ```
- 契约来源：`collector-config.vue`（`CollectorConfig`）

### collect-config-detail —— 采集详情（5 Tab）

- **用途**：配置信息 / 链路状态 / 指标维度 / 存储状态 / 采集状态 五 Tab 详情页。
- **参数**（`props: true`，取 `$route.params`）：`id`（配置 ID，必填）；`title`（可选，用于动态标题）。
- **meta**：`title=采集详情`、`needBack`、`authority.page=[VIEW_AUTH]`。
- **异常**：基础信息与目标两组请求互相隔离——目标失败不阻塞基础展示、可单独重试；切换配置时旧响应被丢弃。
- **约束**：Tab 切换写入 `query.tab`；采集状态 Tab 每 10s 轮询至收敛。
- **使用示例**：
  ```js
  // 列表页进入（跨业务配置走 handleConfigNavigate 自动换业务新标签页）
  this.$router.push({
    name: 'collect-config-detail',
    params: { id: row.id, title: row.name },
  });
  ```
- 契约来源：`collector-detail.tsx`（`CollectorDetail`）

### collect-config-add / collect-config-clone / collect-config-edit —— 四步向导

- **用途**：新建 / 克隆 / 编辑采集配置（同一容器组件，路由名区分模式）。
- **参数**（`props: true`）：`add` 无参数；`clone` 需 `id` + `pluginId`；`edit` 需 `id` + `pluginId`；三者均可带 `title`（动态标题）。
- **meta**：`authority.page=[MANAGE_AUTH]`；`add` 带 `noSpaceCheck: true`。
- **行为语义**（模式差异）：
  | 入口 | 初始化数据 | 保存影响 |
  |------|------------|----------|
  | `add` | 空表单；分类 tab 进入时携带 `pluginType`（Process 带 `objectId=host_process`） | 新建配置 |
  | `clone` | 按 `id/pluginId` 回填源配置，名称需重填 | 新建配置 |
  | `edit` | 列表经 Vuex `SET_ADD_DATA` 预置 + `collectConfigDetail` 拉取现状 | 更新配置；带 `needUpdate` 标记的配置先弹「插件已变更，请先升级」而非直接进入 |
- **异常**：步骤内保存失败停留在当前步；下发步失败可 `rollback` 回滚。
- **约束**：编辑态锁死采集方式与插件；`beforeRouteLeave` 清理 Vuex `infoData`。
- **使用示例**：
  ```js
  // 列表页新建（带分类预选）
  this.$router.push({ name: 'collect-config-add', params: { pluginType: item.id } });
  // 编辑
  this.$store.commit('collector-config/SET_ADD_DATA', row);
  this.$router.push({ name: 'collect-config-edit', params: { id: row.id, pluginId: row.pluginId } });
  ```
- 契约来源：`collector-add.vue`（`CollectorAdd`）、`config-set/config-select/config-delivery/config-done` 子步骤

### collect-config-node —— 增删目标（3 步）

- **用途**：对已有配置增删采集目标（增量下发 `operation: ADD_DEL`）。
- **参数**：`id`（必填）；可选 `title`。
- **meta**：`title=增删目标`、`needCopyLink: false`、`authority.page=[MANAGE_AUTH]`。
- **预期结果**：提交后返回 `diff_node`（added/updated/removed/unchanged），第二步展示下发进度，可回滚。
- **使用示例**：
  ```js
  this.$router.push({ name: 'collect-config-node', params: { id: row.id, title: row.name } });
  ```
- 契约来源：`add-del.vue`（`AddAndDel`）、`bk-host.vue`、`target-table.vue`

### collect-config-update —— 启停 / 升级流程（2 步）

- **用途**：启用 / 停用 / 升级插件的下发流程。
- **参数**（`props: true`）：`data`（列表行对象，含 `id` 等）；`stopStart.type ∈ {START/STOP/UPGRADE}`；升级场景另带升级参数。
- **meta**：`title=启用采集配置`、`noNavBar: true`、`authority.page=[MANAGE_AUTH]`。
- **异常**：操作失败可 `rollback`（回滚下发）；等待期间按钮锁定至实例全部终态。
- **约束**：源码中的 `beforeEnter`（缺 `params.data` 时重定向列表）**被 `applyGuidePage` 覆盖不生效**——依赖该守卫兜底时需自行处理缺参场景。
- **使用示例**：
  ```js
  // 列表行「启用/停用」
  this.$router.push({
    name: 'collect-config-update',
    params: { data: row, stopStart: { type: row.status === 'STARTED' ? 'STOP' : 'START' } },
  });
  ```
- 契约来源：`stop-start-view.vue`（`StopStartView`）、`stop-start-host.vue`（`StopStartHost`）

### collect-config-operate-detail —— 执行详情

- **用途**：单次下发操作的目标级执行明细（重试/终止/查看日志）。
- **参数**：`id`（必填）；`title` 可选（默认「执行详情」）。
- **meta**：`authority.page=[VIEW_AUTH]`。
- **异常**：10s 轮询至全部目标收敛；过期响应按 `pollingCount` 丢弃。
- **使用示例**：
  ```js
  this.$router.push({ name: 'collect-config-operate-detail', params: { id: row.id } });
  ```
- 契约来源：`collector-operate-detail.tsx`（`CollectorOperateDetail`）

### collect-config-view —— 可视化

- **用途**：以 `sceneId = collect_<id>` 打开采集数据源场景视图（复用 monitor-k8s `CommonPage`）。
- **参数**：`id`（必填）；跨业务场景从 `route.query.customQuery` 读取 `bizId`。
- **meta**：`title=可视化`、`customContent: true`、`noNavBar: true`、`authority.page=[VIEW_AUTH]`。
- **约束**：不走 `monitor-api/modules/collecting.js`（数据由场景视图框架加载）；页内「数据源管理」跳 `collect-config-edit`。
- **使用示例**：
  ```js

  ```
- 契约来源：`collector-view-detail/collector-view.tsx`（`CollectorView`）

## 二、数据层与核心复用组件契约

### TableStore（列表数据格式化层）

契约来源：`TableStore`（`store.ts`）

#### constructor(originData, bizList)

- **用途**：把 `config_list` 接口响应转换为表格行模型，并预构造 tab 统计。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | originData | object | 是 | **完整响应体**（同时含 `config_list` / `total` / `type_list` 三个键——构造器直接读 `originData.config_list` 与 `originData.type_list`）；`config_list` 为空数组时得到空表格；`type_list` 决定 tab 结构 |
  | bizList | array | 是 | 业务列表（`{ id, text }`），用于把 `bk_biz_id` 翻译为业务名；未命中业务显示空串 |
- **返回**：无（构造实例）。
- **异常**：`config_list` 项的 `collect_type` 不在 `type_list` 中时，构造期取 `typeMap[collect_type].name` 抛错（**硬依赖两者一致**）。
- **约束**：每次列表请求后**重建实例**（非增量更新）；行模型含 `statusName`/`doingStatus`/`needUpdate`/`updateParams`（升级链路复用）/`updateTime`（时区化）等格式化字段。
- **使用示例**（真实用法；注意两点：`needRes: true` 时业务体在 `res.data`；构造器要的是**完整响应体**而非 `config_list` 数组）：
  ```js
  // collector-config.vue: getCollectionConfigList（简化自真实调用）
  const res = await collectConfigList(
    { refresh_status: status, order: '-create_time', search: this.getSearchOfParams, page, limit },
    { needRes: true, needMessage: false, signal: controller.signal },
  );
  const data = res.data || { config_list: [], total: 0, type_list: [] };
  const tableInstance = new TableStore(data, this.bizList);
  this.table.data = tableInstance.getTableAllData();
  ```
- **行为语义（关键映射）**：`status` 与 `task_status` 是两组独立状态——行显示名取 `task_status`（`SUCCESS/WARNING/FAILED/TBC`），`doingStatus` 由 `status` 的过渡态（`STARTING/STOPPING/DEPLOYING/AUTO_DEPLOYING/PREPARING`）或 `TBC` 决定。

#### getTableAllData()

- **用途**：取全量行数据（含本地排序）。
- **参数**：无。
- **返回**：`array` — 行模型数组；已按 `sortProp/sortOrder` 排序（如有）。
- **约束**：本地排序**仅作用于当前页数据**（服务端分页）；跨页排序结果不成立。

#### getTableData(type, typeLabel)（遗留）

- **用途**：按分类 / 状态标签 / 关键词做本地过滤 + 本地分页切片。
- **状态**：**遗留方法**——主流程已改为服务端分页/筛选，其调用点仅存在于不可达的旧删除路径。新代码请勿使用。

### DetailRequest（详情请求竞态守卫类）

契约来源：`DetailRequest`（`collector-detail/detail-request.ts`）

#### run(fetch, apply)

- **用途**：发起一次「可被后续请求取代」的详情请求；只应用最新一次的结果。
- **参数**：
  | 参数名 | 类型 | 必填 | 含义与行为语义 |
  |--------|------|------|----------------|
  | fetch | `(signal: AbortSignal) => Promise<T>` | 是 | 真正发起请求的函数——接收取消信号，由实例在 `run` 时注入（请求层通常把 signal 透传给 `request` 的 config） |
  | apply | `(data: T) => void` | 是 | 结果回调；仅当该次请求仍是"最新"时被调用（过期响应被静默丢弃） |
- **返回**：`Promise<boolean>` — 本次请求是否被应用（被取消/过期返回 false）。
- **异常**：请求失败不抛出（捕获后置 error 态），`abort` 不视为错误；调用方从应用层错误状态渲染重试。
- **约束**：同一实例串行语义——`run` 会先取消上一在途请求；组件销毁必须调 `cancel()`。
- **使用示例**（真实用法，取自 `collector-detail.tsx` 的 `getDetails`）：
  ```ts
  // collector-detail.tsx
  requests = { detail: new DetailRequest(), targets: new DetailRequest() /* ... */ };

  getDetails() {
    return this.requests.detail.run(
      signal => frontendCollectConfigDetail({ id: this.collectId, with_target_info: false }, { signal, needMessage: false }),
      data => { this.detailData = data; },
    );
  }
  ```

#### cancel()

- **用途**：取消在途请求并复位 loading。
- **返回**：无。
- **约束**：组件 `beforeDestroy` / 切换配置时必须调用。

## 三、请求层契约（monitor-api/modules/collecting.js）

33 个方法统一形如 `request('<METHOD>', 'rest/v2/collecting_config/<path>/')`，由 `monitor-api/base.ts` 的 `request` 统一处理业务上下文注入 / 响应裁剪 / 错误提示 / 取消。**调用点普遍显式传 `{ needMessage: false }` 自行接管错误展示**。

### （1）列表与详情

#### collectConfigList —— 列表主接口（POST `config_list/`）

- **用途**：采集配置列表（搜索/分页/排序/状态刷新），详情页也用它按 `search.id` 取单条。
- **参数**：
  | 参数名 | 类型 | 行为语义 |
  |--------|------|----------|
  | bk_biz_id | number | 业务 ID（`request` 层也会自动注入） |
  | refresh_status | boolean | `true` 强制后端刷新运行状态（轮询专用）；`false` 用缓存 |
  | order | string | 固定 `-create_time` |
  | search | object | 筛选条件对象：`collect_type` / `status` / `task_status` / `need_upgrade` / `plugin_id` / `id` / `fuzzy` |
  | page / limit | number | 服务端分页 |
- **返回**：`{ config_list: [], total: 0, type_list: [] }`（`needRes: true` 取 `res.data`）——`type_list[]` 元素为 `{ id, name, nums: { STARTED, STOPPED, WARNING, need_upgrade } }`，前端过滤 `log` / `Built-In` 两项。
- **异常**：失败时无弹窗（`needMessage: false`）；首轮失败表格置 500 空态、轮询失败静默保留旧数据。
- **约束**：轮询调用需带 `refresh_status: true`；搜索/分页/筛选均下推服务端。
- **使用示例**（真实用法）：
  ```js
  const res = await collectConfigList(
    { refresh_status: true, order: '-create_time', search: this.getSearchOfParams, page, limit },
    { needRes: true, needMessage: false, signal: controller.signal },
  );
  ```

#### collectConfigDetail（GET `config_detail/`）

- **用途**：单个配置明细（编辑/增删目标页回填）。
- **参数**：`{ id }`。
- **返回**：配置详情对象（供 `getConfigParams` 拍平为表单模型）。
- **使用示例**：`const detail = await collectConfigDetail({ id: this.configId });`

#### frontendCollectConfigDetail（GET `frontend_config_detail/`）

- **用途**：前端友好的配置详情（侧滑详情 / 详情页「配置信息」Tab）。
- **参数**：`{ id, with_target_info?: boolean }`；`with_target_info=false` 时跳过目标解析（详情隔离决策，见 C5 决策 3）。
- **返回**：`{ basic_info, extend_info: { log, process }, metric_list, runtime_params }`。
- **使用示例**：
  ```js
  frontendCollectConfigDetail({ id, with_target_info: false }, { needMessage: false })
  ```

#### frontendCollectConfigTargetInfo（GET `frontend_target_info/`）

- **用途**：采集目标信息（与上述接口成对使用，可独立重试）。
- **返回**：`{ target_node_type, table_data: [] }`；`target_node_type ∈ {TOPO, SET_TEMPLATE, SERVICE_TEMPLATE, DYNAMIC_GROUP, INSTANCE}`。
- **使用示例**：
  ```js
  const { table_data, target_node_type } = await frontendCollectConfigTargetInfo({ id }, { needMessage: false });
  ```

### （2）保存与执行控制

#### saveCollectConfig —— 保存配置（POST `save/`）

- **用途**：新建 / 编辑 / 增删目标共用保存接口；保存即触发下发（无独立部署按钮）。
- **参数**：`{ name, bk_biz_id, collect_type, plugin_id, params: { collector, plugin }, target_object_type, target_node_type, target_nodes, remote_collecting_host?, label?, id?, operation? }`；`operation: 'ADD_DEL'` 为增删目标增量模式；编辑态带 `id`。
- **行为语义**：`params.collector`（周期/超时等采集器参数）与 `params.plugin`（插件参数）分流；password 类参数仅在用户本次修改后提交；增删目标模式提交前剔除 password 类字段。
- **异常**：取消（`cancelToken`）用于 K8S 分支中止；失败停留在当前步。
- **使用示例**（真实用法）：
  ```js
  // 增删目标增量保存
  await saveCollectConfig({ id, ...newParams, operation: 'ADD_DEL' }, { needMessage: false });
  ```

#### toggleCollectConfigStatus（POST `toggle/`）

- **用途**：启用 / 停用配置。
- **参数**：`{ id, action: 'enable' | 'disable' }`——行为语义：`disable` 为异步停用（需配合 3s/10s 轮询观察进度）；列表删除链路第一步即调用它。
- **使用示例**：`await toggleCollectConfigStatus({ id, action: 'disable' });`

#### upgradeCollectPlugin（POST `upgrade/`）

- **用途**：插件版本升级（与启停共用流程壳，请求体不同）。
- **参数**：`{ id, params: { collector, plugin } }`（来自升级弹窗回传的运行参数）。

#### retryTargetNodes / batchRetryConfig / batchRetry / revokeTargetNodes / batchRevokeTargetNodes

| 方法 | 路径 | 语义 | 行为语义 |
|------|------|------|----------|
| retryTargetNodes | `retry/` | 单目标失败重试 | `{ id, instance_id }`；本地先置 PENDING，失败回滚 |
| batchRetryConfig | `batch_retry/` | 配置维度批量重试 | 全量 FAILED → PENDING 乐观更新 |
| batchRetry | `batch_retry_detailed/` | 明细维度批量重试 | 状态明细表使用；等待就绪后恢复轮询 |
| revokeTargetNodes | `revoke/` | 撤销单目标下发 | `{ id, instance_ids }` |
| batchRevokeTargetNodes | `batch_revoke/` | 批量终止 | 本地置 FAILED 并刷新 |

#### rollbackDeploymentConfig（POST `rollback/`）

- **用途**：回滚本次下发（编辑/启停/增删目标流程均提供）。
- **参数**：`{ id }`；返回后需重新拉目标状态。**约束**：二次确认（`$bkInfo`）后调用。

### （3）状态与就绪

#### isTaskReady（POST `is_task_ready/`）—— 就绪门闩

- **用途**：查询部署任务是否进入「可查询目标状态」阶段；前端 5 处以其为下发表格出现前的门闩。
- **参数**：`{ collect_config_id }`。
- **返回**：`boolean`——`true` 表示可进入下一步。
- **行为语义**：调用方统一采用「非 ready 或异常 → 2s 递归重试」策略（`config-delivery`/`target-table`/`config-deploy`/`collector-status-details`；`stop-start-host` 为 2010ms），**永不 reject**；等待期间以「准备中」占位或按钮 loading 表达。
- **使用示例**（真实用法）：
  ```js
  const taskReadyStatus = id => new Promise(resolve => {
    const retry = () => setTimeout(() => taskReadyStatus(id).then(resolve), 2000);
    isTaskReady({ collect_config_id: id })
      .then(show => (show ? resolve(true) : retry()))
      .catch(() => retry());
  });
  ```

#### collectTargetStatus（GET `status/`）

- **用途**：目标级状态与下发内容（进度轮询主接口，10s 档）。
- **返回**：`{ contents, ... }` 目标明细；存在 RUNNING/PENDING 即续轮询。

#### collectRunningStatus（GET `running_status/`）

- **用途**：启停页只读状态（`created` 时首查）。

#### collectInstanceStatus（GET `collect_instance_status/`）

- **用途**：实例级采集状态（旧版执行详情；新版执行详情已改用 `collectTargetStatus`）。

#### getCollectLogDetail（GET `get_collect_log_detail/`）

- **用途**：目标执行日志详情（失败行「详情」侧滑）。
- **使用示例**：`const { log } = await getCollectLogDetail({ id, instance_id }, { needMessage: false });`

### （4）校验与统计

#### checkPluginVersion（POST `check_plugin_version/`）

- **用途**：进程采集保存前校验插件版本（低版本主机清单）。
- **返回**：`{ result: boolean, ... }`——`result=false` 时前端弹二次确认（列出低版本主机、可跳节点管理），**用户确认后仍可继续保存**。
- **使用示例**（真实用法）：
  ```js
  const res = await checkPluginVersion(params).catch(() => ({ result: false }));
  if (!res.result) { /* 弹窗确认是否继续 */ }
  ```

- **用途**：顶部统计卡（类型 × 状态计数）。
- **返回**：`type_list` 形态数组（`{ id, name, nums }`）；失败走页面级 `statsError` 而非弹窗。

#### listRelatedStrategy（POST `list_related_strategy/`）

- **用途**：删除前查询关联策略。
- **返回**：`{ accurate_strategies: [{ strategy_id }], fuzzy_strategies: [{ strategy_id }] }`——删除弹层据此提示并可勾选级联删除（配合策略模块 `delete_strategy_config`）。

## 四、权限与常量契约

### 权限常量（`authority-map.ts`）

| 常量 | action id | 用途 |
|------|-----------|------|
| `VIEW_AUTH` | `view_collection_v2` | 查看：列表 / 可视化 / 采集详情 / 执行详情 |
| `MANAGE_AUTH` | `manage_collection_v2` | 管理：新建 / 克隆 / 编辑 / 增删目标 / 启停 |
| `PLUGIN_MANAGE_AUTH` | 复用插件管理 `MANAGE_AUTH` | 插件相关跳转 |
| `STRATEGY_VIEW_AUTH` | `view_rule_v2` | 关联策略查看 |
| `ALARM_GROUP_MANAGE_AUTH` | 复用告警组 `MANAGE_AUTH` | 告警组管理 |

- **生效方式**：路由 `meta.authority` → `authorityMixinCreate(authMap)`（`created` 批量取权，结果 `provide`/`inject` 下发）→ 按钮级 `v-authority` 指令与 `authority.MANAGE_AUTH` 三元短路。**无权限不隐藏按钮而是弹权限申请**（`handleShowAuthorityDetail`）；分享态（`__POWERED_BY_BK_WEBWEB__` + token）与超管直接放行。
- **跨业务约束（不变量）**：行 `bizId !== 当前业务` 时——写操作全部 `return` 拦截；读入口经 `handleConfigNavigate` 用 `getBizRouteHref` 拼所属业务 URL 后新标签页打开（直链场景 `location.replace`）。

### 状态常量（`collector-host-detail/utils.ts`）

- `EStatus` / `STATUS_LIST`（未终结态集合，轮询终止判据）/ `statusMap`（状态名与颜色）/ `labelMap`（增删变更重试标签）/ `operatorMap`（`last_operation` → 「增删目标/升级/启用/停用/回滚」）。

### 视图变量持久化（`collector-view/variable-set.ts`）

- `getCollectVariable` / `setCollectVariable` / `delCollectScene` / `batchDelCollectRecord`：localStorage（key `collectVariablesConfig`）持久化可视化视图变量与图表展开记录；**被 performance 模块跨模块复用**（改动需回归 performance 详情面板）。
