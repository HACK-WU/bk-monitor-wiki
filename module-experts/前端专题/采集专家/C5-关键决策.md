## 决策清单

### 决策 1：接口契约-跨业务配置行只读、读入口跳所属业务

- **分类**：接口契约
- **动机**：避坑（跨业务行沿用当前业务上下文 → 详情查询报 `CollectConfigNotExist`（3311003），升级入口无归属限制）
- **决策**：采集列表可见「全局插件在其它业务中的配置」行，但对这些行实施：
  1. **读跳所属业务**：名称/可视化/状态入口经 `getBizRouteHref` 拼 `?bizId=<归属业务>#/<path>` 后新标签页打开（`window.open(..., 'noopener')`）；
  2. **写全拦截**：编辑/启停/删除/克隆/增删目标/升级等写入口对 `bizId !== 当前业务` 直接 `return`，默认隐藏升级与写操作入口；
  3. **直链兜底**：列表 `?id=` 直链在异步加载后以 `location.replace` 跳所属业务（避免 `window.open` 被浏览器拦截）；
  4. **统计口径标注**：顶部统计区标注「本业务」，表格总数仍取全部可见配置。
- **背景约束**：后端列表口径 = 本业务 ∪ 全局插件关联的其它业务配置（有意为之的数据源语义）；而详情/写接口严格按 `(id, 当前业务)` 校验——跨业务行在当前业务下**必然不可读写**，只能在归属业务操作。
- **被否决方案**：无（commit 未记录备选；从实现看也未走"放开详情接口跨业务读"的路线）
- **重新评估触发条件**：后端把列表口径收窄为「本业务 ∪ 全局插件本业务配置」（跨业务行消失）；或产品要求跨业务行可在当前业务直接管理（需后端放开详情/写接口的跨业务校验）
- **关联代码**：`handleConfigNavigate` / `handleShowDetail` / `handleCheckView` / `handleCheckStatus` / `initPageData` @ `collector-config.vue`；`getBizRouteHref` @ `monitor-common/utils/index.ts`
- **证据来源**：commit `1bcb1fb3a4`「fix: 修正跨业务采集配置的查看与只读入口 (#12736)」（message 明写背景与四项改动）；代码注释（`collector-config.vue`：直链在异步加载后进入详情，避免新窗口被浏览器拦截）；回归测试 `tests/collector-cross-business.test.cjs`（11 用例锁定守卫矩阵）

### 决策 2：架构设计-加载态分区骨架、分区失败重试、刷新失败保留已有内容

- **分类**：架构设计
- **动机**：避坑（请求期间无统一骨架 → 失败被误看成空数据，或一直停在加载中）
- **决策**：统计、列表（详情同理）**各分区各自展示骨架**，失败可局部刷新或重试；同一次数据区**只采纳最后一次请求**（`requestId` + `AbortController`，离开页面/切换时取消未完成请求）；**已有内容时，后续刷新失败保留已有内容**（不清空）；列表 200ms 延迟才显示骨架，避免短请求闪骨架。
- **背景约束**：列表常驻 5s 轮询，必须区分「真的没有数据」与「这次请求失败」；统计与列表加载互不阻塞。
- **被否决方案**：无（commit 未记录备选）
- **重新评估触发条件**：无
- **关联代码**：`CollectorConfigSkeleton` @ `collector-config-skeleton.tsx`；`getCollectionConfigList` / `fetchCollectConfigStat` / `startListLoading` / `showTableSkeleton` @ `collector-config.vue`
- **证据来源**：commit `bf6ee7e84e`「采集配置统一加载骨架与失败重试 (#12678)」（message 明写「统计、列表和详情各分区现在各自展示骨架；失败可以刷新或重试；同一次数据区只采纳最后一次请求；已有内容时，后续刷新失败保留已有内容」）

### 决策 3：架构设计-详情基础信息与目标查询隔离

- **分类**：架构设计
- **动机**：避坑（基础信息读取会先解析目标，拓扑目标解析又依赖实时 Agent 状态查询 → 查询超时使基础配置一起失败、侧栏关闭）
- **决策**：基础信息接口跳过目标解析（`frontend_config_detail` 带 `with_target_info=false`）；目标接口只查询计数与标签（关闭拓扑/模板的 Agent 状态查询）；前端两侧分别展示加载结果与错误——**目标失败不阻塞基础展示、可单独重试，同一配置已加载的基础信息继续可见**。
- **背景约束**：目标解析（实时 Agent 状态）是慢路径且可能超时；基础信息（名称/插件/参数）本不依赖它。
- **被否决方案**：无（commit 未记录备选）
- **重新评估触发条件**：后端目标解析性能提升（实时 Agent 查询可稳定快速返回）后，可评估是否合并回单接口
- **关联代码**：`frontendCollectConfigDetail` / `frontendCollectConfigTargetInfo` @ `monitor-api/modules/collecting.js`；`DetailRequest` @ `collector-detail/detail-request.ts`；`CollectorConfiguration` / `CollectorConfigDetail`（侧滑）
- **证据来源**：commit `ba9c6546e9`「fix: 隔离采集详情基础信息与目标查询 (#12697)」（message 明写背景与前后端改动）；回归测试 `tests/collector-detail-isolation.test.cjs`（12 用例）

### 决策 4：[推测] 性能取舍-列表整表轮询、以服务端为权威

- **分类**：性能取舍
- **动机**：一致性（采集状态由后端下发链路推进，前端无法本地推导）
- **决策**：[推测] 列表通过 `collectConfigList({ refresh_status: true })` 每 5s 整表重建（首轮 1s 后开始），以服务端响应整体替换 `table.data`——本地派生字段随重建丢失、行级 UI 状态在轮询开始时主动隐藏；`deactivated` / `beforeDestroy` 停止轮询并取消在途请求。
- **背景约束**：`status` / `task_status` 只能由后端推导；用户需要近似实时的状态视图（下发/启停后要看到进度）。
- **被否决方案**：无（未找到记录）
- **已知代价**：每 5s 一次全量列表请求与整表重渲染；任何纯本地的行级编辑不会保留；轮询失败静默保留旧数据（页面可能长时间展示过期状态）。
- **重新评估触发条件**：轮询请求频次造成后端压力、或状态实时性收益不达预期（PM 走查 Q4 待产品评估是否降频/加暂停）
- **关联代码**：`getCollectionConfigList(status, needLoading, pollingDelay = 5000)` @ `collector-config.vue`；`stopLoading` / `cancelListRequest`
- **证据来源**：无直接证据，基于轮询参数化（`pollingDelay` 可调）、显式 `refresh_status` 开关、失活停止与整表替换的实现结构推断

### 决策 5：[推测] 性能取舍-筛选与分页下推服务端、排序留本地

- **分类**：性能取舍
- **动机**：兼容处理（列表口径含跨业务可见行与后端聚合统计，前端无全量数据）
- **决策**：[推测] 分类/状态/关键词筛选与分页均翻译为 `search` / `page` / `limit` 下推服务端；排序仅在前端对**当前页**数组执行（接口固定 `order: '-create_time'`）。
- **背景约束**：统计卡与 tab 徽标来自后端聚合（`fetch_collect_config_stat`），与列表数据同源口径；接口未提供通用排序参数。
- **被否决方案**：无（未找到记录）
- **已知代价**：跨页排序结果不成立——用户按 ID 排序后翻页顺序不连续（PM 走查 N5）。
- **重新评估触发条件**：产品要求全局排序能力（届时需接口支持 `order` 参数并取消本地排序）
- **关联代码**：`getSearchOfParams` @ `collector-config.vue`；`handleSortChange` / `getTableAllData` @ `store.ts`
- **证据来源**：无直接证据，基于请求参数映射（`search`/`page`/`limit` 均入请求、`order` 固定为 `-create_time`）与本地排序实现结构推断
