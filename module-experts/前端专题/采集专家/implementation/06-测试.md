## 简介

面向采集配置功能域（`monitor-pc/pages/collector-config/` + `monitor-api/modules/collecting.js`）的测试资产分为两类：

- **单元回归测试**：`bkmonitor/webpack/tests/` 下 3 个采集专测文件、共 28 个用例，使用 Node 原生 `node:test`，通过 `typescript.transpileModule` **直跑真实源码**（不经打包，不建测试双）；

## 框架与组织

- **运行器与断言**：`node:test` + `node:assert/strict`（`assert.equal / deepEqual / match / ok`）；命名惯例 `*.test.cjs`（少数 `.test.mjs`）。
- **直跑真实源码（不打包）的四种手法**：
  1. TS/TSX 经 `ts.transpileModule`（CommonJS + ES2022 + `jsxFactory: 'h'`）编译后 `new Function` 执行；
  2. `.vue` 用 `vue/compiler-sfc` 的 `parse` + `compileTemplate`，手动装配 render（cross-business 直接以 Vue 2 组件选项实例化并 `_render()`）；
  3. TSX 类组件用 `ts.factory` 重写类声明、transform 删除全部装饰器后，在注入 `window`/`h` 的作用域内运行（isolation 的 `pageClass`、detail-back 的 `navBarClass`）；
  4. 依赖经自定义 `require` 映射注入桩（如 `monitor-api/modules/collecting` 返回可控 Promise、`detail-request` 桩），不加载浏览器环境组件。
- **环境注入**：`window`（含 `cc_biz_id`、`history.length`、`i18n.t`）、`location.replace`、`VueRouter`（abstract mode）按用例构造。
- **竞态模拟**：手写可控 Promise 数组（`api()` 外抛 resolve/reject）表达"请求未落地 → 落地 → 过期响应"序列；`setImmediate` 作为 flush。
- **旧实现对照钩子**：cross-business 支持 `COLLECTOR_CONFIG_TEST_SOURCE` 环境变量替换被测源码文件（提交记录中"旧版本四个对照用例失败"即用此机制验证回归有效性）。

章节来源：[collector-detail-isolation.test.cjs](file://bkmonitor/webpack/tests/collector-detail-isolation.test.cjs)（关键符号：`transpileModule`、`pageClass`）；[collector-cross-business.test.cjs](file://bkmonitor/webpack/tests/collector-cross-business.test.cjs)（关键符号：`COLLECTOR_CONFIG_TEST_SOURCE`）

## 运行命令

前置：`cd /root/bk-monitor/bkmonitor/webpack`（node_modules 已就绪）。以下均为实测过的原文（Node v22.19.0）：

```bash
# 单文件
node --test tests/collector-detail-back.test.cjs
node --test tests/collector-detail-isolation.test.cjs
node --test tests/collector-cross-business.test.cjs

# 只跑采集 3 个：glob（node 自行展开，可用）
node --test 'tests/collector-*.test.cjs'

# 等价写法：显式列出
node --test tests/collector-cross-business.test.cjs tests/collector-detail-back.test.cjs tests/collector-detail-isolation.test.cjs

# 目录批量：必须用 glob
node --test 'tests/**/*.test.cjs'   # 159 用例（19 个 cjs 文件）
node --test 'tests/**/*.test.*'     # 225 用例（含 3 个 mjs）
```

⚠️ 陷阱：`node --test tests/`（直接传目录）在 Node 22 下会报 `Cannot find module '.../tests'`（目录被当作入口模块执行）——不要使用，用上方 glob 或文件列表替代。

**已知失败（供主 agent 建 known-failures）**

- 文件：`tests/collector-cross-business.test.cjs`——**全部 11 个用例同因失败**
  - 报错：`TypeError: VueRouter is not a constructor`，发生于 `setup()` 的 `new VueRouter({...})`（测试文件第 83 行），全部用例未进入业务断言
  - 原因初判：**环境依赖链接漂移，非用例缺陷**。`webpack/node_modules/vue-router` 被 hoist 为 `vue-router@4.5.1`（Vue 3 版，由 `@blueking/ai-ui-sdk` 的 auto-install peer 引入）；测试面向 Vue 2 生态、期望 `vue-router@3.6.5`（`src/monitor-pc/package.json`、`src/apm/package.json` 声明 `^3.6.5`；pnpm 存储中存在 3.6.5 安装，但未链接到 webpack 根）
  - 验证：将 `require('vue-router')` 临时强制解析到 `.pnpm/vue-router@3.6.5_vue@2.7.16/node_modules/vue-router` 后，**11/11 通过**（907ms）——证明用例逻辑正确，仅依赖链接问题
  - 可修复方向（建议，未执行）：重指向根链接 / 重跑 `pnpm install` 观察 hoisting / 为 `tests/` 补一层 node_modules 映射

## 覆盖与缺口

**已覆盖（3 文件 28 用例）**

1. **跨业务守卫矩阵**（cross-business）：3 个只读入口（`handleShowDetail`/`handleCheckView`/`handleCheckStatus`）跨业务 → 新标签页 + 归属 `bizId`（含负数 `bizId`）且当前页不动；本业务 → 原页面路由；10 个写操作/弹层入口的跨业务拦截（不改状态、不导航、不调用删除）；同业务的升级/改目标/克隆/新建仍可用；异步直链（`initPageData`）跳转归属业务替代 `window.open`；渲染层跨业务行只读（隐藏升级/编辑/增删目标、"查看"不需源业务管理权限、"本业务"文案）
2. **返回键兜底**（detail-back）：新标签页（`history.length=1`）打开 `collect-config-detail` / `collect-config-operate-detail` / `collect-config-add` → push 回 `collect-config`；有历史正常 `back()`；策略详情/自定义指标详情既有兜底不回归；其它路由行为不变
3. **详情请求隔离**（detail-isolation）：基础与目标两组请求独立状态（失败互不污染）、重试只重发对应组、切换配置中断旧请求（`signal.aborted`）且旧响应不可写入、侧滑面板重开/切换/关闭的延迟响应竞态、重命名串行化与关闭忽略

**主要缺口**（对照 PM 走查报告 N1–N8 与模块功能面）

| 缺口 | 说明 | PM 条目 |
|------|------|---------|
| 统计与筛选口径 | `FAILED` 不在"异常采集目标"统计与筛选中；`fetchCollectConfigStat` / `task_status=WARNING` 无测试 | N1 |
| 统计单位口径 | 统计卡"目标"是配置数 vs 行内"可视化 (N)"是实例数 | N2 |

| 行内异常重试入口 | `retry` / `batchRetry` 未接入列表 | N6 |

其它无自动化覆盖的功能面：列表 tab/搜索/分页交互、4 步新建流程（`collector-add` 的 select→set→delivery→done）、启停（`stop-start-view`）、删除/克隆弹层、任务轮询（`collectorTaskData`）、变量注入与预览（`collector-view/*`）、主机详情（`collector-host-detail/*`）、升级（`collector-config-update`）、可视化配置（`view-settings`）；e2e 无入库用例，不构成回归基线。

## 结论

- 采集配置域现有 **3 个 node:test 回归文件、28 个用例**：跨业务守卫（11）、返回键兜底（5）、详情请求隔离（12）；全部直跑真实源码、无需打包，属本地手工回归（CI 不执行）。
- 当前环境实测：`collector-detail-back` 5/0、`collector-detail-isolation` 12/0 全绿；`collector-cross-business` **11 个用例因根 `node_modules/vue-router` 链接为 4.5.1（应为 3.6.5）而全数失败**——强制解析到 3.6.5 后 11/11 通过，属环境问题而非用例缺陷（修复方式待决策）。
- e2e 基础设施（Playwright 1.63.0 + 本地运行目录机制）自检 5/6 通过（缺 Chromium），且**无采集 e2e 用例入库**，暂不能作为回归证据。
- 覆盖集中在"跨业务只读守卫、返回键、详情隔离"三个修复主题；列表交互、写操作流程与统计口径（N1–N8）等大面积无自动化，属主要缺口。
