## Web API 接口表

所有接口通过 `ShieldViewSet` 暴露，基础路径为 `/api/cc/monitor/shield/`（ResourceViewSet 路由）。

权限模型：查询类操作（GET 方法 + POST 查询类 action）需要 `VIEW_DOWNTIME` 权限；管理类操作需要 `MANAGE_DOWNTIME` 权限。

| Endpoint | Method | Action | 权限 | 说明 |
|----------|--------|--------|------|------|
| `shield/shield_list/` | POST | `shield_list` | VIEW_DOWNTIME | 告警屏蔽列表（通用） |
| `shield/frontend_shield_list/` | POST | `frontend_shield_list` | VIEW_DOWNTIME | 告警屏蔽列表（前端，含展示增强） |
| `shield/shield_detail/` | GET | `shield_detail` | VIEW_DOWNTIME | 告警屏蔽详情（通用） |
| `shield/frontend_shield_detail/` | GET | `frontend_shield_detail` | VIEW_DOWNTIME | 告警屏蔽详情（前端，含维度展示） |
| `shield/frontend_clone_info/` | GET | `frontend_clone_info` | VIEW_DOWNTIME | 告警屏蔽克隆详情（前端） |
| `shield/shield_snapshot/` | POST | `shield_snapshot` | VIEW_DOWNTIME | 告警屏蔽详情（快照，基于传入配置） |
| `shield/add_shield/` | POST | `add_shield` | MANAGE_DOWNTIME | 新增屏蔽（通用） |
| `shield/bulk_add_alert_shield/` | POST | `bulk_add_alert_shield` | MANAGE_DOWNTIME | 批量告警屏蔽 |
| `shield/edit_shield/` | POST | `edit_shield` | MANAGE_DOWNTIME | 编辑屏蔽（通用） |
| `shield/disable_shield/` | POST | `disable_shield` | MANAGE_DOWNTIME | 解除屏蔽（通用，支持批量） |
| `shield/update_failure_shield_content/` | GET | `update_failure_shield_content` | MANAGE_DOWNTIME | 更新失效屏蔽的屏蔽内容（测试接口） |

### 快捷屏蔽接口（独立 ViewSet）

| Endpoint | Method | Action | 权限 | 说明 |
|----------|--------|--------|------|------|
| `event/quick_shield/` | POST | `quick_shield` | `AlertPermissionResource` | 快速屏蔽事件（支持 scope/strategy/event 三种类型） |
| `event/alert/quick_shield/` | GET | `alert/quick_shield` | `QuickActionTokenResource`(token) | 快捷告警屏蔽（默认3小时，通知链接触发） |
| `event/alert/quick_ack/` | GET | `alert/quick_ack` | `QuickActionTokenResource`(token) | 快捷告警确认（通知链接触发） |

> 快捷屏蔽接口不在 `ShieldViewSet` 中。`quick_shield` 注册在 `weixin/event/views.py` 的 `EventViewSet`（`NoCsrfSessionAuthentication`），`alert/quick_shield` 和 `alert/quick_ack` 注册在 `fta_web/alert/views.py` 的 `QuickAlertHandleViewSet`（`PlainTextRenderer`）。

> `query_post_actions`（`shield_list`、`frontend_shield_list`、`shield_snapshot`）虽为 POST 方法，但属于查询操作，使用 VIEW_DOWNTIME 权限。

## 告警引擎内部接口

### ShieldManager.shield

位于告警引擎收敛层，用于在告警处理流程中判断告警是否被屏蔽。

```python
from alarm_backends.service.converge.shield.manager import ShieldManager

# action_instance: ActionInstance 告警动作实例
# alerts: 可选的告警快照列表
is_shielded, shielder = ShieldManager.shield(action_instance, alerts=None)
# 返回: (bool, Shielder|None)
# is_shielded=True 时，shielder 为匹配到的屏蔽器实例
```

**执行流程**：
1. 先执行 `GlobalShielder`（全局屏蔽检测），匹配则直接返回 `(True, global_shielder)`
2. 获取告警列表（优先使用传入的 `alerts` 快照，否则从 DB 获取 `AlertDocument`）
3. 依次执行 `AlertShieldConfigShielder`（告警屏蔽配置检测）和 `AlarmTimeShielder`（告警时间屏蔽检测）
4. `AlertShieldConfigShielder` 对每个 alert 逐一检测，任一匹配即返回屏蔽
5. 全部不匹配则返回 `(False, None)`

**Shielders 元组**：`(AlertShieldConfigShielder, AlarmTimeShielder)`

章节来源：[ShieldManager](file://bkmonitor/alarm_backends/service/converge/shield/manager.py#L13-L55)

## 快捷屏蔽接口对比

### 两个 quick_shield 接口的区别

| 维度 | `QuickShield` | `QuickAlertShield` |
|------|--------------|-------------------|
| **端点** | `POST /event/quick_shield/` | `GET /event/alert/quick_shield/` |
| **文件** | `weixin/event/resources.py` | `fta_web/alert/resources.py` |
| **ViewSet** | `EventViewSet` | `QuickAlertHandleViewSet` |
| **认证方式** | `NoCsrfSessionAuthentication`（Session 登录） | `QuickActionTokenResource`（通知链接 token 验证） |
| **输入** | `type` + `event_id` + `end_time` | `action_id` + `token` + `bk_biz_id` |
| **屏蔽对象** | 单个事件，按 type 分发为 scope/strategy/event 屏蔽 | 一个 action 下的**多个 alert**，逐条创建 alert 屏蔽 |
| **屏蔽时长** | 由调用方传入 `end_time` | 默认 3 小时，可通过 `shield_hours` 调整 |
| **返回格式** | JSON `{"id": shield_id}` | HTML 重定向（成功）或纯文本统计（部分失败） |
| **入口场景** | 移动端/微信端手动快速屏蔽 | 通知消息中的"屏蔽"链接点击 |

### add_shield 与 quick_shield 的区别

两者最终都调用同一个 `resource.shield.add_shield`（即 `AddShieldResource`），但 quick_shield 在调用前做了大量**简化封装**：

| 维度 | `add_shield`（完整版） | `quick_shield`（快捷版） |
|------|----------------------|------------------------|
| **权限** | 校验 `MANAGE_DOWNTIME` 权限 | 不校验（`AlertPermissionResource` 仅做基础鉴权） |
| **category** | scope / strategy / alert / dimension 全支持 | 仅 scope / strategy / alert（event） |
| **周期配置** | 支持单次/每天/每周/每月/自定义 | **固定单次**（`cycle_config={"type": 1}`） |
| **通知配置** | 支持 `notice_config`，可配置接收人 | **固定不发通知**（`shield_notice=False`） |
| **开始时间** | 由调用方指定 `begin_time` | **自动取当前时间** |
| **is_quick 标记** | 由调用方决定 | **固定 `True`** |
| **重复检查** | strategy 类型会检查是否已存在屏蔽 | **不检查** |
| **Alert 状态更新** | alert 类型会更新 `AlertDocument.is_shielded=True` | **不更新**（quick_shield 走的是 `handle` 方法而非 `handle_alert`） |
| **dimension_config** | 完整构造（含 `_alert_id`、`_severity`、`_dimensions` 等展示字段） | 最小化构造（仅含屏蔽匹配所需字段） |

> **核心结论**：`add_shield` 是功能完整的屏蔽创建入口，支持所有配置项；`quick_shield` 是它的简化包装，自动填充 `is_quick=True`、单次周期、不发通知、当前时间开始，牺牲灵活性换取操作便捷性。

章节来源 [QuickAlertShield](file://bkmonitor/packages/fta_web/alert/resources.py#L3078-L3126)

## 移动端为何有独立 API

移动端 `QuickShield`（`POST /event/quick_shield/`）没有复用 `ShieldViewSet` 的 `add_shield` 端点，而是注册在独立的 `EventViewSet` 中，原因有三：

### 1. 认证方式不同

`ShieldViewSet` 使用默认的 `SessionAuthentication`（要求 CSRF token），而 `EventViewSet` 显式替换为 `NoCsrfSessionAuthentication`。移动端运行在微信 WebView / 企业微信内置浏览器中，CSRF token 机制不可靠，需要绕过。

### 2. 权限模型不同

`ShieldViewSet` 要求 `MANAGE_DOWNTIME` 权限（IAM 管理权限），而 `EventViewSet.get_permissions()` 直接返回 `[]`，把权限交给 Resource 自身（`AlertPermissionResource`）做更宽松的校验。移动端用户通常不具备完整的 IAM 管理权限，但应该能快速屏蔽自己收到的告警。

### 3. 输入复杂度不同——移动端不需要知道 dimension_config

这是最关键的设计差异。`AddShieldResource` 要求调用方构造完整的 `dimension_config`（含 `scope_type`、`target`、`metric_id` 等），移动端无法也不应构造这些复杂参数。`QuickShield` 只需要三个参数（`type` + `event_id` + `end_time`），后端自动从事件数据推导出 dimension_config：

```python
# handle_scope: 根据 event.target_type 自动映射
#   HOST   → scope_type=ip, target=[{ip, bk_cloud_id}]
#   SERVICE → scope_type=instance, target=[bk_service_instance_id]
#   TOPO   → scope_type=topo, target=[{bk_obj_id, bk_inst_id}]
# handle_strategy → dimension_config={id: [strategy_id]}
# handle_event    → dimension_config={alert_id: alert.id}
```

> **本质**：`QuickShield` 是一个**适配层**——把移动端的简单输入翻译成 `add_shield` 需要的复杂参数，同时绕过 CSRF 和 IAM 限制。这不是冗余，而是面向不同客户端的合理抽象。

## 结论

告警屏蔽模块的接口分为三层：

- **Web API 层**：通过 `ShieldViewSet` 暴露 11 个端点，分为通用资源（后端）和前端资源（展示增强），权限按 VIEW/MANAGE_DOWNTIME 区分。
- **内部调用层**：通过 `resource.shield.xxx` 在服务端跨模块调用，前端资源内部也依赖后端资源。
- **告警引擎层**：`ShieldManager.shield` 在告警处理流程中做屏蔽判定，`ShieldCacheManager` 提供缓存层加速，`ShieldCacheManager.refresh` 定期同步 DB 到 Redis。
- **定时任务层**：`check_and_send_shield_notice` 负责屏蔽通知的定时检测与发送，`UpdateFailureShieldContentResource` 负责补充失效屏蔽的展示内容。

event 类型的屏蔽在 `AddShieldResource` 中会被转换为 alert 类型存储，数据库中不保留 event 类别。批量告警屏蔽支持按拓扑节点转为 scope 类型屏蔽。
