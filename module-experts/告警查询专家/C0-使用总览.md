# C0-使用总览：告警查询专家 / fta_web.alert

> 黑盒使用文档。无需阅读实现代码即可使用本模块的查询能力。详细方法契约见 [C1-能力契约.md](C1-能力契约.md)：业务目标级流程见 [C2-使用流程.md](C2-使用流程.md)。实现层导航见 `implementation/`。

## 能力清单
本专家覆盖告警域的**只读查询（读）能力**，全部以 ES 文档 `AlertDocument` 为数据源：

| 能力 | 入口 | 说明 |
|------|------|------|
| 告警列表查询 | `resource.alert.search_alert(...)` / `SearchAlertResource`（`alert/search`） | 分页列表 + 总览 `overview` + 维度聚合 `aggs`，支持状态/条件/全文本 |
| 直接构造处理器 | `AlertQueryHandler(...).search()` | 在 Python 内部直接调用，免去 HTTP 层 |
| 趋势直方图 | `resource.alert.alert_date_histogram(...)` / `AlertDateHistogramResource` | 按 begin/end/init 三段时间桶统计状态分布 |
| 维度 TopN | `resource.alert.alert_top_n(...)` / `AlertTopNResource` | 按字段聚合 TopN，支持时间分片并行 |
| 全量导出 | `resource.alert.export_alert(...)` / `ExportAlertResource` | 导出 CSV 包（含关联信息） |
| 关联事件 | `resource.alert.search_event(...)` / `SearchEventResource` | 某告警下的关联事件 |
| 处理记录 | `resource.alert.search_action(...)` / `SearchActionResource` | 某告警的处理动作记录 |
| 事件计数 | `resource.alert.alert_event_count(...)` / `AlertEventCountResource` | 按告警 ID 批量统计事件数 |
| 关联信息 | `resource.alert.alert_related_info(...)` / `AlertRelatedInfoResource` | 主机/拓扑等关联信息 |
| 维度下钻 | `resource.alert.dimension_drill_down(...)` / `DimensionDrillDownResource` | AIOps 维度下钻（GET） |
| 反馈列表 | `resource.alert.list_alert_feedback(...)` / `ListAlertFeedbackResource` | 某告警的用户反馈（GET） |
| 业务鉴权展开 | `AlertQueryHandler.parse_biz_item(bk_biz_ids)` | 将 `-1`（全业务哨兵）展开为授权业务集 |

## 能力边界
- **只读**：本专家不覆盖写入（ack / 处理 / 反馈提交 / 收藏保存等），写接口不在范围内。
- **数据源唯一**：所有查询均来自 ES `AlertDocument`，无 ORM 模型参与，不支持跨源聚合（与 CMDB 查询独立）。
- **实时性**：`total` 受 `track_total_hits=10000` 限制，超 1 万时总数不精确。
- **鉴权前置**：调用方需具备 `VIEW_EVENT`（列表还需 `VIEW_BUSINESS`）权限；负责人/关注人可见性降级为预期内行为。
- **无子专家**：本专家为单一业务域（告警查询），未拆分。

## 已知问题与常见坑

### 1. `bk_biz_ids=-1` 必须展开
- **现象**：传 `bk_biz_ids=[-1]` 直接查不到任何告警，`total=0`。
- **触发条件**：用「全部业务」哨兵但未展开。
- **正确做法**：经 `resource.alert.*` 调用时框架自动展开；直接构造 `AlertQueryHandler` 时同样会自动展开（构造期 `BaseBizQueryHandler` 解析），**切勿**把 `-1` 直接塞进 ES `terms` 过滤。

### 2. `query_string` 空串/裸词处理
- **现象**：`query_string=""` 不过滤（符合预期）；裸词走全字段模糊；词过短/过长且非枚举显示名时返回 `match_none`，结果可能为空。
- **触发条件**：前端传入不规范搜索词。
- **正确做法**：结构化检索用 `field:value`；裸词检索依赖 `FULLTEXT_SEARCH_FIELDS` 白名单（id / alert_name / event.description / labels / appointee / follower / event.bk_biz_id）；`query_string` 条件条数超限抛 `ValidationError`。

### 3. `issue_id` 过滤需展开合并成员
- **现象**：按合并后的主 Issue ID 过滤时，被并入的告警不出现。
- **触发条件**：`issue_id` 命中合并关系但未展开。
- **正确做法**：经 `AlertQueryHandler` 时构造期 `_expand_merged_issue_conditions()` 会自动展开为「主 + active members」，无需手动处理；其基于已解析的 `authorized_bizs`（非原始 `-1`）查询合并关系。

### 4. 查询异常 fail-open
- **现象**：ES 异常时 `search()` 返回空响应而非整页 500，但 `exc.data` 携带部分结果后重抛。
- **触发条件**：ES 抖动 / DSL 错误。
- **正确做法**：排查时关注日志 `search alerts error`，前端可见降级数据；不要误判为「无数据」。

### 5. `page_size` 与 `total` 护栏
- **现象**：`page_size>5000` 被 `RequestSerializer` 拒绝；`total` 超过 1 万不精确。
- **触发条件**：大业务量全量拉取。
- **正确做法**：导出用 `export_alert`（全量 `scan`，`page_size=0` 语义）；列表分页遵守上限；超大总量以聚合/TOPN 替代全量列表。
