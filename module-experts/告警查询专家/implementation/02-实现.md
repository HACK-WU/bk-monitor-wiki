## 简介
告警查询的实现核心是 `BaseQueryHandler` 提供的可组合查询构建管线：`get_search_object → add_conditions → add_query_string → add_ordering → add_pagination →（可选）add_overview/add_aggs → execute`。`AlertQueryHandler` 在其上叠加业务语义（时间切片、状态、合并告警展开、字段翻译）。

章节来源：[base.py](file://bkmonitor/packages/fta_web/alert/handlers/base.py#L309-L389)

## 查询对象构建细节
- `get_search_object`（`alert.py:702`）：以 `AlertDocument.search(start_time, end_time)` 起手，按 `is_time_partitioned` 选择时间切片过滤（解决告警 `begin_time/end_time` 与查询窗口的交叠），再 `add_biz_condition` 与 `username` 过滤（明确带用户名时仅过滤 assignee/appointee）。
- `add_conditions`（`base.py:467`）：遍历 `SearchConditionSerializer` 条件，经 `AlertQueryTransformer.transform_condition_fields` 将展示字段映射为 ES 字段，按 `method`（eq/neq/include/exclude/gt...）生成 `Q`。
- `add_query_string`（`base.py:456`）：经 `build_query_string_q` 解析——裸词走全字段模糊（`build_bare_fulltext_query_q`），结构化 `field:value`/布尔走 `AlertQueryTransformer.transform_query_string` 生成 DSL；空串返回 `None` 不加过滤。
- `add_pagination`（`base.py:378`）：标准 `[start_offset:end_offset]` 切片；`page_size=0` 表示不分页（全量，配合导出）。
章节来源：[alert.py](file://bkmonitor/packages/fta_web/alert/handlers/alert.py#L702-L770)、[base.py](file://bkmonitor/packages/fta_web/alert/handlers/base.py#L378-L607)

## 状态语义与全文本
- 状态语义（`alert.py:744-765`）：`MINE` / `MY_ASSIGNEE` / `MY_APPOINTEE` / `MY_FOLLOW` 映射为 assignee/appointee/follower 的 term 查询；`SHIELDED_ABNORMAL` / `NOT_SHIELDED_ABNORMAL` 组合 `status=ABNORMAL` 与 `is_shielded`；其余直接 `status=term`。多状态以 `operator.or_` 合并。
- 全文本（`base.py:401-454`）：`FULLTEXT_SEARCH_FIELDS` 白名单 + `luqum` 解析；词过短/过长且非枚举显示名时返回 `Q("match_none")`，避免静默丢条件后返回全量数据。`conditions[key=query_string]` 走 `build_query_string_condition_q`，条数超限抛 `ValidationError`（见 `serializers.validate_fulltext_condition_value_count`）。
章节来源：[alert.py](file://bkmonitor/packages/fta_web/alert/handlers/alert.py#L744-L765)、[base.py](file://bkmonitor/packages/fta_web/alert/handlers/base.py#L401-L454)、[serializers.py](file://bkmonitor/packages/fta_web/alert/serializers.py#L68-L140)

## 查询字符串翻译器（AlertQueryTransformer）
`AlertQueryTransformer`（`alert.py:191`）继承 `BaseQueryTransformer`（`base.py:111`，基于 `luqum` 的 `BaseTreeTransformer`），是 `query_string` / `conditions` 中**展示字段名 → ES 字段名**、**展示值 → 原始值**，以及若干特殊字段（嵌套 KV、`assign_tags` 回退、`action_id`/`converge_id` 改写）的翻译中心。它是 02 节管线中 `add_conditions` / `add_query_string` 的字段映射来源（见 `base.py:467-473`、`base.py:456-465`）。

### 字段白名单 query_fields
`query_fields`（`alert.py:207-260`）是全部可搜索字段的声明式清单，每项 `QueryField`（`base.py:66`）：
- `field` 展示英文名（如 `ip`）、`display` 中文名（如 `目标IP`）；
- `es_field` 实际 ES 字段（如 `event.ip`），缺省等于 `field`；
- `agg_field` 聚合用字段（如 `alert_name.raw`），缺省等于 `es_field`；
- `is_char` 字符字段（影响 wildcard / 分词）；
- `searchable=False` 表示纯计算字段（不进 ES，如 `plugin_display_name`）；
- `alias_func` 自定义改写（如 `metric` 经 `readable_name_alias_to_id`）。

**新增可查询字段必须在此注册**，否则前端字段查不到（见技术债）。

### 嵌套 KV 与 assign_tags 回退
- `NESTED_KV_FIELDS = {"tags": "event.tags", "assign_tags": "assign_tags"}`（`alert.py:192`）：`tags.x:y` 被改写为 `event.tags{key=x AND value.raw:y}` 嵌套查询（`base.py:135-148`）。
- `ASSIGN_TAGS_FALLBACK_FIELDS = {"event.ip": "ip", "event.bk_cloud_id": "bk_cloud_id"}`（`alert.py:195`）：传统主机告警（`event.ip` 有值）与 K8s 告警（仅 `assign_tags.ip` 有值）并存，故 `visit_search_field` 将这些字段**自动 OR 展开**为 `(event.ip:x) OR nested(assign_tags{key=ip AND value.raw:x})`（`alert.py:284-319`）。注意靠 `context["assign_tags_expanded"]` 标记防止 `generic_visit` 递归重入导致的无限递归。

### 值翻译 VALUE_TRANSLATE_FIELDS
`VALUE_TRANSLATE_FIELDS = {"severity": EVENT_SEVERITY, "status": EVENT_STATUS, "event.target_type": EVENT_TARGET_TYPE, "event.data_type": DATA_SOURCE_LABEL_CHOICE}`（`alert.py:200-205`）：用户输入展示值（如 `致命`）时，`visit_word` 经 `_process_not_search_field_name` 改写为 `(致命) OR (severity:1)`（`alert.py:344-364`）；指定字段时 `_process_value_translate_fields` 直接把展示值转回原始值（`alert.py:366-377`）。

### visit_search_field / visit_word 的特殊分支
- `visit_search_field`（`alert.py:262`）在父类基础上额外处理 `_process_stage_field`（阶段字段）与 `_process_metric_field`（指标名 ↔ ID 别名）。
- `visit_word`（`alert.py:321`）的 `process_fun_list` 依次尝试：`_process_not_search_field_name`（裸词值翻译）、`_process_value_translate_fields`、`_process_action_id`、`_process_converge_id`、`_process_event_ipv6`、`_process_action_name`、`_process_module_id`、`_process_set_id`。
- `_process_action_id` / `_process_converge_id`：将 `action_id:xxx` / `converge_id:xxx` 改写为对应的**告警 ID 集合**查询（动作 / 收敛 ID 不是告警标准字段，需先查出关联告警 ID），见 `alert.py:379-408`、`alert.py:410+`。

### 已知缺陷（务必注意）
- **en locale 下 `action_id` / `converge_id` 查询失效**（`_process_action_id` FIXME，`alert.py:386-390`）：`_("处理记录ID")` 在 `locale=en` 下返回 `"Handling Record ID"`（含空格），luqum 不接受含空格字段名，被切碎后 `search_field_origin_name` 落到 `'ID'` 不命中白名单。需前端只用 `action_id` 或独立 PR 修复。
- 与 `SearchAlertResource.detect_action_id_query`（`resources.py:1612`）的 regex 白名单必须保持同步，否则 Path A 扩时间窗但 Path B 未改写 query 会语义冲突导致 0 命中。

## 热点路径
- `search_raw` 的 `search_object.params(track_total_hits=10000).execute()`（`alert.py:785`）：`track_total_hits=10000` 限制总数统计开销；`page_size` 上限 5000（`serializers` 约束）。TopN 走 `bulk_request` 分片并行（`AlertTopNResource`，`resources.py:2184`）。
- 字段翻译（`alert.py:806-812`）：`MetricTranslator` / `StrategyTranslator` / `BizTranslator` / `CategoryTranslator` / `PluginTranslator` 对每页命中做字典翻译，是响应后处理的主要 CPU 开销点。
章节来源：[alert.py](file://bkmonitor/packages/fta_web/alert/handlers/alert.py#L785-L812)、[resources.py](file://bkmonitor/packages/fta_web/alert/resources.py#L2146-L2196)

## 技术债
- `date_histogram` 中 `TODO: tags开头的字段是否能够进行嵌套聚合？`（`alert.py:867`）——多 `tags.` 字段聚合被硬性限制为 1 个，属已知约束。
- `AlertQueryHandler` 与 `SearchHostMetricResource` 等模块存在类似的「并行聚合 + 字典就地填充」模式，但告警查询走 ES 而非 CMDB，无跨源并行聚合。
- `add_conditions` / `add_query_string` 的字段映射依赖 `AlertQueryTransformer.query_fields` 白名单，新增可查询字段需同步维护映射，否则前端字段查不到。
章节来源：[alert.py](file://bkmonitor/packages/fta_web/alert/handlers/alert.py#L867-L873)

## 结论
- 查询管线高度可组合，新增查询维度通常只需扩展 `AlertQueryTransformer.query_fields` 与 `conditions` 支持，无需改动管线本身。
- 两个高频坑：**`bk_biz_ids=-1` 未展开** 与 **`query_string` 空串/裸词处理**，是"查不到/数量异常"的首要怀疑点。
- 异常被 `search()` 捕获并 fail-open，排查时需关注日志 `search alerts error` 与 `exc.data` 中的部分结果。
