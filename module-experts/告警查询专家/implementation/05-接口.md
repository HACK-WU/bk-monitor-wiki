## 简介
告警查询相关接口由 `AlertViewSet.resource_routes` 统一挂载，方法多为 `POST`，路径形如 `/rest/v2/alert/...`（经 `urls.py` 的 `ResourceRouter` 注册）。本篇聚焦查询（读）类端点；写操作（ack / save_experience / feedback 等）不在此专家范围。

## 契约示例（alert/search）
请求（`AlertSearchSerializer` + `SearchAlertResource.RequestSerializer`）：
- `bk_biz_ids: list[int]`（可含 `-1` 全业务）、`space_uids: list[str]`（可选，转 bk_biz_ids）
- `status: list[str]`、`conditions: list[{key,value,method,condition}]`、`query_string: str`
- `start_time` / `end_time: int`（必填）、`username: str`（可选）
- `ordering` / `page` / `page_size`（`page_size` 上限 5000）、`show_overview` / `show_aggs` / `show_dsl` / `record_history`
- `must_exists_fields`：要求字段存在的过滤

响应（`SearchAlertResource.perform_request` → `handler.search`）：
```json
{ "alerts": [...], "total": 104, "overview": {...}, "aggs": {...}, "dsl": {...} }
```

## 错误与鉴权
- 鉴权：`AlertViewSet.check_permissions` 对 `alert/search` 要求 `VIEW_EVENT` + `VIEW_BUSINESS`；其余读接口要求 `VIEW_EVENT`；并支持负责人/关注人/操作人的有限可见降级（`views.py:104-176`）。
- 参数错误：`validate_fulltext_condition_value_count` 对 `query_string` 条件条数超限抛 `ValidationError`（`serializers.py:68-82`）；`AlertIDField` 校验告警 ID 合法性。
- 查询异常：`search()` 捕获后返回空响应并 `exc.data` 附带部分结果重抛（`alert.py:792-827`），前端可见降级数据而非整页 500。
章节来源：[views.py](file://bkmonitor/packages/fta_web/alert/views.py#L104-L176)、[serializers.py](file://bkmonitor/packages/fta_web/alert/serializers.py#L68-L140)、[alert.py](file://bkmonitor/packages/fta_web/alert/handlers/alert.py#L792-L827)

## 结论
- 查询接口高度统一（同一 `AlertSearchSerializer` + Handler 管线），新增查询端点通常只需在 `views.py` 加 `ResourceRoute` 并复用 `AlertQueryHandler`。
- 鉴权有两层：IAM 动作权限 + 负责人/关注人可见性降级，排查"无权限但能看到自己告警"属预期行为。
- `page_size` 上限 5000、`track_total_hits=10000` 是接口层面的规模护栏。
