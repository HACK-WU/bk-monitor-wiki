## 覆盖与缺口
- **缺口（高危）**：以下核心逻辑无单测保护，改动易引入回归且无告警：
  - `bk_biz_ids=-1` 全业务展开（`BaseBizQueryHandler.parse_biz_item`，`base.py:836-850`）
  - `issue_id` 合并告警展开（`_expand_merged_issue_conditions`，`alert.py:666-700`）
  - `query_string` 解析与全文本分支（`build_query_string_q`，`base.py:401-454`）
  - 状态语义映射（`MINE` / `SHIELDED_ABNORMAL` 等，`alert.py:744-765`）
  - 时间切片交叠过滤（`get_search_object`，`alert.py:702-770`）
- **建议补测优先级（P0）**：`parse_biz_item` 的 `-1` 展开与权限收敛；`query_string` 空串/裸词/结构化三种分支；`issue_id` 展开在合并/非合并下的命中差异。
章节来源：[base.py](file://bkmonitor/packages/fta_web/alert/handlers/base.py#L401-L454)、[base.py](file://bkmonitor/packages/fta_web/alert/handlers/base.py#L836-L850)、[alert.py](file://bkmonitor/packages/fta_web/alert/handlers/alert.py#L666-L765)

## 结论
- 告警查询读路径**测试空白**，是本次专家梳理发现的最高风险点；任何对查询管线 / 业务鉴权 / 合并逻辑的修改都应先补对应单测。
- 建议以 `AlertQueryHandler` 为入口，用 ES 测试索引（或 `mock` `AlertDocument.search`）覆盖上述 P0 场景。
