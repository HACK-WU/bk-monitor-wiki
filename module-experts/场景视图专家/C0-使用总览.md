# 使用总览：场景视图专家

> 契约快照生成于 2026-07-27（commit ca831622）。
> 若使用中发现行为与契约不符，可能代码已变更——expert-lookup 会自动增量修正，或用 expert-team 全量重建。

## 能力清单
模块能干什么：
- **场景管理**：获取业务下的监控场景列表（内置场景 + 自定义场景）
- **视图配置读取**：按 `(bk_biz_id, scene_id, type, id)` 获取单个视图的完整配置（panels/order/variables/options），支持分屏模式
- **视图列表读取**：按 `(bk_biz_id, scene_id, type)` 获取视图列表（含面板数量统计），支持 overview/detail 合并返回
- **视图配置写入**：创建或更新视图配置（含模式/变量/面板/排序/列表配置）
- **视图排序管理**：批量更新视图名称与排序顺序，单视图排序调整（行级锁保证并发安全）
- **视图删除**：按 ID 或 ID 列表删除视图，同步清理排序配置
- **内置视图同步**：读取时自动补齐内置默认视图（JSON 骨架 → DB 双向同步），保证内置视图幂等存在
- **维度查询**：查询视图可用维度列表与维度候选值（基于 MetricListCache + UnifyQuery）
- **表格列表框架**：提供分页/排序/筛选/列格式化通用流水线（`PageListResource` + `TableFormat`）
- **主机进程列表**：聚合 CMDB 进程信息 + 4 路并发 TSDB 查询（端口健康/运行时指标/启动时间/实例数）
- **主机/拓扑详情**：获取主机基础信息、Agent 状态、拓扑归属、进程绑定信息
- **策略与事件计数**：查询指定场景下的策略数和近 1 小时告警事件数
- **多场景内置处理器**：host/kubernetes/uptime_check/apm/alert/custom_metric/custom_event/observation_scene/collect 共 10 种场景处理器

## 能力边界
模块不做什么：
- **不做数据采集**：面板取数通过 UnifyQuery 代理，采集配置归对应采集模块
- **不做告警策略管理**：策略数仅通过 `resource.strategies.get_strategy_list_v2` 查询，策略 CRUD 归策略模块
- **不做 APM 应用管理**：APM 场景变量（apm_app_name 等）作为入参透传，应用管理归 apm_web
- **不做 K8s 资源管理**：K8s 对象列表通过 CMDB/BCS API 查询，资源管理归 kubernetes 模块
- **不做异步任务调度**：`tasks.py` 为空占位，无 Celery 任务
- **不做视图缓存**：内置 JSON 每次读盘无缓存，`_BUILTIN_VIEWS` 变量已声明但未使用

## 已知问题与常见坑
| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| 内置视图被误删 | 某场景的 JSON 骨架文件临时缺失或改名，`create_default_views` 的差集删除逻辑会物理删除 DB 视图行 | 确保 `view_configs/*.json` 文件名与 Processor 的 `filenames` 列表一致后再部署；不要临时移除 JSON 文件 |
| 国际化遗漏 | `_translate_config` 仅翻译 `_(...)` 包裹的字符串，新增 JSON 字段忘加包裹则不翻译 | 在 JSON 骨架中所有需要翻译的字符串均用 `_(...)` 包裹 |
| mode 枚举值不一致 | 模型层 `SceneViewModel.mode` 值为 `auto`，序列化层 `SceneViewSerializer.mode` 值为 `tile`，跨层处理易混 | 读取时注意映射：DB `auto` ↔ API `tile`；写入时 `UpdateSceneViewResource` 使用 `auto`/`custom` |
| 视图类型被忽略 | `apm_application`/`apm_service`/`kubernetes`/`alert` 场景的 `type` 参数被 `validate_scene_type` 强制置空 | 这些场景不需要传 `type` 参数，传了也会被忽略 |
| 重复 IO 开销 | 每次 `load_builtin_views` 都读盘 + 递归国际化翻译 | 高频场景可考虑启用 `_BUILTIN_VIEWS` 模块级缓存（当前未使用） |
| 表格筛选项 O(N) | `get_response_columns` 遍历全量数据构造筛选项，数据量大时性能下降 | 大数据量列表接口考虑分批或前端异步拉取筛选项 |
| 进程列表字段映射 | `GetHostProcessListResource` 的 `runtime_metric_map` 硬编码 UI→TSDB 字段名映射 | 前端字段变更时需同步更新 `runtime_metric_map` |
| memRss/memUsage 单位混淆 | 进程列表字段单位易误判：`memRss`→`system.proc.mem_res`（**字节**，4.5G 即 4.5G）；`memUsage`→`system.proc.mem_usage_pct`（**percentunit 0-1**，0.58=58%） | 进程维度按 percentunit 理解（0.x = xx%）；与主机列表接口同名 `mem_usage`（→`system.mem.pct_used`，percent 0-100，0.58=0.58%）含义完全不同，判读前先确认接口是进程还是主机维度 |
| 进程指标 SUM 聚合语义 | `get_process_runtime_metrics` 对 `mem_res`/`mem_usage_pct` 等用 SUM 聚合，多实例进程值为各实例之和 | 多进程实例场景 `memRss` 是合计值，非单实例 |
