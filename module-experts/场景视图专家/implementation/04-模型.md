## 简介
场景视图的持久化由 3 个 Django ORM 模型承载：`SceneModel`（场景）、`SceneViewModel`（场景视图）、`SceneViewOrderModel`（视图排序）。配置字段大量使用 `JSONField` 存放动态结构（面板/变量/排序/选项），迁移随主应用统一管理。

## 字段与约束
- **唯一性**：`SceneModel` 唯一键 `(bk_biz_id, id)`；`SceneViewModel` 唯一键 `(bk_biz_id, scene_id, type, id)` 且建有同字段联合索引；`SceneViewOrderModel` 唯一键 `(bk_biz_id, scene_id, type)`。
- **视图类型 `type`**：`overview`（概览）/ `detail`（详情），允许空串（apm/kubernetes/alert 场景被 `validate_scene_type` 置空）。
- **运行模式 `mode`**：`SceneViewType` 枚举 `auto`(平铺) / `custom`(自定义)，默认 `auto`。
- **排序更新不变量**：`SceneViewModel.update_order` 用 `@atomic` + `select_for_update` 锁 `SceneViewOrderModel` 行，避免并发下 `config` 顺序错乱。
- **JSONField 设计**：`variables`/`panels`/`list`/`order`/`options` 均为 `JSONField`，无 DB 层结构校验，合法性依赖序列化层和内置 JSON 骨架。
章节来源：[models/scene_view.py](file://bkmonitor/packages/monitor_web/models/scene_view.py#L46-L112)

## 序列化契约
`SceneViewSerializer` 是视图配置的对外契约，字段与 `SceneViewModel` 基本对应：`bk_biz_id/scene_id/id/name/variables/type/mode/order/panels/options`。其中 `variables` 用嵌套 `RowSerializer`（含 `PanelSerializer`），`type` 限 `overview/detail`，`mode` 限 `tile/custom`。面板输出结构则由 `Panel.to_dict` 定义。

`DataSourceSerializer` 是数据源抽象契约，子类 `TimeSeriesDataSourceSerializer` 和 `LogDataSourceSerializer` 分别固定 `datasource` 和 `data_type` 值。
章节来源：[serializers.py](file://bkmonitor/packages/monitor_web/scene_view/serializers.py#L37-L61) · [base.py](file://bkmonitor/packages/monitor_web/scene_view/base.py#L42-L50)

## 结论
模型以「关系键定位 + JSON 存动态配置」为核心设计，灵活但缺乏 DB 层结构校验，配置合法性依赖序列化层与内置 JSON 骨架。注意 `SceneViewModel.mode` 的模型枚举值（`auto`）与 `SceneViewSerializer.mode` 的对外值（`tile`）命名不一致，跨层处理时需留意映射。
