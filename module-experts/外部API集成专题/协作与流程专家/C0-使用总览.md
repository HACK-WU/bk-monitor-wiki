# C0-使用总览：协作与流程专家

## 1. 能力清单

| 能力域 | 入口 | 说明 |
|--------|------|------|
| 缺陷/需求/任务 | `api.tapd.*` | 已授权项目、需求/缺陷/任务 CRUD、模板/字段、webhook、OAuth token |
| Issue 聚合 | `api.issue.*` | 告警聚合 Issue 状态流转（assign/resolve/archive/rename/merge/split 等 12 接口） |
| 审批单 | `api.itsm.*` | 快速审批、审批结果、撤销、token 校验、单状态（5 接口） |
| 消息发送 | `api.cmsi.*` | 邮件/微信/短信/语音/企微机器人/RTX（8 通道） |
| 标准运维 | `api.sops.*` | 项目/模板/流程树/任务创建启动/状态（9 接口） |
| 作业平台 | `api.job.*` | 方案列表/详情/执行/脚本快速执行/实例状态/主机日志（8 接口） |
| 研发流水线 | `api.devops.*` | 用户/应用态项目、流水线列表（4 接口） |
| 企业微信 | `api.bkchat.*` | 通知组/详情/发送消息（3 接口） |
| 故障管理 | `api.bk_incident.*` | 流程模板/任务/诊断面板/故障详情/配置（约 15 接口） |

## 2. 能力边界

- **`api.issue` 是 Issue 专家（fta_web/issue）的外部桥**：web 端 `RenameIssueResource` 经 `api.issue.rename` 转发到 kernel_api（详见 Issue 专家）。
- **`tapd` 认证特殊**：`TapdAPIResource` 用 contextvar 管理 `access_token`，Basic（APP_ID:SECRET）与 Bearer（access_token）双模式。
- **`devops` 依赖 Cookie**：从 Cookie `bk_ticket` 取用户态票据注入请求，未部署时抛 `DevopsNotDeployedError`。
- **`cmsi` 通道多**：apigw/esb 动态切换 + 8 种通知通道，`GetMsgType` 补虚拟通道（wxwork-bot/bkchat）。

## 3. 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| tapd 401 | access_token 过期 / 未传 | `UserOauthTokenResource` 用 code 换 token；`perform_request` 会 pop `access_token` 参数仅用于认证头 |
| tapd 返回 status!=1 | 上游业务失败 | `render_response_data` 已抛 `BKAPIError`（code=status/message=info） |
| itsm 审批人错误 | 未注入正确用户名 | `ITSMBaseResource.full_request_data` 设 `bk_username=COMMON_USERNAME` |
| sops/job 权限不足 | 无执行权限 | `perform_request` 有权限码 3599999/`APIPermissionDeniedError` 重试/兜底逻辑 |
| devops 未部署 | 环境未装 BKCI | 抛 `DevopsNotDeployedError`，调用方需捕获 |
| bk_incident 参数错误 | 业务 ID 未转换 | `perform_request` 自动 `bk_biz_id→scope_value`、`bk_biz_id_list→scope_id_list` 转换 |
