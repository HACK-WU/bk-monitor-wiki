## tapd access_token 管理实现

`TapdAPIResource`（源码 confirmed）：
- 模块级 `tapd_access_token = contextvars.ContextVar("tapd_access_token", default="")`。
- `perform_request`：`access_token = validated_request_data.pop("access_token", "")`（避免污染 body）→ `tapd_access_token.set(token)` → `try/finally: tapd_access_token.reset(token)`。
- `get_headers`：`token = tapd_access_token.get()`；非空 → `Bearer {token}`；空 → base64(`TAPD_APP_ID:TAPD_APP_SECRET`) → `Basic {encoded}`。
- `render_response_data`：`status != "1"` → 构造 BKAPIError（code=status/message=info/data=data）+ `report_api_failure_metric`；成功返回 `response_data["data"]`。

章节来源：[api/tapd/default.py](file://bkmonitor/api/tapd/default.py)（关键符号：`tapd_access_token` / `TapdAPIResource.get_headers`）

## cmsi 通道切换实现

`CMSIBaseResource`（源码 confirmed）：
- `base_url` 为 property：apigw（`cmsi_gateway_url`）/ esb（`cmsi_esb_url`）/ 自定义间动态切换。
- `use_apigw` / `switch_apigw` / `switch_esb` / `switch_default` + `gateway_type` 实例态。
- 各通道 Resource 覆写 `render_response_data` 或 `perform_request` 归一化返回：`CheckCMSIResource`（`username_check.invalid/message`）、`GetMsgType`（补 `wxwork-bot`/`bkchat` 虚拟通道 + is_active 适配）、`SendMail`（内外部用户 `@tai` 分流）。

章节来源：[api/cmsi/default.py](file://bkmonitor/api/cmsi/default.py)（关键符号：`CMSIBaseResource` / `GetMsgType`）

## 结论

协作流程封装的差异集中在"认证（contextvar/凭证/票据）+ 响应适配（非标准格式/参数转换）"。排查问题按"认证 → URL → 参数转换 → 响应适配"四步定位。
