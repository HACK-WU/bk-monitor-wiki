# C0-使用总览：基础平台与网关专家

## 1. 能力清单

| 能力域 | 入口 | 说明 |
|--------|------|------|
| 用户/租户 | `api.bk_login.*` | 租户列表、用户列表/详情、部门、虚拟用户、租户变量、用户展示信息、敏感信息（unity-user） |
| 应用信息 | `api.bk_paas.*` | 蓝鲸应用集群命名空间 |
| 插件能力 | `api.bk_plugin.*` | 插件元信息/表单/执行/调度/部署信息（含系统级插件查询） |
| 权限中心 | `api.iam.*` | 批量实例授权 |
| API 网关 | `api.bk_apigateway.*` | 获取 apigw 公钥（`GetPublicKeyResource`，认证用） |
| 文档中心 | `api.bk_docs_center.*` | 按路径取文档链接 |
| 公共基类 | `common/default.py` | `CommonBaseResource`：动态 URL 渲染 + BKAPIError 统一包装 |

## 2. 能力边界

- **不含** CMDB/容器/数据平台/协作/监控等其他外部系统（见专题其他专家）。
- **`common/` 不是全量基类**：多数系统自建基类；`CommonBaseResource` 是"动态 URL + 统一异常"模板，按需选用。
- **`bk_login` 双模式**：`use_apigw()` 按 `ENABLE_MULTI_TENANT_MODE` 切换 ESB（compapi）与 apigw 两条 base_url/action。

## 3. 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| `api.bk_login` 返回 ESB 路径而非 apigw | 多租户未开启时 `use_apigw()` 为 False | 确认 `ENABLE_MULTI_TENANT_MODE` 配置；action 路径两套不同 |
| 插件调用鉴权失败 | `BkPluginSystemResource` 需插件独立凭证 | 确认 `settings.BK_PLUGIN_APP_INFO`（插件凭证）配置；该类覆写 get_headers 替换 x-bkapi-authorization |
| 上游返回"权限不足" | `result_json["code"]` 命中 `APIPermissionDeniedCodeList`（9900403 等） | 框架自动抛 `APIPermissionDeniedError`；按权限中心授权处理 |
| 错误信息为"第三方系统异常" | `CommonBaseResource` 捕获 BKAPIError 后重写 | 上游错误在 `api_error.data["message"]`；`system_name=plugin_key`、`url=url_path` 定位到具体第三方 |
