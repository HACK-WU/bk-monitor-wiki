## CommonBaseResource 动态 URL 实现

`__init__`（源码 confirmed）：
1. `self.url = Jinja2Renderer.render(self.url, {"bk_paas_inner_host": "", ...})`——占位符置空版本（报错展示用）。
2. `self.base_url = Jinja2Renderer.render(self.url, {"bk_paas_inner_host": settings.BK_COMPONENT_API_URL.rstrip("/"), "bk_paas_host": settings.BK_PAAS_HOST..., "itsm_v4_api_url": settings.BK_ITSM_V4_API_URL...})`——完整替换版本（实际请求用）。
3. `self.method` / `self.plugin_key = self.module_name`。

`perform_request`：`params.pop("action_plugin_key", None) or self.plugin_key`；`params["_origin_user"] = get_global_user()`；`except BKAPIError` → 以 `system_name=self.plugin_key, url=self.url_path, result=str(error_message)` 重抛。

章节来源：[api/common/default.py](file://bkmonitor/api/common/default.py)（关键符号：`CommonBaseResource.__init__` / `perform_request`）

## bk_login 双模式实现

`BkUserApiResource`（源码 confirmed）：
- `use_apigw()` 返回 `settings.ENABLE_MULTI_TENANT_MODE`。
- `base_url` 为 `@property`：apigw → `BK_USER_API_BASE_URL or {BK_COMPONENT_API_URL}/api/bk-user/prod/`；ESB → `{BK_COMPONENT_API_URL}/api/c/compapi/v2/usermanage/`。
- `get_request_url` 对 URL 做 `.format(**params)`。
- 子类 action 双份：如 `GetUserInfo` 在 apigw 用 `/api/v3/open/tenant/users/{bk_username}/`、ESB 用 `/retrieve_user/`。
- 单租户下 `ListTenantResource.perform_request` 直接返回默认租户（不请求远端）。

章节来源：[api/bk_login/default.py](file://bkmonitor/api/bk_login/default.py)（关键符号：`BkUserApiResource` / `ListTenantResource`）

## bk_plugin 凭证替换实现

`BkPluginSystemResource`（源码 confirmed）：
- `get_headers()`：调 super 拿到 `x-bkapi-authorization`（JSON 串），解析后把 `bk_app_code`/`bk_app_secret` 替换为 `settings.BK_PLUGIN_APP_INFO`，再序列化写回。
- `IS_STANDARD_FORMAT=False`：插件系统返回非标准 envelope，由 `render_response_data` 适配。

`BkPluginBaseResource.full_request_data`：注入 `settings.BK_PLUGIN_APP_INFO`。

章节来源：[api/bk_plugin/default.py](file://bkmonitor/api/bk_plugin/default.py)（关键符号：`BkPluginSystemResource.get_headers`）

## 结论

基础平台封装核心是"基类 + 覆写点"：动态 URL（common）、双模式切换（bk_login）、凭证替换（bk_plugin），其余系统为薄封装。排查调用失败按"base_url 模式 → 认证头 → action 路径"三步定位。
