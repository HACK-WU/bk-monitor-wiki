# C0-使用总览：数据平台专家

## 1. 能力清单

| 能力域 | 入口 | 说明 |
|--------|------|------|
| BKData 计算平台 | `api.bkdata.*` | 结果表查询/批量拉取、数据查询（SQL，token/user 双鉴权）、数据链路、DataFlow 创建/查询、数据接入、降精度、时序/维度（约 60 类） |
| 监控元数据 | `api.metadata.*` | 数据源/结果表/存储详情/集群信息/事件分组/时序分组/空间（约 70 类，走 bk-monitor 自身 `metadata_v3` 网关） |
| 统一查询 | `api.unify_query.*` | 时序/指标查询（结构化/PromQL/原始/参考）、维度/标签/序列发现、结构化↔PromQL 互转、K8s 关联、exemplar（18 类，自建 HTTP 网关） |
| 日志检索 | `api.log_search.*` | DSL/搜索查询、索引集 CRUD、场景化检索、采集器、自定义上报、Grafana 对接、日志抽取（约 30 类） |
| AIOps 推理 | `api.aiops_sdk.*` | 时序（Tf）/异常检测（Kpi）/离群（Acd）三个分支的预测/分组预测/初始化（9 类） |

## 2. 能力边界

- **unify_query 非 APIGW**：直接继承 `Resource`，用 `requests` 调 unify-query 服务（非 `APIResource`），带空间/租户路由头。
- **metadata 走自身网关**：`MetaDataAPIGWResource(KernelAPIResource)` 调 bk-monitor 自身 apigw（`api/bk-monitor/{stage}/`），module_name=`metadata_v3`。
- **bkdata 认证特殊**：`UseSaaSAuthInfoMixin` 注入 SaaS 侧 `SAAS_APP_CODE`/`SAAS_SECRET_KEY`；`QueryDataResource` 支持 token/user 双模式。
- **无空间路由 vs 有空间路由**：log_search 仅按 `bk_biz_id`；unify_query 按 `space_uid`/`bk_biz_ids`/`bk_tenant_id` 路由。

## 3. 已知问题与常见坑

| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| bkdata 查询鉴权失败 | 企业版后台 AppCode 独立 | 用 `UseSaaSAuthInfoMixin` 注入 `SAAS_APP_CODE`/`SAAS_SECRET_KEY`（`full_request_data`/`get_headers` 双处） |
| bkdata 查询报 token 错误 | `QueryDataResource` 无 `BKDATA_DATA_TOKEN` 且非 user 模式 | 配置 `BKDATA_DATA_TOKEN` 或 `_user_request=True`（user 模式走 `COMMON_USERNAME`） |
| unify_query 路由错误 | `space_uid` 未正确传入 | 确认 `UNIFY_QUERY_ROUTING_RULES` 与 `get_unify_query_url`；请求头带 `X-Bk-Scope-Space-Uid` |
| log_search 索引集路径错误 | `index_set_id` 未 pop 出 | `IndexSetResource` 子类会 `pop` 出 `index_set_id` 并 format 进 action URL |
| metadata 结果表查询慢 | 批量查询 | 用 `QueryEventGroupResource`/`QueryTimeSeriesGroupResource`（CacheResource + batch_request 分包） |
| AIOps 灰度切换 | `serving_config.grey_to_bkfara` | `BKFaraGrayMixin` 自动切换请求地址与 action 路径 |
