## 简介

本文件拆解数据平台封装的四个关键实现（SaaS 认证注入 / 双鉴权 / 空间路由 / index_set 路径）。

章节来源：[api/bkdata/default.py](file://bkmonitor/api/bkdata/default.py)（关键符号：`UseSaaSAuthInfoMixin`）

## UseSaaSAuthInfoMixin 实现

`UseSaaSAuthInfoMixin`（源码 confirmed）：
- `full_request_data`：调 super 后注入 `validated_request_data["bk_app_code"] = settings.SAAS_APP_CODE`。
- `get_headers`：取 `x-bkapi-authorization`（JSON），注入 `bk_app_code=SAAS_APP_CODE` 与 `bk_app_secret=SAAS_SECRET_KEY`，序列化写回。
- 目的：计算平台按 AppCode 分配 data token，企业版后台/Web AppCode 独立时需 SaaS 侧应用凭证。

章节来源：[api/bkdata/default.py](file://bkmonitor/api/bkdata/default.py)（关键符号：`UseSaaSAuthInfoMixin.full_request_data`）

## QueryDataResource 双鉴权实现

`QueryDataResource`（源码 confirmed）：
- `_user_request=True` → user 模式：`bk_username=COMMON_USERNAME`。
- 否则：有 `BKDATA_DATA_TOKEN` → `bkdata_authentication_method="token"` + `bkdata_data_token`；无 → 回退 user 模式。
- `BkDataAPIGWResource` 基类自身也在 `full_request_data` 注入 `bk_app_code`。

章节来源：[api/bkdata/default.py](file://bkmonitor/api/bkdata/default.py)（关键符号：`QueryDataResource`）

## unify_query 空间路由实现

`UnifyQueryAPIResource`（源码 confirmed）：
- `method`/`path` 空串由子类填。
- `get_unify_query_url(space_uid)`：按 `UNIFY_QUERY_ROUTING_RULES` 路由到 `UNIFY_QUERY_URL`。
- `perform_request`：注入请求头 `Bk-Query-Source`（来源追踪）、`X-Bk-Scope-Space-Uid`、`X-Bk-Scope-Skip-Space`、`X-Bk-Tenant-Id`；超时 60s。

章节来源：[api/unify_query/default.py](file://bkmonitor/api/unify_query/default.py)（关键符号：`UnifyQueryAPIResource`）

## log_search index_set 路径实现

`IndexSetResource` 子类（源码 confirmed）：
- `get_request_url` 从请求数据 `pop` 出 `index_set_id` 并 `format` 进 action URL（如 `/index_set/{index_set_id}/search/`）。
- 多个 `{collector_config_id}`/`{task_id}` 类同——路径参数先 pop 再 format。

章节来源：[api/log_search/default.py](file://bkmonitor/api/log_search/default.py)（关键符号：`IndexSetResource`）

## 结论

数据平台封装的差异集中在"认证注入（SaaS/token/user）"与"路由（空间/index_set 路径）"。排查问题按模块形态（APIGW vs 直连）定位认证与 URL 生成逻辑。
