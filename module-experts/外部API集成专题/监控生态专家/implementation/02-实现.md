## 简介

本文件拆解监控生态封装的三个关键实现（grafana 直连 / exporter 模板化 / aidev 流式）。

章节来源：[api/grafana/default.py](file://bkmonitor/api/grafana/default.py)（关键符号：`GrafanaApiResource`）

## grafana 直连实现

`GrafanaApiResource`（源码 confirmed）：
- 类属性 `method`/`path`/`with_org_id` 驱动请求。
- `perform_request`：`requests` 拼接 `settings.GRAFANA_URL` + `path` 发原生 HTTP；注入 `X-WEBAUTH-USER`（请求用户）与 `X-Grafana-Org-Id`（`with_org_id=True` 时从参数读 org_id）；返回统一信封 `{result, code, message, data}`。

章节来源：[api/grafana/default.py](file://bkmonitor/api/grafana/default.py)（关键符号：`GrafanaApiResource.perform_request`）

## exporter 模板化实现

`DashboardExporter`（源码 confirmed）：
- `templateize_datasource`：把面板/变量/查询里的数据源引用替换为 `$DS_xxx` 模板变量，生成 `__inputs`/`__requires` 元数据与 `datasource_mapping` 映射。
- `replace_table_id_with_data_label`：结果表 ID → data_label。
- `make_exportable`：遍历 templating 变量与 panels，清理 `id`/`uid`，输出可导入的仪表盘模板。

章节来源：[api/grafana/exporter.py](file://bkmonitor/api/grafana/exporter.py)（关键符号：`DashboardExporter.make_exportable`）

## aidev 流式实现

`CreateKnowledgebaseQueryResource`（源码 confirmed）：
- `IS_STANDARD_FORMAT=False`、`INSERT_BK_USERNAME_TO_REQUEST_DATA=False`。
- `handle_stream_response`：知识库问答流式响应，返回 `StreamingHttpResponse`。
- `ChatCompletionResource.get_headers`：切换 `AIDEV_AGENT_APP_CODE` 凭据（区别于基类 `BK_PLUGIN_APP_INFO`）。

章节来源：[api/aidev/default.py](file://bkmonitor/api/aidev/default.py)（关键符号：`ChatCompletionResource` / `CreateKnowledgebaseQueryResource`）

## 结论

监控生态封装的关键差异：grafana 直连（无 APIResource 封装）、exporter 工具类（非 API）、aidev 流式（StreamingHttpResponse）。排查问题先判断所属形态。
