## 能力清单
模块能干什么：
- **主机列表聚合**：获取业务下全量主机的基础信息 + 性能指标 + Agent 状态 + 进程 + 告警计数（走 `HOST` 缓存）
- **主机详情**：获取单台主机的基础信息 + 拓扑归属 + Agent 状态 + 业务名
- **拓扑节点详情**：获取拓扑节点的主机数 + 告警数 + 策略数 + 负责人
- **拓扑节点进程列表**：获取拓扑节点下所有进程名列表（status 置灰 UNKNOWN）
- **主机基础信息查询**：获取业务下全量主机的基础信息 + 模块拓扑链
- **主机实时指标查询**：按 `bk_host_ids` 精确查询 Agent 状态 + 性能指标 + 进程 + 告警计数（无缓存，支持时间范围）
- **多源并行聚合**：通过 `ThreadPool` 4 路并发拉取 CMDB + TSDB + Agent 状态 + 告警，缩短响应时间
- **主机列表按页加载**：`SearchHostInfoResource` 传 `page/page_size` 时改走 `api.cmdb.get_host_page`，由 CMDB 端完成过滤与分页，只实例化本页主机；拓扑只为本页模块构造路径
- **性能卡片统计**：`SearchHostMetricStatsResource` 按节点范围单次 instant UQ 查询，一次算出「超阈值主机数 + 身份完整性」，供 CPU/内存/磁盘三张卡片在页级阶段就展示
- **主机身份白名单**：`api.cmdb.get_host_identities` 复用业务主机预热缓存（`cmdb_api_list`）输出统计所需身份，不发额外 CMDB 请求

## 能力边界
模块不做什么：
- **不做数据持久化**：`models.py` 为空，所有数据为运行时聚合
- **不做采集配置管理**：仅读取 TSDB 性能指标，采集配置归采集模块
- **不做告警策略管理**：仅查询策略数量和告警计数，策略 CRUD 归策略模块
- **不做拓扑树管理**：拓扑树由 CMDB API 提供，本模块仅读取和组装
- **不做进程实时状态查询**：`TopoNodeProcessStatusResource` 硬编码 status 为 `UNKNOWN`，不查实时状态
- **不做缓存管理**：`HOST` 缓存由 `CacheResource` 框架自动管理，模块内无主动刷新/失效逻辑
- **不做超时熔断**：`ThreadPool` 并行无独立超时控制，单源慢会拖慢整体
- **不做前端分页/全量接替**：页级与全量数据的编排、Worker 三级缓存、「翻页只切片」都在前端（`webpack/src/trace/pages/host`），本模块只提供页级与全量两类接口
- **不接受任意查询表达式**：统计接口 `category` 仅 `cpu`/`mem`/`disk` 白名单，表达式由 `host_metric_stats.py` 固定拼装
- **不负责进程/告警的历史版本**：页级与统计路径同样只读当前 CMDB 快照与所选时间窗内的 TSDB 数据

## 已知问题与常见坑
| 现象 | 触发条件 | 正确做法 |
|------|----------|----------|
| 主机列表数据不实时 | `HostPerformanceResource` 走 `HOST` 缓存，缓存未失效时返回旧数据 | 需要实时数据时用 `SearchHostMetricResource`（无缓存） |
| 告警数据静默缺失 | `SearchHostMetricResource.get_alarm_count` 有 `try/except` 降级，异常时 `alarm_count` 为空列表且仅记日志 | 排查告警缺失时检查日志中 `get_alarm_count failed` 异常 |
| 告警异常中断聚合 | `HostPerformanceResource.get_alarm_count` 无 `try/except`，告警查询异常会中断整个 `ThreadPool.join` | 与 `SearchHostMetricResource` 版本不一致，修改时注意同步 |
| 进程 component 字段差异 | `HostPerformanceResource` 版含 `ports`/`protocol`，`SearchHostMetricResource` 版不含 | 跨接口消费时注意字段差异 |
| 拓扑进程状态全置灰 | `TopoNodeProcessStatusResource` 硬编码 `status=AGENT_STATUS.UNKNOWN`，不查实时状态 | 这是设计如此，不是 bug |
| ~~权限缺失~~（已修复，条目过期） | ~~`SearchHostInfoViewSet` 未继承 `PermissionMixin`~~ | 2026-08-12 的 commit 24f090ed5e 已补齐，**当前 6 个 ViewSet 全部继承 `PermissionMixin`**；分享场景另有 `validate_scope_host_ids` 做 host_ids 越权校验。详见 [C5-关键决策.md](C5-关键决策.md) 决策 10 |
| 拓扑节点 child_count 逻辑 | `bk_obj_id == "module"` 时 `child_count` 取 `len(hosts)`，否则取 `len(node.child)` | 模块层级和上层节点含义不同 |
| 并行无超时 | `ThreadPool` 4 路并行任一路慢会拖慢整体响应 | 依赖 TSDB/CMDB 自身的超时机制 |
| `get_process_status` 代码重复 | `HostPerformanceResource` 和 `SearchHostMetricResource` 各有一份，逻辑近乎相同 | 修改一处时注意同步另一处 |
| 同一接口两种响应结构 | `SearchHostInfoResource` 传 `page/page_size` 返回 `{items,total,page,page_size}`，不传返回数组 | 消费方必须先判断是否带分页参数；`page`/`page_size` 必须成对，否则 `InvalidParamsError` |
| 统计卡片显示「未知」 | 查询 `partial`、结果非有限值、字段缺失，或身份歧义（`duplicates>0` / id_count 与 ip_count 同时非 0 / ip_count 且该主机 `has_duplicate_ip`） | 这是**故意的 fail-safe**：显示未知而不是误报 0，排查时先看 `complete`/`reason`，不要当成数据为 0 |
| `GetHostIdentities` 缓存失效（性能退化） | 预热缓存键为 `(bk_biz_id, Host.Fields)` 位置参数，调用方式或字段集变化会另建缓存键 | 修改调用参数前先确认 `cmdb_api_list` 预热位置参数一致，否则统计会退化为全量回源 |
| `GetProcess(bk_host_ids)` 不生效 | 仅当 `push_host_target=True` **且** `bk_host_id` 为空（页级多主机场景）时才下发 `bk_host_ids` | 单主机/全量路径行为不变，改动时不要顺手加到所有分支 |
| `GetTopoTreeResource(raw=True)` 返回类型不同 | `raw=True` 直接返回原始 dict（不构造 `TopoTree`） | 只有 dict 时才能喂给 `TopoTree.module_links_from_raw`；调用 `convert_to_topo_link()` 会报错 |
| 页级模式部分能力暂不可用 | 全量数据未就绪期间，前端故意禁用全局排序/过滤/置顶/跨页全选/全局搜索 | 属设计行为（避免前后端口径不一致）；已保存条件会暂存并在全量就绪后自动生效 |
| 分享列表接口只校验一页 | `HostApiAuthChecker` 对两个列表接口只取 `page=1,page_size=1` 做存在性校验 | 新增列表类分享接口必须同步登记 `HOST_LIST_ACTIONS`，否则会退化为「拉全量再校验」；后代节点放行仅限 stats 与带 page 的 info，其余仍 fail-close |
