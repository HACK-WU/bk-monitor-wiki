## 加载主机列表页：前端主机场景页首次渲染
- **调用顺序**：
  1. 调用 `resource.performance.host_performance(bk_biz_id=2)` 获取全量主机列表（走缓存）
  2. 前端按 `status`/`cpu_usage`/`mem_usage` 等字段渲染列表
- **事务边界**：无事务（纯读 + 缓存）
- **预期结果**：返回 `{hosts, update_time}`，每台主机含基础信息 + 性能指标 + Agent 状态 + 进程 + 告警
- **错误处理**：各 fetch 静态方法对缺失 host 做 continue 跳过；`get_alarm_count` 无降级（异常会中断聚合）
- **使用示例**：
  ```python
  result = resource.performance.host_performance(bk_biz_id=2)
  # => {"hosts": [{"bk_host_id": 11, "cpu_usage": 12.3, "status": 1, ...}], "update_time": "2026-07-27 10:00:00+0800"}
  ```

## 查询指定主机实时指标：前端主机详情页/刷新场景
- **调用顺序**：
  1. 调用 `resource.performance.search_host_metric(bk_biz_id=2, bk_host_ids=[11])` 获取实时指标
  2. 可选传 `start_time`/`end_time` 指定时间范围
- **事务边界**：无事务（纯读，无缓存）
- **预期结果**：返回 `{bk_host_id: {status, cpu_usage, mem_usage, ..., component, alarm_count}}`
- **错误处理**：`get_alarm_count` 有 `try/except` 降级，异常时 `alarm_count` 为空列表
- **使用示例**：
  ```python
  # 默认最近三分钟
  metrics = resource.performance.search_host_metric(bk_biz_id=2, bk_host_ids=[11])
  # => {11: {"status": 1, "cpu_usage": 12.3, "component": [...], "alarm_count": [...]}}

  # 指定时间范围
  metrics = resource.performance.search_host_metric(
      bk_biz_id=2, bk_host_ids=[11], start_time=1722000000, end_time=1722000180
  )
  ```

## 获取拓扑节点详情：前端拓扑树点击节点
- **调用顺序**：
  1. 调用 `resource.performance.host_topo_node_detail(bk_biz_id=2, bk_obj_id="module", bk_inst_id=100)` 获取节点详情
  2. 可选调用 `resource.performance.topo_node_process_status(bk_biz_id=2, bk_obj_id="module", bk_inst_id=100)` 获取进程列表
- **事务边界**：无事务（纯读）
- **预期结果**：节点详情含主机数/告警数/策略数/负责人；进程列表含去重后的进程名（status 置灰）
- **错误处理**：无异常抛出
- **使用示例**：
  ```python
  # 获取节点详情
  detail = resource.performance.host_topo_node_detail(bk_biz_id=2, bk_obj_id="module", bk_inst_id=100)
  # => {"host_count": 5, "alarm_count": 3, "operator": ["admin"], "alarm_strategy": {"enabled": 2, "disabled": 1}, ...}

  # 获取进程列表
  processes = resource.performance.topo_node_process_status(bk_biz_id=2, bk_obj_id="module", bk_inst_id=100)
  # => [{"status": 0, "display_name": "nginx", "ports": [], "protocol": ""}]
  ```

## 扩展主机列表返回字段：新增聚合字段
- **调用顺序**：
  1. 在 `HostPerformanceResource.perform_request` 的 `host_dict` 默认值中添加新字段（默认 `None`）
  2. 新增静态 fetch 方法（或修改现有方法）拉取新字段数据
  3. 在 `ThreadPool` 注册新方法（如 `pool.apply_async(self.get_new_field, args=(...))`）
  4. 如需实时查询也支持，在 `SearchHostMetricResource` 同步添加
- **事务边界**：无事务
- **预期结果**：主机列表返回结果中包含新字段
- **错误处理**：新 fetch 方法应对缺失 host 做 continue 跳过
- **使用示例**：
  ```python
  # Step 1: 在 host_dict 默认值中添加
  "new_field": None,

  # Step 2: 新增静态方法
  @staticmethod
  def get_new_field(bk_biz_id, hosts, data):
      result = resource.cc.get_new_field(bk_biz_id=bk_biz_id, hosts=hosts)
      for bk_host_id, value in result.items():
          if bk_host_id not in data:
              continue
          data[bk_host_id]["new_field"] = value

  # Step 3: 注册到 ThreadPool
  pool.apply_async(self.get_new_field, args=(bk_biz_id, hosts, host_dict))
  ```

## 获取主机详情：前端主机详情页加载
- **调用顺序**：
  1. 调用 `resource.performance.host_performance_detail(bk_biz_id=2, bk_host_id=11)` 获取主机详情
- **事务边界**：无事务（纯读，无缓存）
- **预期结果**：返回单台主机的基础信息 + 拓扑归属 + Agent 状态 + 业务名
- **错误处理**：主机不存在时抛 `CustomException(f"host({bk_host_id}) not found")`
- **使用示例**：
  ```python
  detail = resource.performance.host_performance_detail(bk_biz_id=2, bk_host_id=11)
  # => {"bk_host_id": 11, "bk_host_innerip": "10.0.0.1", "status": 1, "bk_biz_name": "蓝鲸", "module": [...]}
  ```

## 加载新版主机列表：按页加载 + 全量接替（2026-09 新增）
- **调用顺序**（前端一次 `loadData()` 并发三条链）：
  1. **页链**：`search_host_info(bk_biz_id, page, page_size[, 范围])` → 先渲染本页基础行（指标列骨架）→ `search_host_metric(bk_biz_id, bk_host_ids=本页IDs, start_time, end_time)` 填本页指标
  2. **全量链**：`search_host_info(bk_biz_id)`（无 page，保持数组响应）+ `search_host_metric(...)`（普通业务省略 IDs；分享/明确 ID 场景带 IDs）→ 交给前端 Worker `INIT_BASE` / `MERGE_METRICS` / `COMPUTE`
  3. **卡片链**：`search_host_metric_stats(bk_biz_id, category, 范围, start_time, end_time)` × 3（cpu/mem/disk），互相独立失败与重试
- **事务边界**：无事务（纯读；无写操作、无缓存写）
- **预期结果**：页级先出屏；全量算完后表格与统计卡片**在同一轮提交中接替**，页级与单卡响应全部失效；全量失败时仍可按页浏览
- **错误处理**：三类请求按「整轮 / 页 / 指标 / 全量 / 视图 / 单卡」六层代次拒绝迟到响应；全量失败回落到页级态并提示；单卡失败显示 `--` 并可单独重试
- **注意**：全量未就绪期间，服务端不禁止排序/过滤请求，但前端禁用这些入口（依赖全量集合才能给出一致结果）；已保存条件会暂存并在全量就绪后生效

## 查询单张性能卡片统计：页级阶段展示 CPU/内存/磁盘超阈值数（2026-09 新增）
- **调用顺序**：
  1. 调用 `search_host_metric_stats(bk_biz_id=2, category="cpu", bk_obj_id="module", bk_inst_id=100)` 获取单卡统计
  2. 传 `start_time`/`end_time`（必须成对）复用列表的时间锚点，否则按当前时间取 180s 窗口
- **事务边界**：无事务（单次 instant UQ 查询）
- **预期结果**：`{"category": "cpu", "value": 12, "complete": True}`；若身份歧义/部分失败 → `{"value": None, "complete": False, "reason": "ambiguous_identity"}`
- **错误处理**：查询异常按标准路径上抛（不重试、不回退原生查询），由前端单卡重试；`reason` 供前端决定是否展示「未知」
- **使用示例**：
  ```python
  stats = resource.performance.search_host_metric_stats(
      bk_biz_id=2, category="cpu", bk_obj_id="module", bk_inst_id=100,
      start_time=1722000000, end_time=1722000180,
  )
  # => {"category": "cpu", "value": 12, "complete": True}
  ```
