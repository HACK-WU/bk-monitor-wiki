## 简介
性能场景模块是纯聚合层，自身无持久化，数据流为「请求 → 多源拉取 → 内存聚合 → 响应」的单向管道。两条主干：列表路径走 `HOST` 缓存 → 缓存未命中时全量拉取；详情/指标路径为实时查询无缓存。**2026-09 起新增第三条主干：页级加载（CMDB 端分页 + 本页指标 + 目标模块路径）与卡片统计（单次 instant 表达式）**，两者都不落缓存、不出本进程。
章节来源：[resources.py](file://bkmonitor/packages/monitor_web/performance/resources.py#L43-L472) · [resources.py](file://bkmonitor/packages/monitor_web/performance/resources.py#L313-L435)

## 数据生命周期
```mermaid
flowchart TD
  In[HTTP 请求] --> VS[ViewSet 鉴权 VIEW_HOST]
  VS --> RS[RequestSerializer 校验]
  RS --> PR[Resource.perform_request]
  PR -->|HostPerformanceResource| Cache{HOST 缓存命中?}
  Cache -->|是| Out1[返回缓存数据]
  Cache -->|否| CMDB1[api.cmdb.get_host_by_topo_node 拉主机]
  CMDB1 --> CMDB2[api.cmdb.get_topo_tree 拓扑链]
  CMDB2 --> HD[构造 host_dict 默认值]
  HD --> TP[ThreadPool 4 路并行填充]
  TP --> Out2[返回 hosts + update_time\n同时写入 HOST 缓存]
  PR -->|SearchHostMetricResource| CMDB3[api.cmdb.get_host_by_id 精确拉主机]
  CMDB3 --> TP2[ThreadPool 4 路并行填充\n支持 start_time/end_time]
  TP2 --> Out3[返回 data 字典\n无缓存]
  PR -->|SearchHostInfoResource 带 page 2026-09| HP[api.cmdb.get_host_page\nCMDB 端过滤 + 分页]
  HP --> HP2[TopoTree.module_links_from_raw\n只建本页模块路径]
  HP2 --> Out4[返回 items + total + page + page_size]
  PR -->|SearchHostMetricStatsResource 2026-09| HI[api.cmdb.get_host_identities\n预热缓存身份 + has_duplicate_ip]
  HI --> ST[单次 instant UQ 表达式\n180s 窗口]
  ST --> Out5[value/id_count/ip_count/duplicates\n→ complete / reason]
```
读路径要点：`HostPerformanceResource` 走缓存，缓存 key 为 `CacheType.HOST` + `bk_biz_id`；`SearchHostMetricResource` 每次实时查。聚合结果在内存中以 `host_dict`（`dict[int, dict]`）为容器，各 fetch 静态方法原地 `update` 填充。

## 状态与数据变换关键节点
- **host_dict 初始化**：每台主机默认值 `status=AGENT_STATUS.UNKNOWN`、`cpu_usage/mem_usage/io_util/disk_in_use/cpu_load/psc_mem_usage=None`、`component=[]`、`alarm_count=[]`，保证缺失数据有兜底值。
- **Agent 状态填充**：`get_agent_status` 调 `resource.cc.get_agent_status` 获取 `{bk_host_id: status}` 映射，按 ID 匹配覆盖 `data[bk_host_id]["status"]`。
- **性能指标填充**：`get_performance_data` 调 `resource.cc.get_host_performance_data` 获取 `{bk_host_id: {cpu_usage, mem_usage, ...}}`，按 ID 匹配 `data[bk_host_id].update(metrics)` 原地覆盖 `None` 值。
- **进程信息填充**：`get_process_status` 调 `resource.cc.get_process_info` 获取 `{bk_host_id: [process_dict]}`，映射为 `component` 列表。
- **告警计数填充**：`get_alarm_count` 调 `resource.cc.get_host_alarm_count` 获取 `{bk_host_id: {level: count}}`，转为 `[{level, count}]` 按 level 排序。
- **拓扑链构造**：`SearchHostInfoResource.get_module_info` 按 `bk_module_ids` 在 `topo_links` 中查找，输出 `topo_link`（`bk_obj_id|bk_inst_id` 列表，reversed 根节点在前）和 `topo_link_display`（节点名列表）。
- **缓存写入**：`HostPerformanceResource` 继承 `CacheResource`，`perform_request` 返回后自动写入 `HOST` 缓存。
- **页数据变换（2026-09）**：CMDB 过滤 + 分页 → `GetHostPage` 只实例化本页 `Host` → 本页模块 ID 集合 → `TopoTree.module_links_from_raw` 产出本页模块路径 → `get_module_info(..., module_cache)` 组装 `module` 字段 → `{items, total, page, page_size}`；页内指标由前端再用本页 IDs 请求 `search_host_metric`。
- **统计量变换（2026-09）**：`GetHostIdentities` 取身份（无新 CMDB 请求）→ `build_host_stats_query` 组 a/b 两数据源 → 一次 instant 查询 → 四量 `value/id_count/ip_count/duplicates` → 完整性判定 → `{value, complete, reason}`；**「未知」是显式终态，不落任何缓存**。
- **口径对齐锚点（2026-09）**：统计复用列表的 instant 时间对齐、设备过滤与 180 秒窗口；阈值 79.995 与 Python `round(v, 2) >= 80` 等价——即**卡片与列表的数值必须同源可对拍**。
章节来源：[resources.py](file://bkmonitor/packages/monitor_web/performance/resources.py#L79-L127) · [resources.py](file://bkmonitor/packages/monitor_web/performance/resources.py#L286-L310)

## 异步流
模块自身无 Celery 定时任务/队列/回调。`ThreadPool` 并行是同请求内的线程级并发（非异步任务），4 路并行填充 `host_dict` 后 `pool.join()` 汇合；页级路径额外有一个 `ThreadPool(2)` 并发（`get_host_page` ∥ `get_topo_tree(raw=True)`），仍是同请求内线程级并发。`SearchHostMetricResource` 的 `get_alarm_count` 有 `try/except` 异常降级，其他 3 路无异常保护。

**真正的异步编排在前端**（2026-09）：页链 / 全量链 / 卡片链由 `useHostListData` 并发发起，用「整轮 / 页 / 指标 / 全量 / 视图 / 单卡」六层代次丢弃迟到响应；全量链在 Worker（Blob Worker + 三级缓存 `nodeResult → filteredResult → sortedResult`）中计算，就绪后与统计卡片在同一轮 Vue 更新中接替。后端对这些代次无感知——**服务端只需保证同一请求内的结果自洽**。
章节来源：[resources.py](file://bkmonitor/packages/monitor_web/performance/resources.py#L104-L112) · [resources.py](file://bkmonitor/packages/monitor_web/performance/resources.py#L415-L432) · `webpack/src/trace/pages/host/composables/use-host-list-data.ts`

## 结论
数据流简洁清晰：请求 → 多源拉取 → 内存聚合 → 响应，无中间状态持久化。一致性依赖 `HOST` 缓存刷新周期与实时接口的 TSDB 查询时间范围。`host_dict` 的默认值兜底设计保证了部分数据缺失时仍能返回完整结构。2026-09 起「一致性」新增一层约束：**页级数据、全量数据与卡片统计必须口径一致**，服务端不做校验，靠前端对拍测试与共享的时间锚点/阈值口径（180s 窗口、79.995 阈值）保证。主要风险在 `HostPerformanceResource.get_alarm_count` 无异常降级（告警查询异常会中断整个聚合），以及统计在身份歧义/部分失败时长期显示「未知」需要用户自行排查 IP 重复。
