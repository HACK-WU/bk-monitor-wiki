# 数据源查询构造 使用总览

## 能力清单

本专家覆盖 BK-Monitor 中「查询的第一步」——选择和构造数据源。从工厂函数 `load_data_source` 到实例化查询描述对象的全链路。

| 能力 | 说明 |
|------|------|
| 数据源选型 | 了解 14 个 `(DataSourceLabel, DataTypeLabel)` 组合各自的含义和适用场景 |
| 路径预判 | 知道每个组合会走 unify-query 统一查询后端还是原生查询路径 |
| 查询描述构造 | 掌握 `data_source_class(bk_biz_id, interval, metrics, table, group_by)` 的参数规范 |
| 表名字段查源 | 理解 `table` / `metrics[].field` / `group_by` 来自哪里、如何确定 |

## 能力边界

不负责：
- 查询执行（详见 `UnifyQuery查询专家`）
- 元数据的增删改（由 metadata 服务管理）
- 自定义数据源的注册（由配置/运营侧管理）

## 数据源速查矩阵

```
                    TIME_SERIES     EVENT       LOG         ALERT
bk_monitor          UNIFY (硬编码)   NATIVE      GRAY        NATIVE
custom              UNIFY (硬编码)   GRAY        —           —
bk_data             GRAY            —           —           —
bk_log_search       GRAY            —           GRAY         —
bk_fta              —               NATIVE      —           NATIVE
bk_apm              NATIVE          —           GRAY         —
prometheus          NATIVE          —           —           —
```

**图例**：
- **UNIFY（硬编码）**：恒走统一查询后端，`use_unify_query()` 始终返回 `True`
- **GRAY（灰度）**：根据业务和配置决定，可能走 unify-query 也可能走原生路径
- **NATIVE**：永远走原生查询路径，不经过 unify-query

## 已知问题与常见坑

| # | 现象 | 触发条件 | 正确做法 |
|---|------|----------|----------|
| 1 | 查询返回空 | 使用了错误的 `(label, type)` 组合，该组合未注册 | 查阅 C1 确认组合是否在 `load_data_source` 注册表中 |
| 2 | 查询走错了分支 | 不确定数据源是灰度还是硬编码走 unify-query | 查阅本文速查矩阵或 C1 的完整映射表 |
| 3 | event/alert 类查询结果异常 | 这些组合走原生路径，行为与时序查询不同 | 确认数据源类型，原生路径直接查 ES 等后端 |
| 4 | `table` 填了不存在的表名 | 表名来自 `ResultTable.table_id`，非随意字符串 | 查阅 `init_resulttable.json` 或 metadata 确认正确表名 |
