# 数据源系统架构

## 简介

BK-Monitor 的数据源系统由三个层次组成：**工厂层**（`load_data_source` 注册表）、**类层**（各 `DataSource` 子类实现）、**路径决策层**（`use_unify_query` 判定）。它为上层查询（`UnifyQuery`）提供标准化的数据源选择与查询描述构造能力。

## 注册机制

`load_data_source` 在模块加载时将 14 个 `(DataSourceLabel, DataTypeLabel)` 组合映射到对应的 `DataSource` 子类。这些组合覆盖了监控平台的 6 大数据来源（采集、自定义、计算平台、日志、APM、FTA/Prometheus）和 4 种数据类型（时序、日志、事件、告警）。

```
load_data_source(ds_label, type_label)
    → 查内置字典 { (ds_label, type_label): DataSourceClass }
    → 返回类本身（未实例化）
```

## 路径决策架构

```mermaid
flowchart TD
    A["load_data_source(label, type)"] --> B{组合在注册表中?}
    B -->|否| C[报错]
    B -->|是| D{在 UnifyQueryDataSources?}
    D -->|是| E[恒走 unify-query]
    D -->|否| F{在 GrayUnifyQueryDataSources?}
    F -->|是| G[灰度判定: switch_unify_query(bk_biz_id)]
    G -->|True| E
    G -->|False| H[原生路径]
    F -->|否| H
    H --> I[DataQueryHandler 路由到存储后端]
```

**UnifyQueryDataSources**（硬编码）：`(BK_MONITOR_COLLECTOR, TIME_SERIES)`、`(CUSTOM, TIME_SERIES)`
**GrayUnifyQueryDataSources**（灰度）：共 6 个组合，各有独立的 `switch_unify_query` 判定
**原生路径**：FTA事件/告警 → 直连ES；Prometheus → PromQL；APM时序 → metadata服务

## 表名与字段来源

查询描述里的 `table` / `metrics[].field` / `group_by` 都来自元数据：

- **ResultTable 模型**：`table_id`（如 `system.load`）、命名规则 `DB.TABLE_NAME`
- **ResultTableField 模型**：`tag` 区分 metric/dimension/timestamp
- **DataSource → ResultTable**：一对多关系，通过 `DataSourceResultTable` 关联表建立
