# 数据源注册与路径决策实现

## load_data_source 注册实现

`load_data_source` 在 `data_source/__init__.py` 中维护一个内部字典，key 为 `(data_source_label, data_type_label)` 元组，value 为对应的 `DataSource` 子类。模块加载时完成注册，共 14 个组合。

**入口调用**：
```python
data_source_class = load_data_source(label, type)  # 返回类，非实例
```

## 数据源类继承体系

所有数据源类继承自 `DataSource` 基类。基类提供 `query_data`、`query_log`、`query_dimensions` 等抽象方法。每个子类实现自己的 `to_unify_query_config`（构造 query_list）、`switch_unify_query`（灰度判定）等。

## use_unify_query 决策逻辑

```
use_unify_query()
  → 取 data_source.id = (data_source_label, data_type_label)
  → 若不在 UnifyQueryDataSources ∪ GrayUnifyQueryDataSources → False (NATIVE)
  → 若在 GrayUnifyQueryDataSources → switch_unify_query(bk_biz_id) (GRAY)
  → 若在 UnifyQueryDataSources → True (UNIFY)
```

**UnifyQueryDataSources**（硬编码）：
- `(BK_MONITOR_COLLECTOR, TIME_SERIES)` — 最常用，恒走 unify-query
- `(CUSTOM, TIME_SERIES)` — 自定义指标，恒走 unify-query

**GrayUnifyQueryDataSources**（6 个灰度组合）：
- `bk_data + time_series`：按 `BKDATA_USE_UNIFY_QUERY_GRAY_BIZ_LIST` 灰度列表判定
- `bk_log_search + time_series/log`：按 DB 白名单判定
- `bk_monitor + log`：按白名单判定
- `custom + event`：按白名单判定
- `bk_apm + log`：按黑名单 + query_string 特征判定

**NATIVE 路径**（永不走 unify-query）：
- FTA 事件/告警 → `BkFtaEventDataSource` / `BkFtaAlertDataSource` → 直连 ES
- 系统事件/告警 → `BkMonitorEventDataSource` / `BkMonitorAlertDataSource` → 直连 ES
- APM 时序 → `BkApmTraceTimeSeriesDataSource` → metadata/ES
- Prometheus → `PrometheusTimeSeriesDataSource` → PromQL 直查

## metrics 拼装规则

`to_unify_query_config` 将 `metrics` 列表中的每个元素展开为独立的 `query_list` 条目：

- `field_name = metric["field"]`
- `reference_name = metric["alias"].lower()` 或 `metric["field"].lower()`
- 方法映射：`AVG` → `avg_over_time` + `mean`；`SUM` → `sum_over_time` + `sum` 等
- `table_id` = `data_label`（如有）或 `table` 参数的原始值

详见 `UnifyQuery查询专家` 的 C1 能力契约中「两层聚合机制」章节。
