- 规范原文：bkmonitor/support-files/apigw/README.md（监控平台网关管理规范），网关名 bk_monitor，接口定义落在 resources/{internal,external}/{app,user}/*.yaml
- 内部接口含义：蓝鲸体系内部使用方调用（监控各模块之间互调；内部蓝鲸应用如日志平台、容器管理平台调监控）；不公开、不允许自助申请权限，只能由网关管理员或配置文件授权
- 外部接口含义：对外开放给蓝鲸体系之外的调用方（如蓝盾流水线插件）；公开、允许自助申请权限并由网关管理员审批
- 语义澄清：内与外不是内网外网或公司边界概念，判断依据不是网络位置，而是调用方是否为蓝鲸体系内部的既定使用方
- 目录是唯一事实源：support-files/apigw/scripts/merge_resources.py 第 34-61 行把四个目录合并进同一份 resources.yaml（同一个网关、同一 host 与 stage），并自动推导字段：isPublic 取 目录等于 external，userVerifiedRequired 取 第二级目录等于 user，appVerifiedRequired 与 resourcePermissionRequired 取 yaml 值且默认 true
- 过时文档点：README 写内部接口 allowApplyPermission 为 false，但脚本无条件改写为 true；internal/app/issue.yaml 注释自认该点，内部接口的私有性只由 isPublic 为 false 保证（不进公开与可申请列表）
- 与内外正交的第二维度是应用态与用户态：app 前缀为应用态（userVerifiedRequired 为 false，按 app_code 与 app_secret 认证），user 前缀为用户态（userVerifiedRequired 为 true，需要用户登录态）
- 四象限落位：internal/app、internal/user、external/app、external/user
- 部署同步机制：bkmonitor/management/commands/sync_apigw.py 先执行 merge_resources 再执行 sync_apigw_resources 带 delete 全量同步，在网关页面手工添加的接口会被删除；仓库里提交的 resources.yaml 是部署时自动重生成的中间产物
- 排查口诀：判断一个接口是内部还是外部，看目录或看资源里的 isPublic，不要看 allowApplyPermission
