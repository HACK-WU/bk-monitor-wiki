- 内部用户态：support-files/apigw/resources/internal/user/strategy.yaml 的 /user/strategy/get_devops_strategy_list/（isPublic 为 false、allowApplyPermission 为 false、appVerifiedRequired 为 false、userVerifiedRequired 为 true），后端路径 /api/v4/alarm_strategy_v3/get_devops_strategy_list/
- 该接口实现：monitor_web/strategies/resources/v2.py 第 3848 行 GetDevopsStrategyListResource，先校验 bk_biz_id 为数字且不为 0，再取 get_request_username()，再用 Permission.is_allowed_by_biz 校验用户对业务的权限
- 该接口失败形态：返回 result 为 false 加 data 为空列表加 message，而蓝盾 selector 只按 dataPath 等于 data 取值，因此下拉框为空且不给提示，用户容易误判为该业务没有策略
- 对外应用态：support-files/apigw/resources/external/app/shield.yaml 的 /app/shield/add/ 与 /app/shield/disable/（isPublic 为 true、appVerifiedRequired 为 true、userVerifiedRequired 为 false、resourcePermissionRequired 为 true），后端路径 /api/v4/shield/*
- 插件场景结论一：蓝盾插件编排页的 selector 选项接口必须走内部用户态（由浏览器带用户登录态发起，实测裸 GET 报 user authentication failed），插件进程调用的 add 与 disable 走对外应用态（app_code 与 app_secret，且该 app 需被授权该资源）
- 插件场景结论二：把内部用户态接口搬到插件进程侧使用不可行，进程没有用户登录态且 app_secret 代替不了 user token，对外侧也没有等价的策略列表资源，真要用需先在 external 目录注册资源并发布网关
- 后端路径与前端资源路径的映射是双向核对点：/app/shield/add/ 对应 /api/v4/shield/add/，/user/strategy/get_devops_strategy_list/ 对应 /api/v4/alarm_strategy_v3/get_devops_strategy_list/
