kernel_api 字段适配：ApiRenderer 在响应渲染时递归把内核字段名映射为蓝鲸规范字段名，ApiModelFilterSet 在请求侧把蓝鲸规范参数反向映射回内核字段，MCP 请求注入 trace_id。

## 关键类/函数
- 符号: `ApiRenderer.format_field(result, level=0)` / `ApiModelFilterSet` / `API_FIELD_FORMATED_MAPPINGS`
- 位置: `bkmonitor/kernel_api/adapters.py`

## ApiRenderer 行为
- `level=0` 不转换（保留最外层 envelope 键 result/message/data/code）
- 递归深层时把 `API_FIELD_FORMATED_MAPPINGS` 中的键映射为蓝鲸规范键
- 映射示例：`biz_id→bk_biz_id`、`app_code→bk_app_code`、`plat_id→bk_cloud_id`、`company_id→bk_supplier_id`
- `get_result` 中为 MCP 请求（存在 trace_id）注入 `trace_id` 字段（`get_mcp_trace_id`）

## ApiModelFilterSet 行为
- 过滤器基类，把 `bk_biz_id` 等蓝鲸规范参数自动映射回内核字段（`API_FIELD_FORMATED_MAPPINGS` 反向）
- `Meta.extend_fields` 可显式声明映射；未声明时按 `get_extend_fields()` 自动推导
- 在 `__init__` 中把请求参数反向映射后再交给 DjangoFilterBackend

## 踩坑点
- 改 `API_FIELD_FORMATED_MAPPINGS` 映射表 → ApiRenderer（响应侧）+ ApiModelFilterSet（请求侧）双向映射必改，前端消费方也要改
- 最外层 envelope 键不被映射（level=0），深层业务字段才映射
