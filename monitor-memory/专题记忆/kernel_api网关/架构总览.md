kernel_api 是 BK-Monitor 的内核 API 网关 Django app（部署角色 api），对外暴露监控内核能力，并作为 web（monitor_saas）访问告警后台（alarm_backends）的唯一中转层。config/role/api.py 同时继承 web+worker 配置，单进程内既访问 SaaS Resource 又访问 alarm_backends。

## 关键文件
- 符号: `register_url` / `register_v2` / `register_v3` / `register_v4`
- 位置: `bkmonitor/kernel_api/urls.py`
- 符号: `AuthenticationMiddleware` / `api_exception_handler` / `ApiRenderer` / `KernelAPIRouter` / `KernelAPIConfig.ready`
- 位置: `bkmonitor/kernel_api/middlewares/authentication.py` / `exceptions.py` / `adapters.py` / `dbroutors.py` / `apps.py`

## 分层
- 路由注册 `urls.py`：v2/v3/v4 版本化注册、扩展点加载
- 中间件 `middlewares/`：认证、时区、语言、异常日志
- 异常处理 `exceptions.py`：DRF 统一异常渲染（恒 200 + body.code）
- 字段适配 `adapters.py`：响应字段映射 + 过滤器
- DB 路由 `dbroutors.py`：双库路由（monitor_api/metadata → backend 库）
- 视图层 `views/`：对外 API 视图集（v2/v3/v4）
- 内部复用层 `resource/`：批发场景 Resource
- RPC 层 `rpc/`：函数注册与执行

## 角色边界
- web 角色不能直接 import alarm_backends，必须经 API 网关访问 kernel_api 中转
- api 角色 = web 配置 + worker 配置 + kernel_api app，`ROOT_URLCONF="kernel_api.urls"`
- `SKIP_IAM_PERMISSION_CHECK=True`（api 角色默认跳过 IAM，MCP 请求单独校验）

## 请求生命周期
客户端→AuthenticationMiddleware(认证+租户上下文注入)→urls 路由→ViewSet/Resource(perform_request)→异常经 api_exception_handler 渲染 200+body.code / 成功经 ApiRenderer 字段映射
