kernel_api 认证与安全：AuthenticationMiddleware 按优先级判定四种认证方式（apigw JWT / MCP / API Token / app_code 白名单），AppWhiteListModelBackend 自动建用户，is_match_api_token 按命名空间授权，公钥经 lru_cache+login_db 缓存。

## 关键类/函数
- 符号: `AuthenticationMiddleware.process_view(request, view, *args, **kwargs)`
- 位置: `bkmonitor/kernel_api/middlewares/authentication.py`
- 符号: `BkJWTClient.validate` / `AppWhiteListModelBackend.authenticate` / `is_match_api_token` / `get_apigw_public_keys` / `_handle_mcp_auth` / `_handle_api_token_auth`
- 位置: `bkmonitor/kernel_api/middlewares/authentication.py`

## 认证判定顺序（源码确认 authentication.py:603）
1. `view.login_exempt=True` → 跳过认证
2. apigw JWT：`X-Bkapi-From: apigw` + `X-Bkapi-Jwt` → `BkJWTClient.validate()`（RS512 验签，取 app.app_code/user.username）
3. MCP：`X-Bkapi-Mcp-Server-Name`（或旧头/app_code 匹配）→ `_handle_mcp_auth`（IAM 权限动作校验 + `_report_mcp_metric` 上报 MCP_REQUESTS_TOTAL）
4. API Token：`Authorization: Bearer` → `ApiAuthToken` 校验（有效性/视图白名单/命名空间 `biz#{id}`）
5. 兜底：app_code 白名单 + `AppWhiteListModelBackend.authenticate` 自动建用户

## 关键实现细节
- `get_apigw_public_keys()` 用 `functools.lru_cache(maxsize=1)` + `login_db` cache 缓存公钥，公钥为空时 120s 短缓存防抖
- `AppWhiteListModelBackend.authenticate` 用 `User.objects.get_or_create` 自动建用户；多租户模式下校验用户租户与当前租户匹配，不匹配时查 `bk_login` 确认后更新 `tenant_id`
- MCP 认证中 `OPENCLAW_RECOVERING_MCP_TOOLS` 白名单限流 OpenClaw 工具
- CSRF 豁免：`KernelSessionAuthentication.enforce_csrf` 直接置 `csrf_processing_done=True`

## 踩坑点
- MCP 请求缺 `bk_biz_id` 被拒（403）：调用方必须携带 `bk_biz_id`（GET/POST表单/JSON body）
- `get_request_tenant_id()` 在标准请求中不可靠（RequestProvider 未调 set_request）：用 `bk_biz_id_to_bk_tenant_id(bk_biz_id)` 反查租户
- JWT 解析失败报 public key not found：检查 `FROM_APIGW_NAME` 配置与 apigw 公钥发布
