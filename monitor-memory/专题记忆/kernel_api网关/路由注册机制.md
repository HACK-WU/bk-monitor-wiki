kernel_api 路由注册机制：register_url 把一组视图模块注册为 ResourceRouter 的 URL 前缀，v2/v3/v4 三层版本化装配，v3 按 INSTALLED_APIS 环境变量裁剪模块，扩展点 ALLOW_EXTEND_API 动态加载 extend_views。

## 关键函数
- 符号: `register_url(prex, views_module_list, namespace)`
- 位置: `bkmonitor/kernel_api/urls.py`
- 实现: `__import__(views_module, fromlist=["*"])` 导入视图模块 → 创建 `ResourceRouter()` → `router.register_module(views_module)` 扫描所有 `ResourceViewSet` 子类 → 返回 `re_path(prex, include((router.urls, "kernel_api"), namespace))`

## 版本注册
- `register_v2()` → `/api/v2/`（视图模块 `views.v2`：bkdata/monitorapi/component，历史兼容版本）
- `register_v3()` → `/api/v3/{模块名}/`（按 `INSTALLED_APIS` 环境变量过滤，默认 `collector,meta,models,query`；`ROOT_MODULE_V3="kernel_api.views.v3"`）
- `register_v4()` → `/api/v4/`（视图模块 `views.v4`，当前主版本，40+ 文件）

## 扩展点
- `settings.ALLOW_EXTEND_API=True` 时 v2/v3/v4 均追加 `extend_views` 模块
- 扩展模块不存在时 `urls.py` 捕获 `ImportError` 置 `extend_views=None`，不影响主路由
- 扩展点是可选加载，扩展代码不能依赖主代码 import 顺序

## 踩坑点
- 新增 v4 endpoint 必须同时：① 在 `views/v4/{module}.py` 定义 ViewSet+resource_routes ② 在 `views/v4/__init__.py` 加 `from .{module} import *`（漏导出则路由不生效）
- v3 新增模块必须进环境变量 `INSTALLED_APIS` 才暴露
- grafana（`/rest/v2/`）、apm（`/apm_api/v1/`）、rum（`/rum_api/v1/`）也挂在 kernel_api 的 URLConf 下，不是唯一入口
