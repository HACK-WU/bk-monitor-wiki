【专题记忆｜前端改动护栏与交付纪律】
- G1 动手前核验：需求含「有没有 X / 好像没生效 / 补上 X」时先查是否已实现，输出三态（已存在 / 部分存在 / 不存在）+ 依据（读了哪些文件行、git log 查到什么）；二义词（隐藏 / 下线 / 和旧版一致 / 复用）必须先问清语义；先 git status / git branch 确认基线，未提交改动归属不清时先问
- 二义需求黑名单：隐藏 / 下线 / 去掉 / 先关掉 / 暂时不要 有三种实现（只藏导航保留直链 / 藏入口且剔除产物 / 彻底删代码），问语义前先确认当前状态并枚举页面全部入口；「和旧版保持一致」要对齐默认值 → UI 展示 → 交互 → API 请求参数完整链路；「复用 XXX」要确认直接 import / 抽公共组件 / 本目录复制
- G2 写码前影响面预算：默认只改本需求目录；高危项必须停下单独确认——公共路由（router-config.ts、scenes/*.ts、meta.navId、applyGuidePage）、权限与业务上下文（setGlobalBizId、isCanAllIn、window.cc_biz_id、authority 指令）、共享模块反向改动（trace-explore、monitor-ui、monitor-common、monitor-api）、跨 package 改动
- G2 局部映射优先：复刻旧页面行为时在页面层或工具函数层做映射，不改公共元数据（26 个文件消费 navId / applyGuidePage）；复用共享组件用 import + adapter，不反向改源头，抽公共组件作为独立提案
- G3 交付前同类扫描：修一类模式时 rg 全局搜同类并列出清单，由用户决定本次修几处；微前端新页面按清单逐项核对，Vue2 容器 class 名不能与自定义元素 tag 的 kebab-case 撞名（否则无限递归栈溢出）
- G4 交付模板三段式：改了什么（文件路径 + 一句话）/ 验证到哪一步（[已验证] 只写实际执行过的动作与输出，[未验证] 必填且不能写「无」）/ 影响面与风险；禁止用「已修复 / 已解决 / 已定位根因」等断言句，根因结论必须附确认方式；零改动时改用现状核验 / 结论 / 需确认三段
- 红线：公开 PR / commit 不出现内网 URL，只用 --story=<shortID> / --bug=<shortID> 关联；Cookie / Token / bk_ticket 零接触；postMessage 禁 targetOrigin='*'，接收侧校验 event.origin，/share/:token 不外广播；不用 --no-verify；不碰 local.settings.js；不留 debugger 与提交用 console.log；跑 dev server / 构建 / 批量 lint 修复先获授权；GPG 签名由用户本地执行
- 熔断：给出根因判断后用户说「还是没有 / 并没有生效」，停止继续打补丁，先输出复现路径、实际观察（Network 参数与响应 / Console 报错 / 关键变量值）、与上轮不同的根因假设，再改代码
