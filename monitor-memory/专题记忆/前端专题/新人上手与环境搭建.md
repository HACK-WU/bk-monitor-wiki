【专题记忆｜前端新人上手 G0-G6 关卡】
- 适用：零开发经验的 UI 设计师 / 产品经理；一次推进一个关卡，关卡内由 agent 连续执行，不把搭环境拆成十几轮确认；仅支持 macOS
- G0 按需向 mentor 确认当前关需要的信息，不挡 G1/G2；G1 安装 git / nvm / Node 22 / pnpm / gh 并登录，通关判据同一次完整权限体检出现 NODE:v*:OK（>=20.17.0）、PNPM:10.*:OK、GIT:*:OK、GH:*:OK（脚本对任意 pnpm 版本都报 OK，要自己核对 10.x）
- G2 在当前工作区 fork / clone 并配置 upstream，通关判据 REPO_ROOT:<路径>:OK、REMOTE_ORIGIN:<fork-owner>:OK、REMOTE_UPSTREAM:OK；G3 同步团队 skill、配置 Figma/TAPD MCP、最后切换工作区，通关判据 SKILLS:12/12:OK、MCP_FIGMA:PRESENT、MCP_TAPD:PRESENT（PRESENT 只说明配置有键，还要各成功调用一次，失败不算通过且不回显 token），工作区切到 <仓库>/bkmonitor/webpack
- G4 安装依赖、生成 local.settings、配置 hosts、启动并验证，判据 DEPS:OK、LOCAL_SETTINGS:VALID、HOSTS:<host>:OK，且浏览器能打开、接口无 401/403；G5 完成第一次改动（普通改动交接 bkmonitor-dev，Figma 还原交接 blueking-figma-dev）；G6 交接 blueking-tapd-dev 完成交付，PR 链接生成并回填 TAPD
- doctor 脚本：G2 之前在任意目录执行 bash <skill目录>/scripts/doctor.sh，REPO_ROOT:NOT_FOUND 正常；G2 之后 cd <仓库目录> 再跑；只依据最后一行 NEXT_GATE:<G1|G2|G3|G4|DONE> 路由；失败值就是修复入口，修完最早关卡后重跑
- HOSTS 特殊判定：HOSTS:<host>:MISSING 未通过；HOSTS:UNKNOWN 只是无法确定，不代表通过，必须请用户 grep appdev /etc/hosts 核对期望域名在未注释行且指向 127.0.0.1；PORT_7001 只是参考信息，不作判据（portfinder 会顺延，实际端口以启动日志为准）
- GitHub 登录态误报：沙箱里 GH:*:NOT_LOGGED_IN / STATUS_UNREADABLE 视为无效读数，用完整权限重跑，不得让用户重新登录；完整权限下仍 STATUS_UNREADABLE 先再跑一次，仍如此说明钥匙串异常；完整权限下 NOT_LOGGED_IN 才是真未登录
- 硬护栏：禁止 --no-verify、push --force、直推 upstream/master、git add -f local.settings.js / .agents/** / skills-lock.json；sudo 改 hosts 不代跑；不代跑 lint 修复与构建；不改 pnpm-lock.yaml；不执行 rm -rf node_modules；绝不打印 / 复述 / 回显 Cookie、CSRFToken、TAPD Token；不得要求用户把凭据粘贴到对话；凭据只能写入 local.settings.js 或 ~/.cursor/mcp.json；绝不读取或外发 SSH 私钥
- 环境约束：只用 pnpm 10.x（pnpm@8 已过时）；Node 下限 20.17.0，目标 .nvmrc 的 22；MCP 只配置 figma 与 tapd_mcp_http；不得假定 skill 或脚本已在仓库里（G2 之前仓库不存在）
