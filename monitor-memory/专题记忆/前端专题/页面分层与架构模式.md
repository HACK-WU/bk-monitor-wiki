【专题记忆｜前端页面分层与架构模式】
- 页面级四层：typings（按业务域切分 + index.ts 桶文件）/ services（唯一允许 import monitor-api 的层）/ hooks（状态编排）/ components（只读 hook 返回值，自身不发请求）/ utils（纯函数）；依赖方向单向 components → hooks → services → monitor-api，组件层直接发请求是反模式
- 纯映射单独成文件：DTO 到视图模型的转换独立成 transform.ts（不要学 rum-controller.ts 的错误命名），不要混在组件或 hook 里
- 多变体场景：取数侧用 services/base.ts 抽象基类 + factory + 子类；渲染侧用 scenarios/base-scenario.ts + 子类；由 use-scenario-renderer 用 Map 缓存实例驱动 initialize / cleanup；新增类型两侧各加子类，不改既有分支
- Composable 五条：文件 use-xxx.ts 导出 useXxx；单一 options 对象入参且字段为 MaybeRef<T>，内部用 vueuse get() 解包；出参是扁平对象（shallowRef + handleXxx），不返回 reactive；导出 UseXxxReturn = ReturnType<typeof useXxx> 供子组件复用；自带 watchEffect 重取与 onScopeDispose 清理 AbortController
- 何时抽 composable：判据是「有没有异步生命周期要管」（请求 + loading + 取消 + 清理）；纯展示格式化放 formatters.ts / transform.ts
- 目录命名：trace 下 hooks/ 18 个、composables/ 5 个是既存分歧；新页面统一用 hooks/，同一页面不要两个都建
- Pinia 边界：只有跨区域（header / 检索区 / 侧栏 / 表格）读写的状态才进 store；单区域内部状态留组件；刷新用 refreshImmediate 信号量广播；排序用 sortParams getter + sortParamsToTableSortContainer 反解成对提供
- trace-explore 是事实共享库：被 alarm-center / host / failure / rum / plugins 引用 40+ 处；复用 hub 为 explore-chart、trace-explore-table/typing、table hooks + empty、favorite-box / layout / field-type-icon / utils；复用直接 import，路径统一用 @/ 别名
- 类型与后端契约：typings 按业务域切分 + 桶文件；接口类型 JSDoc 标注后端资源编号；DTO 保持 snake_case 原样，只有视图模型转驼峰，并成对预计算排序值 value 与展示值 display；用泛型条件类型把场景与行类型绑死
- Service 层：monitor-api/modules/*.js 是极薄声明层，request('POST','path/') 一行一个；页面 service 在错误处兜底，返回 { data, isAborted }，区分请求取消与失败
- 微前端边界：注册自定义元素 → attachShadow → loadApp({ setShadowDom: true, scopeCss: true, scopeJs: true, scopeLocation: false }) → mount；beforeDestroy 先调 unmountCallback?.() 再 unmount(appId)；data 是唯一通信通道；自定义元素可跨页面复用但注册前判重
- Vue2/Vue3 差异：Vue3 用 hooks + MaybeRef + AbortController + onScopeDispose；Vue2 用平铺纯函数 + CancelToken + beforeDestroy 手动 cancel；Vue2 babel injectH 只把 h 注入能访问 this 的类方法，模块级函数拿不到 h，JSX 必须待在类方法里
