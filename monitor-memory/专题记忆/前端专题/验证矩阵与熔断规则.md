【专题记忆｜前端验证矩阵与熔断规则】
- 交付报告三段式：改了什么（src/... 文件 + 一句话）/ 验证到哪一步 / 影响面与风险；[未验证] 不允许为空也不允许写「无」，除非真的在浏览器跑通完整交互；[已验证] 只能写实际执行过的动作与输出；禁止用「已修复 / 已解决 / 已定位根因」等断言句，根因结论必须附确认方式
- 现成回归用例：bkmonitor/webpack/tests/ 下有 26 个 *.test.cjs + 3 个 *.test.mjs，用 node --test 直接跑，秒级、不用起 dev server；改动前先 ls tests/ | grep 关键词 看有没有覆盖；注意：skill 里写「package.json 有 10 个 test:* 脚本」已过时，实测 package.json 没有 test:* 脚本，直接 node --test
- 按改动类型的验证矩阵：任何改动先查 tests/ 有无覆盖；「加个 X / 有没有 X」先核验 X 是否存在并输出三态；修条件不刷新要 rg 列出全部同模式位置并说明请求参数怎么变；新旧版对齐要打开旧实现逐段对照四层；权限相关覆盖触发器展示 / 下拉补项 / hover 锁标 / 点击申请链接 / API 不返 403 五条链路；路由导航说明直链 / 侧栏高亮 / 切业务跳转；微前端新页面按 checklist 逐项确认；设计稿还原列出设计稿与接口差异及处置；深拷贝确认入参不是响应式 Proxy 并 rg 同文件其他调用
- 熔断计数口径：按「你已经给出过明确根因判断」的轮次算，不按用户说话次数算；给出根因后用户说「还是没有 / 并没有生效 / 还是不行 / 有 X 但没有 Y」立即停止打补丁；如果上轮是多个互斥假设，用户的「还是没有」没有排除任何一个，更不该改代码而要观察数据
- 熔断后先输出三点：复现路径（点哪里、URL、参数）/ 实际观察（Network 请求参数与响应、Console 报错、关键变量值，拿不到就说明需要用户提供哪项）/ 根因假设及与上轮假设的差别；说不出差别说明还没找到根因
- 自欺清单：把「已修复 X」写成「改了 X 处，未本地运行验证，需要你确认 Network」；把「逻辑已对齐旧版」写成「对照了 A/B 两处，C 没找到对应实现，需确认」；把「应该没有影响其他页面」写成「rg 确认 X 只被本目录引用」或「Y 有 3 处引用，已逐个检查」；把「测试通过」写清测了什么、怎么测的
