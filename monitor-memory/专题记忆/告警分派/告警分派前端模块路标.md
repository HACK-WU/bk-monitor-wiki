【专题记忆｜告警分派专家】
- 资产路径：.module-experts/前端专题/告警分派专家/（用 expert-lookup 加载详细资产）
- 一句话职责：monitor-pc 前端「告警分派」功能域——规则组列表（/alarm-dispatch）+ 分派规则配置（/alarm-dispatch-config/:id），配置「什么告警分派给哪些告警组、如何执行（通知/通知升级/ITSM流程套餐）、是否调整等级/追加标签」
- 核心能力：RuleData.getSubmitParams（前端态到提交体唯一映射）、CommonCondition（tag 式条件编辑器）、DebuggingResult（效果调试三态：全局调试/调试并删除/调试并生效）、AlarmBatchEdit（11 种字段批量编辑）、batchUpdate（整组保存）、matchDebug（试算）——以上均见 C1-能力契约
- 高频坑（≤3）：① 配置页所有修改（含组名优先级）不即时落库，必须走「调试并生效」整组 batchUpdate，只编辑不点调试则不发任何写请求；② 列表页删除入口是「调试并删除」，真正 destroyAssignGroup 在调试抽屉保存时执行（源码中直接删除的旧实现被注释保留）；③ 条件编辑器对 value 更新不响应，外部数据刷新必须换组件 key（conditionsRenderKey / conditionsKey / conditionsSelectorKey）
- 关键代码位置：RuleData / RuleGroupData → bkmonitor/webpack/src/monitor-pc/pages/alarm-dispatch/typing/index.ts；列表页 AlarmDispatch → 同目录 alarm-dispatch.tsx；配置页 AlarmDispatchConfig → 同目录 alarm-dispatch-config.tsx；条件编辑器 CommonCondition（现行版）→ components/common-condition-new.tsx（旧版 common-condition.tsx 与 common-condition-selector.tsx 为零引用死文件，勿改）；调试抽屉 DebuggingResult → components/debugging-result.tsx
- 数据落地（如有）：分派规则组与规则配置（提交体 rule_groups + rules）→ 后端 fta/assign/*（FTA 应用持久化），由后端 AssignInfoEnricher 在告警构建链执行分派；调试数据不落库
- 检索触发词：告警分派, alarm-dispatch, 分派规则, 规则组, 优先级, 匹配规则, 分派动作, 告警组, 通知升级, ITSM流程套餐, 效果调试, match_debug, 条件编辑器, 调试并生效, 调试并删除
