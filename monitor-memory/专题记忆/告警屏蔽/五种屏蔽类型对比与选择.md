五种屏蔽类型（scope/strategy/alert/dimension/event）的核心区别在于屏蔽的是"什么范围的对象"以及"如何匹配告警"。event 在 AddShieldResource.perform_request 中被立即转换为 alert，数据库不保留 event 类别。

- 符号: `ShieldCategory`、`ShieldEndPolicy`、`handle_scope`、`handle_strategy`、`handle_alert`、`handle_dimension`
- 位置: `bkmonitor/packages/monitor_web/shield/resources/backend_resources.py`、`bkmonitor/constants/shield.py`

类型对比:
- scope（范围屏蔽）: 屏蔽一批主机/实例/节点/动态分组/业务的所有告警；dimension_config 含 scope_type+target+metric_id；引擎层每个维度 key 做 EqualCondition AND 匹配；不更新 ES
- strategy（策略屏蔽）: 屏蔽某策略产生的告警；dimension_config 含 strategy_id+level+dimension_conditions+可选范围；有重复检查（DuplicateQuickShieldError）；不更新 ES
- alert（告警屏蔽）: 针对一条具体告警，提取其维度，后续相同维度告警也匹配；dimension_config 含告警维度键值对+_前缀元数据；更新 ES AlertDocument.is_shielded=True
- dimension（维度屏蔽）: 纯维度条件匹配，不绑定目标或策略；dimension_config 仅含 dimension_conditions+_strategy_id；is_dimension_scope=True 跳过层一；不更新 ES
- event（事件屏蔽）: 本质是 alert，存储时立即转换为 alert

正交维度 end_policy（屏蔽结束处理方式）:
- notify_once（默认）: 屏蔽结束对未恢复告警补发一次通知，保持原有行为；不传该字段时的默认值
- close（屏蔽结束静默关闭）: 屏蔽期间产生的告警被接管托管，期间不通知、不执行处理套餐，屏蔽结束后由独立任务静默关闭
- 可用范围: 仅 scope/strategy/dimension 类新建屏蔽页可选；alert/event 类与 is_quick=True 的快捷屏蔽禁止（BaseSerializer.validate 抛「快捷屏蔽不支持屏蔽结束时关闭告警」）
- 不可变: EditShieldResource 若传入与当前不同的 end_policy 抛「结束处理方式创建后不可修改」

选择决策:
- 知道要屏蔽哪个策略 → strategy（可叠加范围/级别/维度条件）
- 针对一条具体告警 → alert（自动提取维度，后续相同维度也屏蔽）
- 按主机/实例/节点 → scope（屏蔽目标上所有告警）
- 都不是，按自定义维度条件 → dimension（最灵活）
- 维护窗口内不想收到任何告警、且希望窗口结束后这批告警自动关闭 → 在上述任一类型上叠加 end_policy=close

核心原则: scope 屏蔽"谁"，strategy 屏蔽"什么策略"，alert 屏蔽"哪条告警"，dimension 屏蔽"满足条件的"；end_policy 决定屏蔽"结束时怎么办"，与类型选择互相独立
