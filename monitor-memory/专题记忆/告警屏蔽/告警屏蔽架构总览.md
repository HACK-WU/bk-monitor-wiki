告警屏蔽模块横跨 Web 管理面与告警引擎面两大子系统。Web 管理面（monitor_web/shield）负责屏蔽配置的 CRUD 和前端展示，告警引擎面（alarm_backends/service/converge/shield）负责在告警处理流水线中实时执行屏蔽匹配和状态管理。屏蔽结束处理方式 end_policy 是与屏蔽类别正交的第二个维度：notify_once（默认，屏蔽结束对未恢复告警补发一次通知，保持原有行为）与 close（屏蔽期间产生的告警被接管托管，期间不通知、不执行处理套餐，屏蔽结束后静默关闭）。

- 符号: `ShieldViewSet`、`AddShieldResource`、`ShieldManager`、`ShieldObj`、`ShieldCacheManager`、`ShieldStatusChecker`、`CloseShieldMatcher`、`check_shield_end_close_alert`
- 位置: `bkmonitor/packages/monitor_web/shield/`、`bkmonitor/alarm_backends/service/converge/shield/`、`bkmonitor/alarm_backends/service/alert/manager/shield_tasks.py`

三层架构:
1. Web 层: ShieldViewSet 声明 11 个端点，按 action 分配 IAM 权限（VIEW_DOWNTIME/MANAGE_DOWNTIME），ViewSet 仅做路由分发
2. Resource 层: 后端 CRUD（backend_resources.py）+ 前端展示（frontend_resources.py）+ Celery 异步（celery_resources.py），序列化器按 category 分发到 5 个子类；end_policy 在 BaseSerializer 层校验（category=alert/event 或 is_quick=True 时禁止 close）
3. 告警引擎层: ShieldManager.shield() 链式执行 GlobalShielder → AlertShieldConfigShielder → AlarmTimeShielder，任一命中即返回

数据层:
- Shield 模型（MySQL alarm_shield 表）: category/scope_type/dimension_config(JSON)/cycle_config(JSON)/end_policy/begin_time/end_time/failure_time/is_enabled；end_policy 为 CharField(16) 默认 notify_once，迁移 0205_shield_end_policy
- AlertDocument（ES）: is_shielded/shield_id/shield_left_time 字段由引擎层更新；新增 shield_end_close(Boolean) 标记该告警被 close 型屏蔽接管
- Redis 缓存: key=shield.biz_{bk_biz_id}，存该业务所有生效屏蔽配置 JSON 列表

关键设计:
- 解除非即时生效: DisableShieldResource 仅设 is_enabled=False，需等 ShieldCacheManager.refresh 后引擎重新匹配才生效
- 缓存预取 10 分钟: refresh 拉取 begin_time <= now+10min 的配置，让即将生效的屏蔽提前进缓存
- dimension_config 中 _ 开头字段为元数据（_alert_id/_severity/_alert_message/_dimensions），不参与匹配
- end_policy 与屏蔽类别正交：close 仅对 scope/strategy/dimension 类生效（close.py 过滤掉 alert/event 与 is_quick），快捷屏蔽两入口（weixin EventViewSet 与 fta_web QuickAlertHandleViewSet）不传该字段走默认 notify_once；EditShieldResource 显式拒绝修改 end_policy（创建后不可变）
- 托管告警隔离点（alert.shield_end_close=True 时切断全部副作用，共 7 处）：① 通知信号 core/alert/alert.py should_send_signal() 返回 False，且 update() 中托管告警到达恢复事件时 clear_next_status 保持去重身份不被终结；② 分派 enricher/rule_assign.py AssignInfoEnricher.enrich_alert 直接 return alert；③ 信号下发 service/alert/processor.py BaseAlertProcessor.send_signal 跳过；④ composite 处理 service/composite/tasks.py check_action_and_composite 跳过；⑤ 动作创建 fta_action/tasks/create_action.py 过滤掉 shield_end_close 告警；⑥ 周期检查 manager/tasks.py check_abnormal_alert 与 check_blocked_alert 的 ES 查询条件排除 shield_end_close，manager/processor.py 二次过滤；⑦ 独立关闭扫描 manager/shield_tasks.py 只接管这批告警
- 发布顺序依赖：DB 迁移（0205）→ ES mapping 加 shield_end_close → 消费者分流（上述隔离点）→ 关闭任务部署（config/role/worker.py 注册每分钟 cluster 任务）→ 前端放开选项二
