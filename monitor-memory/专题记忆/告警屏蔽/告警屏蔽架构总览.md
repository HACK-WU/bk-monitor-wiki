告警屏蔽模块横跨 Web 管理面与告警引擎面两大子系统。Web 管理面（monitor_web/shield）负责屏蔽配置的 CRUD 和前端展示，告警引擎面（alarm_backends/service/converge/shield）负责在告警处理流水线中实时执行屏蔽匹配和状态管理。

- 符号: `ShieldViewSet`、`AddShieldResource`、`ShieldManager`、`ShieldObj`、`ShieldCacheManager`、`ShieldStatusChecker`
- 位置: `bkmonitor/packages/monitor_web/shield/`、`bkmonitor/alarm_backends/service/converge/shield/`

三层架构:
1. Web 层: ShieldViewSet 声明 11 个端点，按 action 分配 IAM 权限（VIEW_DOWNTIME/MANAGE_DOWNTIME），ViewSet 仅做路由分发
2. Resource 层: 后端 CRUD（backend_resources.py）+ 前端展示（frontend_resources.py）+ Celery 异步（celery_resources.py），序列化器按 category 分发到 5 个子类
3. 告警引擎层: ShieldManager.shield() 链式执行 GlobalShielder → AlertShieldConfigShielder → AlarmTimeShielder，任一命中即返回

数据层:
- Shield 模型（MySQL alarm_shield 表）: category/scope_type/dimension_config(JSON)/cycle_config(JSON)/begin_time/end_time/failure_time/is_enabled
- AlertDocument（ES）: is_shielded/shield_id/shield_left_time 字段由引擎层更新
- Redis 缓存: key=shield.biz_{bk_biz_id}，存该业务所有生效屏蔽配置 JSON 列表

关键设计:
- 解除非即时生效: DisableShieldResource 仅设 is_enabled=False，需等 ShieldCacheManager.refresh 后引擎重新匹配才生效
- 缓存预取 10 分钟: refresh 拉取 begin_time <= now+10min 的配置，让即将生效的屏蔽提前进缓存
- dimension_config 中 _ 开头字段为元数据（_alert_id/_severity/_alert_message/_dimensions），不参与匹配
