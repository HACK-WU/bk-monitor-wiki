ShieldObj 是告警引擎中的屏蔽匹配核心对象，执行时间匹配（TimeMatch）和维度匹配（AndCondition/OrCondition 条件树）的双重校验。AlertShieldObj 继承 ShieldObj，增加告警维度预处理和类级缓存。对 end_policy=close 的屏蔽，时间校验从「当前时间是否在窗口内」改为「告警 begin_time 是否落在窗口内」。

- 符号: `ShieldObj.is_match`、`_parse_dimension_config`、`_clean_dimension`、`_parse_dimension_conditions`、`AlertShieldObj._calculate_alert_dimension`、`AlertShieldObj._parse_cycle_config`、`CloseShieldMatcher.take_over`
- 位置: `bkmonitor/alarm_backends/service/converge/shield/shield_obj.py`、`bkmonitor/alarm_backends/service/converge/shield/close.py`、`bkmonitor/alarm_backends/service/converge/shield/window.py`

维度匹配两层级独立并行:
- 层一（顶层 KV → EqualCondition AND 链）: _clean_dimension 保留非 _ 前缀的顶层键值对，每个转为 EqualCondition，全部 AND 连接
- 层二（dimension_conditions → Or/And 条件树）: _parse_dimension_conditions 弹出 dimension_conditions 键，根据 condition 字段构建 OrCondition/AndCondition 树，支持 eq/neq/gt/lt/contain/reg 等匹配方法
- 两层数据来自不同来源，在 dimension_config 中平级共存，引擎各自提取处理

维度清理规则:
- category 值为 all 的维度（表示全量，无需匹配）
- 值包含 00 的维度（历史兼容）
- 以 _ 开头的键（元数据字段如 _alert_id/_severity/_alert_message/_dimensions）

fail-close 语义:
- _parse_dimension_conditions 对解析失败的条件（脏数据缺 key/value、非 dict 条目）替换为永不命中占位 _NeverMatchCondition
- 使所在 AND 组整体不命中，屏蔽范围收窄而非扩大（fail-close）
- 分组边界仅由 condition 声明的 and/or 关系决定，与解析成败无关
- regex 语法错误不在此列：RegexCondition 在匹配期编译正则并自行捕获错误返回不匹配

AlertShieldObj 维度补全:
- 从 alert.origin_alarm.data.dimensions 和 alert.dimensions 双源合并
- 补充 strategy_id/level/bk_topo_node/bk_host_id/bk_biz_id/metric_id
- 双向补全 IP/云区域/服务实例别名字段（ip↔bk_target_ip 等）
- 展开 tags. 前缀字段
- 类级缓存 _alert_dimension_cache 上限 1000，超限删最旧 500

close 型屏蔽的接管判定（告警维度接管，与普通屏蔽的时间语义不同）:
- 时间语义反转：普通屏蔽看「现在是否在窗口内」（time_check.is_match(source_time)），close 型屏蔽看「告警 begin_time 是否落在窗口内」（matching_window(time_check, now) 得到 inclusive 的 [begin,end] epoch 秒区间，判断 window[0] <= alert.begin_time <= window[1]）——目的是把屏蔽期间产生的历史告警都纳入接管范围，而非只看当前时刻
- 时间解析走 _BusinessCalendar：window.py 的 close_time_matcher 按 cycle_config.type 选 _CloseDay/_CloseWeek/_CloseMonth（继承 TimeMatchByDay/Week/Month 并覆写 is_week_match/is_month_match 用 time_tools.localtime 取业务时区日期），单次屏蔽用 TimeMatchBySingle；AlertShieldObj._parse_cycle_config 对 end_policy=close 改走 close_time_matcher，并在 timezone.override(业务时区) 下构造
- 业务时区一次性解析并复用：CloseShieldMatcher 按 biz 缓存 business_timezone(bk_biz_id) 与解析后的 AlertShieldObj 列表，避免逐告警重复查 CMDB
- 首接粘滞（已接管不重选）：CloseShieldMatcher.take_over 入口即判断 alert.shield_end_close，已接管直接返回，后续轮次不再重新匹配（避免多屏蔽竞争时归属漂移）
- 多屏蔽竞争选谁：对命中屏蔽按 (窗口结束时间, -shield_id, 窗口开始时间, shield_id) 取 max，即窗口最晚结束者优先，同窗口取 id 小者
- 匹配失败不影响主流程：take_over 捕获异常仅记日志（「A failed match must not prevent unrelated alerts from being saved」），单条告警匹配异常不会中断整批告警保存
- 匹配前补策略快照：若 alert 有 strategy_id 但 extra_info 无 strategy，先跑 StrategySnapshotEnricher.enrich_alert，因为接管判定早于常规 enrichment 阶段
- 接管动作：alert.set(shield_end_close=True)、set(is_shielded=True)、set(shield_id=[shield_id])、update_extra_info(shield_end_close_config={shield_id, window_begin, window_end})、clear_next_status()
