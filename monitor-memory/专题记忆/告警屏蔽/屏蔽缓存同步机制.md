ShieldCacheManager 是引擎面读取屏蔽配置的唯一入口，避免每条告警都查 MySQL。通过 Celery 定时任务 refresh 将 DB 中生效的屏蔽配置全量同步到 Redis。屏蔽结束静默关闭走独立任务链、不复用该缓存——结构依据：refresh 只拉取 begin_time <= now+10min 且 end_time >= now 且 is_enabled=True 的配置，已结束的屏蔽物理上不在缓存中，无法用于判断「是否已结束」；且缓存条目不含 is_deleted 软删除信息。

- 符号: `ShieldCacheManager.refresh`、`get_shields_by_biz_id`、`publish_failure`、`get_last_failure_end`、`check_shield_end_close_alert`、`shield_is_active`、`check_shield_end_close_finished`
- 位置: `bkmonitor/alarm_backends/core/cache/shield.py`、`bkmonitor/alarm_backends/service/alert/manager/shield_tasks.py`

缓存结构:
- Key: CACHE_KEY_PREFIX.shield.biz_{bk_biz_id}
- Value: 该业务下所有生效屏蔽配置的 JSON 列表（extended_json.dumps 序列化）
- TTL: CACHE_TIMEOUT（继承 CacheManager 基类）
- 故障事件: Redis Hash，key=shield.failure.{module}，field=target，value=expected_end_timestamp

刷新逻辑 refresh():
- 拉取所有业务中 begin_time <= now+10min 且 end_time >= now 且 is_enabled=True 的屏蔽配置
- 多预取 10 分钟：让即将生效的屏蔽配置提前进入缓存
- 按业务分组写入 Redis pipeline
- 无屏蔽的业务删除对应 Key
- 序列化用 extended_json（支持 datetime 等自定义类型）

读取路径 get_shields_by_biz_id():
- 从 Redis 读取 JSON 字符串
- extended_json.loads 反序列化为 dict 列表
- 遍历每条配置，将 begin_time/end_time/failure_time 补充 UTC tzinfo
- 缓存不存在时返回空列表 []

匹配快照缓存 ALERT_SHIELD_SNAPSHOT:
- Key: strategy_id + alert_id 组合（无策略的第三方告警不缓存）
- Value: 匹配到的屏蔽配置 ID 列表（JSON 字符串）
- 写入时机: 首次匹配完成后写入，带 TTL 过期
- 作用: 避免每轮检测都重新遍历所有屏蔽配置

屏蔽结束静默关闭任务（独立扫描，读 DB 而非缓存）:
- 任务注册：config/role/worker.py 注册 check_shield_end_close_alert 为每分钟执行的 cluster 任务（与 check_abnormal_alert 同频，但走独立扫描入口）
- 扫描条件：AlertDocument.search(all_indices=True) 过滤 status=ABNORMAL 且 shield_end_close=True，只取 id/strategy_id/event.bk_biz_id 字段，再按 get_cluster_bk_biz_ids() 过滤集群归属业务；每满 BATCH_SIZE 调一次 check_shield_end_close_finished
- 归属与到期判定：从告警 extra_info.shield_end_close_config 取 shield_id（缺失/非法记 error 并保留告警），用 Shield.origin_objects.in_bulk 批量读 DB（origin_objects 含软删除记录——记录缺失不等于明确删除，保留告警并记日志；SQL 异常直接抛出，整批不关闭）；shield_is_active 判定 is_deleted/is_enabled 后，在业务时区下用 close_time_matcher(cycle_config, begin_time, end_time).is_match(now) 判断当前是否仍在屏蔽中，时间配置不可读则记 exception 并保留告警（fail-safe 不关闭）
- 关闭动作：仅当 active 明确为 False 才关闭（active 为 None 即未判定成功时保留）；set_end_status(EventStatus.CLOSED, AlertLog.OpType.CLOSE, description="屏蔽结束，期间产生的告警已关闭")
- 并发保护：用 multi_service_lock(ALERT_UPDATE_LOCK) 按 dedupe_md5 加锁，锁内二次 mget 复核 is_abnormal + shield_end_close，避免与其他状态检查链并发
- 落盘顺序：先 AlertDocument.bulk_create(UPSERT) 持久化，BulkIndexError 时按错误 _id 剔除失败项（部分回滚），成功项再更新 AlertCache 与 AlertLog；写入前按 ID 更新，避免旧告警覆盖后继去重身份
