屏蔽通知由 Celery 定时任务驱动，通过 Redis 锁 NOTICE_SHIELD_KEY_LOCK 保证开始/结束通知各只发送一次。

- 符号: `check_and_send_shield_notice`、`do_check_and_send_shield_notice`、`ShieldObj.check_and_send_notice`、`can_send_start_notice`、`can_send_end_notice`、`send_notice`
- 位置: `bkmonitor/alarm_backends/service/converge/shield/tasks.py`、`bkmonitor/alarm_backends/service/converge/shield/shield_obj.py`

定时任务调度:
- check_and_send_shield_notice(): 查询所有 is_enabled=True、failure_time>=now 的屏蔽配置
- perform_sharding_task 分片，每批 10 条
- do_check_and_send_shield_notice(ids): Celery task，队列 celery_cron
- 对每条配置创建 AlertShieldObj，调用 check_and_send_notice()

通知触发条件:
- 开始通知 can_send_start_notice(): notice_time 分钟后在屏蔽范围内 + 无锁 → SET 锁 + send_notice('start')
- 结束通知 can_send_end_notice(): notice_time+1 分钟后不在屏蔽范围 + 有锁 → DELETE 锁 + send_notice('end')
- 无 notice_config 则返回 False

通知发送 send_notice():
- parse_notice_receivers(): 解析 user#username 提取用户名，group#role 通过 get_business_roles 展开为用户列表
- get_notice_context(): 构建 notice_type/shield_id/start_time/category_name/cycle_duration/shield_content/description
- 遍历 notice_way，为每种方式创建 Sender，使用 notice/shield/{notice_way}_title.jinja 和 _content.jinja 模板
- sender.send(notice_way, notice_receivers) 发送

解除屏蔽通知:
- ShieldStatusChecker.check 检测告警从被屏蔽变为未屏蔽时触发
- 告警处于恢复期则设 ignore_unshield_notice=True 抑制通知
- push_actions 中对解除通知执行 QoS 限流后异步推送
