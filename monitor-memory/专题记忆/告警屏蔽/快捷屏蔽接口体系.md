快捷屏蔽有两条独立入口：QuickShield（移动端手动操作）和 QuickAlertShield（通知链接点击）。两者最终都调用 AddShieldResource，但 quick_shield 跳过了大量处理逻辑。

- 符号: `QuickShield`、`QuickAlertShield`、`QuickAlertAck`、`AddShieldResource`
- 位置: `bkmonitor/packages/weixin/event/resources.py`、`bkmonitor/packages/fta_web/alert/resources.py`

QuickShield（POST /event/quick_shield/）:
- 移动端/微信端手动快速屏蔽，支持 scope/strategy/event 三种类型
- EventViewSet 使用 NoCsrfSessionAuthentication（绕过 CSRF）
- get_permissions() 返回 []，权限交给 AlertPermissionResource 宽松校验
- 只需 type+event_id+end_time 三个参数，后端自动推导 dimension_config
- handle_scope: 按 event.target_type 映射 IP/实例/拓扑
- handle_strategy: dimension_config={id: [strategy_id]}
- handle_event: dimension_config={alert_id: alert.id}
- 固定 is_quick=True、shield_notice=False、cycle_config={type:1}、begin_time=当前时间
- 返回 JSON {id: shield_id}

QuickAlertShield（GET /event/alert/quick_shield/）:
- 通知消息中的屏蔽链接点击，token 验权无需登录态
- QuickAlertHandleViewSet 使用 PlainTextRenderer
- 继承 QuickActionTokenResource，验证 token 并解析 alert_ids
- 对每个 alert_id 调用 resource.shield.add_shield(category=alert)
- 默认屏蔽 3 小时，可通过 shield_hours 调整
- 成功→重定向到告警详情页（HTML）；部分失败→纯文本统计

add_shield vs quick_shield 关键差异:
- add_shield 校验 MANAGE_DOWNTIME 权限；quick_shield 不校验
- add_shield 支持所有 category + 周期 + 通知；quick_shield 固定单次+不发通知
- add_shield 的 alert 类型更新 AlertDocument.is_shielded=True；quick_shield 不更新
- add_shield 的 strategy 类型检查重复；quick_shield 不检查
- 需要通知/周期/重复检查/ES状态同步时必须走 add_shield
