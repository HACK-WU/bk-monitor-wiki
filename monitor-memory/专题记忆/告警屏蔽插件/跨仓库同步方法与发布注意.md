- 同步首选做法（2026-09-21 在 bkop 实操验证）：在主仓库用 git show 导出目标提交的补丁，用脚本剔除 URL 相关的 hunk，再在目标仓库 git apply --check 确认后应用；bkop 上 command_line.py 三个 hunk 以 offset 8 行干净应用、task.json 一个 hunk 干净应用
- 不能整包 apply 的原因：环境副本的 URL hunk 上下文不存在（bkop 本来就是正确路径），整包会报 patch does not apply
- 不能 cherry-pick 的原因：三仓库历史独立且包目录名不同（bk_monitor_shield 与 bk_monitor_shield_bkop、bk_monitor_shield_bksg），整包会去创建不存在的目录并搬运目标仓库没有的 tests 与 requirements-dev.txt
- 主仓库测试不能直接搬到环境副本：整套测试对 bkop 跑出 19 failed、35 passed、4 xfailed，19 条失败全是 TypeError 提示 list indices must be integers，根因是 bkop 的 build_request_body 返回列表而测试按字典断言
- 可复用的测试部分：test_dimension_processor.py 可原样使用；4 条 xfail（用户输入错误码归类方向相反、duration 传空串崩溃、HTTP 200 非 JSON 未捕获）在环境副本同样成立，因为 error_code.py 与主仓库逐字节相同
- 环境副本特有缺口：bkop 的批量语义（返回列表与多 id 逗号拼接）主仓库测试完全没有覆盖
- 复现环境：把主仓库 tests 目录与目标包拷到临时目录，把测试里的 import 包名替换为目标包名后用主仓库 venv 的 pytest 运行
- 发布与上架：task.json 是发布物，改动后需重新上架；bkop 走 prod-v1.x 线，兼容式功能更新按次版本加一（下一个版本为 v1.5.0）；按官方规则次版本 latest 会被存量流水线自动升级，因此路径类改动要谨慎评估
