GetHostProcessListResource 聚合 CMDB 进程信息 + 4 路并发 TSDB 查询（端口健康/运行时指标/启动时间/实例数），是场景视图模块中最复杂的实时数据流。

- 符号: `GetHostProcessListResource`、`get_process_runtime_metrics`、`runtime_metric_map`、`ThreadPool`
- 位置: `bkmonitor/packages/monitor_web/scene_view/resources/host.py`

4 路并发 TSDB 查询:
1. 端口健康状态: 查 system.proc_port 的 port_health（GetHostProcessPortStatusResource 单独接口）
2. 运行时指标: 查 system.proc 的 cpu_usage_pct/mem_res/mem_usage_pct/fd_num/fd_limit_soft（get_process_runtime_metrics）
3. 启动时间: 查 system.proc 的 uptime
4. 实例数: 查 system.proc 的进程实例数（count_without_time）

聚合模式:
- 用 ThreadPool 并发执行 4 路 TSDB 查询
- 结果按进程名索引合并到 CMDB 进程数据中
- TSDB 查询失败时各指标降级为空值/None，不影响整体返回

runtime_metric_map 硬编码映射:
- UI 字段名 → TSDB 字段名
- cpuUsage → cpu_usage_pct（percentunit）
- memRss → mem_res（字节，4.5G 即 4.5G）
- memUsage → mem_usage_pct（percentunit 0-1，0.58=58%）
- fdNum/fdLimit → fd_num/fd_limit_soft（个）
- instanceCount → count_without_time 统计实例数
- 前端字段变更时需同步更新 runtime_metric_map

单位混淆高频坑:
- memRss → mem_res 是字节
- memUsage → mem_usage_pct 是 percentunit 0-1（0.58=58%）
- 与主机列表接口同名 mem_usage（→system.mem.pct_used，percent 0-100，0.58=0.58%）含义完全不同
- 进程指标 SUM 聚合语义：多实例进程值为各实例之和

入参:
- bk_host_id 或 bk_target_ip+bk_target_cloud_id（二选一）
- start_time/end_time（秒级时间戳，不传默认最近三分钟）
