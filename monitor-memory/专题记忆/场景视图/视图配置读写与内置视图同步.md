视图配置读写由 resources/view.py 的 Resource 层 + builtin/ 的 Processor 协作完成。读取时先 create_default_views 补齐默认视图，再取目标 SceneViewModel 行，最后 get_view_config 分发到 Processor 生成最终配置。

- 符号: `GetSceneViewResource`、`GetSceneViewListResource`、`UpdateSceneViewResource`、`DeleteSceneViewResource`、`BulkUpdateSceneViewOrderAndNameResource`、`create_default_views`
- 位置: `bkmonitor/packages/monitor_web/scene_view/resources/view.py`、`bkmonitor/packages/monitor_web/scene_view/builtin/__init__.py`

读路径（GetSceneViewResource.perform_request）:
1. create_default_views 补齐默认视图（JSON 骨架↔DB 双向同步）
2. 查 SceneViewModel.objects.get(bk_biz_id, scene_id, type, id)，缺失抛 Http404
3. get_view_config(view, params) 分发到 Processor 生成配置
4. 响应结构: {bk_biz_id, scene_id, id, name, variables, type, mode, order, panels, options}
5. panel 由 Panel.to_dict 输出 {id, title, sub_title, targets, options, grid_pos}

列表读路径（GetSceneViewListResource）:
- 非 kubernetes 场景不传 type 时自动拼接 overview+detail 两列表返回
- panel_count: get_panel_count 递归统计 panels，排除 row 容器和 tag-chart
- 排序: 查 SceneViewOrderModel.config，按视图ID顺序排，不在顺序里的排最后
- validate_scene_type: apm/kubernetes/alert 场景的 type 参数被强制置空

写路径（UpdateSceneViewResource）:
- 创建或更新视图配置，id 不传则自动生成 custom_{count}
- id 必须匹配 ^[0-9a-zA-Z_]+$，config.mode 限 auto/custom

删除路径（DeleteSceneViewResource）:
- 支持单个或批量删除，删除后同步清理 SceneModel.view_order 中的对应ID

排序路径（BulkUpdateSceneViewOrderAndNameResource）:
- 批量更新视图排序及名称，不在排序配置中的视图ID自动追加到末尾
- SceneViewModel.update_order 用 @atomic + select_for_update 锁 SceneViewOrderModel 行，避免并发顺序错乱
