外部API集成专题架构总览：`api/` 目录是 BK-Monitor 的外部 API 统一封装层，每个外部系统一个子目录，子目录内 `default.py` 定义该系统的 APIResource 子类集合。
- 入口: `core.drf_resource.contrib.api.APIResource`（HTTP 基类）
- 位置: `bkmonitor/api/`
- 调用方式: 全局入口 `resource.xxx.yyy()` / `api.xxx.yyy()` 或直接实例化 `SomeResource().request(params)`
- 标准封装模板: `class XxxSystemResource(APIResource)` → 设 `base_url`/`module_name`/`action`/`method` + 嵌套 `RequestSerializer`
- 关键覆写点: `base_url`(远端基地址) / `get_request_url`(URL动态format) / `get_headers`(自定义认证头) / `full_request_data`(注入应用认证) / `render_response_data`(非标准响应适配) / `perform_request`(错误包装/参数弹出) / `use_apigw`(ESB/apigw切换) / `cache_type`+`CacheResource`(结果缓存) / `batch_request`(分页批量)
- 跨专家架构: 调用方(monitor_web/fta_web/kernel_api/AI-MCP) → api/common 公共基类 → 5个专家域(基础平台/CMDB容器/数据平台/协作流程/监控生态) → 外部系统(ESB/APIGW/CMDB/K8s/BKData/TAPD等)
- 公共基类: `CommonBaseResource`(api/common/default.py) 提供动态URL渲染 + BKAPIError统一包装，但多数系统自建基类
