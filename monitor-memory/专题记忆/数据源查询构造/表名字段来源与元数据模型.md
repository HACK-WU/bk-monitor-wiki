查询中的 table/metrics[].field/group_by 都来自元数据模型。ResultTable 定义表名，ResultTableField 定义字段角色，DataSource 与 ResultTable 通过 DataSourceResultTable 关系表一对多关联。

- 符号: `ResultTable`、`ResultTableField`、`DataSource`、`DataSourceResultTable`
- 位置: `bkmonitor/metadata/models/result_table.py`、`bkmonitor/bkmonitor/models/base.py`

ResultTable 模型:
- table_id: 结果表ID（如 system.load、system.proc_port）
- 命名规则: DB.TABLE_NAME，DB=监控范围（system/docker），TABLE_NAME=指标集合（cpu/mem/proc）
- label: 监控范围分类（如 os）
- schema_type / default_storage: 存储类型
- 初始化数据: init_resulttable.json

ResultTableField 模型:
- table_id + field_name 联合唯一
- tag 区分角色: metric=指标（可聚合数值、带 unit）、dimension=维度（描述性字符串、用于分组/过滤）、timestamp=时间
- 指标字段带 unit（如 %、MB），可聚合
- 维度字段是描述性字符串，用于 group_by
- 示例: system.proc 表含 display_name(进程显示名称)、pid、username 等维度与 cpu_usage_pct、uptime、fd_num 等指标

DataSource 模型:
- bk_data_id: 主键，定义采集通道
- data_name: 数据源名称
- etl_config: ETL配置
- source_label / type_label: 数据源标签
- 一个数据源可采集多种指标

DataSourceResultTable 关系表:
- bk_data_id + table_id
- 关系一对多: 一个数据源对应多个结果表
- 示例: snapshot(bk_data_id=1001) 对应 system.cpu_summary、system.io、system.disk、system.mem 等多表

关键约束:
- table 参数必须填 ResultTable.table_id 中存在的表名，非随意字符串
- metrics[].field 必须填 ResultTableField 中 tag=metric 的 field_name
- group_by 必须填 ResultTableField 中 tag=dimension 的 field_name
