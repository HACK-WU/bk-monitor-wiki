[强关联] 元数据核心模型 与 外部消费者（alarm_backends/apm/api/kernel_api）
强度：必改——改 DataSource/ResultTable/EntityRelation 字段定义时，alarm_backends/apm/api/kernel_api 必须跟着改；改外部模块消费逻辑，核心模型不用管
原因：alarm_backends 引用 metadata 模型做告警计算，apm 引用做 APM 拓扑（EntityRelation 被消费），api/kernel_api 通过网关暴露模型，模型字段变更级联影响所有外部消费者

源端（核心模型）:
- `DataSource` / `ResultTable` @ `bk-monitor-base/src/bk_monitor_base/metadata/models/data_source.py` / `result_table.py`
- `EntityRelation` / `EntityMeta` @ `bk-monitor-base/src/bk_monitor_base/metadata/models/entity_relation.py`

目标端（外部消费者）:
- `alarm_backends/` @ `bk-monitor-base/src/bk_monitor_base/alarm_backends/`（引用 metadata 模型做告警计算）
- `apm/` @ `bk-monitor-base/src/bk_monitor_base/apm/`（引用 metadata 模型做 APM 拓扑，EntityRelation 被 APM 层消费）
- `api/metadata/default.py` @ `bkmonitor/api/metadata/default.py`（通过 API 网关暴露）
- `kernel_api/` @ `bkmonitor/kernel_api/`（路由注册与直连）
- 修改 DataSource/ResultTable 字段需评估告警计算影响
