[强关联] 元数据核心模型 与 存储引擎/数据链路模型
强度：必改——改 Storage 模型（ClusterInfo/ESStorage/InfluxDBStorage）或 DataLink 模型时，DataSource/ResultTable 必须跟着改；改 DataSource/ResultTable 字段，Storage/DataLink 不用管
原因：DataSource 的 MQ 集群配置依赖 Storage 集群模型，ResultTable 的存储创建与管理依赖 Storage，DataLink 依赖 DataSource/DataSourceResultTable，模型间 1:N 关系（DataSource→ResultTable→Storage）级联影响

源端（核心模型）:
- `DataSource` @ `bk-monitor-base/src/bk_monitor_base/metadata/models/data_source.py`（MQ 集群配置、register_to_bkbase）
- `ResultTable` / `ResultTableField` @ `bk-monitor-base/src/bk_monitor_base/metadata/models/result_table.py`（存储创建与管理）

目标端（存储/数据链路模型）:
- `ClusterInfo` / `InfluxDBStorage` / `ESStorage` / `KafkaStorage` / `DorisStorage` @ `bk-monitor-base/src/bk_monitor_base/metadata/models/storage.py`（Storage 依赖 ResultTable table_id 外键、DataSource bk_data_id）
- `DataLink` / `DataLinkResourceConfigBase` / `DataIdConfig` / `ResultTableConfig` @ `bk-monitor-base/src/bk_monitor_base/metadata/models/data_link/`
- DataLink 依赖 DataSource、DataSourceResultTable
