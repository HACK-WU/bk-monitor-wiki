【决策记录｜Issue 名称唯一性分场景：用户改名强制唯一，系统自动标题允许重名】
- 分类：接口契约
- 动机：避坑（把给用户的约束套到系统自动标题上，会让自动标题被卡回默认名）
- 决策：IssueDocument.rename 用 enforce_unique 区分两种调用方：用户改名（默认 True）人手填重名是误操作，撞名抛 IssueNameDuplicatedError 拦下；系统自动标题（False）同类错误天然生成相同标题（标题描述错误、不含实例维度），实例区分交由 Issue 的结构化维度承担，允许重名
- 背景约束：自动标题只描述是什么错，不携带实例维度，因此同策略同类错误的多个 Issue 标题必然相同
- 被否决方案：对系统自动标题也强制唯一，否决理由为 docstring 原文「不应被给用户用的唯一性约束卡回默认名」
- 已知代价：同业务下可能存在多个同名 Issue（系统生成的），依赖结构化维度区分；按名称检索时需预期重名结果
- 重新评估触发条件：自动标题开始携带实例维度（可恢复强制唯一）
- 关联代码：IssueDocument.rename @ bkmonitor/documents/issue.py；build_issue_default_name @ issue_processor.py
- 证据来源：rename 方法 docstring（用户改名撞名拦截；系统自动标题同类错误天然生成相同标题允许重名，不应被给用户用的唯一性约束卡回默认名）
