决策：Issue 批量拆分采用逐条独立执行、无跨条目事务，部分失败不阻塞其余条目。
- 背景: REQ-20260901-001 批量拆分，kernel_api SplitResource 新增 member_issue_ids（≤50）批量契约，单条拆分原为原子 UPDATE 无事务
- 实现: 批量逐条调 _mark_split（条件 UPDATE WHERE status=active，rowcount=0 记 skipped 幂等防并发/重复拆分），单条异常隔离记 failed 统一通用文案不透出内部细节；ES 重置按主 Issue 分组合并调 bulk_reset_for_split
- 被否决方案: 整批事务（rejected）——事务内多 member 关系改写，单条失败整批回滚；否决理由：单条拆分本身即为原子 UPDATE 无事务，整批事务会放大锁持有时间与死锁风险，且部分成功对拆分场景可接受（skipped/failed 逐条反馈、幂等可重试）
- 重新评估触发条件: 若拆分引入跨表/跨服务副作用需要原子性（如拆分联动 TAPD 状态回写），或调用方无法接受部分成功语义时
- 证据: `kernel_api/views/v4/issue.py` SplitResource.perform_request 批量分支 + `alarm_backends/tests/service/fta_action/test_issue_merge.py` TestSplitBatch
