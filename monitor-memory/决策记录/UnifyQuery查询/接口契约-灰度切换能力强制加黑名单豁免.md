【决策记录｜UnifyQuery 灰度数据源切换判定采用能力强制开启加黑名单反向豁免】
- 分类：接口契约
- 动机：避坑（原生路径不支持某能力时静默出错）、止损（出问题时用黑名单快速切回而非改代码发布）
- 决策：灰度数据源的 switch_unify_query 采用黑名单语义，默认走统一查询，命中黑名单的业务不走；同时把仅统一查询支持的能力设为无条件开启：_value 排序（TopK）、query_string 非星号（nested 场景）、日志聚类表 _clustered 后缀、自定义事件 group_by 含 type（聚合补 0）直接返回 True；黑名单中星号表示全部业务不走。计算平台走另一套白名单灰度：web 角色恒走、有 functions 恒走、metrics 多于一个视为特殊逻辑不走改用 bksql、灰度期按 BKDATA_USE_UNIFY_QUERY_GRAY_BIZ_LIST 判定且列表含 0 即全量
- 背景约束：黑名单用于线上快速止损，但某些能力原生路径根本没有，黑名单也无法把它们切回原生
- 被否决方案：统一用白名单（默认不走逐个放开），无相关记录；从现状看黑名单语义可让新业务自动纳入统一查询，减少维护成本
- 已知代价：黑名单命中即整业务降级，粒度粗无法按场景豁免；与能力强制开启规则冲突时以能力优先，黑名单对该场景无效
- 重新评估触发条件：出现某能力需要按业务维度豁免的需求（当前黑名单无法覆盖）；或黑名单长期为空可移除
- 关联代码：BaseBkMonitorLogDataSource.switch_unify_query（TopK _value 与 nested query_string 与黑名单）、LogSearchTimeSeriesDataSource.switch_unify_query（日志聚类 _clustered 后缀加黑名单）、BkMonitorLogDataSource.switch_unify_query（自定义事件 group_by 含 type 聚合补 0，子类 CustomEventDataSource 继承）、BkdataTimeSeriesDataSource.switch_unify_query（灰度业务列表加特殊场景豁免）@ data_source/__init__.py
- 证据来源：代码注释（如果业务在黑名单中则不使用 UnifyQuery、星号在黑名单中则不使用、_value 是内置的聚合排序 TopK 关键字仅 UnifyQuery 支持、query_string 可能存在 nested 场景仅 UnifyQuery 支持、聚合补 0 仅 UnifyQuery 支持、不支持一次查询多个指标使用 bksql、灰度状态灰度业务列表不包含 0 业务表示灰度中）
