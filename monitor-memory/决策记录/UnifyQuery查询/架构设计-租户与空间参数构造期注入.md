【决策记录｜UnifyQuery 租户与空间参数在构造期统一注入，不由调用方逐条拼装】
- 分类：架构设计
- 动机：避坑（多租户下漏传 bk_tenant_id 导致鉴权失败或跨租户数据误判）
- 决策：UnifyQuery 构造时未显式传 bk_tenant_id 则由 bk_biz_id 推导，推导失败则记录 warning 并取 DEFAULT_TENANT_ID，随后对每个 data_source 调用 set_bk_tenant_id 注入；space_uid 由 bk_biz_id_to_space_uid 转换并以 cached_property 延迟计算
- 背景约束：多租户改造后每个子查询都必须带上租户标识，逐条拼装易漏
- 被否决方案：无（未找到相关记录）
- 已知代价：租户推导失败时静默降级为默认租户（只 warning），可能掩盖配置错误
- 重新评估触发条件：出现租户推导失败但未被发现的线上问题；或默认租户策略调整
- 关联代码：UnifyQuery.__init__、UnifyQuery.space_uid @ unify_query/query.py
- 证据来源：commit 3c2f49a154（数据查询模块支持多租户改造）、fe7bfc819b（unify-query 支持多租户主动传参）；代码注释（如果未传入租户 ID 则根据业务 ID 获取租户 ID、设置租户 ID）
