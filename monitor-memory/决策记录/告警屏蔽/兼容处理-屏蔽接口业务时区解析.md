【决策记录｜告警屏蔽 屏蔽接口的时间字段按业务时区解析与展示】
- 分类：兼容处理
- 动机：一致性（屏蔽时间由用户按本地时间填写与查看，后台统一存 UTC）
- 决策：屏蔽相关接口在出入参两侧做业务时区转换，详情与列表用 utc2biz_str 或 strftime_local 输出，解析用 localtime 或 str2datetime；周期屏蔽的时间处理同样基于业务时区
- 背景约束：DB 与告警引擎统一使用 UTC，而用户按业务所在时区理解几点到几点
- 被否决方案：统一用 UTC 或服务器时区，无相关记录；从现状看业务时区是明确选择
- 已知代价：时区转换分散在多个 Resource 与 DisplayManager 中，新增时间字段时容易漏做转换；跨时区业务的屏蔽展示需按各自业务时区渲染
- 重新评估触发条件：出现跨时区业务的时间展示错误；或统一改为前端负责时区渲染
- 关联代码：AddShieldResource、EditShieldResource、ShieldDetailResource、FrontendShieldListResource 的时间转换 @ monitor_web/shield/resources/；ShieldDisplayManager @ bkmonitor/utils/shield.py
- 证据来源：commit 40c0c40403 与 586259c915（屏蔽相关接口支持时区）、393ce1df90（屏蔽时间处理逻辑问题）；代码实现（utc2biz_str、strftime_local、localtime 调用）
