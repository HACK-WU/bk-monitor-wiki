【决策记录｜窗口快照仅溯源不参与关闭判定】
- 分类：接口契约
- 动机：一致性（关闭与否必须反映屏蔽配置的最新状态，而非接管时刻的旧状态）
- 决策：接管时把窗口快照写入 extra_info.shield_end_close_config（shield_id / window_begin / window_end），但关闭任务只消费 shield_id，到期判定重新按 DB 中该屏蔽的 cycle_config / begin_time / end_time 实时构造 matcher 计算
- 背景约束：屏蔽创建后时间可被 EditShieldResource 修改、可被解除（is_enabled=False）或软删除；按快照判到期会出现配置已缩短却仍等旧窗口、或配置已延长却提前关闭
- 被否决方案：
  - 按快照 window_end 直接判到期：否决理由 —— 无相关记录，从实现看选择实时读 DB
- 重新评估触发条件：需要按「屏蔽原定结束时间」口径关闭
- 关联代码：CloseShieldMatcher._match @ alarm_backends/service/converge/shield/close.py；shield_is_active @ alarm_backends/service/alert/manager/shield_tasks.py
- 证据来源：代码实现（shield_tasks 仅 config.get("shield_id")，window_begin / window_end 无任何消费方；shield_is_active 用 close_time_matcher(shield.cycle_config, shield.begin_time, shield.end_time) 实时构造）；代码注释（shield_tasks.py：「只检查本轮配置的状态与时间；不重匹配维度，不回放短时变更」）
