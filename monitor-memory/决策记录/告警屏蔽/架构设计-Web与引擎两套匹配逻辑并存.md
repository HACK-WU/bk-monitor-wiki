【决策记录｜推测 告警屏蔽 Web 层与引擎层两套匹配逻辑并存，未合并】
- 分类：架构设计（本条为推测，置信度低于其他条目，查询侧请降级使用）
- 动机：性能取舍（Web 层只需快速判断，引擎层需精确匹配）
- 决策：ShieldDetectManager（Web 侧，集合交集快速检测，用于策略列表页判断是否被屏蔽）与 ShieldObj（引擎侧，条件树加时间匹配精确判定）并存，各服务各场景，未抽取公共匹配内核
- 背景约束：Web 层面向策略列表页是否被屏蔽这类高频轻量判断；引擎层面向告警是否真的被屏蔽的精确判定，两者输入（策略维度与告警维度）与精度要求不同
- 被否决方案：无（未找到相关记录）
- 已知代价：两套逻辑不可混用，Web 层结果只能用于展示性判断，不能作为告警是否被屏蔽的依据；两边语义漂移时不易发现
- 重新评估触发条件：出现 Web 层显示已屏蔽但引擎未屏蔽或反之的反馈；或需要统一的屏蔽预检能力
- 关联代码：ShieldDetectManager @ monitor_web/shield/utils.py；ShieldObj @ converge/shield/shield_obj.py
- 证据来源：无直接证据说明为何不合并，基于两套实现的并存结构、各自用途差异与 C0 已知坑 3「不要混用」的提示推断
