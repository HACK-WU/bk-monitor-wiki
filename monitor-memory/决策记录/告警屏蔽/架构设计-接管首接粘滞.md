【决策记录｜接管首接粘滞：已接管的告警不再重新匹配】
- 分类：架构设计
- 动机：避坑（每轮重匹配 → 屏蔽窗口滑动或配置变更时归属在轮次间跳变，关闭依据 shield_id 漂移）
- 决策：CloseShieldMatcher.take_over 入口即判断 alert.shield_end_close，已接管直接 return；接管后 shield_end_close_config 中的归属 shield_id 不再改写
- 背景约束：同一条告警会被反复处理（事件更新、状态检查、多轮 builder），归属必须稳定才能作为关闭依据
- 被否决方案：
  - 每轮重新匹配取当前最优：否决理由 —— 无相关记录，从实现看选择首接粘滞
- 重新评估触发条件：出现「应被新屏蔽接管却停留在旧归属」的反馈
- 关联代码：CloseShieldMatcher.take_over @ alarm_backends/service/converge/shield/close.py
- 证据来源：代码实现（take_over 首行 if alert.shield_end_close or not alert.is_abnormal(): return）；测试实现（test_shield_close.py 中已接管告警二次 take_over 后 shield_end_close_config 的 shield_id 保持不变）
