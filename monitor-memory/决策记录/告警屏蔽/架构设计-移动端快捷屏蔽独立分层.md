【决策记录｜告警屏蔽 移动端快捷屏蔽独立分层：绕过 CSRF、权限下沉、自动推导 dimension_config】
- 分类：架构设计
- 动机：可维护性（移动端限制无法复用标准屏蔽链路，只能另开入口）
- 决策：QuickShield 独立于 ShieldViewSet，具备独立的 ViewSet、认证与权限模型：EventViewSet 使用 NoCsrfSessionAuthentication 绕过 CSRF，get_permissions 返回空列表把权限交给 Resource 自身做宽松校验，QuickShield.handle_scope、handle_strategy、handle_event 从事件数据自动推导 dimension_config，移动端只需传 type、event_id、end_time
- 背景约束：移动端（微信 WebView）CSRF 机制不可靠；移动端用户通常无 MANAGE_DOWNTIME 权限；移动端无法构造完整的 dimension_config
- 被否决方案：复用标准 ShieldViewSet 链路，否决理由为上述三条约束下走不通（CSRF 校验失败、权限不足、参数构造不出）
- 已知代价：quick_shield 与 add_shield 最终都调用 AddShieldResource，但 quick_shield 跳过大量处理——不更新 AlertDocument.is_shielded、不检查重复屏蔽、不处理通知、不校验 MANAGE_DOWNTIME 权限；两个 quick_shield 接口（QuickShield POST 返回 JSON 与 QuickAlertShield GET token 验权返回 HTML 重定向）易混淆
- 重新评估触发条件：移动端需要通知、重复检测或 ES 状态同步能力（届时不能简单走 quick_shield）
- 关联代码：QuickShield @ 移动端事件侧 ViewSet；AddShieldResource @ monitor_web/shield/resources/backend_resources.py
- 证据来源：C0 已知坑 9、10、11 条目（2026-07-28 资产沉淀时记录的设计说明，含上述三条背景约束）；代码实现（认证类与 get_permissions 覆写）
