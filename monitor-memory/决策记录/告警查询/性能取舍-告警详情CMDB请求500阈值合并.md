【决策记录｜告警查询 告警详情 CMDB 关联查询：小于等于 500 个主机 ID 时合并为单次请求】
- 分类：性能取舍
- 动机：优化（告警详情按主机 ID 查 CMDB 时存在额外计数请求与重复调用）
- 决策：精确主机 ID 不超过 500 个时单次查询 CMDB，避免额外计数请求；空主机 ID 列表直接返回；单页结果不完整时回退原分页逻辑；告警详情只请求拓扑富化需要的五个主机字段
- 背景约束：告警详情的关联信息展示是高频路径，CMDB 调用次数与字段量直接影响响应
- 被否决方案：统一走分页或批量请求，否决理由为小批量场景下计数请求是纯浪费；commit 明确超过 500 个唯一主机 ID 时保留原分页路径（即不搞一刀切）
- 已知代价：500 是硬阈值，超过后行为回退（优化不覆盖大结果集）；通用 batch_request 未改动，其他调用方不受益
- 重新评估触发条件：CMDB 接口支持更大的单次批量；或出现 500 边界附近的性能差异反馈
- 关联代码：告警详情关联信息与主机信息查询 @ packages/fta_web/alert/resources.py
- 证据来源：commit 458460c006（body 变更内容三条、变更边界三条、48 passed 测试）；commit 85cc50592f（优化告警详情关联信息的无效 CMDB 调用）
