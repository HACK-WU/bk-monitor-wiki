【决策记录｜告警查询 bk_biz_ids=-1 是全业务哨兵，必须展开为授权业务集后才能过滤】
- 分类：接口契约
- 动机：避坑（把 -1 当真实业务 ID 塞进 ES terms 会查不到任何告警，total=0）
- 决策：BaseBizQueryHandler.parse_biz_item 在构造期把 -1 解析为用户实际授权的业务集（authorized_bizs）；经 resource.alert.* 或直接构造 AlertQueryHandler 都会自动展开，切勿把 -1 直接写进 ES terms 过滤
- 背景约束：-1 是全部业务的前端标记，不是真实业务 ID，也不应出现在 unauthorized_bizs 里（commit bdc35a27d2 已把它归一化移除）
- 被否决方案：把 bk_biz_ids 原样透传给 ES，否决理由为会查不到任何数据
- 已知代价：展开结果依赖 IAM 授权集，授权为空时业务子句为空（由 fail-close 兜底）；下游若绕过 handler 直接查 ES 会踩这个坑
- 重新评估触发条件：引入新的全部业务表达方式（需同步所有 handler 的解析）
- 关联代码：BaseBizQueryHandler.parse_biz_item @ packages/fta_web/alert/handlers/base.py；get_biz_filter_ids
- 证据来源：C0 已知坑 1（切勿把 -1 直接塞进 ES terms 过滤）；commit 71b100a2dd（新增 get_biz_filter_ids 收口 bk_biz_ids 的 -1 哨兵，防按业务过滤查空复发）
