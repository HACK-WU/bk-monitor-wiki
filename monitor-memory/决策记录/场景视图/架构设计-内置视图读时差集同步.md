【决策记录｜场景视图内置视图采用读时对齐保证幂等存在，同步策略因场景而异】
- 分类：架构设计
- 动机：避坑（内置视图定义随版本演进而业务侧无视图行 → 页面空白）、降本（免为每个环境执行迁移脚本）
- 决策：每次视图列表/详情读取前先执行 create_default_views，把 JSON 骨架定义的视图与 DB 已存在视图对齐；对齐策略由各场景 Processor 自行实现，分三类：第一类双向差集（新增加删除）为 NormalProcessorMixin（alert 场景）、HostBuiltinProcessor（仅 view_type 为 detail 才执行）、KubernetesBuiltinProcessor、ApmBuiltinProcessor（删除只按 bk_biz_id 加 scene_id 过滤，未按 type 收敛，删除面更宽）；第二类仅首次补齐、已有视图即跳过从不删除，为 CollectBuiltinProcessor 及其子类 custom_event/custom_metric/observation_scene 与 UptimeCheckBuiltinProcessor；第三类完全不建默认视图，为 CustomMetricV2BuiltinProcessor（默认视图为自由视图）
- 背景约束：内置视图定义随版本演进会增删改；视图按 bk_biz_id 加 scene_id 加 type 逐业务逐类型落库；模块无独立迁移入口（tasks.py 为空占位）
- 被否决方案：无（未找到相关记录）
- 已知代价：删除分支只存在于第一类场景，这些场景下 JSON 骨架文件临时缺失或改名即物理删除 DB 视图行，APM 场景删除还跨 type 生效；第二三类无删除风险，但内置视图增删改不会自动同步到 DB
- 重新评估触发条件：出现用户自建视图被内置同步删除的线上工单；或单场景内置视图数 > 50 且列表接口 P95 > 500ms
- 关联代码：NormalProcessorMixin.create_default_views @ scene_view/builtin/__init__.py；各 Processor 覆写的 create_default_views @ scene_view/builtin 下 host、kubernetes、apm、collect、uptime_check、custom_metric_v2.py；调用点 GetSceneViewResource.perform_request @ scene_view/resources/view.py
- 证据来源：各 Processor 的 create_default_views 实现（bulk_create 加差集 delete、已有视图即 return、直接 return 三种分支）；commit 58d27694cc（该机制同文件的线上事故修复）
