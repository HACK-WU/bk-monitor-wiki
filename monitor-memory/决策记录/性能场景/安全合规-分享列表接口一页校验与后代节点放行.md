【决策记录】
- 分类：安全合规
- 动机：优化，避坑：校验若仍拉全量，分享场景的页级优化会被自己抵消
- 决策：新增 HOST_LIST_ACTIONS（SearchHostInfoViewSet 与 SearchHostMetricStatsViewSet 的 create），get_allowed_hosts 对这两个接口只取 page=1、page_size=1 做存在性校验；check 对它们跳过 query_configs_check 改走 params_check；params_check 仅对 stats 接口或带 page 的 info 放行授权节点的后代节点（bk_host_id 用 get_host_page 反查、拓扑节点用拓扑链判断），其余落回原严格校验
- 背景约束：分享令牌只能访问授权子集；页级接口的 page_size 不能用来做范围校验（校验需要全量，与优化目标冲突）
- 被否决方案：沿用拉全量后校验：否决理由——与页级优化目标冲突
- 重新评估触发条件：出现绕过校验的越权反馈；或分享新增范围维度（如按集群分享）
- 关联代码：HostApiAuthChecker.HOST_LIST_ACTIONS @ bkmonitor/share/handler.py:193；get_allowed_hosts @ bkmonitor/share/handler.py:208；params_check @ bkmonitor/share/handler.py:291
- 证据来源：代码注释（bkmonitor/share/handler.py:209-217：这两个接口直接校验 scope 参数，无须为存在性检查构造整棵拓扑的 Host）；PR 描述（分享分页和统计校验授权子范围，页级指标保持授权根和明确 IDs）；测试 test_host_page_share_scope.py
