【决策记录｜性能场景 分区部分失败时保留已返回数据，不整块丢弃（含 fail_on_incomplete 的一次反复）】
- 分类：接口契约
- 动机：避坑（少量缺失导致整个主机列表不可用）、可观测性（失败必须留日志）
- 决策：SearchHostMetricResource.perform_request 对 4 路 future 逐个 get 并单独 try 与 except 记录日志（logger.exception get host metric section failed），单路失败不影响其它路；传递给 UQ 的 fail_on_incomplete 为 False，即不因部分不完整而整块判定失败
- 背景约束：策略经历过一次反复：d5fd6d16cb（2026-08-12）修复主机指标线程异常与部分结果被伪装为正常值；07c4e20586（2026-08-13）给 agent_status、performance_data、process_status 三路传 fail_on_incomplete 为 True（严格模式，不完整即视为失败并暴露为未知，不再伪装正常）；4faf55fb50（2026-08-20）改为 False 并确立 partial 或单指标异常时保留已返回数据
- 被否决方案：部分不完整即整块失败（返回空或报错），否决理由为少量缺失会丢弃同一分区内已可用的数据
- 已知代价：调用方可能拿到部分字段为未知的半完整记录；失败原因只在日志中，接口响应不体现
- 重新评估触发条件：出现半完整数据被下游误当作完整数据使用的问题；或需要把分区失败原因回传给前端
- 关联代码：SearchHostMetricResource.perform_request（逐路 try 与 except 加 metric_kwargs）@ monitor_web/performance/resources.py
- 证据来源：代码注释（主机列表优先返回 UQ 已取得的记录，partial 或单指标失败时未取得的字段保持未知，不能因为少量缺失丢弃同一分区内已经可用的数据）；commit d5fd6d16cb、07c4e20586（diff 显示三路改为 fail_on_incomplete 为 True）、4faf55fb50
