【决策记录】
- 分类：接口契约
- 动机：避坑：阈值取整规则不一致，同一台主机在列表里被算作超阈值、在卡片里不算
- 决策：统计表达式写 count(a 大于等于 79.995) 与 count(b 大于等于 79.995)；79.995 是使 Python round(value, 2) 大于等于 80 成立的最小 float64，其前一个相邻浮点数 round 后是 79.99
- 背景约束：列表侧对 cpu_usage、mem_usage、disk_in_use 的阈值判定是两位小数取整后大于等于 80，卡片统计必须同口径
- 被否决方案：直接写大于等于 80 或用 PromQL round(v, 2) 大于等于 80：否决理由——与列表侧取整口径不一致（PromQL round 的中点规则与 Python 不同）
- 重新评估触发条件：列表侧改为不按两位小数取整；或阈值改为可配置
- 关联代码：build_host_stats_query 表达式 @ host_metric_stats.py:48
- 证据来源：代码注释（host_metric_stats.py:48：79.995 是使 Python round(value,2) 大于等于 80 的最小 float64，避免 PromQL round 的中点规则差异）；测试 test_stats_threshold_matches_python_two_decimal_rounding
