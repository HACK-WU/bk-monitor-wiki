【决策记录｜性能场景 进程信息是半实时语义：CMDB 当前快照加时间窗仅作用于存活状态】
- 分类：接口契约
- 动机：一致性（明确界定哪些字段会随时间变化、哪些不会，避免调用方误解）
- 决策：get_process_status 返回的进程基本信息（名称、端口、启动命令、用户等）取 CMDB 当前快照，不支持历史查询；start_time 与 end_time 仅作用于进程存活状态判定（system.proc_port 的 proc_exists 指标）。即选择历史时间后，进程列表仍是当前 CMDB 数据，只有进程启停状态与所选时间窗口一致
- 背景约束：CMDB 进程配置不保存历史版本；进程存活状态来自时序指标，可按时间窗查询
- 被否决方案：无（未找到相关记录）
- 已知代价：历史时间点查询时，进程列表与当时真实配置可能不一致（已改名或改端口的进程按当前配置展示）
- 重新评估触发条件：CMDB 支持进程配置历史版本；或出现历史视图下进程配置与实际不符的业务反馈
- 关联代码：SearchHostMetricResource.get_process_status 与 HostPerformanceResource.get_process_status @ monitor_web/performance/resources.py
- 证据来源：代码 docstring（注意：CMDB 进程基本信息（名称、端口、命令等）为当前快照，不支持历史查询；start_time 与 end_time 仅作用于进程存活状态判定（system.proc_port 的 proc_exists 指标）。选择历史时间后，进程列表仍反映当前 CMDB 数据，但进程启停状态与所选时间窗口一致）
