【决策记录】
- 分类：架构设计
- 动机：优化
- 决策：SearchHostInfoResource 增加可选 page 与 page_size，成对传入时改走 CMDB 端过滤分页只取本页；前端一次 loadData 并发三条链（页链、全量链、卡片链）；全量算完后表格与统计卡片在同一轮 Vue 更新中一起接替，页级与单卡响应全部失效；全量未就绪期间前端禁用全局排序、过滤、置顶、跨页全选
- 背景约束：全量请求耗时由最慢一路决定，不能作为首屏前置；排序与跨页全选依赖全量集合，页级阶段无法给出一致结果，只能禁用
- 被否决方案：等全量数据回来再渲染（原实现）：否决理由——首屏与交互被全量请求阻塞
- 重新评估触发条件：真实 CMDB 与页级接口联调后发现页级与全量口径不一致；或线上首屏收益不达预期（PR 待办验收项）
- 关联代码：SearchHostInfoResource.perform_request @ bkmonitor/packages/monitor_web/performance/resources.py:369；useHostListData.loadPageData、retryFullData、refreshList @ webpack/src/trace/pages/host/composables/use-host-list-data.ts:152、237、191
- 证据来源：PR #12574 描述（先展示当前页基础信息及指标，全量请求在后台并发进行；全量完成后表格和统计卡片一起切换到同批数据）；代码注释（use-host-list-data.ts:190：Vue 在同一轮更新中提交表格及统计，之后页级与独立统计响应均失效）
