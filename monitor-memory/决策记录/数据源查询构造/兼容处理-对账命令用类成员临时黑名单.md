【决策记录｜数据源查询构造 提供对账命令，用类成员临时黑名单做切换前后一致性比对】
- 分类：兼容处理
- 动机：避坑（切换统一查询后口径变化不易察觉，需要可复现的 A 与 B 比对手段）
- 决策：新增管理命令 reconcile_log_strategy，通过临时改写 LogSearchTimeSeriesDataSource.LOG_UNIFY_QUERY_BLACK_BIZ_LIST 类成员变量，分别在强制日志平台数据源与强制 UnifyQuery 下执行同一策略的查询并比对结果；比对时移除最后一个时间点的数据（注释：因为日志平台数据源可能存在最后一个时间点数据不稳定的情况）
- 背景约束：线上黑名单来自环境变量或 DB 全局配置，不便为对账临时修改；类成员变量优先级高于环境变量，可在进程内临时覆盖
- 被否决方案：无（未找到相关记录）
- 已知代价：类成员变量是进程级全局状态，对账过程中若并发执行真实查询会受影响；命令内以 finally 恢复为 None，但异常中断仍有残留风险
- 重新评估触发条件：对账完成、日志数据源切换全量稳定后可移除该命令与 LOG_UNIFY_QUERY_BLACK_BIZ_LIST 类成员
- 关联代码：LogSearchTimeSeriesDataSource.LOG_UNIFY_QUERY_BLACK_BIZ_LIST 与 _fetch_black_list @ data_source/data_source/__init__.py；reconcile_log_strategy 命令 @ management/commands/reconcile_log_strategy.py
- 证据来源：命令 docstring（本命令用于验证日志平台数据源切换到 unify-query 前后查询结果的一致性，通过临时黑名单分别强制使用日志平台数据源和 UnifyQuery 比较两种查询方式的结果是否一致）；代码注释（用于灰度对账的临时黑名单列表类成员变量，对账完成后会清空此列表以恢复正常逻辑；仅用于命令行对账，线上环境恒定为 None；移除最后一个时间点的数据如果存在，因为日志平台数据源可能存在最后一个时间点数据不稳定的情况）
