【决策记录｜推测 数据源查询构造 中 7 个组合恒走原生路径，未纳入统一查询灰度】
- 分类：架构设计（本条为推测，置信度低于其他条目，查询侧请降级使用）
- 动机：可维护性（这些后端与统一查询的查询模型差异大，接入成本高）
- 决策：以下 7 个组合既不在 UnifyQueryDataSources 也不在 GrayUnifyQueryDataSources，use_unify_query 恒返回 False 直连各自后端：PROMETHEUS 加 TIME_SERIES（PromQL 直查）、BK_MONITOR_COLLECTOR 加 EVENT 与 ALERT（直连 ES）、BK_FTA 加 EVENT 与 ALERT（直连 ES）、BK_APM 加 TIME_SERIES 与 BK_RUM 加 TIME_SERIES（metadata 或 ES）。注意 APM 与 RUM 的日志组合已灰度接入，但两者时序组合均未接入
- 背景约束：无直接证据说明未接入原因；从查询形态看，PromQL 直查与事件告警的文档模型与统一查询的时序与日志查询模型差异较大
- 被否决方案：无（未找到相关记录）
- 已知代价：这些组合无法享受统一查询的多源关联与表达式计算能力；使用方必须按原生路径的行为预期处理返回
- 重新评估触发条件：统一查询后端支持 PromQL 直查或事件告警文档模型；或 APM 与 RUM 时序检索需要多源关联能力
- 关联代码：UnifyQueryDataSources 与 GrayUnifyQueryDataSources @ constants/data_source.py；PrometheusTimeSeriesDataSource、BkMonitorEventDataSource、BkMonitorAlertDataSource、BkFtaEventDataSource、BkFtaAlertDataSource、BkApmTraceTimeSeriesDataSource、BkRumTimeSeriesDataSource @ data_source/data_source/__init__.py
- 证据来源：无直接证据，基于两个常量列表未包含这 7 个组合、且各原生数据源类均独立实现 query_data 与 query_log 直连后端的结构推断
