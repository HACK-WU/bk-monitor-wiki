【决策记录｜数据源查询构造 load_data_source 注册表用显式类列表加每次调用重建映射，未注册组合直接抛 KeyError】
- 分类：架构设计
- 动机：可维护性（组合数量可控，显式列表一眼可查全部数据源）
- 决策：load_data_source 在函数体内硬编码数据源子类列表，每次调用都用字典推导重建 label 加 type 到类的映射后取键；组合未注册时直接抛 KeyError，无兜底类、无降级、无业务异常封装
- 背景约束：组合数量可控（当前 16 个类）；调用方几乎都从元数据拿 data_source_label 与 data_type_label，理论上不会出现未注册组合
- 被否决方案：无（未找到相关记录）
- 已知代价：新增数据源必须改这个列表，漏改即运行时 KeyError；每次调用重建映射有微小开销；调用方拿到 KeyError 而非可读业务异常
- 重新评估触发条件：注册组合数大于 30；或需要插件化或装饰器自动注册（如第三方数据源动态接入）
- 关联代码：load_data_source @ data_source/data_source/__init__.py
- 证据来源：代码实现（函数内列表加字典推导加直接下标取值）
