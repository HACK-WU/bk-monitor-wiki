【数据流｜分派规则组与规则配置】
- 实体类型：数据结构（前端提交体，前端侧无持久化）
- 结构：规则组 {id, name, priority(1~10000 越大越优先), edit_allowed} + 规则 {id?, user_groups[], conditions[{condition,and|or,field,method,value}], actions[notice{is_enabled,upgrade_config} 或 itsm{action_id}], alert_severity(0保持原样~3提醒), additional_tags[{key,value}], is_enabled}；组级提交体 = {bk_biz_id, assign_group_id, priority, group_name, rules[], settings:{public_conditions}}
- 生产方：createAssignGroup / partialUpdateAssignGroup（组级，列表页行内编辑即时落库）/ batchUpdate（整组规则，配置页「调试并生效」，经 matchDebug 试算）：bkmonitor/webpack/src/monitor-api/modules/model.js 与 modules/assign.js；提交体由 RuleData.getSubmitParams 生成 @ alarm-dispatch/typing/index.ts
- 主要消费方：后端 fta assign 引擎（AssignInfoEnricher 在告警构建链执行分派动作与内容调整 @ alarm_backends/service/alert/enricher/rule_assign.py）；本模块列表页/配置页回读；告警流转记录（?group_id= 跳回规则组）；告警组页「相关分派规则」（?groupName= 直达）
- 业务用途：定义「什么告警分派给哪些告警组、如何执行（通知/通知升级/ITSM流程套餐）、是否调整等级/追加标签」，是告警自动分派的唯一配置载体
- 详细流向：见 .module-experts/前端专题/告警分派专家/C4-数据流向与消费.md
