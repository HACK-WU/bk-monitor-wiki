【数据流｜调试试算数据（matchDebug）】
- 实体类型：数据结构（请求体=待保存规则快照；响应=命中告警；前端侧无持久化）
- 结构：请求 = 提交体 + {start_time, end_time}（删除模式为 {exclude_groups} + 时间窗）；响应 = [{group_id, group_name, priority, alerts_count, rules:[{user_groups, conditions, is_enabled, is_changed, alerts:[{id, severity, alert_name, metrics, content}]}]}]
- 生产方：DebuggingResult.getRuleMatchDebug @ bkmonitor/webpack/src/monitor-pc/pages/alarm-dispatch/components/debugging-result.tsx（打开调试抽屉时请求；默认时间窗 now-7d~now，可改并重查）
- 主要消费方：调试抽屉三级折叠展示（命中告警可跳告警中心）；配置页保存链复用同一份 debugData 提交 batchUpdate（调试所见即保存所提交）
- 业务用途：「保存/删除」前的效果预览闸门——用户看到规则实际命中哪些告警（时间窗内前 1000 条）再确认；删除动作的「影响面预览」
- 详细流向：见 .module-experts/前端专题/告警分派专家/C4-数据流向与消费.md
