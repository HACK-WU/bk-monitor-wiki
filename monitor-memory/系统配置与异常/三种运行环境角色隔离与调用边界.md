三种运行环境角色隔离与调用边界：web（monitor_saas）、api（kernel_api）、worker（Celery Worker/Beat）三种角色在部署层面为独立进程/容器，通过 INSTALLED_APPS 差异与 ROOT_URLCONF 形成架构硬隔离，monitor_saas 调用告警后台必须经 API 网关访问 kernel_api。

> 来源：`settings.py` + `config/role/{web,api,worker}.py` 联动分析

## 配置加载顺序

```
settings.py
    ↓ config.default          (基础 INSTALLED_APPS / DATABASES / MIDDLEWARE)
    ↓ blueapps.patch          (蓝鲸 PaaS 框架 patch)
    ↓ config.{env}            (dev/stag/prod 环境覆盖)
    ↓ config.role.{role}      (web / api / worker 角色覆盖)
```

## 三种角色核心差异

| 角色 | 部署实体 | 关键文件 | ROOT_URLCONF | alarm_backends 在 INSTALLED_APPS？ |
|------|---------|---------|-------------|-----------------------------------|
| **web** | monitor_saas | `config/role/web.py` | `"urls"` | 否 |
| **api** | kernel_api   | `config/role/api.py` | `"kernels_api/urls"` | 是（通过 `from config.role.worker import *`） |
| **worker** | Celery Worker / Beat | `config/role/worker.py` | `"alarm_backends/urls"` | 是 |

## 关键代码路径

- 位置: `bkmonitor/config/role/web.py` — `INSTALLED_APPS += (...)` 追加 `monitor_web`、`fta_web`、`weixin`、`apm_web`、`iam`、`bkoauth`，**不含 `alarm_backends`**。
- 位置: `bkmonitor/config/role/worker.py` — `INSTALLED_APPS = INSTALLED_APPS + ("alarm_backends", ...)`，**不含 `monitor_web`/`fta_web`/`weixin`**。
- 位置: `bkmonitor/config/role/api.py`：
  ```python
  from config.role.web import *
  from config.role.worker import *
  ```
  然后通过 `INSTALLED_APPS += ("kernel_api", "bkmonitor")` 同时持有 SaaS + Worker 两类 APP。

## 调用边界结论

```
monitor_saas (web 角色)
    │
    ├── 直接调用 → monitor_web / fta_web / weixin 等 (✅ 同进程内)
    │
    ├── 直接调用 → alarm_backends 模块 (❌ 非 INSTALLED_APPS，不可 import)
    │
    └── API 网关 → kernel_api (api 角色)
                        │
                        └── 直接调用 → alarm_backends 模块 (✅ 已挂载)
```

**核心约束**：monitor_saas 若需调用告警后台（策略缓存、告警检测、通知发送等），**必须通过 API 网关访问 kernel_api**，由 api 角色进程中转。三种角色在部署层面为独立进程/容器，形成架构硬隔离。
