## 四态标记定义与设计取舍

### 状态定义（B-01 接口专用）

| 状态 | 含义 | 用户可见文案 | 触发场景 |
|------|------|-----------|---------|
| `bound` | 已关联（绑定记录存在且正常） | 「已关联」 | `TapdWorkspaceBinding` 存在，且 `status=normal`、同步校验通过 |
| `stale` | 已关联但异常（需修复） | 「去关联」 | `TapdWorkspaceBinding` 存在，但同步校验失败（如项目 ID 变更、权限失效） |
| `importable` | 有权限但尚未关联（一步可完成） | 「去关联」 | TAPD 项目侧已授权给当前用户，但尚未创建绑定记录 |
| `unbound` | 完全未关联（需要走过应用态授权流程） | 「去关联」 | 未安装或未授权 |

### B-07 不返回 `is_bound` 的原因

- B-07 调用的是 TAPD 用户态 API（`/workspaces/get_workspaces`），返回的是「用户在 TAPD 上能看到的项目」
- B-01 在 B-07 原始数据上叠加了蓝鲸侧的绑定状态（四态），因此数据结构天然不同
- **设计原则**：「TAPD 能看到的所有项目」≠「已关联的项目」；如果强行让 B-07 返回绑定状态，需要逐条查库，性能差且语义混乱

### 同步机制
- 同步状态（Pending → Running → Success / Failed）与四态标记是独立轴线
- 成功同步 → `status=normal`，异常 → `status=stopped` 或进入 stale（视具体错误类型）
