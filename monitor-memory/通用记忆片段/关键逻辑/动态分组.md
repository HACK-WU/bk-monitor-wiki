动态分组（Dynamic Group）是 CMDB 提供的「按条件自动变化的主机集合」，监控平台不维护它，只作为消费方把它展开成主机列表，用于策略监控目标、告警屏蔽范围、告警分派/通知订阅条件、无数据告警目标、采集部署目标、as_code 策略即代码等场景。
- 类型枚举: `TargetFieldType.dynamic_group`（constants/strategy.py）、`ScopeType.DYNAMIC_GROUP`（constants/shield.py）、`TargetNodeType.DYNAMIC_GROUP`（采集）
- 后台缓存: `DynamicGroupManager`（alarm_backends/core/cache/cmdb/dynamic_group.py），Redis hash `cache.cmdb.dynamic_group`，TTL 7 天；由 BMW daemon `daemon:alarm:cmdb_cache_refresh` 错峰全量刷新，动态分组刷新周期约 6827s（~113.8min），故变更生效有分钟级延迟
- 展开逻辑（CMDB 动态分组 → 主机）: `AssignCacheManager.parse_dynamic_group`（core/cache/assign.py）把条件字段 dynamic_group 转成 bk_host_id；`bkmonitor/utils/range/target.py` 转成 bk_target_ip；`shield_obj.py` 解析屏蔽范围；`nodata/scenarios/base.py` 无数据目标解析；`action/alert_assign.py:get_host_ids_by_dynamic_groups` 实时调 `api.cmdb.batch_execute_dynamic_group`
- 前端/接口: `DynamicGroupHandler`（bkm_ipchooser/handlers/dynamic_group_handler.py）提供 list / execute / agent_statistics 三个接口
- 关键点: 仅支持主机动态分组（bk_obj_id == "host"），集群/业务类型有 TODO 未支持；动态分组查不到主机时补哨兵 id 0，保证规则有效但永不匹配（屏蔽场景下即不误屏蔽）
