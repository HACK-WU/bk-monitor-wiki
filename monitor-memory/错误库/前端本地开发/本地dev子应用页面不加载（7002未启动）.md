【错误库｜本地 dev 子应用页面不加载（7002 未启动）】
- 报错原文片段：浏览器 Network 中对 http://<devHost>:7002/... 的资源请求失败（连接被拒绝 / 无响应），子应用容器空白或一直 loading。注：未采集到真实控制台报错原文，此处为可预期表现，非实测堆栈
- 现象：只跑 pnpm run dev 时主应用能打开，但 APM / 主机监控 / 调用链检索 / 告警中心 / 告警屏蔽 / 故障详情 / RUM / RUM 探索 / 报表 / Profiling / 轮值 等页面空白或一直 loading；主应用自身页面正常
- 根因：前端是微前端多应用架构，pnpm run dev 等价 pnpm pc:dev，只启动主应用 monitor-pc，每个应用是独立 dev server；monitor-pc 内 13 处子应用容器硬编码请求 http://<devHost>:7002，而端口由 portfinder 从 devConfig.port(7001) 起抢占，故子应用必须占 7002 且必须先启主应用（否则主应用落到 7002 导致加载错乱）
- 解法：两个终端分别启动，先 make dev-pc（占 7001）再 make dev-vue3 或 dev-apm 或 dev-fta（占 7002）；用 lsof -i:7001 -i:7002 确认两个端口都在监听；一次只能挂一个子应用（7002 唯一），换调试目标先停旧的；若顺序反了导致主应用在 7002，两个进程全停后按序重启；端口被占用时不要依赖自动顺延
- 验证方式：lsof -i:7001 -i:7002 两个端口均有监听；打开目标子应用页面，Network 中打向 :7002 的资源请求返回 200
- 关联方案：无。页面到子应用的映射（trace 覆盖主机监控/告警中心/告警屏蔽/RUM/Profiling/报表/轮值，apm 与 fta 各自独立）与完整机制见 bkmonitor/webpack/wikis/local-dev.md；对应 skill 为 .codebuddy/skills/bkmonitor-dev-server（已内置双进程铁律）
