进程详情/主机进程指标视图切换工具栏「汇聚方法」（AVG/SUM/MIN/MAX）图表完全不变，不是查询 bug：面板生成时 system.proc 核心指标的 method 被硬编码，不含 $method 占位符，工具栏变量替换为空操作。
- 符号: `METRIC_METHOD` / `get_metric_panel`
- 位置: `bkmonitor/packages/monitor_web/scene_view/builtin/host.py`（METRIC_METHOD 定义约 110-117 行，method 取值约 231 行）
- 硬编码映射: cpu_usage_pct/mem_usage_pct/mem_res/mem_virt/fd_num → sum_without_time（跨 series 求和，配合 ignore_group_by 剔除 bk_host_id 实现同名进程组汇总）；uptime → MAX
- 补充语义: `*_without_time` 变体在查询构造时不加 xxx_over_time 时间窗口（`bkmonitor/data_source/data_source/__init__.py:1105-1117`），interval 仅用于普通方法的 window——因此调大汇聚周期对进程面板取数同样无效果，验证汇聚方法应去主机详情页（走 $method）
- UI 误导根因（2026-09-03 challenger 修正）: 配置层 process.json 的 panel_tool 本就未开启 method_select（host.json 才开启，配置意图是进程视图隐藏该方法选择器）；是新版前端 `webpack/src/trace/pages/host/components/host-metric/metric-toolbar.tsx:247-263` 无条件渲染汇聚方法选择器、未消费 panel_tool 配置，才导致用户可操作恒不生效的参数
- 修复建议: metric-toolbar 按 panel_tool.method_select 控制渲染（配置已就绪，改动最小）
