按时间窗查询 AlertDocument 时索引上界必须为 now，不能透传查询截止时间——ABNORMAL 文档每天被 reindex 搬运到当天索引，历史 end_time 收窄索引窗口会把未恢复告警误判为 0。

- 不变式: ABNORMAL 告警文档「每天被 rollover reindex（每24分钟一轮，worker.py 调度 */24 * * * *）搬到当天物理索引」；RESOLVED 文档永久停在状态切换那天的索引。因此告警查询窗口必须 [begin_time, now]。
- 关键配置: `AlertDocument.REINDEX_ENABLED=True` + `REINDEX_QUERY=filter(status=ABNORMAL)`（bkmonitor/documents/alert.py:34-35），reindex 源查询 = REINDEX_QUERY AND create_time >= 新切片日期（bkmonitor/utils/elasticsearch/ilm.py:739-801）。
- 权威注释（勿再误判为过期）: alert.get() 注释（alert.py:156-160）与 alert.mget() 注释（alert.py:183-184）均声明该模型；incident.py:210 亦佐证（incident 同机制）。
- 代码佐证: get()/mget() 的索引上界都是 now；mget 专门按 id 去重处理「reindex 过渡期同一告警在新旧索引各存一份」。
- 踩坑案例: get_host_alarm_count 曾把 end_time 传给 AlertDocument.search 收窄索引窗口，且按 now-end_time 扩 lookback——历史截止时间（如『昨天』）下索引窗口不含今天，未恢复计数=0（外部评审 Request changes 指出，AI 两轮 review 均未识破，第一轮还把权威注释误判为过期）。正确写法：`AlertDocument.search(days=days)` 上界恒 now，end_time 仅做 begin_time lte 文档级过滤；跨多日窗口 scan 时按 alert id 去重防双份计数。
