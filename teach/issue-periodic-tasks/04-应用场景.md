# 应用场景与待解决问题

## 一、这个模块解决什么痛点

[专用] Issue 的聚合发生在告警处理主链路，而主链路有两条硬约束：**必须快**（每条告警都要过一遍）、**必须不阻塞**（聚合失败不能拖垮告警处理）。这两条约束决定了主链路只能做"尽力而为的增量写入"，由此产生三类必须由周期任务解决的问题：

| 主链路的妥协 | 留下的坑 | 周期任务怎么补 |
|---|---|---|
| 抢锁失败就跳过 | 告警不进任何 Issue，静默丢失 | backfill 漏关联补偿 |
| 只写增量不重算 | `alert_count` / `impact_scope` 漂移 | 每 5 分钟全量重算 |
| 异常态无人发现 | 空 Issue 长期存在 | orphan 检测打 error |

一句话定位：**周期任务是主链路"性能与不阻塞"取舍的代价支付者**。

## 二、适用的场景

| 场景 | 说明 |
|---|---|
| 主链路瞬时失败后的自愈 | ES 抖动、Redis 超时、抢锁冲突导致的漏关联，5 分钟内自动补回 |
| 派生字段的最终一致 | `alert_count` / `last_alert_time` / `impact_scope` 允许秒级滞后，周期性收敛即可 |
| 配置变更后的影响范围重算 | 聚合维度改了，impact_scope 按新维度重新收窄 |
| LLM 示例冷启动 | 每小时把人类改名样本预热进 Redis，避免每次生成标题都查 ES |

## 三、不适用的场景（重要）

| 场景 | 为什么不适用 | 该用什么 |
|---|---|---|
| **实时性要求秒级** | 周期 5 分钟，端到端最坏延迟 >5 分钟 | 走主链路 `IssueAggregationProcessor`，别指望补偿 |
| **6 个月前的历史漏关联** | backfill 扫描下界硬限 7 天 | 管理命令 `backfill_issue_fingerprint` |
| **orphan Issue 自动清理** | 只打日志，无任何修复动作 | 人工介入，或用 bkm-cli 诊断 |
| **精确的一次性副作用** | 本模块所有逻辑都是幂等重算，无法承载"只做一次"的语义 | 不适合放这里 |
| **LLM 标题强制重生成** | 周期任务只管示例缓存，不管标题本身 | `regenerate_issue_llm_title`（管理命令 / API） |

## 四、待解决问题与技术债

| # | 问题 | 影响 | 位置 |
|---|---|---|---|
| 1 | **逐 Issue 发 ES 聚合请求 + 逐条 bulk_create** | 活跃 Issue 规模上万时，单轮耗时与请求数线性增长，可能超过 5 分钟周期导致丢轮次 | `issue_tasks.py#L180-L191`、`L217` |
| 2 | **backfill 7 天窗口的历史盲区** | 超过 7 天的漏关联告警周期任务不补，注释称"由 process 主路径兜底"，但主路径只处理新告警，实际无兜底 | `issue_tasks.py#L231`、`L320` |
| 3 | **orphan Issue 只报不修** | 空 Issue 会一直存在直到人工处理 | `issue_tasks.py#L198-L211` |
| 4 | **多集群重复执行** | 幂等所以不出错，但算力与 CMDB 缓存回源压力按集群数放大 | `worker.py#L241`、`L243` |
| 5 | **`_build_impact_scope` 单函数约 310 行** | 全文件最长的函数，混合了维度解析、CMDB 回填、K8S/APM 分流、序列化四种职责，可维护性与可测试性偏低 | `issue_tasks.py#L456-L767` |

> 以上为**描述性记录**，非质量裁决。若要判断"这些问题该不该修、怎么修"，请用 `code-review` 或 `artifact-optimizer`。

## 五、扩展点

| 扩展点 | 怎么加 |
|---|---|
| 新增统计字段 | 在 `_process_single_issue` 的 `update_doc` 里加字段，ES 聚合按需扩展 |
| 新增影响范围维度 | 在 `_allowed_scope_keys` 加映射规则 + `_build_impact_scope` 加提取与序列化分支 |
| 新增周期职责 | 在 `sync_issue_alert_stats` 主循环内加调用（注意保持幂等 + 单条异常隔离） |
| 新增独立周期任务 | 在 `worker.py` 的 `ACTION_TASK_CRONTAB` 注册，选 `cluster`（每集群跑）或 `global`（仅默认集群跑） |

> ⚠️ 新增 `cluster` 模式任务前务必确认逻辑幂等——多集群会重复执行。
